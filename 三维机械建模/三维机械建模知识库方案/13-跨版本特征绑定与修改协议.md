# 跨版本特征绑定与修改协议

2026-10-16；参考共同[16身份与范围](../../CAD识图评分/CAD图纸智能审查系统_全套建设文档/知识库重点建设方案/16-首轮实施与最小契约设计.md)、[19关系证据修订](../../CAD识图评分/CAD图纸智能审查系统_全套建设文档/知识库重点建设方案/19-真实工程样例B验证与方案修订.md)。本文把02的绑定原则展开为可实施协议，算法仍待验证。

## 1. 四种身份

- 工程对象ID：孔、槽、轴肩或零件的持久逻辑身份，来源于登记或显式建模计划。
- 对象revision：本次参数、作用关系和语义的版本。
- 表示version：模型文件/内存几何快照，绑定内容哈希与生产方法。
- 表示内实体locator：当前快照中的面/边/区域。只在其表示版本内有意义，不跨版本保证稳定。

同一孔可能由一个圆柱面，也可能因周期接缝、布尔分割或导入形成多个面。工程对象与拓扑实体必须允许一对多、多对一及部分区域，不能要求一个特征等于一个面。

## 2. 绑定记录

binding_id、object_ref/revision、representation_ref/version、entity_locators、semantic_role、scope_region、method_run_ref、support_refs、candidate_set、state、valid_for、invalidated_by。它是共同Relation/Observation的专门用法，未来统一合同；不另建三维来源事实库。

entity_locator可以包含原生持久句柄（仅当格式保证）、模型内索引和局部几何/拓扑定位。索引可作为当前快照地址，但不承担跨版本对象身份。显示网格三角形索引与BRep面索引也不可互换。

## 3. 候选生成与核对顺序

1. 优先使用可信生成步骤/内核历史映射（如果实际API提供且已验证），记录分裂/合并/删除。
2. 没有可靠历史时，使用所属零件、对象种类、局部frame、几何量区间、曲面类型、邻接和支撑关系生成候选。
3. 对候选执行任务相关核对：例如孔轴线、半径、轴向范围、开口/贯穿关系；几何相似分数不等于确认。
4. 唯一且证据足够时RESOLVED；多个等价候选AMBIGUOUS；无匹配UNRESOLVED；输入已变化未重定位INVALIDATED。
5. 记录选择/拒绝依据；需确认的只请求指定对象/范围，不让确认扩张到整件设计。

不能为了成功率默认按数组顺序选第一个，不能用“最近中心点”覆盖对称歧义。候选唯一但依据不足也不能自动RESOLVED。

## 4. 分裂、合并、删除和语义变化

|变化|处理|
|---|---|
|一个面分裂为多个面|验证并记录集合覆盖与所属同一特征，不改成其中任意一个|
|多面合并|保留共同支撑与区域映射；原局部语义不一定能直接移植|
|删除孔或切断槽|原对象可保留历史身份，新版本记录不存在/删除依据，不把未找到当删除|
|圆角替换锐边|旧边绑定失效，新的过渡面/边记录形成新关系|
|复制/镜像特征|创建不同工程对象/实例身份，不能因几何相同合并|
|保持几何但改功能意图|几何绑定可能有效，工程适用性和结论仍需重新判断|

无法证明拓扑映射完整时返回覆盖未知。面数相等、体积相同、哈希相似均不足以证明同一绑定或几何等价。

## 5. 修改协议

输入：base_model_version、object_revisions、知识/工况快照、变更要求、允许修改区和冻结约束。基版本变化即返回STALE_INPUT，重装配后再运行，不静默把旧计划施加到新模型。

步骤：固定输入快照 → 计算保守影响集合 → 对副本执行候选计划 → 记录拓扑/参数变化 → 使受影响绑定和结论失效 → 重定位/重新验证 → 保存新表示版本 → 发布范围化结果。失败保留候选与诊断，旧已验收版本不变。

几何生成与发布可以分阶段：worker写临时模型/日志并fsync或校验完整性，生成内容manifest；共同发布服务在事务中登记结果引用并切换当前版本。发布前崩溃的临时文件不成为已发布模型；事务后崩溃应可按manifest回查。跨SQLite与文件系统不存在天然单事务，需显式staged→verified→registered协议与幂等恢复，不能写“原子发布”就假定已经解决。

首阶段可采用串行发布者、不可变文件、共同目录事务及孤儿清理清单。外置盘离线时不切换当前版本，恢复后核对同一输出哈希再登记。生产故障协议仍需测试，不能以本文设计代替实现。

## 6. 保留区与冻结约束

允许修改区域通常与工程对象、参数和几何范围共同声明。圆角/偏置可能影响区域外的邻接、壁厚和配合；超出范围必须形成候选新计划及影响说明。不得通过放宽冻结约束或删掉失败检查来宣布成功。

几何版本检查通过，不说明旧工程结论可沿用。依赖分为几何、参数、对象语义、知识版次、工况、方法版本；各自变化触发相应复检，依赖不全时保守扩大失效范围。

## 7. 可实施验收序列

A：板双对称孔，改变一个孔半径，要求重定位基于来源与参数，不按顺序。

B：单孔被其他切削分割，要求一特征多实体映射或明确UNKNOWN，不能丢掉半个特征。

C：倒角后原边消失，旧边上的操作请求必须STALE_BINDING；不能自动找邻近边继续切削。

D：计划构建后基模型版本改变，执行拒绝；重装配形成新计划而非修改旧回执。

E：worker成功、发布前断盘，当前版本不变；恢复核验同hash后可幂等登记。

F：几何无变化但手册适用条件/工况变化，原工艺结论失效而原模型字节保留。

以上均为待执行设计例。需要实际内核提供的历史接口能力先查版本；若没有则如实采用候选匹配与人工复核范围，不能写一个理想历史API假称内核支持。

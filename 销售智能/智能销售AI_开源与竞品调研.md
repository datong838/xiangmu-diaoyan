# 智能销售 AI 需求：开源方案与竞品调研

> 需求本质一句话：**把"销售出门=黑盒"改成"销售在前线说啥、后方实时知道"，并自动分流给老板（管话术/实情）、行政（资源准备）、财务（资金准备）。**
>
> 这对应两个成熟赛道的交叉：
> 1. **智能工牌（AIoT 采集层）**——解决"线下面对面沟通怎么无感录音+准实时回传"；
> 2. **销售会话智能 Conversation Intelligence（分析层）**——解决"录音转文字、分析话术对不对、判断客户意向、预警风险"。
>
> 第三条"信息分流给行政/财务"属于**系统集成/工作流**能力，是选型时的关键加分项，下文单列。

---

## 一、需求拆解：你的 5 个核心诉求

| 编号 | 你的原始诉求 | 对应标准能力 | 关键判定点 |
|---|---|---|---|
| ① | 销售佩戴公司胸卡工牌，全场录音 | 智能工牌硬件（拾音+续航+加密） | 外勤 vs 门店？续航要 8h+ |
| ② | 与客户的沟通记录 + 会议纪要 | ASR 转写 + 角色分离 + 摘要 | 能否分清"谁说的" |
| ③ | 老板准实时知道谈了啥、话术对不对 | 准实时传输 + 话术/SOP 质检评分 | **"准实时"=分片上传还是整段回传** |
| ④ | 部分信息同步行政做资源准备 | 事件/标签触发 + Webhook/审批流 | 需要开放 API 与 OA/钉钉打通 |
| ⑤ | 部分信息同步财务做资金准备 | 成交/报价/回款信号 → 财务系统 | 需对接业财系统（好业财/用友/金蝶等） |

**一句话选型标准**：纯录音硬件遍地都是，**真正稀缺的是"准实时 + 话术评分 + 开放集成"三位一体**。下面按这把尺子衡量所有方案。

## 二、开源 / 自建方案

适合"数据不能出内网、想自己控制、有技术团队"的团队。注意：开源只覆盖**分析层**，工牌**硬件仍需自采或定制**。

### 2.1 核心推荐：Playcall ⭐（最接近需求的成品）

- **定位**：自称 "The open-source AI alternative to Gong"，即开源自托管的 Gong 替代品 [citation:32][citation:13]
- **核心能力**：
  - **话术评分**：把对话按你自己的销售剧本（Playbook）打分，支持 MEDDPICC / BANT / SPIN，**也支持上传你自己的话术手册自动生成评分量表**——这直接对应你的"话术对不对" [citation:32][citation:28]
  - **买家上下文感知**：结合公司阶段、客户角色、商机阶段动态调整评分权重 [citation:28]
  - **教练演练（Coaching Drills）**：每个低分项生成具体改进练习，而不只是"总结" [citation:13]
  - **结果挂钩**：评分与成交结果、pipeline 关联，能看出哪些话术真推动成交 [citation:32]
- **技术栈**：Next.js + Supabase + Vercel AI SDK + OpenAI Whisper，MIT 协议，**BYOK（自带模型 Key）**，可自部署 [citation:13]
- **成本**：官方称运行成本可控制在 **50 美元/月以下**（模型调用为可变成本）[citation:37]
- **短板**：
  - ⚠️ **聚焦"上传后分析"，不是自动实时采集**——需自行对接录音来源 [citation:13]
  - 项目较新，需实测稳定性再规模推广
  - **不含工牌硬件、不含行政/财务分流**，这两块要自建集成

### 2.2 分析引擎备选

| 项目 | 特点 | 与需求匹配度 |
|---|---|---|
| **SalesCopilot**（GitHub 342★, MIT） | Deep Lake + Whisper + LangChain + GPT，可自托管 [citation:1] | 中等；有转写+LLM 分析底座，但偏开发者工具、UI 简陋、无托管版 [citation:1] |
| **Voice Summary**（DrDroidLab） | FastAPI + Next.js + PostgreSQL，转写分析+分类+标签+Web UI+实时时间线 [citation:15] | 较高；**含现代 Web UI 和异步处理**，适合做内部平台底座 [citation:15] |
| **Open Customer Insights**（Together AI 开源） | 聚合销售通话+Slack+工单 → 可检索洞察，集成 Gong/Pylon/Slack [citation:38] | 偏"客户洞察沉淀"，非实时话术质检 |
| **SalesGPT** | 开源版 ZoomInfo+Gong 集合体，含 Conversation Intelligence 模块 [citation:33] | 大而全，成熟度需验证 |

### 2.3 "实时分析"参考实现（偏 Demo，不能直接商用）

GitHub 上大量基于 **Vosk/Whisper + DistilBERT + Streamlit** 的实时销售助手，功能含实时转写、情感分析、异议处理、产品推荐、Google Sheets 存储 [citation:7][citation:9][citation:11]。
**价值**：作为"技术可行性验证"和二次开发脚手架，**不建议直接当产品用**（无安全、无合规、无硬件集成）。

### 2.4 开源方案总评

✅ 优势：数据不出域、无席位费、话术评分可完全自定义、能与内部系统深度打通。
❌ 劣势：**要自己拼完整链路**——硬件采购 + 实时传输 + 分析引擎 + 工作流分发 + 运维，**真实成本（人力+模型调用）往往高于采购 SaaS**。

> **结论**：若坚持自建，推荐组合 = **Playcall（话术评分核心）+ 自研/定制工牌（采集）+ 工作流引擎（分发）**。

## 四、"准实时 + 分流行政/财务"能力专项对比

这是你需求里**最容易被忽略、也最决定落地成败**的部分。逐家评估：

| 方案 | 准实时采集回传 | → 老板看板 | → 行政（资源准备） | → 财务（资金准备） |
|---|---|---|---|---|
| 明略 灵听工牌 | ✅ WiFi/4G 准实时 [citation:25] | ✅ 指标看板 [citation:25] | ⚠️ 需 API/定制对接 | ⚠️ 需 API/定制对接 |
| 得助工牌 | ✅ 边录边分析 [citation:10] | ✅ | ⚠️ 智能体底座可扩展 | ⚠️ 智能体底座可扩展 |
| Playcall（开源） | ❌ 需自建采集 | ✅ | ✅ 自建 | ✅ 自建 |
| 钉钉+好业财（畅捷通） | ✅ 外勤签到/日志实时 | ✅ 人效仪表盘 | ✅ **审批流直驱行政执行** [citation:34] | ✅ **合同/开票/收款秒级同步** [citation:29] |

**关键洞察**：

> **"话术分析"和"业财分流"目前没有一家完美打通，是两件事。**
> - 工牌厂商（明略/得助）擅长**采集+话术**，但行政/财务分流要**通过开放 API 对接**；
> - 钉钉/好业财这类 **业财一体平台擅长"销售→行政/财务"的自动触发**（销售单自动转采购、审批流直驱行政、回款实时同步）[citation:34][citation:29]，但**不做话术质检**。

**因此你的完整架构几乎必然是"双拼"**：`工牌会话智能（明略/得助/Playcall）` + `工作流/业财平台（钉钉+好业财/自建）`，靠 **Webhook / API / 消息队列** 把前者提取的"事件/标签"（如"客户已意向""谈定价格""需定制资源""涉及预付款"）推给后者。

## 五、选型决策矩阵

### 场景 A：重管理的中大型、多门店/强 SOP、老板要盯话术实情
→ **明略灵听工牌 或 得助工牌** 做 POC（软硬一体、准实时、话术评分最强）[citation:26][citation:35]，再对接内部审批/业财系统。

### 场景 B：数据不能出内网、有技术团队、想完全可控
→ **Playcall 自部署 + 定制/自采工牌 + 自建工作流**；把"话术对不对"量化成你自己的 Playbook [citation:32]。

### 场景 C：更看重"行政/财务资源资金同步"，话术分析是加分
→ **钉钉+好业财**类业财一体方案为主，话术部分叠加会话智能模块 [citation:34][citation:29]。

### 场景 D：预算敏感的小团队、先跑通 MVP
→ **Avoma（海外）** 或开源 **Playcall / Voice Summary** 起步，硬件先用手机+录音 App 替代工牌。

## 六、落地建议（行动清单）

1. **先定"准实时"的硬指标**：是"说完 5 分钟内可查"还是"当天回传够用"？外勤无网时要本地缓存+补传——这直接决定硬件和流量成本。
2. **先做合规红线**：录音告知/同意、数据加密、敏感信息脱敏是工牌厂商的标配（变声、芯片级加密、敏感信息抹除）[citation:10]，自建务必补齐。
3. **定义"话术对不对"的评分量表（Playbook）**：这是整个项目的核心资产。参考 MEDDPICC/BANT/SPIN，把你家的标准动作落成可打分事件——明略、Playcall、Megavvy 都支持这套逻辑 [citation:25][citation:32][citation:31]。
4. **明确分流的事件字典**：例如 `客户高意向 / 需报价 / 需定制资源 / 涉及预付款 / 竞品提及`，每个事件对应一个接收方（老板/行政/财务）——这是打通工牌与业财系统的契约。
5. **POC 策略**：工牌厂商（明略 vs 得助）各取 10–20 人试点 1 个月，同时用 Playcall 搭一个自建原型对照，再决定"买 vs 建"。

# W9-7A1 实践项目事实确认链验证记录

> 日期：2026-10-18　状态：合成环境验证通过。  
> 对应方案：77、78。  
> 当前结论：实践项目事实可以受控登记、退回、补充和确认；实践案例编制与审核尚未实现，下一工程切片为 W9-7A2。

## 1. 本次完成的产品能力

教师或专业群负责人可以建立实践项目草稿，分别记录合作单位、起止日期、活动次数、学生汇总人数、教师汇总人数、公开范围和项目说明。学生只保存汇总人数，没有建立学生个人信息库。项目按专业归属，教师只能办理本人负责且在本人专业范围内的项目。

实践材料直接引用学校资料空间中已有的确切材料版本，并注明任务、过程、检查、交付或评价阶段及用途。材料关系绑定项目版本，项目提交时生成内容和材料目录完全固定的提交版本；提交后不能继续追加材料或人工结果。

人工检查、交付、验收和企业评价先作为结果候选登记，保留结果日期、原责任人、原始结论和依据材料。只有候选中登记的原责任人可以确认或退回结果；专业群负责人不能代办。项目确认是另一项独立决定，只核对项目身份、合作单位、参与汇总、活动次数和材料目录，不替代人工结果确认。

专业群负责人退回项目时必须写明原因。教师以退回版本为基线建立新草稿并重新关联材料，再次提交后由负责人确认。已确认版本可以与现有建设任务建立“支持”或“相关”关系；这项关系不改变任务状态，也不直接写入指标正式进度。

## 2. 已实现对象与接口

新增八类数据对象：

- 实践项目及其当前版本指针；
- 不可覆盖的项目版本；
- 项目版本与材料版本关系；
- 人工结果候选及其依据材料；
- 原责任人人工结果决定；
- 专业群负责人项目决定；
- 已确认项目与建设任务的关系。

新增九条接口：

1. 建立实践项目；
2. 建立新的项目草稿版本；
3. 关联已有材料版本；
4. 登记人工结果候选；
5. 由原责任人确认或退回人工结果；
6. 提交当前草稿并固定提交版本；
7. 由专业群负责人确认或退回提交版本；
8. 为已确认项目建立建设任务关系；
9. 回查项目全部版本、材料、结果、决定和建设关系。

全部写入均使用学校、专业群和建设周期范围，校验当前版本和操作人，执行防重复提交，并同时形成操作回执、建设账本和 Outbox 事件。

## 3. 贯穿案例验证

合成案例使用“A 企业校企协同育人实践”：

- 参与汇总为 20 名学生、2 名教师；
- 活动次数为 1 次；
- 合作单位为 A 企业，企业数量没有从学生、教师或材料数量推导；
- 材料包括实践任务单、过程记录、企业评价和成果人工验收记录；
- 李老师登记“按任务单完成并通过人工验收”，并由李老师本人确认；
- 项目与既有 B 企业建设任务登记为“相关”，明确不等于该任务完成。

办理轨迹共保留六个项目版本：

```text
v1 草稿
  → v2 提交
  → v3 负责人退回
  → v4 补充后的新草稿
  → v5 再次提交
  → v6 负责人确认
```

验证同时证明：提交后追加材料被拒绝；负责人代替李老师确认人工验收被拒绝；机械制造专业教师看不到人工智能专业项目；教务审核人员可以只读查看；信息支持人员不能读取项目详情；项目版本和人工决定不能更新或删除。

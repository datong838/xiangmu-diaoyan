# W9-9A 正式工作台壳层与任务首链实现方案

> 版本：v1.0　日期：2026-10-19　状态：编码前方案已冻结。  
> 上位方案：第 96 份完成度审计与 W9-9 分段实施方案。

## 1. 本段目标

在正式工程新增可运行的学校工作台，使合成环境中的教师或负责人能够用浏览器完成“验证身份与范围—查看建设总览—查看任务—建立任务—核对回执—刷新回查”的首条真实链。

## 2. 页面结构

### 2.1 全局壳层

- 左侧：建设总览、计划与任务；后续模块显示建设中状态，不能进入伪页面；
- 顶部：当前专业群、建设周期、当前人员与角色、退出当前会话；
- 中部：当前业务页面；
- 右侧：当前对象关系和办理说明，只显示当前接口能够证明的内容。

### 2.2 进入工作台

用户填写 API 地址、会话凭证、学校编号、专业群编号和建设周期编号。页面先调用 `/me`，再调用专业群详情确认范围。通过后把设置保存在当前浏览器会话，失败时不保存。

### 2.3 建设总览

并行读取本人、专业群详情、运行总览和任务列表，形成四类信息：当前范围、待推进任务、状态分布、最近任务。任一局部读取失败时显示局部错误，其余已确认信息继续可见。

### 2.4 任务列表与详情

列表以状态、责任人和更新时间帮助用户进入任务。详情显示稳定编号、当前版本、状态、说明、责任人、确认人、计划日期和材料要求。服务端未返回的信息不自行补造。

### 2.5 新建任务

表单先从正式知识检索中选择来源知识，再从当前专业群和建设周期的有效参与人员中选择责任人、确认人，并填写任务标题、说明、计划日期和所需材料。提交时形成幂等键并调用正式任务接口。成功后进入详情并保留回执；冲突、无权和未知结果分别处理。

首轮浏览器核对发现，仅显示和手填人员 UUID 不符合学校人员使用要求。本段补充一个只读参与人员接口：仅拥有 `task:manage` 权限的当前范围负责人可读取该专业群、建设周期内尚未撤销且在有效期内的角色人员姓名、角色和专业范围。该接口不授予角色、不扩大任务权限，也不返回范围外人员。

## 3. 前端状态模型

业务对象不写入本地缓存。浏览器只保存当前会话连接设置、当前路由和未提交表单。统一状态包括：`idle`、`loading`、`ready`、`empty`、`forbidden`、`conflict`、`unknown`、`error`。

写入进行时禁用重复提交。若请求得到明确失败，允许用户修正后形成新的幂等键；若网络中断导致结果未知，保留原幂等键和操作编号，提示先对账，不自动重发。

## 4. 组件划分

- `SessionGate`：候选会话和范围验证；
- `AppShell`：导航、顶部上下文与页面容器；
- `OverviewPage`：运行总览；
- `TaskListPage`：任务筛选和列表；
- `TaskDetailPage`：任务详情与关系摘要；
- `TaskCreatePage`：正式知识选择和任务创建；
- `ReceiptPanel`：对象、版本和操作回执；
- `StatusPanel`：空白、无权、冲突、未知和一般错误；
- `apiClient`：统一鉴权、范围参数、错误映射和请求取消。

## 6. 验证计划

1. 静态检查：构建、类型/代码检查、不得含固定令牌；
2. 组件逻辑：会话验证、接口错误映射、任务创建字段与回执；
3. 后端回归：既有 `pnpm verify` 继续通过；
4. 浏览器首链：在专用合成数据库完成进入、总览、列表、详情、创建和刷新回查；
5. 负向：无效会话、缺少范围、无权范围、必填缺失和冲突提示；
6. 人员选择：负责人只能列出当前范围有效参与人员，教师不能调用任务管理人员列表；
7. 视觉：常见桌面宽度、页面溢出、导航、表单可读性和键盘焦点；
8. 一致性：逐项核对第 96、97 份方案与实际实现，不把后续模块写成已完成。

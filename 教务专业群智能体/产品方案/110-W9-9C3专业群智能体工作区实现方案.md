# W9-9C3 专业群智能体工作区实现方案

> 版本：v1.0  
> 日期：2026-10-19  
> 状态：实施前方案  
> 依据：第 03、05、08、12、30、65、96、105、108、109 份产品方案及现有 W9-5 接口

## 1. 本轮目标

把已经具备的专业群智能体能力接入正式工作台，让“专业群助手·小慧”成为教师、专业群负责人和教务审核人员都能看见、能够持续协作的数字员工。

本轮解决的不是增加一个聊天窗口，而是把一次请求变成可检查、可确认、可继续办理的工作任务：

1. 使用人用日常语言提出问题或交办事项；
2. 系统明确本次办理所属学校、专业群、建设周期和专业范围；
3. 小慧只从当前使用人有权访问的正式资料、任务、指标和进度中形成资料依据；
4. 小慧先列出办理计划、需要的资料和人工确认点；
5. 查询类事项可以按计划逐步执行，修改或新建业务对象的事项必须先由有权人员确认计划；
6. 每一步都保留来源、执行结果、缺项、冲突、拟写入内容和回执；
7. 使用人可以补充说明、刷新资料范围、暂停或继续同一项工作。

## 2. 产品定位

### 2.1 数字员工，不是通用问答框

小慧占有的不是一份静态资料目录，而是当前专业群有权限的建设工作上下文。她能理解一项工作与建设依据、目标指标、年度任务、责任人员、材料版本、成果和进度之间的关系，并按已有规则协助办理。

首批开放四类已经被系统规则验证的事项：

| 事项 | 使用人可提出的例子 | 系统形成的结果 |
|---|---|---|
| 查询指标进度 | “新增合作企业指标现在完成多少，还差什么？” | 固定规则、统计截止点、候选计算、正式确认和差距清单 |
| 查询任务状态 | “B 企业正式合作这项工作现在到哪一步了？” | 当前任务版本、办理状态、工作记录数、提交版本数和待办 |
| 查询正式知识 | “这项建设要求来自哪份文件，现在是否适用？” | 已发布知识、原文件位置、适用期和来源版本 |
| 准备差距后续工作 | “把已确认差距整理成后续任务草稿。” | 差距逐项核对、缺少条件、任务草稿建议；经计划和结果确认后才可建立草稿 |

像“做一下今年的国家级人工智能试点校申报材料”这类更完整的成果编制任务属于后续成果编制工作区。本轮可以记录原始请求并明确尚未进入首批动作目录，不伪装为已经能够完成。

### 2.2 资料依据与动作边界

小慧每次办理形成独立的“本次资料依据”，固定所用对象、版本、用途、截止点和有效期。资料后来发生变化，不会静默改写已经执行的结果；使用人需要主动刷新资料范围并形成新版本。

页面用学校人员能够理解的词呈现：

- “本次资料依据”，不在主界面强调内部知识包术语；
- “办理计划”，不只显示动作代码；
- “需要确认”，明确由谁、确认什么；
- “执行结果”，同时展示来源、缺项、冲突和拟形成内容；
- “过程记录”，保留补充说明、刷新、暂停和继续。

## 3. 页面结构

### 3.1 入口

左侧底部“专业群助手·小慧”由不可用状态改为正式入口，并显示当前职责：“协助查询、整理和受控办理”。入口不改变原有任务、资料、知识库和进度菜单。

### 3.2 专业群助手工作台

工作台包含四部分：

1. **交办区**：输入原始请求，选择系统已经支持的办理类型和确切对象；
2. **能力卡片**：说明四类已开放事项及其人工确认边界；
3. **进行中的协作任务**：显示事项编号、类型、当前阶段、状态和预期结果；
4. **工作原则**：明确“先确定范围和资料依据，再形成计划；涉及写入必须由人确认”。

### 3.3 建立协作任务页

根据办理类型显示对应目标选择器：

- 指标进度：选择一条已经形成的指标计算记录；
- 任务状态：选择当前使用人可见的建设任务；
- 正式知识：通过现有知识库检索并选择确切知识条目；
- 差距后续工作：选择正式进度确认后仍处于可处理状态的差距。

提交前同时填写预期结果。提交后形成稳定的智能体任务、资料依据和办理计划；不直接执行任何步骤。

### 3.4 协作任务详情页

详情页采用“请求—资料依据—计划—执行—结果—继续协作”的单线结构：

1. 顶部状态说明当前处于资料待补、计划待确认、可执行、执行中、结果待确认、已完成、已暂停或已拒绝中的哪一步；
2. 原始请求和预期结果始终可见；
3. 本次资料依据逐项显示对象类型、用途、版本和关键摘要；
4. 办理计划按顺序显示步骤、读取或写入性质、预计结果及确认要求；
5. 写入计划提供“同意计划”“要求调整”“拒绝计划”，只记录决定，不自动越过下一步；
6. 当前可执行步骤只出现一个“执行本步骤”入口，不能跳步；
7. 执行结果显示结构化结果、来源数量、缺项、冲突和拟写入内容；
8. 需要结果确认时，明确提供“确认采用”或“拒绝采用”；
9. 补充说明、刷新资料范围、暂停和继续均进入过程记录。

## 4. 状态与用语

| 系统状态 | 页面用语 | 使用人下一步 |
|---|---|---|
| waiting_for_input | 等待补充资料 | 查看缺项并补充或更换对象 |
| waiting_plan_confirmation | 等待确认办理计划 | 有权人员确认、要求调整或拒绝 |
| ready_to_execute | 可以开始办理 | 按顺序执行当前步骤 |
| executing | 正在办理 | 查看当前步骤和已形成结果 |
| waiting_result_confirmation | 等待确认本步结果 | 确认采用或拒绝采用 |
| completed | 已完成 | 查看最终答复、来源和过程记录 |
| paused | 已暂停 | 补充说明后继续办理 |
| rejected | 已拒绝 | 保留拒绝原因，不继续执行 |

页面不把“计划已确认”表述为“工作已经完成”，不把候选结果表述为正式结论，不把缺少责任人、专业或完成节点的差距直接变成任务。

## 5. 权限与角色

1. 专业群负责人可使用全部首批事项，并对涉及写入的计划和结果作出确认；
2. 教务审核人员可查询指标进度和正式知识，不得建立写入类协作任务；
3. 教师可查询本人负责的任务状态和可访问的正式知识；
4. 信息支持人员不能读取业务内容；
5. 每个人只看到自己建立的协作任务；专业范围继续由现有授权控制。

页面入口可以对角色显示，但最终权限仍由服务端判断；前端不通过隐藏按钮代替正式权限。

## 6. 本轮改动范围

### 6.1 产品文档

- 新增本实现方案；
- 完成后新增验证记录，并同步导航、路线图、决策风险台账和实现状态。

### 6.2 前端

- 修改 `apps/web/src/App.jsx`：开放小慧入口，新增助手工作台、建立协作任务页和协作任务详情页；
- 修改 `apps/web/src/api-client.js`：接入智能体任务、计划决定、步骤执行、结果决定、消息、刷新、暂停和继续接口；
- 修改 `apps/web/src/styles.css`：增加协作任务、资料依据、计划步骤和执行结果样式。

### 6.3 后端与数据库

本轮优先复用已经通过 W9-5 验证的正式接口和数据结构。只有在真实页面联调发现现有读取结果无法支持必要展示时，才做最小增量，并补充接口测试和契约。

## 7. 不在本轮伪装完成的能力

1. 自动生成完整申报书、年度报告或 PPT；
2. 任意自然语言自动识别所有业务意图；
3. 外部大模型调用、语音形象和主动通知；
4. 未经确认自动建立正式任务、修改指标或发布成果；
5. 跨学校、跨专业群或超出使用人权限的资料检索。

## 8. 自测与通过门槛

### 8.1 自动验证

1. 前端构建、类型检查和既有测试通过；
2. 全仓验证不回退；
3. 若修改后端，相关 W9-5 集成测试必须在新数据库通过。

### 8.2 浏览器真实链

至少使用候选环境中的真实对象完成：

1. 从小慧入口建立“查询新增合作企业指标进度”协作任务；
2. 核对资料依据包含已固定的规则、计算快照、正式进度和差距；
3. 按顺序执行读取规则、读取进度和组织答复三个步骤；
4. 最终页面能清楚说明目标 3 家、正式确认 1 家、差距 2 家及来源；
5. 刷新页面后协作任务、步骤结果和过程记录可恢复；
6. 再建立一项需要写入确认或资料不足的任务，验证系统停在正确的人工作业点，不越权写入。

## 9. 风险控制

1. **普通聊天化风险**：所有请求必须转成稳定事项并展示资料依据、计划和回执；
2. **把回答当正式结论**：只有已经正式确认的数据才以正式进度显示；
3. **自动写入风险**：写入类计划和结果保留双确认，页面不得自动连点；
4. **资料变化风险**：显示本次资料截止点和刷新入口，旧结果保持原样；
5. **专业范围泄露风险**：复用现有范围与角色授权，不在浏览器拼接未经服务端确认的业务内容；
6. **页面过度承诺风险**：未进入动作目录的请求明确显示当前尚不能办理，并保留请求供后续扩展。

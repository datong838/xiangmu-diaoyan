# W9-9C1 工作记录、提交、退回与确认实现方案

> 版本：v1.1　日期：2026-10-19　状态：已实现并通过验证。

> 对应任务：T04、T07、T08。

## 1. 本段目标

把现有任务详情从只读信息页变成实际办理页，走通：

```text
任务草稿
  → 负责人派发
  → 责任人填写工作记录
  → 选择确切工作记录版本和材料版本提交
  → 负责人退回并填写原因与补充要求
  → 责任人补充原工作记录形成新版本
  → 再次提交形成提交 v2
  → 负责人确认完成
  → 历史版本、材料和决定全部保留
```

本段不建立指标进度。任务完成后页面必须继续提示“指标需按独立规则计算并由负责人确认”。

## 2. 页面设计

### 2.1 工作记录入口

- 左侧“工作记录”正式启用，进入当前人员获准的任务办理清单；
- 按待填写、已提交、已退回、已完成等任务状态显示；
- 点击任务进入同一个任务详情和办理页，避免建立脱离任务的工作记录库。

### 2.2 任务详情与动作

- 草稿且当前人为负责人：显示“派发任务”，填写派发原因；
- 已派发、进行中或已退回，且当前人为责任人或负责人：显示“填写工作记录”；
- 工作记录表单包括业务日期、完成事项、参与人员、形成结果、存在问题、下一步和修改原因；
- 已退回任务默认允许选择既有工作记录继续补充，形成该记录的新版本；
- 任务进行中或退回后：显示“提交办理结果”，选择当前工作记录版本和当前范围材料版本，并填写每份材料用途；
- 已提交且当前人为确认人：显示“确认完成、退回补充、事实确认但证据不足”；后两项必须填写补充要求；
- 所有动作成功后显示准确回执并重新读取任务详情。

### 2.3 历史与关系

- 工作记录按稳定记录分组，显示版本、日期、完成事项、结果、问题、下一步和修改原因；
- 提交按 v1、v2 展示说明、固定工作记录版本、固定材料版本、决定、原因和补充要求；
- 任务版本时间线保留 draft、assigned、in_progress、submitted、returned、completed；
- 材料显示业务标题和版本，不能只显示内部编号；如现有任务详情只返回材料版本编号，页面用材料目录在当前授权范围补足业务名称；
- 负责人和教师都能看到与本人权限一致的历史，审核人员只读，信息支持零内容。

## 3. 接口复用

- `POST /tasks/{taskId}/assign`
- `POST /tasks/{taskId}/work-records`
- `POST /tasks/{taskId}/submissions`
- `POST /task-submissions/{submissionId}/reviews`
- `GET /tasks`
- `GET /tasks/{taskId}`
- `GET /materials`

不新增迁移或写接口。Web 客户端增加现有接口封装，并始终使用当前任务版本作为预期版本；补充工作记录同时使用稳定工作记录编号和当前工作记录版本。

## 4. 写入与失败规则

- 每次派发、记录、提交和审核使用新的操作编号与幂等键；
- 页面写入前固定当前任务版本，刷新后若已变化则显示版本冲突；
- 提交至少选择一条工作记录版本和一份材料版本；
- 材料用途不能为空；
- 审核只处理当前提交版本，旧提交不能重复审核；
- 网络结果未知时保留操作编号，不自动重复；
- 成功后从服务端重新读取任务、工作记录、提交、材料和版本；
- 页面不允许把“事实确认但证据不足”显示为任务完成。

## 5. 自测门槛

1. 草稿任务可由负责人派发，刷新后为已派发；
2. 责任人可建立工作记录，任务进入进行中；
3. 提交固定确切工作记录版本和材料版本，任务进入待确认；
4. 负责人退回后显示原因与补充要求；
5. 补充同一工作记录形成 v2，旧版本保留；
6. 再提交形成提交 v2，旧提交和退回意见保留；
7. 确认完成后任务完成，但页面明确指标未被自动修改；
8. “证据不足”回到退回状态，不伪装完成；
9. 教师只办理本人任务，审核人员只读，信息支持和跨范围零泄露；
10. 旧版本、重复审核、空材料和空工作记录失败关闭；
11. 浏览器用合成数据走通派发—工作 v1—提交 v1—退回—工作 v2—提交 v2—确认；
12. W9-4A 专项测试和全工程回归通过，W9-9A/B 页面无回归。

# 视觉设计信息架构与关键页面输入

> 版本：v1.1　日期：2026-10-18　状态：等待产品方案评审后进入页面实施。  
> 用途：作为后续 4181 产品视觉稿改造的直接输入，避免从业务沟通稿跨越到界面。

进入视觉设计前，必须同时读取《13-核心对象与关系详细设计.md》《14-状态版本操作与建设账本详细设计.md》《15-专业群智能体任务执行协议详细设计.md》《17-T01至T05跨页面办理流程详细设计.md》《21-T06至T11指标任务进度与差距跨页面办理流程.md》《22-T09及T12至T14查询总结成果编制与改稿流程.md》《23-多专业知识图谱演示样例与验证.md》和《25-T15至T18选配事项产教融合与多专业群复制流程.md》，确保页面能够实际填写、提交、修改、确认和写回。

## 1. 视觉设计需要回答的问题

视觉稿回答“系统怎样承载业务”：谁在操作、操作什么对象、智能体怎样协助、信息怎样关联、谁来确认、形成什么结果。页面不是业务说明书，也不是只读展示板。

## 2. 一级信息架构

```text
建设工作台
我的工作
专业群智能体
专业群知识库
建设依据
目标与指标
计划与任务
工作记录
资料与证据
进度与问题
成果与报告
组织与协作
试点与验收
管理设置
```

专业群智能体作为全局入口持续可见，同时拥有完整任务办理页；知识库是可查看和可管理的产品工作区，不隐藏为技术后台。

## 3. 全局框架

### 顶部

当前学校、专业群、建设周期、统计期间、角色、全局搜索、通知和个人入口。

### 左侧业务导航

使用浅色、紧凑的业务导航，与主工作区协调。显示本人待办数量，但不把所有业务状态挤进菜单。

### 主工作区

根据对象显示列表、详情、表单、关系、办理历史和操作。系统以“写和办理”为主，页面必须有清晰的录入、提交、修改、退回和确认区域。

### 右侧智能体协作区

显示当前上下文、智能体理解、所用知识、建议动作和待确认事项。支持展开为独立任务办理页。

### 持续任务与跨页位置

顶部在全局范围之下显示当前办理链，例如“建设依据 → 年度任务 → 工作提交 → 进度判断 → 差距处理 → 成果编制”。进入子页面后仍显示所在节点、上一步、下一步和同节点页面，避免依赖左侧菜单寻找。

## 4. 三条核心办理链与选配链

视觉原型必须先走通三条核心链，再承载总工作台汇总；同一对象在不同链中只保留一个身份和一条版本链。

### 链 A：资料与建设依据（T01—T05）

```text
资料交接与保全
  → 识别专业、组织和人员关系
  → 教师持续提交工作与材料
  → 按用途整理内容
  → 从申报书、任务书、实施方案形成建设依据
```

主要页面：资料交接批次、知识吸收确认、组织关系、教师工作提交、内容整理、建设依据对照。主要写操作：登记、补充、纠错、确认候选对象、发布知识、提交工作、确认条款。

### 链 B：指标、任务、进度与差距（T06—T11）

```text
业绩分类和候选匹配
  → 年度/月周任务分解
  → 教师执行、提交、退回和补充
  → 确定性计算进度
  → 人工确认达成情况
  → 区分原因并建立补充任务
  → 周期总结与下期计划
```

主要页面：业绩分类、年度计划分解、任务办理、指标逐项对照、差距处理、周期总结。完成率不能直接编辑，只能由已确认事实和规则形成计算快照。

### 链 C：查询、成果编制与改稿（T09、T12—T14）

```text
自然语言查询并确认范围
  → 带来源的结果或固定快照
  → 创建总结或正式成果任务
  → 固定模板、期间、输入版本和审核人
  → 章节编写与引用
  → 指定范围改稿
  → 独立审核
  → 正式导出与归档
```

主要页面：查询工作区、结果详情、成果编制中心、章节编写台、改稿对照、审核、导出归档。草稿、审核中、批准和归档必须对应确切版本。

### 链 D：选配事项与多群推广（T15—T18）

```text
确认选配范围
  → 教学检查 / 考试事项 / 真实实践资料办理
  → 人工确认后建立建设关系
  → 试点方法沉淀
  → 新专业群独立初始化与隔离校验
```

主要页面：选配能力设置、检查归集、考试事项跟踪、产教融合案例、多专业群初始化和隔离检查。未确认选配范围时，只显示“待确认”，不能表现为已启用能力。

## 5. 第一批关键页面

### P01 建设总工作台

目的：让不同角色看到当前状态和可以立即办理的事情。

必须呈现：当前群和周期、本人待办、建设进度、问题分类、重点节点、最近变化、智能体任务。所有卡片可进入明细和操作。

### P02 专业群智能体任务办理页

目的：证明智能体能够执行工作，而不只是回答。

必须呈现：用户要求、办理目标、任务知识包、办理步骤、调用的业务模块、已形成对象、待确认事项、继续办理和结果入口。

### P03 专业群知识地图

目的：表现多个专业、依据、指标、任务、人员、材料和成果的关系。

必须呈现：当前范围、分层关系、关系筛选、对象详情、知识成熟度、冲突与未知、从关系进入办理。

### P04 专业档案

目的：表现上百个专业中的某一个专业在各专业群和周期中的真实建设情况。

必须呈现：群关系、核心/支撑身份、负责人、目标任务、教师工作、成果证据、问题和报告贡献。

### P05 教师工作记录与材料提交

目的：表现重写入的日常使用。

必须呈现：工作日期、内容、参与人、结果、材料、任务关联建议、智能体补全、保存草稿、提交和退回修改。

### P06 建设依据对照

目的：把三类文件对应成同一建设事项。

必须呈现：原文定位、目标、指标、责任、时间、材料要求、冲突和人工确认。

### P07 指标、任务和进度

目的：从目标进入执行和差距处理。

必须呈现：目标、期间、实际、证据、状态、责任人、更新时间、原因分类和创建补充任务。

### P08 资料与证据办理

目的：表现原件、版本、分类、关系和审核。

必须呈现：预览、来源、版本、解析状态、关联建议、正式证据确认、撤回影响和受限范围。

### P09 成果编制与引用

目的：表现按模板写、查依据和局部改稿。

必须呈现：章节、正文编辑、智能体协助、事实卡、引用、缺项、版本和修改范围。

### P10 成果审核与导出

目的：表现学校最终决定权。

必须呈现：确切版本、关键事实核对、引用有效性、退回原因、批准、重新审核、正式导出和归档。

### P11 建设依据与资料吸收办理页

目的：让资料从“已收到”经过拆解、候选确认和发布，成为可用建设知识。

必须呈现：交接批次、原件与版本、候选对象、冲突、逐项确认、发布范围、影响对象和撤回处理。

### P12 计划分解与任务派发页

目的：把目标和差距变成可以执行的责任事项。

必须呈现：来源目标、任务草稿、责任专业和人员、时间、预期产出、材料要求、负荷提示、确认派发和调整版本。

### P13 指标逐项对照与差距页

目的：分开显示计算、建议和人工正式判断，并从差距建立后续动作。

必须呈现：原文要求、统计口径、目标、事实明细、计算快照、证据覆盖、建议判断、人工结论、原因分类和补充任务。

### P14 查询、总结与成果任务入口

目的：把日常问答连接到正式办理。

必须呈现：查询范围、截止点、来源、未知项、保存快照、创建总结、创建成果编制任务和进入源对象。

### P15 多专业群初始化与隔离检查页

目的：验证产品能够服务多个专业群，同时保留各群差异和数据边界。

必须呈现：新群依据、专业关系、人员权限、可复用配置、禁止复制内容、缺项、跨群串用检查和负责人启用确认。

## 6. 第二批页面

任务中心、问题中心、模板中心、组织关系、权限管理、冲突与未知、版本影响、建设账本、教学检查、考试事项、产教融合案例、选配能力设置、后台任务、试点验收、备份恢复和运行保障。

## 7. 统一对象页面

每个对象页面使用相同结构：

1. 标题、状态、责任人、期间和版本；
2. 已确认事实和待确认建议；
3. 相关对象关系；
4. 当前角色可执行动作；
5. 提交、退回、确认和修改历史；
6. 智能体可以协助的下一步；
7. 上一步、下一步和同节点子页面导航。

对象页默认提供四个工作区：“内容/字段”“关系”“版本与办理历史”“专业群助手”。能够修改的字段直接进入编辑态；不能修改的历史事实明确显示来源和纠错入口。

## 8. 页面状态与动作矩阵

视觉稿不能只画正常状态。首批关键页至少包含以下状态：

| 状态 | 页面表现 | 允许动作 |
| --- | --- | --- |
| 草稿 | 可编辑、未进入正式办理 | 保存、删除未提交草稿、提交 |
| 待确认 | 显示建议与依据，突出确认责任人 | 修改、确认、拒绝、要求补充 |
| 办理中 | 显示当前节点、责任人和截止时间 | 填写、补材料、转交获准人员 |
| 已退回 | 定位退回原因和受影响位置 | 修改后生成新版本并重新提交 |
| 资料不足 | 显示缺项及其影响 | 补充、标记暂缺、调整范围 |
| 口径冲突 | 同时展示冲突版本 | 建立口径确认，不计算假结果 |
| 已确认 | 固定确认版本和确认人 | 查看、发起变更或后续动作 |
| 已失效/已作废 | 保留历史并提示替代版本 | 查看影响、进入有效版本 |
| 无权操作 | 不泄露内容，说明申请或联系路径 | 返回、申请获准范围 |
| 执行失败/结果未知 | 保留请求与步骤记录 | 只读对账、确认未写回后再重试 |

每个写动作都显示将要影响的对象；高影响动作在执行前展示范围，执行后展示结果、版本和建设账本编号。

## 9. 视觉状态语言

- 蓝色：可办理、当前操作、普通信息；
- 绿色：已确认或已完成；
- 橙色：待确认、临期、材料不足；
- 红色：退回、失败、冲突或权限拒绝；
- 灰色：草稿、未开始、已失效或无权操作。

颜色必须配合文字状态，不能只靠颜色表达。

## 10. 文案规则

页面标题和按钮使用产品语言，直接表达功能、对象、动作和状态，例如“建设工作持续推进”“提交工作记录”“确认材料关联”“创建补充任务”。

专业群智能体可以使用自然交流语言，但回答中仍要明确依据、时间、缺项和下一步。页面不使用“把工作写进来、办下去”等沟通稿式表达。

## 11. 关键交互

- 所有统计数字可下钻；
- 所有关系可打开来源和目标对象；
- 智能体建议可一键带入对应编辑区，但需要用户确认；
- 退回意见直接定位修改位置；
- 知识变化显示影响对象；
- 长任务显示进度并允许离开页面；
- 报告引用可以回到原件版本和位置；
- 页面之间沿工作链连续导航。
- 在专业群知识地图中选择关系后，可进入对应对象办理，不停留在关系展示；
- 智能体生成内容先进入可编辑区，显示使用的范围、依据、缺项和将要写回的位置；
- 切换专业群、周期或角色时，持续任务重新校验范围并显式提示；
- 新资料或新版本进入后，显示受影响的指标、任务、总结和成果，由负责人决定复核。

## 12. 建设账本与事实关系呈现

### 12.1 事实与关系

页面同时显示“这个对象是什么”和“它与什么有关”。关系至少区分已确认、候选、历史和失效，能够回到关系依据、确认人和生效时间。知识地图是对象办理的导航面，不是独立的装饰图。

### 12.2 撕不掉的建设账本

任何提交、退回、确认、版本替换、关系建立、权限范围变化和智能体写回都追加记录。用户不能覆盖历史；纠错通过新版本、失效和替代关系完成。账本页支持按对象、人员、时间、任务和请求查看，业务记录与技术访问日志分开展示。

### 12.3 智能体数字员工

右侧助手不只给答案。它展示对任务的理解、已读取的知识清单、当前执行步骤、形成的草稿或业务对象、等待谁确认、失败或停止原因以及确认后写回位置。跨页面后仍保持同一任务身份。

## 13. 不应出现的视觉误导

- 智能体只显示聊天气泡，没有业务动作；
- 工作台只有指标卡和图表，没有写入与办理入口；
- 资料、任务和报告分成互不相通的页面；
- “已上传”被表现为“已完成”；
- “智能体建议”与“人工确认”使用相同状态；
- 页面展示学校未确认的专业、数字或成果而未标演示；
- 左侧黑色导航和浅色业务区形成不协调的割裂；
- 子页面只能从左侧菜单寻找，不能顺着工作链进入。
- 用动态图谱代替资料录入、关系确认和纠错办理；
- 把跨专业群复制画成“一键复制全部数据”；
- 把智能体生成草稿直接显示成学校已确认成果。

## 14. 贯穿原型走查

### 14.1 核心链走查

1. 交接申报书、任务书和实施方案，确认条款和冲突；
2. 导入 A—D 企业说明性样例，确认 A 为本年度已完成，B 推进中，C 为历史，D 待开展；
3. 将目标 3 家分解为任务，由教师提交 B 企业进展并经历一次退回；
4. 运行进度计算，显示 1/3，并由负责人确认尚差 2 家；
5. 对 B 建补材料任务，对 D 建补工作任务；
6. 生成月度总结和年度报告章节，核对引用与支撑目录；
7. 按指定范围改稿，保持目标 3、完成 1、尚差 2；
8. 审核退回、重新提交、批准、导出并归档；
9. 新资料版本进入后，查看影响范围并决定是否复核成果。

### 14.2 多专业与多群走查

1. 在一个专业群中查看核心专业与四个支撑专业的关系和权限；
2. 从知识地图进入某专业档案，再进入教师工作、材料和指标办理；
3. 新建第二个样例专业群，仅复用结构和流程；
4. 用新群账号查询和编制报告，确认不出现 A—D 企业、原群人员、1/3 进度或原群报告内容。

### 14.3 选配链走查

T15、T16 只在演示为“已确认启用”时进入流程；T17 用真实资料样例验证归集、人工确认和案例形成；未确认范围使用禁用或待确认状态，不演示为现成功能。

## 15. 页面实施顺序

1. P02 专业群智能体任务办理页；
2. P05 教师工作记录与材料提交；
3. P07 指标、任务和进度；
4. P09/P10 成果编制、审核与导出；
5. P03/P04 知识地图和专业档案；
6. P01 建设总工作台；
7. P11/P12/P13/P14 补齐三条跨页链；
8. P15 多专业群初始化与隔离检查；
9. 选配和运行保障页面。

先验证“智能体理解—人员操作—形成记录—人工确认—产生成果”的闭环，再完善总览。首页最后汇总已经成立的产品能力，避免先画一个看起来完整但无法操作的驾驶舱。

## 16. 视觉验收清单

- 是否清楚显示当前专业群、周期和角色；
- 是否至少有教师、负责人、审核人和智能体四方协作；
- 是否能看到输入、编辑、提交、退回、确认和审核；
- 是否能从结论回到事实、关系和原件；
- 是否区分建议、待确认和已确认；
- 是否体现上百个专业的知识组织和专业档案；
- 是否支持页面间连续办理；
- 是否没有新增需求依据之外的能力；

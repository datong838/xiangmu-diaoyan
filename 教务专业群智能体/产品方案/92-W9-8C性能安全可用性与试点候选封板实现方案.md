## 1. 本段定位

W9-8C 是候选版封板，不是新一轮业务功能开发。它回答四个问题：

1. 当前正式工程在固定机器、固定数据和固定轮次下，关键操作是否达到候选基线；
2. 越权、跨群、撤权、重复、版本冲突、文件篡改、恢复不完整和旧凭证重放是否仍然失败关闭；
3. 清单、程序、手册、证据和实现状态是否使用同一口径；
4. 哪些内容可以交给学校开展 W10，哪些仍须在学校现场确认。

本段不新增业务表，不改变现有正式接口语义，不补 T01—T04、T07、T12 的产品缺口，不开启 T15/T16、真实解析、向量检索、开放式自然语言理解或外部智能服务。

## 2. 冻结的性能基线

### 2.1 测量环境

性能报告必须记录：

- 操作系统、机器架构、CPU 型号与逻辑核数、内存总量；
- Node.js 与 PostgreSQL 版本；
- 数据库连接标识的脱敏摘要、迁移数量和最后迁移；
- 学校侧文件根目录的脱敏摘要；
- 合成数据来源、数据对象数量、预热轮次和正式测量轮次；
- 测量发生时间和候选版本。

本机结果只作为候选版本的可重放基线。学校网络、设备、并发人数和正式数据规模下的指标必须在 W10 重新确认。

### 2.2 测量对象与候选阈值

在 W9-7B/W9-8B 形成的双专业群合成环境上，预热 5 次、正式测量 30 次，逐项统计成功率、最小值、中位数、P95 和最大值。

| 类别 | 代表操作 | 候选阈值 |
| --- | --- | --- |
| 运行就绪 | 数据库就绪检查 | 成功率 100%，P95 不超过 150ms |
| 建设范围 | 专业群详情 | 成功率 100%，P95 不超过 250ms |
| 正式知识 | 固定范围知识检索 | 成功率 100%，P95 不超过 350ms |
| 建设总览 | 任务、材料、成果等汇总 | 成功率 100%，P95 不超过 350ms |
| 材料读取 | 材料及版本详情 | 成功率 100%，P95 不超过 350ms |
| 模板读取 | 报告模板与版本详情 | 成功率 100%，P95 不超过 350ms |
| 成果读取 | 成果导出详情 | 成功率 100%，P95 不超过 350ms |
| 文件读取 | 已登记导出文件下载 | 成功率 100%，P95 不超过 800ms |
| 可信写入 | 新建一项合成建设任务 | 成功率 100%，P95 不超过 800ms |

这些阈值用于发现明显阻断和回归，不是学校 SLA。单项超过阈值即使功能正确，也使 G09 不通过；不得删除慢样本或改用单次主观体验代替。

### 2.3 写入样本控制

可信写入使用新的合成任务编号、幂等键和操作编号，每轮建立独立对象。写入前固定学校、专业群、周期、负责人和正式知识条目，写入后核对返回回执、对象编号、新版本和数据库累计数量。

性能程序不得直接写业务表。测试身份引导仍沿用现有合成测试机制，所有测量调用正式接口。

## 3. 集中安全负向复核

W9-8C 不重新发明安全模型，而是把已有正式回归集中为一份封板证据：

| 风险 | 必须复核的结果 |
| --- | --- |
| 无权访问 | 不返回标题、数量、摘要、文件名或正文 |
| 跨专业群 | 列表/详情、知识、智能体、汇总、材料、成果、导出和账本八入口均不能串群 |
| 撤销权限 | 撤权后原会话不能继续办理 |
| 重复提交 | 同一幂等键同内容返回原回执，不同内容冲突 |
| 版本冲突 | 过期版本写入被拒绝，不能覆盖当前事实 |
| 审核边界 | 负责人不能替代独立审核人，审核人不能修改原始事实 |
| 文件篡改 | 大小或摘要不一致时核对失败 |
| 恢复缺项 | 数据库、文件或清单缺少任一部分时恢复失败 |
| 清单篡改 | 清单内容或摘要被修改时验证失败 |
| 旧凭证重放 | 恢复后旧会话和旧文件票据失效 |
| 关闭能力 | T15/T16、解析、向量、外部 AI 和开放问答不返回伪成功 |

集中复核由全量 API 回归、数据库/文件/恢复清单测试、候选清单检查和 W9-7C 已生成的故障注入证据共同构成。W9-8C 没有修改恢复实现时，不重复制造一套恢复程序；但必须校验 W9-7C 证据仍存在且当前恢复测试继续通过。

## 4. 实现设计

### 4.1 补充合成证据索引

最小补充 W9-7B 合成证据输出，使性能程序可以通过正式接口定位以下对象：

- 源专业群正式知识条目；
- 源专业群任务与事实快照；
- 源专业群模板及模板版本；
- 源专业群材料及材料版本；
- 源专业群成果编制及版本；
- 源专业群导出成果。

这里只增加测试证据字段，不修改任何正式业务接口。

### 4.2 性能与安全封板程序

新增 `apps/api/scripts/verify-w9-8c-candidate-seal.mjs`，要求：

1. 必须提供专用合成数据库、学校侧文件目录、W9-7B 合成证据和明确确认值；
2. 核对数据库迁移、文件目录和证据对象属于同一环境；
3. 使用正式应用实例和正式接口执行预热、读操作与可信写入测量；
4. 记录机器、数据规模、每项统计和阈值判断；
5. 执行越权、跨群、旧对象、关闭能力等不改变已有数据的集中探针；
6. 读取 W9-7C 恢复证据和本次全量测试结果，形成安全门槛汇总；
7. 任一操作失败、样本不足、阈值超限或边界不一致时返回非零状态；
8. 通过 `W98C_EVIDENCE_PATH` 保存机器可读报告。

5. A03/A04/A10/A11 的现场内容不得被本机预演替代；
6. 任何结果未知先只读对账，不重复写入或导出。

## 6. 验证顺序

1. 在全新合成数据库执行 42 个迁移；
2. 运行全量 API 集成测试，要求失败 0、跳过 0，并生成新的 W9-7B 对象索引；
3. 运行 W9-8C 封板程序，要求所有性能样本成功、阈值通过、安全探针通过；
4. 运行数据库、文件维护和恢复清单测试；
5. 运行候选版静态和运行环境检查；
6. 执行全工程构建、类型检查和测试；
7. 人工复核方案、清单、手册、README、实现状态和证据结论一致。

## 7. 停止与失败规则

- 严重越权、跨群泄露、审核绕过、原件损坏或恢复证据失效：立即停止封板；
- 性能程序出现非 2xx、样本不足或 P95 超限：G09 保持未通过；
- 性能不达标时先定位慢操作，不擅自放宽阈值；
- 结果未知时只读核对，不自动重发写入；
- T15/T16 或关闭能力出现接口/文档伪开放：候选版失败；
- 任何学校现场项不得由合成报告改写为“已验收”。

## 8. 完成门槛

W9-8C 只有同时满足以下条件才完成：

1. 九类关键操作均有固定轮次、机器条件和统计结果；
2. 所有候选性能阈值通过；
3. 全量 API 回归失败 0、跳过 0；
4. 十一类安全负向边界均有当前或连续有效证据；
5. G01—G10 全部有证据，A10 只写“合成环境已预演”；
6. 候选版本清单可机器核对；
7. W10 学校试点交接清单完整；
8. 工程、方案、手册、证据和候选清单口径一致；
9. 未实现能力继续失败关闭；
10. 候选结论只写“可提交学校开展 W10”，不写“学校验收完成”。

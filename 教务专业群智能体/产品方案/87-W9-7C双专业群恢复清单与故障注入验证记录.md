## 1. 本次实际验证范围

本次在三个全新 PostgreSQL 16 数据库中分别完成全量接口测试、源工作空间构造和隔离目标恢复。源工作空间包含同一学校下的源专业群、已启用目标专业群，以及一个已取消并归档的初始化范围；同一负责人兼任两个有效专业群，源群具有独立材料、正式知识、任务、智能体任务、报告模板、事实快照、成果编制、PDF 导出和建设账本记录，目标群具有自己的三类建设依据、专业关系、指标规则和模板。

验证同时覆盖数据库、学校侧材料原件、成果导出文件、访问凭证处置和八入口跨群隔离，没有接入学校真实资料和外部智能服务。

## 3. 干净恢复结果

实际执行：

1. 源数据库在空库应用 42 个迁移，再次执行迁移无重复影响；
2. 源库生成恢复清单并导出 PostgreSQL 备份；
3. 学校侧文件目录独立复制到新的目标目录；
4. 数据库恢复到新的隔离目标，目标再次执行迁移检查；
5. 未失效旧凭证时，核对明确报告 `active_sessions` 和 `active_file_tickets`，整体失败；
6. 使用双重确认命令使恢复出的 1 个会话和 2 个文件票据全部失效；
7. 再次核对时，数据库、范围、版本、关系、5 份文件、账本、隔离证据和实现状态零差异；
8. 恢复环境专用新会话可读取本群内容，旧会话与旧票据均不可再用；
9. 已取消的初始化仍为 `cancelled`，对应专业群和周期均为 `archived`，没有因恢复变为可用。

## 5. 故障注入结果

| 注入情况 | 实际识别结果 |
| --- | --- |
| 删除登记文件 | `file_storage` 失败并指出缺失存储键 |
| 保持文件大小、改写一个字节 | `file_storage` 失败并指出 SHA-256 不一致 |
| 只恢复数据库，不复制文件 | 5 份登记文件全部报告缺失 |
| 删除清单 `scopes` 段 | 报告 `recovery manifest is incomplete: scopes` |
| 修改清单文件字节数但不重签摘要 | 报告 `recovery manifest digest mismatch` |
| 删除 `0042` 已应用迁移记录 | 报告已应用迁移与本地迁移文件不一致 |
| 不执行恢复目标凭证失效 | 报告活动会话和活动文件票据，整体失败 |
| 使用恢复前旧会话和旧票据 | 分别返回无权和不可见，不返回文件 |

各文件故障使用从源文件重新复制的独立目录；迁移故障使用单独恢复数据库；异常样本之后，干净副本再次核对通过。

## 7. 方案一致性与发现的问题

实现过程中发现既有文件核对器只登记材料原件，会把正式成果导出的 PDF 误判为孤儿。没有绕过该异常，而是统一把 `material_blobs` 和 `deliverable_exports` 纳入文件登记、核对和孤儿清理口径，并在最终恢复中验证 4 份材料原件和 1 份成果导出文件。

恢复清单增加全库技术摘要，以覆盖没有直接 `school_id`、但通过父对象归属学校的章节、引用和隔离探针明细；同时保留学校和专业群周期摘要，用于核对范围边界。这一调整已回写第 86 份方案。

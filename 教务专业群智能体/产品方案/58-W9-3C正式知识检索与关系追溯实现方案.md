# W9-3C 正式知识检索与关系追溯实现方案

> 版本：v1.0　日期：2026-10-18　状态：编码基线。  
> 前置条件：W9-3A、W9-3B 已验证。  
> 对应能力：专业群知识库 L3 检索与关系层，为 T02、T05、T06、T09、T10、T12、T13 及后续专业群智能体提供可信查询底座。  
> 本波限制：全文与关系检索使用学校侧 PostgreSQL；向量检索、外部模型和真实学校资料保持关闭。

## 1. 本波目标

W9-3A 已能发布正式知识，W9-3B 已能从固定材料版本形成经人工确认的内容单元。W9-3C 要把“能按字符串找到一条记录”提升为可供教师、教务和智能体使用的正式知识检索：

```text
身份与学校/专业群/周期范围
  → 已发布正式知识过滤
  → 文档类型、要求类型、关系类型和适用时间过滤
  → 全文索引与原文短语组合召回
  → 确定性排序和去重
  → 补充关系链、冲突、缺项和来源版本
  → 返回可继续办理的检索结果
```

检索回答的是“当前获准范围内有哪些已发布知识、为什么命中、来自哪里、与什么对象有关、是否存在冲突或缺项”。它不替代指标计算、进度确认或报告审核。

## 2. 正式知识检索文档

新增 `knowledge_search_documents`，与 `knowledge_entries` 一对一。每条检索文档固定：

- 学校、专业群、建设周期；
- 正式知识条目和发布版本；
- 依据类型、依据编号、依据版本和批准状态；
- 条款类型、建设要求类型、关系类型；
- 建设要求编号与表述；
- 原文摘录和原文位置；
- 材料版本、可选内容单元；
- 适用起止日期；
- PostgreSQL 全文索引字段和规范化检索文本；
- 建立时间与索引格式版本。

检索文档只在正式发布事务中建立。候选关系、已确认未发布关系和被拒绝内容没有检索文档，因此不能被正式搜索召回。

已有正式知识通过一次受控迁移回填检索文档，仍使用其原发布版本和来源，不重新解释正文。

## 3. 检索方式与排序

### 3.1 组合召回

本波使用两个确定性通道：

1. PostgreSQL `simple` 全文索引，适合编号、英文、数字和已分隔词；
2. 原文短语匹配，保证连续中文词组可以命中。

两种通道都在完成范围、正式状态和结构化字段过滤之后执行。不得先做全库召回再隐藏越权结果。

### 3.2 排序规则

排序分值由程序固定：

- 建设要求完整短语命中：最高加权；
- 原文摘录完整短语命中：次高加权；
- 全文词项命中：采用 `ts_rank_cd`；
- 要求编号或依据编号精确命中：额外加权；
- 同分时按正式发布时间和稳定条目编号排序。

返回 `score` 和 `matchReasons`，不使用模型给出无法复核的相关度。

### 3.3 结构化过滤

支持：

- `documentType`：申报书、任务书、实施方案；
- `requirementType`：目标、指标、任务、节点、支撑要求；
- `relationType`：定义、支撑、约束、安排时间、要求证据；
- `asOf`：指定日期的适用知识；
- `limit`：1—50。

默认 `asOf` 为查询当天。适用期之外的知识不作为当前结果，但历史查询可以明确指定日期。

## 4. 关系追溯

### 4.1 从正式知识追到来源

`GET /knowledge/entries/{entryId}/trace` 返回一条确定性关系链：

```text
正式知识条目
  → 知识发布版本
  → 已确认候选关系和确认决定
  → 建设要求及版本
  → 原文条款及版本
  → 建设依据及版本
  → 材料版本
  → 已确认内容单元（如有）
```

同时返回：

- 与该条款有关的未解决/已解决冲突及决定；
- 与来源内容单元有关的待补、已解决和豁免缺项；
- 当前适用日期是否有效；
- 每个节点的对象类型、编号和版本。

### 4.2 从材料反查正式用途

`GET /knowledge/material-versions/{materialVersionId}/usages` 返回该材料版本进入了哪些依据、条款、要求、正式知识发布和关系类型。确认重复关系不删除材料，也不合并两个材料的用途。

未发布候选不进入正式用途列表；需要办理候选时仍从 W9-3A/W9-3B 工作区进入。

## 5. 冲突、缺项和未知提示

每个检索结果返回：

- `warnings.openConflicts`：与条款相关的未解决冲突；
- `warnings.resolvedConflicts`：已有人工口径决定的冲突；
- `warnings.openMissingItems`：来源内容单元仍缺少的内容；
- `warnings.outOfDate`：不在查询日期适用范围内；
- `warnings.sourceContentUnavailable`：没有内容单元或内容单元已不可用。

冲突或缺项不会自动改写为确定事实。默认适用期过滤后 `outOfDate` 不出现在普通结果中，关系追溯仍可查看历史状态。

## 6. 发布门槛加固

正式知识发布新增以下硬条件：

1. 候选关系已经人工确认；
2. 依据版本状态为“已批准”；
3. 条款、要求和材料版本属于同一范围；
4. 同一候选关系不能重复发布；
5. 正式知识条目和检索文档在同一事务建立；
6. 建立失败时整个发布回滚，不留下可查但不可追溯的孤立索引。

草稿或待批准依据可以形成候选并在办理区核对，但不能进入正式知识检索。

## 7. 权限与零泄露

- 教师、负责人和教务审核人员按现有 `knowledge:search` 范围检索正式知识；
- 专业范围角色只能查看本专业获准知识。当前知识条目尚未增加专业维度时，不给专业范围教师返回群级知识，避免范围扩大；
- 信息支持人员、跨学校、跨专业群和跨周期访问统一返回空集合或不可访问；
- 直接猜测条目或材料版本编号时不返回对象是否存在；
- 无权对象不进入 `count`、排序、冲突数、缺项数或高亮摘要。

## 8. 向量检索启用门槛

本波不建立向量、不安装 `pgvector`，状态继续为关闭。后续只有同时满足以下条件才能启用：

1. 学校批准的合成或脱敏评测集；
2. 明确的嵌入模型、版本、维度和校内/私域运行位置；
3. 向量只保存在学校控制环境的证明；
4. 与正式知识条目、范围、版本和撤权联动的数据库约束；
5. 索引备份、恢复和重建验证；
6. 对全文基线的召回质量提升证据；
7. 越权零召回和内容清理验证。

在此之前，接口明确返回 `vectorSearchEnabled=false`，不以普通文本匹配冒充语义搜索。

## 9. 接口

| 接口 | 作用 |
| --- | --- |
| `GET /knowledge/search` | 结构化过滤、全文/短语组合排序，并返回警告摘要 |
| `GET /knowledge/entries/{entryId}/trace` | 查看完整来源与关系链 |
| `GET /knowledge/material-versions/{materialVersionId}/usages` | 从材料版本反查正式用途 |
| `GET /knowledge/capabilities` | 返回正式检索、关系追溯和向量开关，不含业务数量 |

## 10. 合成验收链

1. 发布三个已批准依据的正式知识：两条包含“合作企业”，一条仅包含“师资培训”。
2. “合作企业”只命中前两条，建设要求完整短语命中的条目排在原文局部命中之前。
3. 按任务书和指标类型过滤后只保留正确条目。
4. 指定有效日期时排除尚未生效或已经过期的知识；历史日期可查到历史适用内容。
5. 追溯结果能从正式知识回到发布、确认决定、要求、条款、依据、材料版本和内容单元。
6. 材料反查返回其正式用途，不包含确认但未发布候选。
7. 为一条来源建立未解决冲突和待补项；搜索结果保留正文，同时提示冲突和缺项，不能输出“无风险”。
8. 草稿依据的候选确认后仍不能发布。
9. 信息支持、跨学校、跨群和跨周期查询均为零泄露。
10. 相同查询稳定排序；空白、超长、非法枚举和超限请求被拒绝。

## 11. 自测门槛

- 检索文档只由正式发布事务产生；
- 已有正式知识回填数量和关系一致；
- GIN 全文索引存在并用于可复核查询；
- 中文短语、编号和数字均有命中与排序用例；
- 四类结构化过滤和适用期通过；
- 来源追溯和材料反查完整；
- 冲突、缺项、候选和正式状态不混淆；
- 草稿依据发布被拒绝；
- 专业范围、跨学校、跨群、信息支持零泄露；
- 空库迁移、重复迁移、全工程回归和 OpenAPI 校验通过；
- 向量检索保持关闭并在能力接口中明确展示。

## 12. 明确不在本切片宣称的能力

- 向量或语义检索；
- 外部模型重排和答案生成；
- 专业群智能体任务知识包与连续问答；
- 真实学校数据上的召回率、准确率和性能结论；
- 任务、指标、进度、成果和报告闭环。

# T01—T05 跨页面办理流程详细设计

> 版本：v1.0　日期：2026-10-18　状态：内部评审稿。  
> 对应波次：W4，依赖 W1—W3。  
> 文档职责：把 T01—T05 从单项能力说明推进为用户可连续完成的产品办理链，作为首批视觉原型和产品切片的直接输入。

## 1. 为什么先设计 T01—T05

T01—T05 解决专业群建设最先发生的事情：确定组织范围、接收零散资料、持续记录真实工作、按用途整理内容，并把三类文件变成共同建设依据。它们为 T06—T18 提供事实、关系、指标和任务输入。

首批流程采用同一条贯穿案例，但案例数据仅用于验证产品交互，不代表学校实际情况。

## 2. 首批页面集合

| 页面 | 主要作用 | 重写入动作 |
| --- | --- | --- |
| 专业群工作台 | 查看待办、资料、任务、风险和智能体协作 | 新建、继续办理、确认、退回 |
| 资料收件箱 | 接收文件、图片、说明和资料批次 | 上传、补充说明、分派、批量处理 |
| 资料整理台 | 预览原件并形成工作记录、内容和候选关系 | 编辑、拆分、合并、接受/拒绝建议 |
| 组织与专业关系页 | 维护部门、专业群、专业和人员关系 | 新建关系、调整、确认、失效 |
| 教师工作台 | 持续填写日常工作和补充材料 | 填写、保存、提交、按意见修改 |
| 建设依据中心 | 登记三类文件并核对版本和批准状态 | 上传、登记、替换、确认 |
| 条款对照工作台 | 对照条款、目标、指标、任务和冲突 | 编辑关系、确认、退回、形成决定 |
| 专业群助手任务页 | 贯穿所有页面的智能体办理过程 | 提问、确认计划、接受草稿、继续任务 |
| 版本与建设账本 | 查看内容变化、确认和影响 | 对比、恢复为新版本、查看影响 |

## 3. 贯穿办理链

```text
建立专业群范围与人员
  → 交接三类建设依据和已有资料
  → 系统保全原件并形成待整理项
  → 智能体拆解内容并提出候选关系
  → 人工核对组织、条款、目标和指标
  → 教师持续填入真实工作和材料
  → 按指定用途整理为台账或汇报草稿
  → 已确认结果进入知识库、任务和后续进度链
```

## 4. T03：先建立组织和专业关系

T03 在首批实际操作中先于其余四项，为后续资料和任务建立范围。

### 4.1 发起

校级或专业群指定负责人进入“组织与专业关系”，选择新建专业群或完善现有专业群。系统展示当前学校组织，不强制套用固定层级。

### 4.2 填写与智能体协助

用户填写专业群名称、建设周期、核心专业、支撑专业、负责部门和主要人员。智能体可以从获准文件中发现专业名称和人员候选，但只作为建议。

### 4.3 人工确认

负责人逐项确认核心/支撑关系、人员职责和有效期。系统同时显示确认后影响的资料范围、任务分派和进度汇总。

### 4.4 写回

形成专业群、专业、人员、责任和有效期关系，进入知识库与权限初始化。未确认关系不能自动决定跨专业查看权限。

### 4.5 异常

同一专业出现在多个专业群、组织层级与文件不一致或人员尚未确定时，保留候选和冲突，不阻止先建立专业群草稿。

## 5. T01：零散资料持续进入系统

### 5.1 发起

教师可从工作台“交资料”、教师工作台“补材料”、任务详情“提交佐证”或助手对话中发起。批量初始化使用“资料交接批次”。

### 5.2 收件

用户选择专业群、专业、业务日期、资料用途和可见范围，上传文件或填写说明。系统先保存原件并显示接收结果，读取失败不等于上传失败。

### 5.3 智能体整理

助手识别资料类型、内容、参与人、日期和可能对应的工作/任务/指标，形成工作记录草稿、材料清单、候选关系和缺项。

### 5.4 人机工作区

左侧查看原件，中间编辑工作事实，右侧查看候选关系和缺项。用户可以拆成多个工作事项、合并同批资料、改变专业归属或暂存为待整理。

### 5.5 确认与写回

教师确认自己的说明，负责人确认专业群建设关系。确认结果进入工作记录、材料版本和知识关系；未确认结果保留在待处理区。

### 5.6 继续办理

完成后直接提供“补充任务进度”“匹配建设依据”“整理成台账/汇报”三个下一步入口，不要求回左侧菜单重新寻找。

## 6. T04：把日常工作持续写入同一建设账

### 6.1 教师工作台

教师看到本人待办、被退回记录、近期工作和可继续补充的事项。可以从已有任务创建工作记录，也可以先记录临时工作再由负责人确认关系。

### 6.2 写工作

填写业务日期、做了什么、参与人、形成什么结果、遇到什么问题，并添加文件、图片或说明。系统自动保存草稿。

### 6.3 助手协助

助手可根据已填内容建议标题、结构、所属专业、关联任务、缺少材料和可形成成果，但不能把未开展工作补写成完成。

### 6.4 提交与退回

教师提交具体版本，负责人查看事实、材料和候选关系，可确认、修改关系、退回或要求补充。退回后教师在原记录上形成新版本。

### 6.5 周期性使用

系统允许按周补录和从既有记录继续补材料，避免同一成果每天重复填写。已确认工作成为 T09 总结、T10 进度和 T13 报告的输入。

## 7. T02：把同一批资料整理成指定产物

### 7.1 发起

用户在资料包、工作记录、查询结果或助手任务中选择“整理内容”，说明用途、受众、栏目、输出形式和截止时间。

### 7.2 固定输入

系统保存本次选中的材料及版本快照。助手列出可用内容、读取失败、缺失栏目和可能冲突的事实。

### 7.3 生成可编辑草稿

根据用户指定结构生成文字、表格结构或汇报内容。每个段落或表格行可查看来源；缺失内容留空并进入待补清单。

### 7.4 编辑与版本

用户在内容编辑区直接修改，也可要求助手只改某部分。每轮修改形成新版本和差异说明。若 Excel/PPT 文件输出未纳入当前范围，页面明确标为内容草稿，不能伪装成成品。

### 7.5 保存用途

用户可保存为工作台账、汇报草稿、报告素材或自定义整理成果。整理结果不反向覆盖原件和源事实。

## 8. T05：三类文件形成共同建设依据

### 8.1 文件登记

负责人分别登记申报书、建设任务书和实施方案，填写版本、批准状态、生效日期、适用周期和文件关系。草稿、待批准和正式批准清楚区分。

### 8.2 系统拆解

助手读取三类文件，形成原文条款、目标、指标、任务、节点、责任和证据要求候选，每项保留文件与原文位置。

### 8.3 三类文件对照

条款对照台按建设事项并排显示三个来源，突出一致、补充、缺失和冲突。用户可以把相关条款归为同一建设事项，也可保持独立。

### 8.4 负责人确认

负责人确认文件状态、条款关系、采用口径、目标、指标和任务。冲突需形成口径决定；智能体只能说明影响，不能自行选择。

### 8.5 形成后续对象

确认结果写入建设依据目录、目标指标库、任务草稿和证据要求。每个下游对象都可回到具体文件版本和原文位置。

### 8.6 版本变化

上传新版本后系统形成差异和影响清单，提示哪些任务、进度和报告需复核，不自动改写既有正式结果。

## 9. 页面间的连续导航

每个流程页顶部显示当前任务链：

```text
范围已建立
  → 资料已接收
  → 内容待整理
  → 关系待确认
  → 建设依据已形成
  → 可进入任务与进度管理
```

页面底部和成功反馈均提供“继续当前链路”的下一步，不依赖用户熟悉菜单。返回时恢复原任务、筛选条件和编辑位置。

## 10. 智能体常驻方式

助手不是浮动问答按钮。每页提供：

- 当前办理事项和状态；
- 已找到的相关资料与依据；
- 可以协助的页面动作；
- 待用户确认的建议；
- 缺少内容和异常；
- 完成后写回的位置。

复杂编辑进入中间业务工作区，助手在右侧解释、检查和接收修改要求。

## 11. T01—T05 向后续任务的写回

| 首批结果 | 后续承接 |
| --- | --- |
| 已确认材料、事实和成果 | T06 指标匹配、T10 进度判断 |
| 专业和人员关系 | T07 任务分工、T12 按专业/人员查询 |
| 日常工作记录 | T08 跟踪、T09 总结、T13 报告 |
| 目标、指标、任务和证据要求 | T06—T14 的共同依据 |
| 整理草稿和缺项 | T09、T13 编制及补材料任务 |
| 冲突和口径决定 | T10 计算、T12 查询和 T13 报告口径 |

## 12. 首批原型走查脚本

1. 创建一个专业群并登记五个专业的核心/支撑关系。
2. 交接三类依据文件，其中两处目标数值不一致。
3. 查看系统拆解结果并由负责人处理一处条款关系，保留一处冲突待确认。
4. 教师上传一份协议、一张活动图片并填写工作说明。
5. 助手生成工作记录草稿和指标候选关系，教师修改日期后提交。
6. 负责人确认工作事实，但退回指标关系要求补充正式协议。
7. 教师补充新版本，负责人确认关系。
8. 将这批资料整理为表格台账和汇报文字，检查来源、缺项和版本。
9. 从整理结果直接进入 T06 或从建设依据进入 T07，验证跨页面连续性。

## 13. 首批验收门槛

- 真实或脱敏资料能完整走过 T03→T01/T04→T02/T05；
- 原件、提取、候选、确认和正式使用状态清楚；
- 所有写入都有版本与账本；
- 智能体建议可修改、拒绝且不会越过人工确认；
- 无法读取、资料不足和依据冲突均有可继续办理的路径；
- 用户无需回菜单即可进入同一任务链的下一页；
- 后续 T06—T14 能直接复用首批形成的对象和关系。

# 专业群知识库事实关系证据技术分方案

> 版本：v0.1 评审准备稿  
> 日期：2026-10-19  
> 状态：评审稿编制完成，等待内部评审；尚未冻结，不编码  
> 设计范围：多专业群、上百个专业的建设知识组织，不采用通用文件知识库直接替代

## 1. 建设目标

专业群知识库要回答的不只是“文档里写了什么”，还要回答：

- 这条内容属于哪个学校、专业群、专业和建设周期；
- 它来自哪份文件的哪个版本和位置；
- 它描述的是要求、事实、建议、决定还是结论；
- 与哪些目标、指标、任务、工作、材料和成果有关；
- 由谁确认、何时生效、当前是否仍适用；
- 哪些地方存在缺项、冲突或版本影响；
- 当前用户和当前任务是否有权使用。

因此，知识库由文件来源、业务对象、事实关系、人工决定和检索能力共同组成。

## 2. 知识空间划分

```text
学校知识空间
  ├─ 学校共同规则、模板和组织
  ├─ 专业群 A 知识空间
  │    ├─ 建设周期
  │    ├─ 核心专业与支撑专业
  │    ├─ 依据、目标、指标、任务、工作、资料和成果
  │    └─ 本群事实、关系、决定和版本
  └─ 专业群 B 知识空间
       └─ 独立事实、关系、决定和版本
```

学校共同方法可以被多个群引用；专业群事实默认隔离。某项资料需要跨群共享时建立明确共享关系，写明对象版本、用途、范围、期限和批准人。

## 3. 六层知识结构

| 层级 | 内容 | 作用 |
| --- | --- | --- |
| K1 来源层 | 文件原件、版本、页码、段落、表格、图片说明 | 证明内容来自哪里 |
| K2 对象层 | 学校、专业群、专业、人员、指标、任务、材料、成果 | 确定内容说的是谁或什么 |
| K3 事实层 | 数值、事件、状态、时间、结果、缺项 | 表达已发生或已确认的情况 |
| K4 关系层 | 属于、负责、参与、支撑、对应、引用、替代、影响 | 把分散内容连接成建设网络 |
| K5 规则层 | 指标口径、分类标准、模板栏目、流程和权限规则 | 决定怎样判断和办理 |
| K6 决定层 | 批准、拒绝、确认、撤回、冲突处理和适用结论 | 说明谁在什么条件下作出决定 |

任何正式知识至少能回到 K1 来源；直接由业务办理产生的事实能回到具体对象版本、提交和人工决定。

## 4. 知识陈述类型

1. **来源摘录**：原文内容及位置，不等于已经认可；
2. **候选事实**：系统或智能体从资料中识别，等待人工核对；
3. **已确认事实**：有权人员确认并具有适用范围；
4. **候选关系**：如“材料 A 可能支撑指标 X”；
5. **正式关系**：经过确认、可用于办理和报告；
6. **规则**：统计、分类、流程或模板要求，具有版本和生效期；
7. **人工决定**：针对冲突、例外、确认或审核形成；
8. **推导结论**：由固定规则和输入快照计算，可重算但不覆盖历史。

不同类型不能混排成没有标识的“知识”。

## 5. 资料进入知识库的流程

### 5.1 登记

记录学校、专业群、专业、提交人、来源、用途、敏感级别、业务日期、文件指纹和版本。原件先稳定保存，再进行后续处理。

### 5.2 内容单元化

按页、段、表格、单元格区域和图片说明形成可定位内容单元。扫描质量差、密码保护、格式不支持或内容缺失时保留失败状态和人工补录入口。

### 5.3 候选识别

识别组织、专业、人员、建设事项、目标、指标、任务、时间、数量、材料要求和相互关系。输出候选值、原文位置、识别方式和不确定项。

### 5.4 人工核对

负责人逐条接受、修改、拒绝或标记冲突。批量确认只适用于相同来源、相同规则和相同责任范围，不能一键确认越权内容。

### 5.5 正式发布

核对后的内容形成知识版本，带学校、专业群、专业、周期、适用对象、有效期、敏感级别和权限策略。后续换版通过替代关系发布。

### 5.6 索引更新

分别更新结构化、全文和关系索引。向量或语义索引属于辅助召回，返回结果仍需经过范围、权限、版本和状态过滤；是否启用待评审。

## 6. 专业档案

每个专业形成持续档案：

- 基本信息、所属专业群及核心/支撑角色；
- 负责人、参与教师和任职有效期；
- 承担的建设目标、指标、任务和节点；
- 日常工作、资料、设备或软件建设记录；
- 已确认业绩、证据和成果；
- 当前进度、差距、风险和待补材料；
- 历年变化及与其他专业共同建设的关系。

专业档案不是人工维护的一篇总结，而是从已确认对象和关系形成的视图。

## 7. 专业群知识地图

知识地图以专业群为中心，展示：

```text
专业群
  ├─ 建设周期与依据版本
  ├─ 核心专业 / 支撑专业 / 共同事项
  ├─ 目标 → 指标 → 规则 → 证据要求
  ├─ 计划 → 任务 → 工作 → 材料
  ├─ 事实 → 进度 → 差距 → 后续措施
  └─ 模板 → 成果 → 引用 → 审核 → 归档
```

地图中的每条边都可展开来源、状态、版本和确认人。跨专业汇总时保留各专业贡献，不将共同成果重复计算。

## 8. 检索策略

### 8.1 先确定范围

每次检索先固定学校、专业群、专业、建设周期、统计期间、对象类型、状态和资料截止时间，再执行内容检索。

### 8.2 分通道检索

- 结构化查询：人员、任务、状态、日期、数量、指标和版本；
- 全文查询：获准文件的标题、正文、条款和表格文本；
- 关系查询：从指标追溯材料、从材料反查用途、从成果追溯引用；
- 语义召回：用于查找表达相近内容，结果标为候选并附来源。

### 8.3 返回结构

返回对象、摘要、关系、来源文件及版本、原文位置、确认状态、适用范围、资料截止时间、缺项和冲突。没有找到时说明搜索范围，不能回答成“学校没有”。

## 9. 与专业群智能体的关系

智能体不能直接在全库自由拼接。每次任务由知识库生成受控知识包，内容包括范围、有效版本、正式事实、获准材料、规则、模板、冲突和缺项。任务结束时，智能体新发现的内容以候选形式回到核对流程，不直接发布为正式知识。

## 10. 知识变化传播

| 变化 | 需要检查的影响 |
| --- | --- |
| 建设依据换版 | 目标、指标、任务、智能体任务和成果引用 |
| 指标规则换版 | 尚未确认的计算、计划差距和周期总结 |
| 材料撤回或换版 | 证据关系、成果引用和正式结论 |
| 组织或负责人变化 | 任务责任、权限和待办 |
| 审核决定撤销 | 成果正式状态、导出件和归档说明 |
| 专业群结构变化 | 汇总范围、跨专业关系和权限 |

系统形成影响清单，由相应负责人决定重新核对、保持历史或形成新版本。

## 11. “撕不掉的建设记录”

知识库不通过删除旧事实来保持表面整洁。错误、过期和被替代内容保留历史状态，并记录更正来源、决定人和生效时间。当前视图由有效关系和版本计算，历史报告仍能找到当时引用的旧版本。

## 12. 质量管理

按专业群和专业分别统计：

- 已登记资料、已处理资料、待处理和处理失败；
- 候选事实、已确认事实、冲突和未知；
- 有来源关系、无来源关系和待确认关系；
- 指标的证据覆盖、缺项和重复候选；
- 过期规则、受换版影响对象和待重新核对事项；
- 智能体回答的来源覆盖和无依据停止情况。

质量指标只反映知识准备情况，不自动替代业务完成判断。

## 13. 数据主权与权限

原件、版本、内容单元、索引、事实、关系、决定和知识质量记录均属于学校数据资产。知识检索继承业务对象权限；无权人员不能通过关键词、数量、标题或相似度侧面发现受限内容。

云端动作服务只接收本次任务批准使用的最小内容，不保存为跨任务知识库，不与其他学校或专业群混用。

## 14. 评审与验收样例

用 T05 的 A—D 企业案例验证：三类依据形成年度目标和材料要求；A 企业形成已确认事实和证据关系；B 为正在推进且缺正式协议；C 为历史合作；D 为待开展。随后验证从指标找到四家处理结果、从 A 材料反查指标和报告引用、换版后历史结果不变、跨专业群检索不泄露。

## 15. 待评审事项

- 首批资料类型和允许自动处理的文件格式；
- 候选事实的核对角色和批量确认条件；
- 专业共同成果的汇总与去重规则；
- 语义/向量检索是否纳入首期；
- 索引更新时限、历史保留和重新处理规则；
- 学校共同知识与专业群独立知识的边界；
- 跨群共享的审批方式和默认期限。

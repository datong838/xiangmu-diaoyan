# 试点实施与验收产品方案

> 版本：v1.0　日期：2026-10-18　状态：内部评审稿。

## 1. 目标

用一个真实专业群和一条完整建设工作链验证产品，不用页面演示、功能数量或智能体回答流畅度替代实际使用与验收。

## 2. 试点原则

- 先选择一个专业群，确认其专业、成员、周期和依据；
- 使用学校批准的真实或脱敏样例；
- 先走通“填报—材料确认—进度查询—成果编制—人工审核”；
- 已知但未纳入本期的需求仍登记，不假装不存在；
- 排课单独评估；
- 试点通过后再决定多专业群推广。

## 3. 阶段

### 3.1 资料核对与原型验证

确认样例授权，验证上传、知识吸收、智能体查询、进度对照和草稿生成的基本路径。

### 3.2 需求与产品方案确认

确认总方案、分方案、本期范围、统计口径、模板、角色、资料边界和验收样例。

### 3.3 建设与初始化

建立专业群知识库骨架、组织关系、建设依据、指标、任务、模板、权限和运行条件。

### 3.4 真实试用与修复

教师、负责人和审核人员独立完成实际操作；记录问题、修改、复测和已知限制。

### 3.5 验收与移交

完成 A01—A11，提交使用手册、管理员手册、培训记录、恢复记录、限制清单和资料交接。

### 3.6 推广决策

根据试点结果单独确定新增专业群、专业、批次、资源和范围。

## 4. 试点准备清单

1. 学校和项目基本信息；
2. 一个试点专业群及核心/支撑专业；
3. 参与教师、负责人、审核人和替代审核人；
4. 申报书、任务书、实施方案及批准状态；
5. 一条真实指标、计算规则和证据要求；
6. 一批工作记录、正常与异常材料；
7. 一份优先成果模板和历史合格样例；
8. 专业群智能体的典型问题和办理任务；
9. 查看范围、资料保存和临时处理约定；
10. 使用人数、网络、设备、等待时间和保障联系人。

## 5. 一条必须走通的真实链

```text
负责人确认建设依据
  → 建立年度指标和教师任务
  → 教师提交一次真实工作与材料
  → 智能体协助整理和关联
  → 负责人退回或确认证据
  → 查询目标完成、差距和原因
  → 形成补充任务
  → 生成一份正式模板草稿
  → 编写人修改
  → 独立审核人退回或批准
  → 导出并归档
```

## 6. A01—A11 产品验收包

| 编号 | 产品验收重点 | 主要证据 |
| --- | --- | --- |
| A01 | 试点范围、组织、周期、知识库骨架和依据导入 | 初始化清单、错误清单、重复导入结果 |
| A02 | 指标计算、成果去重和证据关系 | 10 个标注样例及人工结果 |
| A03 | 材料吸收、异常处理和智能推荐 | 建议 100 份样例、正确与遗漏核对 |
| A04 | 智能体进度查询和权限 | 20 个问题、来源回查和越权测试 |
| A05 | 报告生成、引用和局部改稿 | 一份完整报告及修改记录 |
| A06 | 独立审核和 Word/PDF 导出 | 退回、批准、重审和文件核对 |
| A07 | 多范围隔离和撤权 | 两种权限、撤权后访问结果 |
| A08 | 重复、并发、失败、取消和未知结果 | 后台任务与恢复记录 |

## 7. 知识库专项验收

- 专业群、专业、人员、依据、指标、任务、材料、成果和报告可以双向追踪；
- 已登记、可读取、可检索、已整理和已确认分别统计；
- 冲突、未知、受限、失败和未覆盖不被隐藏；
- 新版本变化能够指出受影响对象；
- 新专业群初始化只复用方法，不复制试点事实。

## 8. 智能体专项验收

- 能从自然语言进入具体办理，不要求用户记模块；
- 查询结果与业务页面一致；
- 写入动作形成草稿和确认过程；
- 能连续追问并保持正确范围；
- 缺资料、冲突、越权时正确停止；
- 新事项能列出所需条件并进入业务事项登记。

## 9. 问题与复测

每个问题记录版本、操作者、输入、预期、实际、影响对象、修复内容和复测结果。未通过项必须修复复测或形成双方书面范围调整。

越权泄露、关键事实错误、审核绕过、原件损坏和恢复失败不能仅作为“已知限制”放行。

## 10. 变更控制

新需求记录提出人、原因、受影响产品方案、功能、字段、验收项、时间和批准人。总方案和受影响分方案同版更新，不在视觉稿中静默扩大范围。

## 11. 推广准备

试点结束形成：通用初始化清单、知识结构、能力单元、模板配置方法、培训材料、运行保障方法、试点问题和适用边界。每个新专业群仍需重新确认自己的依据、指标、人员、资料、权限和成果模板。

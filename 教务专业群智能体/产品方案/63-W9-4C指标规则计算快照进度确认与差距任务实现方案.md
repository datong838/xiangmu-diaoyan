# W9-4C 指标规则、计算快照、进度确认与差距任务实现方案

> 版本：v1.0　日期：2026-10-18　状态：编码前冻结稿。  
> 前置：第 21、60—62 份方案与验证记录。  
> 本波覆盖：T10、T11，并复用 W9-4A 的任务对象和 W9-4B 的成果决定。

## 1. 本波要解决的问题

W9-4A 已能保留任务、工作、提交、退回和完成轨迹，W9-4B 已能形成成果分类、材料用途、指标支撑及重复材料的人工决定。W9-4C 将这些已经确认的事实作为固定输入，回答：

1. 当前使用的是哪一版指标规则；
2. 在哪个截止点，具体读取了哪些成果决定、支撑决定和任务版本；
3. 系统为什么算出某个候选结果；
4. 谁把候选结果确认成正式进度；
5. 未达成分别属于缺工作、缺材料、年度不符还是口径待确认；
6. 哪些差距经过负责人确认后转成了新的正式任务。

## 2. 不可混合的三层结果

| 层次 | 结果 | 是否正式进度 |
|---|---|---|
| 规则层 | 目标值、统计期间、计入条件、去重键和证据门槛 | 否 |
| 计算层 | 固定输入和截止点后形成的候选实际值、差值、计入与排除明细 | 否 |
| 确认层 | 负责人确认的达成、未达成、资料不足或口径待确认结论 | 是 |

智能体可以解释规则、检查输入和组织说明，不能替负责人确认正式进度。附件数量不能直接代替业务成果数量。

## 3. 核心对象

### 3.1 指标规则

- `indicator_rules`：稳定规则对象，绑定一条已发布的指标知识；
- `indicator_rule_versions`：目标值、单位、统计起止日期、计数对象、去重键、允许计入的成果分类、指标支撑门槛、证据角色、变更原因和内容摘要；
- 规则修改只能增加新版本，旧计算继续引用旧版本。

首条规则固定为：2026 年新增合作企业目标 3 家；按成果候选计数；只计入负责人确认的 `current_year_completed`；指标支撑必须确认；至少有一份主证据；业务日期位于 2026 年且不晚于计算截止点。

### 3.2 计算运行与输入快照

- `indicator_evaluation_runs`：规则版本、数据截止点、输入摘要、运行状态和发起人；
- `indicator_evaluation_inputs`：每个成果决定、指标支撑决定和任务版本的固定引用、纳入/排除结果、理由和输入摘要；
- `indicator_calculated_results`：目标值、候选实际值、差值、候选结论和结果摘要。

运行创建后不可修改。同一规则版本、截止点和同一组输入无论重复运行多少次，都必须得到相同结果摘要。

### 3.3 正式进度确认

- `progress_confirmations`：负责人对某次计算结果作出 `achieved`、`not_achieved`、`evidence_insufficient` 或 `criteria_pending` 决定；
- 确认保存正式实际值、理由、确认人和时间；
- 实际值低于目标值时不能确认 `achieved`；
- 每个计算结果只允许一条正式确认，幂等重放返回原回执，第二次决定返回冲突。

### 3.4 差距与任务决定

- `gap_items`：差距类型、来源输入、事实说明、建议动作、建议责任人和建议节点；
- 差距类型包括 `quantity_shortfall`、`work_incomplete`、`evidence_missing`、`year_mismatch`、`work_not_started` 和 `criteria_pending`；
- `gap_task_decisions`：负责人决定 `create_task`、`dismiss` 或 `needs_review`；
- 选择 `create_task` 时，在同一事务建立 W9-4A 的任务草稿，并保存差距与任务关系；后续仍由负责人通过 W9-4A 派发，不直接把建议变成已执行任务。

## 4. A、B、C、D 的确定性口径

| 对象 | 固定输入 | 计算处理 | 差距处理 |
|---|---|---|---|
| A 企业 | 已确认本年度完成成果、已确认指标支撑、主证据、重复材料组 | 按成果候选只计 1 家 | 无补充任务 |
| B 企业 | 最终分类为本年度推进中，支撑关系待核实 | 不计入实际值 | `work_incomplete`，建议完成正式签约并补正式文件 |
| C 企业 | 最终分类为历史成果，业务日期为 2025 年，指标支撑被拒绝 | 不计入实际值 | `year_mismatch`，说明不能靠补附件改成本年度成果，通常关闭任务建议 |
| D 企业 | 无成果候选；固定读取一条待开展任务版本 | 不计入实际值 | `work_not_started`，建议先完成正式洽谈并提交记录 |

候选计算结果为目标 3、实际 1、差值 2、候选结论 `not_achieved`。C 用于解释排除原因，不占用“还差 2 家”中的新增名额。

## 5. 首批接口

| 接口 | 行为 |
|---|---|
| `POST /indicator-rules` | 从已发布指标知识建立规则 v1 |
| `POST /indicator-rules/{ruleId}/versions` | 增加规则版本，保留旧规则 |
| `GET /indicator-rules/{ruleId}` | 查看规则版本及关联指标来源 |
| `POST /indicator-evaluation-runs` | 固定规则、截止点、成果候选和任务版本并执行确定性计算 |
| `GET /indicator-evaluation-runs` | 按范围和指标查看计算历史 |
| `GET /indicator-evaluation-runs/{runId}` | 查看规则、输入、计入排除理由、结果、确认和差距 |
| `POST /indicator-evaluation-runs/{runId}/confirmations` | 负责人确认正式进度 |
| `POST /gap-items/{gapId}/task-decisions` | 负责人关闭、待核实或建立 W9-4A 任务草稿 |

所有写接口继续使用范围、期望版本、幂等键、操作者和用途组成的统一信封，并同步写操作回执、建设账本和 Outbox。

## 6. 权限

- 专业群负责人：建立和修订规则、发起计算、确认进度、处理差距并建立任务草稿；
- 教务审核人员：只读规则、计算、明细、确认和差距；
- 教师：通过本人任务和专业范围查看相关办理结果，本波不开放群级指标规则和正式进度决定；
- 信息支持人员：不读取指标、成果、差距、材料名称或统计结果。

无权访问详情统一返回不存在或不可访问，不泄露指标标题、数量或差距。

## 7. 失败和恢复

- 规则、成果决定、支撑决定或任务版本不属于同一学校、专业群和周期时拒绝运行；
- 未人工决定的成果、未固定版本的对象和截止点之后的事实不能静默进入计算；
- 输入发生变化不修改旧运行，必须建立新运行；
- 同一幂等键同一请求返回原回执，不同请求返回冲突；
- 旧规则版本、旧结果版本和已经处理的差距决定不能覆盖现有结果；
- 计算失败不形成部分结果或差距；
- 结果未知时按操作编号只读对账，不能直接重复写入。

## 8. 自测与通过门槛

1. A、B、C 三个成果决定和 D 任务版本形成固定输入；
2. 两次相同输入运行均返回目标 3、实际 1、差值 2，并具有相同输入摘要和结果摘要；
3. A 的扫描件和电子版不造成重复计数；
4. B、C、D 的排除理由及差距类型分别正确；
5. 负责人确认 `not_achieved` 后形成正式进度 1/3；错误确认 `achieved` 被拒绝；
6. C 的年度不符差距可以关闭但不能转成补材料任务；B、D 可由负责人分别建立不同任务草稿；
7. 新任务保持草稿状态，必须回到 W9-4A 另行派发；
8. 审核人员只读、教师和信息支持无群级指标数据泄露；
9. 幂等、第二次决定、跨范围输入、旧版本和直接猜测编号均被正确处理；
10. 19 个既有迁移继续兼容，新增迁移可在空库执行并重复执行；
11. OpenAPI、类型检查、全工程回归、全量集成和方案一致性检查通过。

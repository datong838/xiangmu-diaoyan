# 建设工作台与协同办理产品方案

> 版本：v1.0　日期：2026-10-18　状态：内部评审稿。

## 1. 目标

把教师、专业负责人、专业群负责人、教务审核人员和专业群智能体放在同一建设工作链中。工作台需要支持提交、修改、关联、退回、确认、审核和继续办理，不能只显示指标和统计数字。

## 2. 工作台层次

### 2.1 建设总工作台

面向当前专业群和建设周期，显示整体状态、重点节点、跨专业问题、待确认事项和成果编制进度。所有数字可以进入明细和办理。

### 2.2 我的工作台

面向个人，集中呈现本人待开始、进行中、待提交、被退回、待确认、待审核和即将到期事项。

### 2.3 专业工作台

面向专业负责人，呈现本专业承担的目标、任务、教师、工作、材料、问题和报告贡献。

### 2.4 对象办理页

指标、任务、工作记录、材料、问题和报告都采用“事实—关系—动作—历史—智能体协助”的共同页面结构。

## 3. 统一办理结构

| 区域 | 内容 |
| --- | --- |
| 对象信息 | 名称、状态、责任人、期间和当前版本 |
| 业务事实 | 当前已确认内容和待确认内容 |
| 关系视图 | 关联目标、任务、人员、材料、成果和报告 |
| 当前动作 | 当前角色可以执行的填写、提交、退回、确认等操作 |
| 办理历史 | 谁在何时做了什么，前后版本和原因 |
| 智能体协作 | 查询、整理、补全、检查和后续动作建议 |

## 4. 角色首页

### 教师首页

本人任务、被退回记录、需要补充的材料、近期截止事项、最近提交及“请专业群智能体协助记录”。

### 专业负责人首页

本专业任务分布、教师进展、待确认工作、缺证据事项、跨专业协作和专业阶段总结。

### 专业群负责人首页

建设依据状态、目标进度、专业对照、问题分类、后续任务、报告节点和待确认口径。

### 审核人员首页

待审核成果、关键数字核对、失效引用、退回修改和已批准版本。

## 5. 协同状态

不同对象可有不同状态，但界面共同区分：草稿、已提交、待确认、已退回、已确认、已撤回、已失效。逾期、风险和缺材料作为附加提示，不覆盖业务状态。

## 6. 提交与退回

- 提交前显示缺少的必填内容和材料；
- 退回必须说明原因并定位需要修改的内容；
- 修改产生新记录或新版本，不覆盖已确认内容；
- 已确认内容纠错时建立替代关系；
- 智能体可协助理解退回意见和形成修改草稿。

## 7. 跨页面连续办理

- 从指标进入任务、证据和进度；
- 从任务进入工作记录和材料提交；
- 从材料进入支撑的任务、指标和报告；
- 从问题直接建立补充任务；
- 从报告引用返回原件和确认记录；
- 从智能体回答进入任一具体对象。

每页底部给出当前流程的上一步、下一步和同对象相关页面，避免依赖左侧菜单寻找。

## 8. 通知和待办

首期使用站内待办。提醒按规则去重，显示原因、对象和处理入口。提醒已经发送不表示问题已解决；只有补充、确认、批准调整或取消后才能关闭。

外部邮件、短信或办公平台通知单独确认渠道、频率、接收人和费用，不随站内待办自动启用。

## 9. 搜索

统一搜索任务、人员、专业、材料、指标和报告。结果按对象类型分组，显示专业群、周期、状态和权限；受限对象不能通过标题、数量或片段泄露。

## 10. 移动端与大屏

首期优先保证电脑浏览器和手机浏览器可用。手机侧重点是查看待办、快速记录、拍照上传、补充说明和简单确认；复杂指标维护与报告编制以电脑端为主。大屏只显示经授权汇总，不作为业务办理入口。

## 11. 验收重点

1. 指定教师可以独立完成一次填报、提交和退回修改。
2. 负责人可以从首页进入缺项并形成补充任务。
3. 审核人可以从待审核进入引用核对、退回和批准。
4. 任一状态数字都可下钻到明细。
5. 页面间沿工作链连续进入，不需要回到菜单重新寻找。
6. 智能体协助能够生成真实业务草稿并进入人工确认。

# W9 权限、数据主权与多专业群隔离技术方案

> 版本：v1.0　日期：2026-10-18　状态：历史技术初稿，未经正式组织评审；作为第 122—128 份评审稿的详细参考。  
> 对应方案：08、25、31、36、37、38、39。

## 1. 目标

权限系统必须回答四个问题：谁、因为什么职责、在什么范围内、可以对什么版本执行什么动作。仅隐藏菜单不能作为权限实现。

## 2. 授权模型

采用“角色能力 + 数据范围 + 任务责任 + 临时授权”的组合判断：

```text
允许 = 身份有效
   AND 角色拥有动作能力
   AND 对象处于角色可办理范围
   AND 学校/专业群/专业/周期范围匹配
   AND 任务或审核责任匹配
   AND 对象状态允许该动作
   AND 临时授权未过期
```

### 2.1 角色能力

角色决定动作类型，例如教师可以提交本人任务，负责人可以分工和退回，审核人可以审核，信息支持人员可以处理账号和恢复。

### 2.2 数据范围

范围至少包含学校、专业群、专业、建设周期、对象类型、用途和敏感级别。搜索、数量统计、助手检索、下载和导出都使用同一范围判断。

### 2.3 任务责任

同一角色不等于能办理所有同类事项。任务负责人、配合人、审核人和观察人分别授权。

### 2.4 临时授权

临时授权必须记录目的、对象范围、生效时间、失效时间、批准人和撤销原因。到期自动失效；失效后已有导出链接也不能继续使用。

## 3. 权限判断位置

| 层 | 强制内容 |
| --- | --- |
| Web | 只显示允许操作，提供解释性提示；不能作为最终防线 |
| API | 对每次读取、列表、搜索、写入、下载和导出重新判断 |
| 数据访问层 | 所有查询强制带 `school_id` 和允许范围，避免遗漏过滤 |
| 文件服务 | 使用短期签名授权，生成前再次判断对象和版本权限 |
| 知识服务 | 先过滤范围再检索和排序，禁止“先搜到再隐藏” |
| 智能体 | 任务快照固定角色和范围，工具调用时再次判断 |
| 导出 | 对成果正文及所有引用材料分别校验，不因报告可见而自动开放原件 |

## 4. 默认角色边界

| 角色 | 默认可办 | 默认不可办 |
| --- | --- | --- |
| 教师 | 本人任务、工作记录、材料提交和退回补充 | 指标确认、正式审核、他人私有资料 |
| 专业负责人 | 本专业任务、材料关系、进度建议 | 其他专业私有资料、专业群最终结论 |
| 专业群负责人 | 本群任务分工、关系确认、进度确认和成果提交 | 学校级审批、改写原件 |
| 教务/科研审核人 | 指定范围的审核、退回和批准 | 修改提交者原件、查看无关受限资料 |
| 学校项目负责人 | 项目范围、重大事项和验收确认 | 绕过原责任人伪造事实或材料 |
| 信息支持人员 | 账号、系统状态、备份恢复和脱敏技术日志 | 业务正文、业务判断和代办提交 |
| 服务支持人员 | 学校授权范围内配置、培训和故障协助 | 自行扩大范围、复制资料或作出业务结论 |

## 5. 敏感内容分层

| 级别 | 示例 | 默认处理 |
| --- | --- | --- |
| L0 公开 | 学校批准公开的成果 | 按公开范围展示 |
| L1 校内 | 一般建设材料、总结 | 仅学校身份且符合群/专业范围 |
| L2 受限 | 协议、人员清单、未定稿报告 | 任务相关人员和审核人员可见 |
| L3 高敏 | 试卷正文、答案、个人明细 | 单独存放、单独授权、默认不进入智能体 |

标题、数量、摘要、片段、文件名和搜索命中都属于受保护信息。无权用户不能通过统计或错误信息推断对象存在。

## 6. 学校数据与云端服务边界

### 6.1 学校侧长期保存

- 数据库、文件原件和所有版本；
- 全文及向量索引；
- 用户会话和智能体任务状态；
- 提示上下文快照、生成结果和引用；
- 操作账本、安全事件和备份；
- 正式导出件和验收证据。

### 6.2 云端服务不得长期保存

- 文件原件、解析全文和图片；
- 用户姓名、协议名称、指标正文和任务正文；
- 学校知识索引和检索语料；
- 生成的报告正文和学校修改意见；
- 可还原学校业务内容的提示或响应日志。

### 6.3 单次调用要求

学校侧动作网关发送：调用编号、能力、最小必要内容、用途、截止时间和一次性授权证明。云端返回：结果、引用位置、异常、用量和回执。调用结束后按约定清理临时内容；学校侧保存完整任务证据。

## 7. 多学校与多专业群隔离

1. 学校是最高数据边界；不同学校使用独立工作区和密钥材料。
2. 专业群是默认知识、搜索、智能体和报告范围。
3. 跨专业群共享使用明确关系对象，指定共享对象、版本、用途和期限。
4. 新专业群只复用结构、流程、角色类型、空白模板和控制规则。
5. 初始化后执行搜索、助手、报告、导出四项隔离检查，通过后才能启用。
6. 缓存键、任务键、对象存储路径、索引名称和后台任务均包含学校与专业群范围。
7. 任何缺少范围的请求直接拒绝，不使用“默认专业群”。

## 8. 人员变化与撤权

人员离岗或换岗时：

1. 立即停止新会话、下载和导出授权；
2. 撤销长期及临时授权；
3. 列出未结束任务、草稿、审核和借阅；
4. 由负责人逐项转交或终止；
5. 保留原操作人和历史责任关系；
6. 重新计算共享链接、助手会话和离线导出风险；
7. 记录撤权和转交结果。

## 9. 文件、下载与导出

- 下载链接短时有效且绑定用户、对象版本和用途；
- 导出报告不自动赋予所有引用原件下载权限；
- 高敏正文禁止进入通用预览缓存；
- 批量导出需要额外权限和人工确认；
- 导出包包含清单、版本、生成时间、导出人和校验值；
- 撤权后未使用链接失效，已导出文件按学校管理制度处理。

## 10. 技术支持与运维访问

信息支持和服务支持默认只查看：服务健康、时间、错误类别、操作编号、资源用量和脱敏日志。确需查看业务内容时，必须由学校创建限时授权，明确对象、用途和见证人；授权结束后自动撤销并形成安全记录。

## 11. 备份与恢复

- 数据库、对象存储和索引分别备份但使用同一恢复清单编号；
- 恢复演练在隔离环境进行；
- 恢复后核对对象数量、当前版本、关系、文件校验值、索引版本和账本连续性；
- 云端服务配置可重建，不能成为学校数据唯一副本；
- 恢复时间和恢复点目标由学校在试点前确认。

## 12. 权限与隔离验证集

至少包含：

1. 两个学校、两个专业群、五个专业的正向与拒绝用例；
2. 列表、详情、搜索、助手、数量、下载、报告和导出八个入口；
3. 已知对象编号直接访问；
4. 缓存、后台任务和导出包范围；
5. 临时授权到期和主动撤销；
6. 人员离岗后会话、链接和未结束任务；
7. 信息支持人员处理故障但看不到正文；
8. NEW-G02 不出现 DEMO-G01 的 A—D 企业、人员、1/3 进度或报告内容。

任何越权看到标题、数量、摘要、正文或搜索片段均为不通过，不能作为一般已知限制放行。

## 13. 当前结论

本方案定义了权限和数据主权的强制边界。真实身份提供方、学校组织同步方式、RPO/RTO、对象存储产品和云端临时内容清理时限仍需学校及合作方确认。当前为“已设计”，尚无真实权限与恢复证据。

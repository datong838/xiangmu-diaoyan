# W9-6C 局部改稿、独立审核、正式导出与归档实现方案

> 前置：第 13、14、22、39—43、71—74 份方案与记录。  
> 本文职责：在 W9-6B 成果初稿上补齐指定范围改稿、人工保护、独立审核、真实 Word/PDF 文件、下载与归档，形成 W9-6 的完整首链。

## 1. 目标

W9-6C 建立以下受控链路：

```text
W9-6B 成果初稿
  → 编写人标记必须保留的人工内容
  → 明确本轮允许修改的章节和修改要求
  → 形成新草稿版本、章节差异和未执行原因
  → 提交确切版本给指定独立审核人
  → 退回后建立新版本并重新提交 / 批准当前版本
  → 生成带“草稿”标识的内部文件或批准版本的正式 Word/PDF
  → 固定模板、事实快照、版本、审核决定和导出文件形成归档
```

局部改稿只改变成果表达，不重新计算 W9-6A 事实，不更换 W9-6B 已固定的模板版本、事实快照或材料版本。任何批准都只对一个确切成果版本有效；批准后再修改会形成新的草稿版本并重新审核。

## 2. 产品硬约束

1. **修改范围明确**：请求必须列出允许修改的章节；未列出的章节逐字复制，不允许整篇重写。
2. **锁定事实保留**：被章节引用的事实表述必须完整保留，不能把“目标 3、确认完成 1、尚差 2”改成更好看的数字。
3. **人工内容保护**：编写人可从当前版本标记必须原样保留的文本块；后续版本必须包含完全相同的保护内容。
4. **版本不可覆盖**：修改形成新版本，基版本、章节、引用、材料目录、缺项和保护块继续保留。
5. **审核人与作者分离**：提交时指定本范围内有效的教务审核人员；审核人不能是该成果版本作者。
6. **审核绑定版本**：退回或批准绑定提交时的版本和内容摘要；修改后旧批准不能沿用。
7. **缺项阻止批准**：存在缺事实、缺材料、缺模板说明或未解决冲突时，不得提交正式审核。
8. **正式导出门槛**：正式文件只能来自已批准版本；草稿导出必须有明显草稿标识。
9. **归档不静默变化**：归档固定模板版本、事实快照、成果版本、审核决定、Word/PDF 文件摘要；源数据后续变化不改写归档内容。
10. **学校侧保存**：导出文件写入 `SCHOOL_FILE_ROOT` 管理目录，不发送到外部服务；外部智能服务继续关闭。

## 3. 新增对象

### 3.1 改稿与保护

- `deliverable_protected_blocks`：绑定成果版本和章节，保存保护块编码、原文、摘要、标记者；建立后不可修改或删除。
- `deliverable_revision_requests`：保存基版本、允许修改章节、修改要求、未执行原因、发起人和请求摘要。
- `deliverable_version_diffs`：逐章节记录基版本与新版本摘要、是否变化、锁定事实数量和保护块数量。

新版本继续写入现有 `deliverable_compilation_versions`、`deliverable_sections`、`deliverable_section_facts`、`deliverable_support_materials` 和 `deliverable_missing_items`。引用、材料目录和未解决缺项默认从基版本复制，不接受客户端伪造。

### 3.2 审核

- `deliverable_review_submissions`：绑定成果版本、提交人、指定审核人和提交时内容摘要。
- `deliverable_review_decisions`：绑定一次审核提交，保存 `return` 或 `approve`、原因、涉及章节和审核人。

一次提交只能有一个决定。退回后必须建立新版本再提交；批准后原版本保持批准，新版本仍从草稿重新开始。

### 3.3 导出与归档

- `deliverable_exports`：保存成果版本、审核决定、导出用途、格式、文件名、学校侧存储键、文件摘要、字节数和建立人。
- `deliverable_archives`：固定成果版本、模板版本、事实快照、审核决定、归档原因和建立人。
- `deliverable_archive_exports`：记录归档所包含的正式导出文件。

首批输出格式为 `docx` 和 `pdf`。DOCX 采用标准 Open XML 文件；PDF 使用学校侧确定性排版器形成实际文件。正式归档首批要求同一批准版本同时具有 Word 和 PDF 两种正式文件。

## 4. 局部改稿接口和规则

### 4.1 标记保护块

`POST /deliverable-compilations/{compilationId}/protected-blocks`

- 只允许在当前草稿版本、尚未提交审核时标记；
- 保护内容必须是指定章节当前正文中的完整片段；
- 同一版本、章节和保护块编码不能重复；
- 标记保护块不改变正文版本，但进入建设账本。

### 4.2 建立新版本

`POST /deliverable-compilations/{compilationId}/versions`

请求明确：基版本、允许修改章节、逐章新正文、修改要求和未执行意见。服务端执行：

- 未列入允许范围的章节逐字复制；
- 允许范围与实际更新章节必须一致；
- 新正文必须包含该章节全部保护块原文；
- 新正文必须包含该章节引用事实的锁定表述；
- 引用、材料目录和缺项由服务端复制；
- 保存逐章节前后摘要和是否变化；
- 至少一个章节实际变化，否则拒绝建立空版本。

## 5. 审核接口和状态判断

### 5.1 提交审核

`POST /deliverable-compilations/{compilationId}/review-submissions`

必须满足：

- 提交的是成果当前版本；
- 没有未关闭缺项；
- 必填章节非空且引用事实仍存在；
- 指定审核人具有同学校、专业群和周期的教务审核角色；
- 审核人与版本作者不是同一人；
- 当前版本没有尚未决定的审核提交。

### 5.2 审核决定

`POST /deliverable-review-submissions/{submissionId}/decision`

- 只允许提交时指定的审核人办理；
- `return` 必须填写原因和涉及章节，成果仍须建立新版本；
- `approve` 只批准提交时的确切版本和摘要；
- 智能体、编写人、专业群负责人和信息支持人员都不能代替审核人批准。

成果详情按记录推导 `draft`、`under_review`、`returned` 或 `approved`，不原地改写历史版本状态。

## 6. 导出与归档

### 6.1 导出

`POST /deliverable-compilations/{compilationId}/exports`

- `draft`：当前有权编写者可导出，页眉或首页必须显示“草稿—不得作为正式提交文件”；
- `formal`：必须指定已批准的成果版本，只能由有权人员发起；生成内容必须与批准版本摘要一致；
- Word 与 PDF 均包含成果标题、期间、模板版本、数据截止点、章节正文和支撑材料目录；
- 文件写入学校侧管理目录并登记 SHA-256、字节数和文件名；
- 相同幂等请求返回原导出记录，不重复生成文件。

读取接口：

- `GET /deliverable-exports/{exportId}`：查看文件元数据和对应审核状态；
- `GET /deliverable-exports/{exportId}/download`：在权限校验后下载实际文件。

### 6.2 归档

`POST /deliverable-compilations/{compilationId}/archive`

- 只能归档已批准版本；
- 首批必须同时选择该版本的正式 Word 和正式 PDF；
- 文件摘要、批准决定、模板版本和事实快照必须相互一致；
- 归档记录和所含文件不可修改或删除；
- 归档不代表已对外报送，对外提交继续由学校现有流程完成。

## 7. 权限

- 专业群负责人：标记保护块、建立成果新版本、提交审核、导出和归档；
- 教务审核人员：读取成果并办理本人被指定的审核，不能改稿、导出正式文件或归档；
- 教师：首批不读取或编辑群级成果；
- 信息支持人员：只看系统健康，不见成果名称、数量、正文、审核或文件；
- 跨学校、跨专业群、跨周期对象统一按不存在处理。

新增能力编码：`deliverable:submit`、`deliverable:review`、`deliverable:export`、`deliverable:archive`。

## 8. 失败与恢复

- 旧版本改稿、提交、保护或导出返回版本冲突；
- 修改超出允许章节、保护块丢失、锁定事实表述缺失时整次拒绝；
- 作者自审、非指定审核人决定、重复决定或未补缺项提交均拒绝；
- 未批准版本正式导出、批准版本内容摘要不一致或归档缺 Word/PDF 均拒绝；
- 文件生成或落盘失败时不建立成功回执；若数据库写入失败，清理本次暂存文件；
- 结果不明确时按操作编号只读对账，不自动重试生成另一份正式文件；
- 所有写操作使用统一范围、期望版本、幂等键、回执、建设账本和 Outbox。

## 10. 自测门槛

1. 在无缺项的年度报告初稿上标记一段人工保护内容；
2. 只允许修改指定章节，未指定章节逐字不变；
3. 删除保护内容或改动“目标 3、确认完成 1、尚差 2”的锁定表述均被拒绝；
4. 合法改稿形成 v2、章节差异和连续版本链，引用、材料和源事实不变；
5. 作者自审、负责人代审、非指定审核人决定均被拒绝；
6. 指定审核人退回 v2 后，v2 不能变为批准；建立 v3、重新提交后才能批准；
7. 退回或批准都绑定确切版本和摘要，批准后建立 v4 时不得沿用 v3 批准状态；
8. 有缺项的成果不能提交审核；未批准版本不能生成正式文件；
9. 草稿 Word/PDF 有明显草稿标识，正式 Word/PDF 来自批准版本且文件实际存在、摘要与数据库一致；
10. 正式 Word/PDF 与批准版本章节、模板版本、事实快照和支撑材料目录一致；
11. 归档必须同时包含同一批准版本的正式 Word/PDF，并可回查模板、快照、审核和文件；
12. 教务审核人员只办理指定审核，教师和信息支持零访问，跨范围对象不泄露；
13. 相同幂等请求不重复写入或生成文件，旧版本并发操作被拒绝，历史记录不可修改；
14. 指标、任务、材料、事实快照和 W9-6B 原版本数量与内容不因改稿、审核、导出和归档而改变；
15. 空库迁移、重复迁移、编译、类型检查、全工程测试、DOCX/PDF 文件检查和 OpenAPI 解析通过。

全部通过后标记 `W9-6C-verified`，同时只开启 `formalReviewEnabled`、`formalExportEnabled` 和 `deliverableArchiveEnabled`。`externalAiEnabled`、真实文档自动解析和向量检索继续保持关闭；这不代表 W9、W10 或学校真实试点已经完成。

# W9-5B 受控动作执行、结果确认与草稿写回验证记录

> 日期：2026-10-18　状态：合成环境验证通过；下一步 W9-5C。  
> 对应方案：第 65、67 份文档。

## 1. 验证结论

W9-5B 已把“批准后的计划”落实为可逐步执行、可独立对账的产品动作。智能体不接收任意工具名或业务对象编号，而是由服务端从当前任务、当前计划和固定知识包解析下一步动作。每一步均形成动作运行、结构化结果、来源关系、操作回执和建设账本记录。

计划确认与结果确认已经分开。负责人先确认是否允许智能体读取、分析并准备草稿；智能体形成具体任务标题、责任建议、节点和预期产出后再次停下。负责人查看实际内容并确认后，系统才建立 W9-4A 任务草稿。新任务保持 `draft`，没有自动派发、完成或修改指标正式值。

## 2. 已验证的产品行为

| 行为 | 验证结果 |
|---|---|
| 指标进度查询 | 按 `indicator.read`、`progress.read`、`agent.answer.compose` 顺序执行，形成目标、正式实际、差距、截止点和来源组成的答复 |
| 动作顺序 | 客户端只能提交计划步骤编号；跳过第一步直接执行第二步返回冲突 |
| 动作幂等 | 相同动作请求重放返回原回执，没有第二次运行和第二份业务结果 |
| 失败与恢复 | 草稿写入中责任人失效时整个业务写入回滚，失败运行和失败回执保留；条件恢复后使用新操作编号成功重试 |
| 差距读取 | B 企业“工作未完成”和 D 企业“工作未开始”分别保留来源、责任人、专业和节点 |
| 草稿准备 | 两项差距形成两份不同的候选任务，写入前停在 `waiting_result_confirmation` |
| 缺项保护 | 只有数量差额、没有责任对象和专业来源时不编造草稿，空候选结果不能被批准 |
| 结果确认 | 教务审核人员不能替负责人批准；负责人批准后只开放同计划的下一步草稿建立动作 |
| 草稿写回 | 同一事务建立两条 W9-4A 任务及差距关系，两条任务均为 `draft` |
| 业务边界 | 没有自动派发任务、确认进度、发布知识、审核成果、变更授权或对外提交 |
| 指标独立性 | 草稿写回后指标正式实际值仍为 1，未因智能体动作被改写 |
| 只读对账 | 发起人可按动作编号查看结果、来源、人工决定和业务关系；信息支持人员不能读取业务结果 |

## 3. 两级人工确认

### 3.1 计划确认

计划确认只表示允许执行计划中的读取、分析和候选准备动作。它没有批准尚未生成的具体草稿，也没有授权任务派发或任何正式业务决定。

### 3.2 结果确认

`task.draft.prepare` 成功后，具体草稿字段保存在动作结果中。负责人必须基于当前智能体任务版本作出一次 `approve` 或 `reject`。未确认、审核人员确认、旧版本确认和第二次决定都被拒绝。批准结果只允许下一步建立草稿。

## 4. 本地动作网关与学校资料边界

本地动作网关已启用 `local_deterministic` 模式，首批目录共 8 个动作。网关输入只包含动作运行编号、动作代码、范围证明摘要、知识包摘要、输入摘要、匿名对象引用、超时和取消摘要。

边界测试已经证明：

- 含学校正文、文件名、人员姓名或任意工具参数的请求被拒绝；
- 安全日志不记录匿名对象引用或业务内容；
- `externalEndpoints=[]`；
- `durableSchoolDataStorage=false`；
- `externalAiEnabled=false`。

因此 `actionGatewayEnabled=true` 只表示学校侧确定性动作分派和校验已经运行，不表示云端动作或外部模型已经启用。

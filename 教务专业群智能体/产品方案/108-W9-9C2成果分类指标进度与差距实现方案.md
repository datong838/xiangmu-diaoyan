# W9-9C2 成果分类、指标进度与差距实现方案

> 版本：v1.1　日期：2026-10-19　状态：已实现并通过合成环境验证。  
> 前置条件：W9-9C1 工作记录、提交、退回与确认已经验证。  
> 对应需求：T06、T10、T11，并承接 T04、T07、T08 的任务事实与资料版本。

## 1. 本切片解决什么问题

任务完成只说明一项工作已经办结，不能直接说明建设指标已经达成。本切片把已经确认的工作、确切材料和正式建设要求继续整理为可核对的成果，再按固定规则计算指标候选进度，由专业群负责人确认正式结论，并把差距重新转成后续任务。

```text
已确认工作与确切材料
  → 提出成果候选和指标支撑建议
  → 负责人确认成果分类与支撑关系
  → 从正式知识建立指标规则
  → 固定成果、任务版本和统计截止日期
  → 形成可重复核对的计算快照
  → 负责人确认正式进度结论
  → 差距保留依据并决定是否转成任务
  → 返回工作记录、提交和确认办理链
```

页面必须持续区分四件事：任务是否完成、成果是否成立、材料是否足以支撑、指标是否达成。任何一个状态都不能替代其他状态。

## 2. 使用者和职责

| 使用者 | 本切片中的工作 |
| --- | --- |
| 教师 | 从本人可见的真实任务和材料提出成果候选；查看本人权限范围内的成果与进度 |
| 专业群负责人 | 审核成果分类和指标支撑；建立指标规则；发起计算；确认正式进度；处理差距 |
| 教务审核人员 | 在获准范围内查看成果、规则、计算依据和确认结果，不代替负责人作决定 |
| 信息支持人员 | 不读取成果标题、材料、指标数值、差距说明等业务正文 |

## 3. 页面结构

左侧“目标与进度”进入一个连续工作区，不把成果、指标和差距拆成互不相干的统计页。

### 3.1 顶部状态概览

显示当前范围内的成果候选数、待确认数、指标规则数、最近正式进度和待处理差距。数字必须来自当前学校、专业群和建设周期，不能跨范围汇总。

### 3.2 成果办理区

1. 清单展示成果编号、名称、业务日期、建议分类、当前状态、材料数量和指标支撑数量；
2. 教师或负责人可以从当前可见的材料版本发起成果候选，并可关联来源任务；
3. 每份材料明确用途：主要证据、辅助证据或过程材料；
4. 可以选择一条正式指标知识，提出“该成果可能支撑此指标”的建议并填写理由；
5. 详情页同时显示材料版本、来源任务、支撑建议、人工决定和重复材料关系；
6. 负责人必须逐条决定成果分类和全部指标支撑建议，决定后保留原建议和理由；
7. 成果决定完成后仍显示“指标进度尚未变化”，防止把分类确认误当成指标达成。

### 3.3 指标规则区

指标规则只能从已正式发布的指标知识建立。规则固定：目标值、单位、统计期间、可计入的成果分类、必须具备的证据用途和变更原因。

现有接口只有按编号读取规则详情，无法在页面刷新后恢复指标工作区。因此本切片增加范围内规则清单接口：

`GET /indicator-rules?schoolId&groupId&cycleId`

返回规则编号、来源正式知识、当前版本、目标值、单位、统计期间和规则条件摘要。接口沿用 `indicator:read` 权限；无权读取时返回空清单，不能通过猜测范围获取内容。

### 3.4 计算与正式确认区

负责人选择一个规则版本、统计截止日期、成果候选和相关任务版本后发起计算。系统固定全部输入版本并显示：

- 候选实际值、目标值和尚差数量；
- 哪些成果被计入，哪些没有计入及原因；
- 哪些任务尚未开始、尚未完成或已由成果代表；
- 由规则产生的候选结论；
- 负责人作出的正式结论、确认数值和理由。

计算快照不能随着材料换版、任务更新或成果重新整理而静默变化。需要重新判断时必须建立新的运行记录。

### 3.5 差距办理区

差距按数量不足、工作未完成、工作未开始、年度不符、材料不足、成果分类未确认、指标支撑未确认等原因分别呈现。每条差距显示来源输入、说明、建议动作、建议责任人和当前处理状态。

负责人可作出三种决定：

- 建立任务：只在规则允许且差距有明确工作对象时形成任务草稿；
- 暂不建立任务：保留原因并关闭该差距；
- 待进一步核对：保留差距，不虚构任务或责任人。

差距转成任务后进入 W9-9C1 的任务、工作记录、提交、退回和确认链，不在指标页直接修改工作事实。

## 4. 贯穿示例

正式知识中已有指标“2026 年新增合作企业 3 家”。教师完成 B 企业协议任务并提交材料后，可以提出“B 企业正式合作协议”成果候选，建议分类为“本年度已完成”，把协议正式版本标为主要证据，并建议支撑该指标。

专业群负责人确认成果分类和指标支撑后，指标值仍不自动变化。负责人建立目标值 3 家、统计期间为 2026 年、只计入“本年度已完成”且必须有主要证据的规则，再选择已经确认的成果发起计算。若当前只有 1 家符合规则，系统形成“候选实际 1 家、目标 3 家、尚差 2 家”的快照。负责人确认“未达成”后，数量差距保留为待进一步核对；若另有尚未开始或尚未完成的合作企业任务，则可从相应工作差距建立后续任务。

## 5. 产品状态和操作边界

### 5.1 成果状态

`待确认 → 已确认 / 已拒绝 / 待核实`

成果分类包括本年度已完成、本年度推进中、历史成果和暂未归类。“待开展”属于任务状态，不属于成果分类。没有材料不能为了补齐数量建立成果。

### 5.2 指标进度状态

计算结果先是候选结论；负责人确认后才形成正式进度。正式进度包括已达成、未达成、资料不足和口径待确认。

### 5.3 差距状态

`待处理 → 已建立任务 / 已关闭 / 待进一步核对`

同一差距只能决定一次；旧页面、重复点击和版本冲突不能形成重复任务。

## 6. 接口与页面最小改动

### 6.1 后台

1. 新增范围内指标规则清单读取；
2. 复用现有成果候选、成果决定、指标规则、计算、确认和差距决定接口；
3. 不修改既有表结构和计算口径；
4. 新接口补充 OpenAPI 和范围隔离测试。

### 6.2 前台

1. 开放“目标与进度”菜单；
2. 新增连续的成果、指标、计算与差距工作区；
3. 新增成果详情与负责人决定页面；
4. 新增指标规则详情、计算输入、正式确认和差距办理页面；
5. 所有写操作使用操作编号、预期版本和写入回执；刷新后从后台恢复，不依赖浏览器临时记忆。

## 7. 验证场景

1. 用已经确认的任务、正式材料和正式指标知识建立成果候选；
2. 负责人确认成果和指标支撑，页面明确显示指标尚未变化；
3. 建立目标 3 家的指标规则，刷新后仍可从规则清单进入；
4. 固定成果和任务版本发起计算，得到 1/3、尚差 2 的快照；
5. 负责人确认“未达成”，正式结论与候选结论分别保留；
6. 查看输入未计入原因和差距明细；
7. 对数量差距选择待核对，对明确的工作差距建立任务并返回任务链；
8. 教师、负责人、审核人员和信息支持人员的权限边界通过；
9. 跨学校、跨专业群和跨周期读取返回零内容或不可访问；
10. 全新资料库迁移、专项测试、全工程回归和 OpenAPI 校验通过。

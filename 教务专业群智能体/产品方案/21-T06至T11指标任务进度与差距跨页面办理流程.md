# T06—T11 指标、任务、进度与差距跨页面办理流程

> 版本：v1.0　日期：2026-10-18　状态：内部评审稿。  
> 对应波次：W5，并向 W6 提供周期总结输入。  
> 文档职责：把业绩归类、计划分解、任务执行、进度判断、差距处理和周期总结连成一条可实际办理的产品链。

## 1. 产品目标

这组流程回答六个连续问题：

1. 已有业绩可能支持哪些指标；
2. 年度目标接下来由谁完成什么；
3. 教师任务如何提交、退回、补充和确认；
4. 当前指标究竟完成多少、依据是什么；
5. 未达成是缺工作、缺材料还是缺口径；
6. 本周期完成了什么，下周期怎样继续。

系统不能把六个问题压成一个“完成率”。每一步都形成独立对象和人工决定。

## 2. 页面与工作区

| 页面 | 主要对象 | 关键写操作 |
| --- | --- | --- |
| 业绩分类工作台 | 成果、材料、分类规则、候选指标关系、重复组 | 接受、修改、拒绝、合并、待核实 |
| 年度计划分解台 | 目标、指标、年度/月周计划、任务草稿 | 拆分、指派、调整、确认派发 |
| 任务办理页 | 任务、工作记录、材料、退回意见 | 填进展、提交、退回、补充、确认 |
| 指标逐项对照页 | 目标、计算快照、事实、证据、判断 | 重新计算、核对证据、确认结论 |
| 差距与补充任务台 | 差距、原因、建议动作、任务草稿 | 分类原因、编辑动作、确认生成任务 |
| 周期总结与计划编辑页 | 周/月/年总结、计划差异、遗留、下期任务 | 编辑、引用、确认、建立任务 |
| 专业群助手任务页 | 跨页面任务和建议 | 理解、计划、调用能力、等待确认、写回 |

## 3. 贯穿产品链

```text
已确认建设依据与指标
  → 已有业绩分类和候选匹配（T06）
  → 负责人确认可计入成果及待办差距
  → 年度目标分解为月周任务（T07）
  → 教师持续提交工作和材料（T08）
  → 按规则形成进度计算快照（T10）
  → 负责人确认达成、未达成、资料不足或待确认
  → 对差距形成补工作/补材料/核实建议（T11）
  → 确认后成为新任务并返回 T08
  → 形成本期总结和下一周期计划（T09）
```

## 4. T06：已有业绩归类和指标匹配

### 4.1 发起方式

- 在资料交接批次中选择“整理业绩”；
- 在成果中心批量选择已有成果；
- 在某项指标中选择“查找可能支撑的业绩”；
- 对助手说“把这批业绩按任务书指标整理”。

### 4.2 固定输入

系统保存成果、材料版本、专业范围、建设周期、分类规则版本和有效建设依据。助手先检查重复、业务日期、正式状态和缺少证据。

### 4.3 分类工作区

每行展示：

- 业绩或成果；
- 所属专业和发生时间；
- 建议分类和建议指标；
- 匹配理由及原文要求；
- 现有证据与缺少证据；
- 重复提示；
- 操作：接受、修改、拒绝、标记待核实。

### 4.4 人工确认

负责人确认成果身份、分类和指标关系。确认一条关系只表示该成果可用于相应指标，是否计入数值还要由统计规则和 T10 决定。

### 4.5 示例数据走查

- A 企业正式协议和活动记录：建议关联“2026 年新增校企合作企业”；
- B 企业协议草稿：保留为推进中材料，不建议计入已完成；
- C 企业为 2025 年合作：归入历史合作，不计入 2026 年新增；
- D 企业无有效进展：不生成虚假成果，保留待开展事项；
- A 企业扫描件和电子版：进入同一成果的多个材料版本或证据，不重复计数。

### 4.6 写回

写回成果、专业归属、分类结果、指标候选/确认关系、重复组和待核实项。被拒绝建议保留判断记录，避免重复推荐。

## 5. T07：目标分解为年度、月度和周任务

### 5.1 发起方式

负责人从目标、指标、年度计划或差距页面进入“分解任务”，也可请助手根据学校重点工作和部门计划拟定安排。

### 5.2 计划分解视图

左侧显示上级工作、建设依据、年度目标和当前差距；中间按月/周显示任务草稿；右侧显示智能体建议、人员负荷、节点冲突和缺少的预期产出。

### 5.3 任务草稿内容

每项任务至少有：来源目标/指标、任务说明、责任专业、责任人、协同人、开始和截止时间、预期产出、需提交材料、确认人和优先级。

### 5.4 智能体协助

助手可根据已有任务、人员职责和节点建议拆分，但不能虚构学校行政关系，也不能自动派发。人员冲突仅作为提示，由负责人调整。

### 5.5 人工确认与派发

负责人逐项修改或批量确认同类任务。确认后产生正式任务、通知和建设账本记录。计划后续调整形成新版本，原安排仍可回看。

### 5.6 示例数据走查

“年度新增合作企业 3 家”可以形成：推进 B 企业正式签约、启动 D 企业正式洽谈、持续寻找新的候选企业等任务。A 企业已确认完成的工作不重复安排；C 企业年度不符，不能通过新任务把历史合作改成本年度新增。

## 6. T08：任务执行、提交、退回和问题闭环

### 6.1 教师待办

教师工作台按当前周期显示本人待执行、进行中、被退回、即将到期和待补材料任务。点击直接进入任务办理页。

### 6.2 填写进展

教师填写本次做了什么、业务日期、参与人、结果、问题和下一步，并关联已有工作记录或新建记录，提交材料版本。

### 6.3 助手协助

助手检查是否回答任务要求、日期与周期是否一致、预期材料是否缺少、同一成果是否重复，并生成可编辑说明。助手不能补造正式协议或未发生的洽谈。

### 6.4 提交与核对

教师提交确切版本。负责人可以：

- 确认本次工作事实；
- 退回并说明需补充什么；
- 确认工作但标记证据仍不足；
- 将新问题转入问题清单；
- 调整任务但保留原计划与原因。

### 6.5 闭环

任务完成、工作事实确认、证据确认和指标达成四种结果分别记录。提醒已读不等于问题解决，任务完成也不自动改变指标结论。

### 6.6 写回

写回任务状态、工作记录版本、材料关系、退回意见、问题和确认记录，为 T10 提供已确认事实。

## 7. T10：逐项判断指标达成情况

### 7.1 发起方式

负责人进入“指标逐项对照”，选择专业群、建设周期、统计期间和数据截止点；也可请助手“按任务书逐项检查今年完成情况”。

### 7.2 计算准备

系统固定：指标修订、分期目标、统计规则、适用专业、已确认成果、事实、证据和截止点。规则缺失或冲突时标记不可计算。

### 7.3 确定性计算

系统按规则去重和汇总，形成计算快照。智能体负责解释明细、发现异常和组织说明，不自由生成正式数值。

### 7.4 指标对照表

每行展示：

- 指标及原文位置；
- 目标值和统计口径；
- 已确认实际值及明细；
- 证据要求和当前证据；
- 系统计算结果；
- 智能体建议状态及理由；
- 人工正式结论；
- 截止点和更新时间。

### 7.5 四类正式结论

1. 已达成；
2. 未达成；
3. 资料不足，暂不能判断；
4. 口径待确认，暂停判断。

风险、证据覆盖和业务状态分别显示，不能合成一个红黄绿图标。

### 7.6 示例数据走查

目标 3 家；A 企业符合本年度和正式证据要求，实际确认 1 家；B 为协议草稿，不能计入完成；C 年度不符；D 尚未形成成果。因此计算快照为 1/3，尚差 2 家。负责人可确认该结论，也可退回核对某项事实。

### 7.7 写回

保存计算快照、建议判断、人工结论、所用版本和截止点。正式结论变化时旧结论失效但保留，并触发报告和总结影响复核。

## 8. T11：区分原因并形成补充任务

### 8.1 从差距进入

未达成、资料不足和口径待确认的指标自动进入差距工作台。一个指标可有多个不同原因，不能只写“未完成”。

### 8.2 原因分类

| 原因 | 产品处理 |
| --- | --- |
| 目标数量不足 | 建议补工作或寻找新对象 |
| 工作正在推进 | 保留当前任务并明确下一节点 |
| 工作已完成但证据缺失 | 建议补材料，不重新虚构工作 |
| 材料存在但不符合期间/口径 | 说明不适用原因，不能靠补附件变成符合 |
| 统计规则或依据冲突 | 建立口径待确认事项 |
| 责任或节点不清 | 请负责人确认任务安排 |

### 8.3 助手建议

每条建议显示问题、依据、建议动作、建议责任人、建议节点、所需产出和待确认信息。建议动作先处于草稿状态。

### 8.4 人工处理

负责人可修改后确认、合并重复动作、拒绝建议、要求补充或暂不处理。确认后创建正式补充任务并返回 T08 跟踪。

### 8.5 示例数据走查

- B 企业：工作已推进但缺正式签约，建议完成协议确认并补正式文件；
- D 企业：尚未形成有效进展，建议先完成正式洽谈并提交记录；
- C 企业：年度不符合，不能创建“补附件即可计入”的错误任务；
- 若两份文件目标值冲突：创建口径确认，不先生成数量补充任务。

### 8.6 写回

写回差距分析、原因、建议动作、人工决定和正式任务关系。补充任务完成后重新触发 T10，而不是直接关闭指标差距。

## 9. T09：周期总结与下一周期计划

### 9.1 发起方式

用户手工选择周、月或年，或根据已确认配置生成定时草稿。定时任务只生成草稿，不自动发布。

### 9.2 输入快照

固定本期计划、已确认任务、工作记录、进度结论、未完成原因、上期遗留和新要求。部门工作总结与专业群建设报告分别使用自己的口径。

### 9.3 编辑工作区

五个区域：本期完成事实、计划与实际差异、未完成及原因、遗留问题、下期安排。每条内容可查看来源，也可直接从遗留项创建任务草稿。

### 9.4 人工确认和写回

负责人修改并确认总结；下期安排确认后形成周期计划或任务。总结结论不反向修改源工作和指标事实。

## 10. 页面连续导航

每页顶部显示当前链路和状态：

```text
业绩已整理
  → 计划待确认
  → 任务执行中
  → 进度待判断
  → 差距待处理
  → 补充任务执行中
  → 周期总结待确认
```

对象详情可在不丢失当前位置的情况下打开依据、材料、人员和历史版本。完成当前步骤后直接进入下一节点或返回产生该问题的指标。

## 11. 专业群智能体在链路中的呈现

智能体任务卡持续展示：当前目标、适用范围、所用依据、已完成步骤、待确认建议、下一动作和最终写回对象。用户跨页面后仍在同一任务内，助手不重复询问已经确认的范围。

## 12. 角色动作

| 角色 | 主要动作 |
| --- | --- |
| 教师 | 查看任务、填进展、提交工作与材料、处理退回 |
| 专业负责人 | 核对专业事实、协同任务和材料关系 |
| 专业群负责人 | 确认分类、计划、任务、进度结论和补充任务 |
| 教务/管理人员 | 查看授权范围进度、处理跨部门事项和口径 |
| 审核人员 | 在需要时复核正式结论和成果，不代替日常填报 |
| 专业群智能体 | 整理、建议、计算调用、解释、生成草稿和写回已确认结果 |

## 13. 原型走查脚本

1. 导入 A、B、C、D 四家企业资料并进入分类工作台；
2. 确认 A，标记 B 缺正式协议、C 年度不符、D 待开展；
3. 将年度目标 3 家分解为 B、D 和新候选企业任务；
4. 教师对 B 提交一次进展，被退回补正式文件；
5. 运行指标对照，得到已确认 1、尚差 2 的计算快照；
6. 负责人确认结论并进入差距台；
7. 分别形成 B 的补材料任务和 D 的补工作任务；
8. 完成其中一项后重新计算，不直接手改完成率；
9. 生成本月总结和下月计划草稿，并由负责人修改确认；
10. 从总结中的遗留事项返回正式任务，验证闭环。

## 14. 验收门槛

- T06—T11 使用同一批对象、事实和规则，不复制各自数据；
- 智能体建议、系统计算和人工正式结论视觉上和数据上分开；
- 计划调整、任务退回、进度重算和总结修改均有版本与账本；
- 一项差距能回到依据、事实、证据和计算明细；
- 补充任务必须经确认，并能返回 T08 执行和 T10 重算；
- 用户沿主线完成整条链，不依赖熟悉左侧菜单；
- 失败、资料不足和口径冲突均可继续办理而不是显示假结果。

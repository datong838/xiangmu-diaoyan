# 专业群 AI 工作站产品总方案

> 版本：v1.0 产品方案初稿  
> 编制日期：2026-10-18  
> 主要依据：《专业群AI工作站需求确认单.md》v1.6  
> 文档用途：将已识别的学校业务要求转化为可设计、可建设、可试用和可验收的产品方案，作为后续信息架构、页面原型、交互设计和分阶段建设的共同依据。  
> 当前状态：内部评审稿；其中标为“待校方确认”或“选配”的内容，不视为已经确定的交付范围。

> 本文负责总体产品结构和各分方案的共同口径。专业群智能体、专业群知识库、协同办理、业务闭环、成果编制、权限保障、实施验收和视觉设计输入分别由本目录配套分方案展开。

## 1. 产品定义

### 1.1 产品要解决的问题

专业群建设不是一次性申报，也不是单纯存放材料。建设过程中持续发生以下工作：

- 申报书、建设任务书和实施方案不断转化为年度目标、阶段任务和人员分工；
- 教师与负责人持续提交工作进展、文件、表格、图片和说明；
- 教务、专业群负责人和审核人员不断核对事实、补充材料、退回修改和确认结果；
- 每到周、月、年度、中期或验收节点，都需要依据同一批事实形成不同格式的总结、计划、报告和申报材料；
- 新通知、新模板和临时任务随时出现，不能每出现一项工作就重新建设一个独立系统。

因此，专业群 AI 工作站应当成为专业群建设的持续工作平台：把建设依据、目标任务、人员、工作记录、材料证据、审核结论和正式成果组织成一套相互关联、可持续更新、可追溯的建设记录，并由专业群智能体协助不同角色顺畅完成各项工作。

### 1.2 产品不应被理解为什么

- 不是只回答问题的知识问答工具；
- 不是只展示完成率的统计看板；
- 不是只上传和下载文件的网盘；
- 不是替代教师、负责人和审核人的自动决策系统；
- 不是把校方沟通稿逐页搬进网页；
- 不是排课系统，也不替代学校现有教务、办公或审批工具。

### 1.3 一句话产品定位

**以专业群智能体为统一协作入口，以建设任务为主线，以事实和证据为基础，支持教师、教务和负责人共同推进专业群建设全过程。**

### 1.4 产品价值

| 使用对象 | 产品直接提供的价值 |
| --- | --- |
| 教师 | 看清本人任务，便捷提交真实工作和材料，在智能体协助下补齐说明、关联任务并处理退回事项 |
| 专业负责人 | 把群级目标落实到专业和教师，查看进度与缺项，确认材料、成果和后续任务 |
| 专业群负责人 | 统一管理建设依据、年度目标、任务、进展、证据和成果，及时识别差距并组织补充工作 |
| 教务或科研审核人员 | 核对事实、指标口径、引用和版本，完成退回、审核与定稿 |
| 校级业务负责人 | 在获准范围内查看专业群整体情况、阶段结果和需要协调的问题 |
| 信息处与运行保障人员 | 管理账号、使用环境、备份和故障处理，不默认获取全部业务正文 |

## 2. 产品设计原则

### 2.1 工作围绕对象持续办理

系统中的核心不是菜单，而是建设对象。每项工作都应落到一个明确对象上，例如某项建设依据、年度目标、教师任务、工作记录、材料、成果或报告。用户无论从页面还是从专业群智能体进入，最终都应进入同一对象的办理过程。

### 2.2 事实、关系和证据同时保存

一条“已完成”的结论必须能够回答：完成了什么、由谁完成、发生在什么时间、对应哪项任务或指标、依据哪份材料、由谁确认。系统不能只保存结论而丢失关系，也不能用附件数量代替业务成果数量。

### 2.3 修改形成历史，不静默覆盖

材料换版、指标修订、进展纠错、报告改稿、审核退回和权限变化都应形成新的记录，并保留原记录、原因、人员和时间。已经进入报告或形成确认结果的版本不能被新文件直接覆盖。

### 2.4 智能体协助执行，学校人员确认关键结果

专业群智能体可以理解任务、查找资料、提出关联建议、检查缺项、生成草稿和协助修改，但不能自行：

- 确认指标已经达成；
- 选择冲突文件中的正式口径；
- 将材料认定为正式证据；
- 代替学校审核报告；
- 对外申报、发布或提交正式成果；
- 扩大用户的查看和办理范围。

### 2.5 一项工作只保留一套事实口径

看板、查询、报告和智能体回答应使用同一套已经确认的目标、进展和材料关系。例如“年度目标 3 家、已确认 1 家、尚差 2 家”不应在不同页面产生不同结果。

### 2.6 支持新增事项，不把场景清单写死

T01—T18 是已知业务事项，不是能力边界。后续出现新申报、新检查、新模板或临时任务时，专业群智能体应先识别目标、所需输入、输出格式、查看范围和人工确认点，再通过已有产品能力承接；缺少条件时形成待补清单。

### 2.7 学校掌握资料与最终结果

学校对业务资料、工作记录和生成成果拥有完整权利和控制权。资料可以位于学校内部设备或学校租赁并控制的专用空间。服务能力按授权临时处理必要内容，结果回写学校控制的位置，不能把学校业务内容变成服务方长期持有的数据资源。

### 2.8 专业群知识库按建设业务独立设计

知识库不以“上传文件后可以问答”为完成标准。它需要表达多个专业群、上百个专业、建设周期、核心与支撑关系、文件依据、指标规则、人员任务、工作事实、证据、确认结论和成果版本，并能够说明这些对象为什么相关、关系何时有效、依据变化会影响什么。

知识库同时服务人员查询和智能体办理：既能定位原件，也能为任务分解、材料归类、进度判断、补充工作和成果编制提供可核对的事实与关系。详细设计见《03-专业群知识库产品方案.md》。

## 3. 总体产品结构

### 3.1 “一位智能体、一座专业群知识库、一条工作主线、九个业务工作区、四个保障中心”

#### 一位智能体

每个专业群配置一位专业群智能体。她掌握该专业群中获准使用的建设依据、指标、任务、人员、工作记录、材料、模板和历史成果，是查询入口，也是办理入口。

#### 一座专业群知识库

知识库统一管理全校多个专业群和上百个专业的建设知识，但按学校、专业群、专业、周期、人员权限和资料用途隔离使用。它保存原始资料、可定位内容、结构化事实、对象关系、业务规则、确认结论、历史版本和可复用办理方法，为智能体提供有范围、有依据、有时效的工作上下文。

#### 一条工作主线

```text
建立建设依据
  → 确认目标与指标
  → 分解并安排任务
  → 教师记录工作和提交材料
  → 负责人确认事实与证据
  → 系统判断差距并形成后续任务
  → 编制总结、报告或申报材料
  → 审核、导出和归档
  → 新工作继续进入同一建设记录
```

#### 九个业务工作区

1. 建设总工作台
2. 建设依据
3. 目标与指标
4. 计划与任务
5. 工作记录
6. 资料与证据
7. 进度与问题
8. 成果与报告
9. 组织与协作

#### 四个保障中心

1. 模板与业务规则中心
2. 权限、资料使用与审计中心
3. 试点、验收与运行保障中心
4. 智能服务、后台任务与集成中心

专业群智能体不是第十个孤立模块。她横跨九个工作区和四个保障中心，在用户授权范围内读取相关信息并发起实际办理动作。

### 3.2 产品入口

| 入口 | 适用情况 | 进入后的产品行为 |
| --- | --- | --- |
| 专业群智能体 | 用户知道想完成什么，但不确定应进入哪个栏目 | 识别任务，确认范围和所需条件，展示办理计划，调用对应工作区 |
| 我的工作台 | 教师或负责人处理当日待办、退回事项和截止任务 | 按角色显示需要本人办理的事项，并提供直接操作 |
| 业务工作区 | 用户需要集中维护一类对象 | 进入列表、详情、编辑、审核和历史记录 |
| 全局搜索 | 用户知道材料、任务、人员或报告关键词 | 在授权范围内返回对象及其关系，不混合无权内容 |
| 通知与待办 | 用户收到提醒或审核请求 | 直接定位到需要处理的对象和具体动作 |

### 3.3 统一页面骨架

后续视觉设计应围绕统一骨架，而不是为每项业务重新设计完全不同的页面：

1. **顶部上下文**：当前专业群、建设周期、统计期间、当前角色、资料更新时间。
2. **对象导航**：九个业务工作区与本人待办。
3. **主工作区**：当前对象的列表、详情、表单或编制页面。
4. **关系区**：显示该对象关联的目标、任务、人员、材料、成果和报告。
5. **办理记录**：按时间显示提交、修改、退回、确认、撤回和生成记录。
6. **智能体协作区**：说明智能体理解到的任务、所用资料、建议动作、待确认事项和执行结果。

### 3.4 专业群知识库在产品中的位置

知识库同时具有三种产品形态：

1. **底层共同知识底座**：各业务工作区保存的对象和关系共同进入知识体系，不另复制一份脱节的“知识库数据”。
2. **智能体工作上下文**：智能体围绕当前专业群、专业、周期、人员权限和任务目标组装所需事实、依据、规则、材料和缺项。
3. **可管理工作区**：获授权人员可以查看知识地图、专业档案、资料吸收状态、事实关系、冲突、版本影响和知识覆盖。

资料与证据模块管理文件、版本和证据办理；专业群知识库管理这些资料所表达的建设对象、事实、关系、规则、确认状态和适用范围。两者共享来源与版本，不重复保存两套正文。

## 4. 专业群智能体产品设计

### 4.1 角色定位

专业群智能体是“了解本专业群资料和工作关系的数字协作人员”。她需要同时具备三种能力：

- **理解与查询**：理解自然语言问题，查找相关事实、材料、任务和人员；
- **协助办理**：把用户要求转化为系统内可执行的整理、填报、检查、编制和修改动作；
- **连续跟进**：记住当前任务的上下文、缺项、反馈和已完成步骤，直到形成结果或明确等待谁处理。

### 4.2 智能体不是聊天框，而是办理协调层

一次智能体任务应形成以下结构化记录：

| 内容 | 说明 |
| --- | --- |
| 任务提出人 | 谁提出了问题或办理要求 |
| 当前专业群与周期 | 防止把不同专业群资料混用 |
| 办理目标 | 用户最终希望查询什么或形成什么成果 |
| 使用范围 | 允许读取哪些资料、涉及哪些人员和期间 |
| 办理计划 | 准备执行哪些步骤，需要调用哪些工作区 |
| 已使用资料 | 文件、版本、工作记录、指标和模板 |
| 待补或待确认 | 缺少资料、口径冲突、权限不足或需要人工决定的内容 |
| 执行动作 | 已完成的检索、整理、关联、草拟、建任务或修改 |
| 形成结果 | 回答、表格、草稿、任务、问题清单或材料目录 |
| 人工确认点 | 谁需要确认什么，确认后才能产生何种正式结果 |

智能体每次办理都从专业群知识库取得一个受控的“任务知识包”，其中包括当前任务对象、有效建设依据、相关专业和人员、已确认事实、可用材料、业务规则、冲突、未知项和允许执行的动作。她不能把一次搜索返回的若干相似片段直接当作完整知识。

### 4.3 智能体的统一办理过程

```text
1. 理解要求
   ↓
2. 确认专业群、期间、输出目标和查看范围
   ↓
3. 查找建设依据、任务、工作、材料、模板和历史结果
   ↓
4. 发现缺项、冲突或权限问题时先列明
   ↓
5. 向用户展示可执行的办理计划
   ↓
6. 在相应工作区执行整理、关联、创建、修改或生成
   ↓
7. 将结果保存为草稿或待确认记录
   ↓
8. 交由指定人员确认、审核或继续补充
   ↓
9. 记录全过程，并支持继续追问和办理
```

对于只读查询，可以直接返回有依据的结果；对于会改变正式记录的动作，例如派发任务、确认证据、修改指标口径或提交报告，必须经过相应人员确认。

### 4.4 智能体任务类型

| 类型 | 典型要求 | 智能体需要完成的系统动作 |
| --- | --- | --- |
| 查询 | “今年哪些指标没有完成？” | 明确期间，读取有效指标和已确认进展，形成对照表并显示更新时间与来源 |
| 找材料 | “A 企业的协议和活动材料在哪里？” | 检索材料版本、关联任务和授权范围，返回可查看的材料及定位 |
| 整理 | “把这批业绩按任务书归类。” | 逐条提出分类与指标关联建议，单列重复、不能匹配和缺证据项 |
| 填报协助 | “把这周工作登记一下。” | 根据对话形成工作记录草稿，提示补充日期、成果和材料，用户确认后提交 |
| 任务办理 | “把未完成事项安排到下月。” | 识别遗留事项，提出责任人、节点和输出物，负责人确认后创建任务 |
| 进度检查 | “为什么这项还没有完成？” | 区分工作未完成、证据不足和口径待确认，给出依据和下一步动作 |
| 内容编制 | “生成月度总结和下月计划。” | 按模板读取已确认记录，形成草稿、引用、缺项和后续任务建议 |
| 申报协助 | “按学校模板做人工智能试点校申报材料。” | 核对通知、年度、模板、主体、截止时间和审核人，形成材料草稿与待补清单 |
| 修改 | “按我的意见修改第三部分。” | 锁定指定版本与修改范围，生成新版本，保留其他人工内容并记录修改说明 |
| 新事项承接 | “新增一项临时检查材料。” | 确认事项归属、所需资料、输出模板、人员和权限，建立业务事项及办理清单 |

### 4.5 智能体在界面中的呈现

- 在所有工作区保持可见，但不遮挡主工作区；
- 进入具体对象时自动带入对象上下文，不要求用户重复描述；
- 每次回答显示资料截止时间、主要依据和待确认事项；
- 建议动作以可执行按钮呈现，例如“创建补充任务”“整理为月报草稿”“打开缺失材料清单”；
- 执行动作前显示影响范围，执行后显示形成了哪些记录；
- 支持从智能体结果跳转到具体对象，也支持从对象页请智能体继续处理；
- 对话历史与办理记录关联，但不能成为唯一业务记录。

### 4.6 智能体必须遵守的边界

1. 不使用当前用户无权查看的资料生成回答。
2. 不把建议状态写成已确认状态。
3. 不在资料不足时补造事实或数字。
4. 不在文件冲突时自行选择正式口径。
5. 不把同一成果的多个附件重复计算。
6. 不把历史成果直接计入本期新增成果。
7. 不直接覆盖人工编写或已经审核的内容。
8. 不自动对外提交和发布。
9. 不把一个专业群的对话和资料带入另一个专业群。
10. 无法完成时说明原因、所需条件和下一步承接人。

## 5. 模块一：建设总工作台

### 5.1 模块目标

为不同角色提供当前最需要处理的信息和动作，同时呈现专业群建设的整体状态。工作台不是只读驾驶舱，每个状态都应能够进入对应的办理对象。

### 5.2 页面组成

| 页面区域 | 主要内容 | 可执行操作 |
| --- | --- | --- |
| 专业群与周期 | 当前专业群、核心/支撑专业、建设阶段、统计期间、数据截止时间 | 切换获准专业群或期间 |
| 我的待办 | 本人待提交、待补充、被退回、待确认、待审核和即将到期事项 | 填写、补材料、修改、确认、审核 |
| 建设状态 | 适用指标、已确认进展、证据覆盖、问题分类 | 进入指标或问题清单 |
| 近期工作 | 最近提交、修改、退回、确认和生成的事项 | 查看对象和办理历史 |
| 重点节点 | 月报、年度报告、中期检查、验收和临时申报节点 | 创建准备任务或进入成果编制 |
| 智能体任务栏 | 输入查询或办理要求，查看正在办理和等待确认的智能体任务 | 发起任务、继续办理、取消草稿 |

### 5.3 角色差异

- 教师优先看到本人任务、退回事项和最近提交；
- 专业负责人优先看到本专业任务、人员进展和缺项；
- 专业群负责人优先看到全群目标、跨专业问题和待确认结论；
- 审核人员优先看到待审核版本和事实核对问题；
- 校级负责人只查看获准范围内的汇总与需协调事项。

### 5.4 智能体协作

智能体根据当前角色主动整理“今天需要处理什么”，但提醒不能自动改变业务状态。用户可以直接说“只看本周到期的任务”“把退回的材料按原因整理一下”“准备下个月中期检查”，系统应进入具体对象和办理清单。

### 5.5 关键产品规则

- 首页数字必须能够下钻到明细；
- 上传量不能表示绩效或完成质量；
- 没有填报与实际值为零必须区分；
- 风险状态与业务完成状态分别显示；
- 所有汇总显示统计期间和资料更新时间。

## 6. 模块二：建设依据

### 6.1 模块目标

管理申报书、建设任务书、实施方案及其版本，把三类文件中属于同一建设事项的内容对应起来，形成后续目标、任务、进度和报告共同使用的建设依据。

### 6.2 核心对象

- 依据文件；
- 文件版本与批准状态；
- 原文章节、表格、页码或段落；
- 建设目标；
- 建设事项；
- 指标要求；
- 阶段节点；
- 责任关系；
- 支撑材料要求；
- 文件冲突与口径确认记录。

### 6.3 页面设计

#### 6.3.1 建设依据目录

按文件类型、适用周期、批准状态和版本展示所有依据。支持上传新版本、标记草稿/已批准/已失效、查看引用范围和历史版本。

#### 6.3.2 三份文件对照工作区

围绕同一建设事项并列呈现：

- 申报书中的总体目标和预期成果；
- 任务书中的指标、年度目标和验收材料；
- 实施方案中的责任人、专业分工、时间和措施；
- 尚未对应或存在冲突的内容。

负责人可确认对应关系，并将确认后的内容生成目标、指标和任务草稿。

#### 6.3.3 冲突处理页

当不同文件出现数值、年份、责任人或材料要求冲突时，系统同时显示原文、版本和影响对象，由指定负责人确认采用口径。确认前相关对象显示“口径待确认”。

### 6.4 主要操作

上传依据、登记版本、标记批准状态、定位原文、建立对应、提出修订、确认口径、查看影响、生成目标和任务草稿。

### 6.5 智能体协作

智能体可以读取文件、提取候选目标与指标、定位原文、发现差异并提出对应建议；不能自动使依据生效。用户问“任务书里的新增合作企业要求在哪里”时，她应返回具体文件版本和原文位置，并可继续打开相关目标、任务和材料要求。

### 6.6 人工确认点

- 文件是否正式批准；
- 哪个版本当前有效；
- 三类文件中的内容是否属于同一建设事项；
- 冲突时采用哪一口径；
- 哪些内容进入正式目标、任务和证据要求。

### 6.7 形成结果

建设依据目录、文件对照关系、冲突清单、已确认建设事项、目标与任务草稿、出处清单。

---

## 7. 模块三：目标与指标

### 7.1 模块目标

把建设依据转化为可持续跟踪的目标体系，管理指标层级、分年度要求、计算规则、适用范围、证据标准和历史修订。

### 7.2 页面设计

| 页面 | 主要内容 | 关键操作 |
| --- | --- | --- |
| 指标目录 | 指标树、适用专业、责任人、当前状态 | 新建、导入、排序、归档 |
| 指标详情 | 目标值、单位、期间、标准、证据要求、出处 | 编辑草稿、提交确认 |
| 分期目标 | 年度/学年/建设周期目标 | 设置目标、查看历史 |
| 指标修订 | 修改前后内容、原因、生效时间和影响 | 提交修订、批准生效、重评进展 |
| 指标对照 | 目标、实际、证据、差距和确认结果 | 查看进展、发起补充任务 |

### 7.3 支持的指标情况

- 数量指标；
- 比例或区间指标；
- 定性判断指标；
- 跨年度累计指标；
- 本年度新增指标；
- 不适用指标；
- 联合建设与跨专业成果；
- 有权重和无权重的指标体系。

未确认计算规则的指标可以登记和跟踪，但不能自动给出正式达成结论。

### 7.4 智能体协作

智能体可以从建设依据中提取指标草稿，解释某项指标的目标、统计期间和证据要求，检查已有成果是否可能重复，回答“为什么 C 企业不能算今年新增”。她可以提出达成判断建议，但正式结论由指定审核人确认。

### 7.5 关键产品规则

- 父级指标不与叶子指标重复计入分母；
- 未填报不默认等于零；
- 不适用需要指定人员批准；
- 同一成果在同一指标内不能重复计数；
- 指标修订后新进展使用新口径，旧报告保留旧口径；
- 达成状态、工作状态和风险状态分别管理。

### 7.6 形成结果

指标树、分期目标表、指标口径说明、证据标准、修订历史、指标完成对照表。

---

## 8. 模块四：计划与任务

### 8.1 模块目标

把学校重点工作、部门年度计划和专业群建设目标落实为专业与教师可执行的年度、月度、周度任务，并跟踪到实际完成、退回补充或批准调整。

### 8.2 任务层次

```text
学校重点工作（如适用）
  → 部门年度事项（如适用）
  → 专业群目标或指标
  → 专业任务
  → 教师任务
  → 补充工作或补充材料任务
```

系统不强行补造不存在的行政层级，允许任务直接关联专业群目标。

### 8.3 页面设计

- 年度计划对照表；
- 月度与周度任务板；
- 教师个人任务页；
- 任务详情与提交记录；
- 临期、逾期和缺材料清单；
- 补充任务确认页；
- 任务调整与暂停记录。

### 8.4 任务状态

建议采用：待开始、进行中、已提交、已退回、已完成、已取消。逾期是提示状态，不覆盖任务本身状态；发出提醒不等于问题已经解决。

### 8.5 主要操作

建立任务、关联目标、指定负责人、设置节点与预期产出、提交进展、补充材料、退回、确认完成、调整节点、暂停、取消、从差距生成补充任务。

### 8.6 智能体协作

智能体可以把年度目标拆成建议任务，依据人员分工推荐责任人，汇总教师当前待办，识别没有进展或缺材料的事项，并将已确认的问题转化为补充任务草稿。负责人确认后任务才正式派发。

### 8.7 形成结果

年度/月周任务对照表、教师任务清单、任务办理历史、提醒记录、补充任务和关闭结果。

---

## 9. 模块五：工作记录

### 9.1 模块目标

让教师和负责人用较低负担记录真实发生的建设工作，使日常工作能够持续进入目标、任务、材料和成果体系。

### 9.2 一条工作记录至少说明

1. 什么时候发生；
2. 做了什么；
3. 谁参与；
4. 形成什么结果；
5. 有哪些材料；
6. 可能对应哪个目标或任务；
7. 当前是否需要负责人确认。

业务发生日期与上传日期分别保存。允许按周补录，不要求教师每天重复填写同一成果。

### 9.3 页面设计

| 页面 | 用途 |
| --- | --- |
| 快速记录 | 教师填写一次工作并添加文件、图片或说明 |
| 我的记录 | 查看草稿、已提交、退回和已确认记录 |
| 专业工作台账 | 按日期、专业、教师和建设内容查看工作 |
| 待确认记录 | 负责人核对工作内容、任务关系和材料 |
| 记录详情 | 查看内容、材料、关系、版本和办理历史 |

### 9.4 智能体协作

教师可以直接说“今天和 B 企业确认了协议修改意见”，智能体据此形成记录草稿，询问工作日期、参与人、结果和材料，并建议关联 B 企业任务。智能体也可以把聊天摘录或零散说明整理成规范记录，但必须由提交人确认后进入正式办理。

### 9.5 退回与修订

负责人退回时必须说明原因。教师补充或修改后形成新的提交记录；已确认记录需要纠错时，不覆盖原记录，而是建立替代记录并说明原因。

### 9.6 形成结果

个人工作记录、专业日/周台账、阶段工作清单、任务进展候选、待补信息清单。

---

## 10. 模块六：资料与证据

### 10.1 模块目标

统一管理文件、表格、图片、聊天摘录和其他材料，保留原件与版本，建立材料与工作、任务、指标、成果和报告之间的关系。

### 10.2 页面设计

- 资料上传与批量导入；
- 待整理资料箱；
- 资料库与组合检索；
- 资料详情与在线预览；
- 版本记录；
- 分类与关联确认；
- 重复材料与相似材料处理；
- 证据审核与撤回；
- 回收站和保留期限。

### 10.3 首期材料范围

首期按需求确认单建议支持 docx、xlsx、pptx、可提取文本的 PDF、jpg 和 png。扫描件文字识别、音视频转写、旧版 Office、压缩包和网页采集按样例与本期范围另行确认。

### 10.4 主要操作

上传、预览、补充说明、推荐分类、确认分类、关联工作/任务/指标、提交为证据、审核、退回、上传新版本、撤回、受控下载和删除申请。

### 10.5 智能体协作

智能体可以：

- 从用户指定材料中提取可读内容；
- 推荐专业、事项、业务日期和指标；
- 找出缺少必要说明的材料；
- 识别完全相同的文件，并提示可能相似的材料；
- 回答某项结论使用了哪些材料；
- 将一批材料按指定栏目整理为文字或表格草稿。

推荐结果必须由人确认；图片未经过文字识别或人工说明时，不能声称已经理解图片内容。

### 10.6 证据与普通资料的区别

普通资料可以先保存并继续整理；只有经过指定人员确认、具备有效版本和明确关联的材料才能成为正式证据。材料审核通过也不代表所有成员都能查看。

### 10.7 版本与引用规则

- 同名文件不自动覆盖；
- 新版本需要重新审核；
- 旧报告继续引用当时使用的旧版本；
- 已被正式报告引用的版本不能直接物理删除；
- 撤回证据后，受影响的进度、回答和待审核报告应显示变化。

### 10.8 形成结果

资料目录、版本记录、分类结果、证据关系、缺项清单、重复项处理记录和材料来源定位。

---

## 11. 模块七：进度与问题

### 11.1 模块目标

基于有效建设依据、已确认工作、成果和证据，逐项呈现目标与实际的差距，并把差距转化为可处理的问题和后续任务。

### 11.2 页面设计

| 页面 | 主要内容 |
| --- | --- |
| 专业群进度总览 | 适用指标、已确认完成、正在推进、材料不足、口径待确认和未开始 |
| 指标对照表 | 指标、目标、实际、证据、差距、责任人、更新时间 |
| 专业进度 | 核心和支撑专业分别承担的任务、成果和缺项 |
| 教师进展 | 授权范围内的教师任务、提交、退回和缺失材料 |
| 问题中心 | 工作未完成、证据不足、口径冲突、任务逾期和待审核事项 |
| 后续措施 | 问题对应的建议动作、责任人、节点和确认状态 |

### 11.3 进度分类

系统至少区分：

- 已确认完成；
- 正在推进；
- 工作已做但材料不足；
- 口径或依据待确认；
- 未开始或无有效进展；
- 不适用；
- 已暂停。

这些状态不能简单压缩成“完成/未完成”。

### 11.4 智能体协作

智能体能够回答整体、专业、教师、指标和材料等不同层次的问题，并允许连续追问。例如从“今年总体怎么样”继续追问“B 企业卡在哪里”“李老师下一步做什么”。所有回答必须使用同一统计口径，并显示资料截止时间和主要来源。

对未达成事项，智能体应区分：

- 目标数量不足，需要继续开展工作；
- 工作已经推进，需要完成剩余步骤；
- 工作可能完成，但缺少可确认材料；
- 依据或统计口径冲突，需要负责人决定。

只有负责人确认后，建议措施才转换为正式任务。

### 11.5 形成结果

进度对照表、差距说明、问题清单、补工作清单、补材料清单、待确认口径清单和后续措施。

---

## 12. 模块八：成果与报告

### 12.1 模块目标

用平时积累且已经确认的事实、指标结果和材料，按学校或主管部门的正式模板编制总结、计划、报告和申报材料，并支持多轮修改、审核、导出和归档。

### 12.2 支持的成果类型

- 周工作总结及下周计划；
- 月度工作总结及下月计划；
- 年度工作总结及下一年度计划；
- 专业群建设年度报告或年度自评报告；
- 专业群中期评审材料或中期建设自评报告；
- 专业群终期验收材料；
- 指标完成对照表、差距清单、措施清单和支撑材料目录；
- 业绩分类汇总表和指标对应表；
- 国家级人工智能试点校申报材料；
- 省级“人工智能+教育”应用场景项目申报材料；
- 后续新增且已提供规则和模板的专业群建设成果。

教学检查、听评课和出卷等成果只有在对应业务纳入范围后进入专门流程。

### 12.3 页面设计

| 页面 | 主要能力 |
| --- | --- |
| 成果中心 | 按类型、年度、状态和专业群查看所有成果 |
| 新建成果 | 选择模板、期间、数据截止点、编制人和审核人 |
| 生成前检查 | 显示可用资料、缺失章节、口径冲突和待确认数字 |
| 在线编制 | 按模板章节编辑，查看建议内容、事实依据和人工保留段落 |
| 引用核对 | 逐条核对数字、结论、材料版本和原文位置 |
| 版本比较 | 查看每次生成、人工修改、退回和重新提交的差异 |
| 审核与定稿 | 提交、退回、批准、作废和重新审核 |
| 导出与归档 | 输出 Word/PDF 和证据目录，保存正式版本 |

### 12.4 智能体协作

智能体能够：

- 根据模板和期间建立编制任务；
- 汇总各专业已确认工作和成果；
- 沿用进度模块中的正式指标结果；
- 生成章节草稿、表格和证据目录；
- 显示缺项、冲突和无法确认的内容；
- 按用户指定范围修改某一章节；
- 解释某个数字或结论来自哪里；
- 根据退回意见形成新的修改版本。

智能体不得为了使报告更完整而把建议写成事实，或把过程材料写成已经完成的成果。

### 12.5 模板管理要求

每个模板需要记录：适用项目、主管部门、年度/批次、模板版本、填写说明、正式通知、必填章节、表格结构、字数/页数限制、附件要求、命名规则、页眉页脚、签章要求、提交格式和最终渠道。不同年度或项目的模板不能被一份“通用模板”替代。

### 12.6 审核与版本规则

- 报告作者不能审核自己的报告；
- 审核针对确切版本；
- 审核通过后修改必须生成新版本并重新审核；
- 退回必须说明原因；
- 局部改稿不能覆盖其他人工内容；
- 无依据或有冲突的关键事实不能进入正式定稿；
- 草稿导出必须带草稿标识；
- 正式导出内容必须与审核通过版本一致。

### 12.7 形成结果

成果草稿、修改版本、审核记录、正式报告、Word/PDF 文件、证据目录和待补清单。

---

## 13. 模块九：组织与协作

### 13.1 模块目标

按照学校真实组织关系管理学校、部门/学院、专业群、专业和人员，同时表达核心专业、支撑专业、跨专业共建和人员职责。

### 13.2 页面设计

- 学校与部门结构；
- 专业群及建设周期；
- 核心专业与支撑专业关系；
- 专业群成员；
- 岗位职责与替代人员；
- 跨专业共建关系；
- 人员加入、调离和资格取消记录；
- 各角色可查看和可办理范围。

### 13.3 角色与职责

产品至少支持校级业务负责人、专业群负责人、专业负责人、教师、教务/科研审核人、信息中心/运行保障人员和服务保障人员。一个人可以承担多个角色，但作者不得审核自己的报告。

### 13.4 智能体协作

智能体可依据组织与任务关系回答“核心专业和支撑专业分别做了什么”“王老师有哪些任务”，并在创建任务时建议责任人。她不能自行改变组织关系、增加查看权限或指定正式审核人。

### 13.5 形成结果

专业群构成表、专业分工表、成员职责表、协作关系、替代审核安排和人员变更记录。

## 14. 保障中心一：模板与业务规则

### 14.1 管理内容

- 最终成品及模板清单；
- 指标计算规则；
- 成果去重规则；
- 必需证据类型和数量；
- 周/月/年总结周期；
- 提醒规则；
- 材料分类规则；
- 业务事项类型；
- 审核流程；
- 学校常用写作口径与允许保留的人工章节。

### 14.2 产品要求

规则必须有版本、生效日期、制定人和批准人。规则变化应提示影响哪些指标、进展、报告或智能体任务，不能直接改写历史结果。

### 14.3 智能体协作

智能体按当前有效规则办理任务，并能解释使用了哪一版本规则。遇到规则缺失或冲突时形成待确认事项，不自行补造规则。

## 15. 保障中心二：权限、资料使用与审计

### 15.1 权限模型

权限同时考虑：学校、专业群、专业、对象、操作和有效期。用户能看到某项汇总，不代表能够打开全部材料正文；能够查看材料，也不代表能够确认其为正式证据。

### 15.2 需要分别控制的操作

查看、创建、编辑、提交、退回、确认、审核、下载、导出、分享、授权、撤权和删除。

### 15.3 资料处理过程

```text
用户提出任务
  → 核对身份、专业群和资料权限
  → 读取完成任务所需的最小范围内容
  → 执行查询、整理或生成
  → 将结果保存到学校控制的位置
  → 记录使用范围和处理结果
  → 按约定清除服务过程中的临时内容
```

### 15.4 审计记录

系统记录谁在何时对什么对象执行了何种操作、结果如何，以及修改前后的版本关系。审计记录重点覆盖登录失败、查看受限资料、授权与撤权、导出、删除、指标修订、证据确认、报告审核和智能体执行动作。

### 15.5 智能体协作

智能体只能在当前用户权限内工作。切换专业群或身份范围时重建上下文，不能通过对话引用无权资料，也不能只隐藏链接却泄露标题、数量或内容片段。

## 16. 保障中心三：试点、验收与运行保障

### 16.1 模块目标

把试点准备、样例授权、问题记录、修复复测、培训、备份恢复和最终验收作为产品内可管理的项目过程，而不是散落在会议记录中。

### 16.2 页面与对象

- 试点范围卡；
- 学校资料交接清单；
- 待决策事项 D01—D13；
- 验收样例集；
- A01—A11 验收项；
- 问题、修复和复测记录；
- 培训安排与完成记录；
- 备份与恢复演练；
- 已知限制与最终签收记录；
- 后续推广评估。

### 16.3 智能体协作

智能体可以检查试点资料是否齐备、根据验收项整理测试步骤和证据、汇总未通过项及复测结果。她不能把原型演示写成正式验收通过，也不能替代双方签收。

### 16.4 推广原则

试点流程、模板结构和使用方法可以复制；新专业群的任务书、专业关系、人员、企业、目标、进度和报告数字必须重新建立，不能复制试点事实。

## 17. 保障中心四：智能服务、后台任务与集成

### 17.1 模块目标

承载材料解析、内容整理、智能检索、草稿生成、文件导出和外部工具配合等需要较长时间或外部服务的动作，使用户能够看到执行进度、失败原因、形成结果和后续处理，而不是在页面点击后只能等待或重复提交。

### 17.2 后台任务类型

- 文件解析与内容提取；
- 材料分类和指标关联建议；
- 批量业绩整理；
- 专业群进度查询和复杂汇总；
- 报告、表格或其他成果草稿生成；
- Word/PDF 等文件导出；
- 已批准的外部工具读取或回写；
- 资料导入、索引更新、备份和恢复。

### 17.3 用户可见的任务状态

建议显示：等待处理、正在处理、等待用户确认、处理成功、处理失败、正在取消、已取消和结果待核对。用户能够查看任务提出时间、使用范围、当前步骤、完成比例、结果入口和失败原因。

“已经请求取消”不等于已经取消；外部结果不明确时先核对，不直接重复执行，以免产生重复记录或重复成果。

### 17.4 专业群智能体与后台任务的关系

智能体负责理解用户要求、组织办理计划和解释结果；后台任务负责执行材料读取、整理、生成和导出等动作。用户从智能体发起一项较长任务后，可以离开当前页面，任务中心持续显示状态；完成后回到原会话和业务对象继续确认。

智能体不能仅用一段回答宣称操作已经完成。只要要求涉及创建任务、修改资料、生成报告或导出文件，系统都应产生对应业务记录或后台任务结果，并提供可打开的对象。

### 17.5 智能服务配置

系统管理人员维护已经批准的智能服务、可处理的资料等级、支持的任务类型和可用状态。教师与教务人员只使用产品能力，不接触服务方账号、访问密钥或内部连接信息。

智能服务不可用时，系统保留人工填报、检索、编辑和审核能力，不擅自切换到未获批准的其他服务。每次智能处理记录采用的服务版本、规则版本、模板版本和处理结果，方便问题核对和复测。

### 17.6 外部工具集成

飞书、钉钉、学校网盘、办公审批、教务或排课工具均按独立连接配置管理。每个连接分别记录：

- 平台与学校负责人；
- 读取、接收或回写方向；
- 已批准的数据范围；
- 使用账号与有效期；
- 更新频率；
- 失败处理和停止条件；
- 最近同步结果；
- 外部对象与本地对象的对应关系。

首期 Excel 批量导入属于基础能力；其他自动连接只有完成权限、数据范围、重复处理和失败恢复验证后才启用。提供账号不等于默认允许自动操作。

### 17.7 运行管理

运行保障人员可以查看服务健康、失败任务、处理耗时、用量、备份和恢复状态，但默认不能查看业务正文。临时排查确需读取业务内容时，须有批准人、允许范围、有效时间和审计记录。

### 17.8 形成结果

智能体办理任务记录、后台执行记录、失败与重试记录、服务配置、外部连接配置、同步结果、运行状态和问题处理记录。

## 18. 已知选配业务的产品承接方式

### 18.1 教学检查与听评课

如纳入范围，使用工作记录、资料证据、问题中心和任务闭环能力，增加检查事项、人工评价、整改要求和办结确认。原评价必须保留，智能体负责整理和跟踪，不替代人工评价。

### 18.2 出卷任务与审核

如纳入范围，使用计划任务、资料版本和审核能力，形成“出卷安排—提交—退回—补充—审核通过”的过程。是否存放试卷正文、谁可查看及保密要求另行确认。

### 18.3 产教融合实践

如纳入范围，使用工作记录、成果和证据能力记录实际项目、师生参与、过程资料、企业评价和验收结果。智能体可以整理案例，不能替代真实实操、人工检测和成果验收。

### 18.4 与学校现有工具配合

现有办公平台、教务工具、学校网盘和审批工具分别确认读取或回写内容、频率、账号范围和停止条件。首期以人工上传、导入导出和受控跳转为基础；自动读取或写入只有在实际验证并获得批准后启用。

## 20. 跨模块完整办理示例

以下继续使用需求确认单中的说明性数据，不代表学校实际指标。

### 20.1 建立依据

负责人上传申报书、任务书和实施方案。智能体提取“建设期新增合作企业 10 家”，并对照出 2026 年目标 3 家、张老师负责、需要合作协议和活动记录。负责人核对原文后使该建设事项生效。

### 20.2 安排任务

负责人把 2026 年目标分解为 A、B、D 企业相关任务，指派张老师、李老师和王老师，设置节点和预期材料。智能体提出拆分建议，负责人确认后派发。

### 20.3 教师记录工作

张老师提交 A 企业正式协议和合作活动记录；李老师提交 B 企业协议草稿；王老师尚未提交 D 企业洽谈记录。智能体协助三位教师形成工作记录并推荐关联任务。

### 20.4 确认证据

负责人确认 A 企业材料有效；B 企业草稿只能作为过程材料；C 企业为 2025 年历史合作；D 企业无有效进展。每项判断保留确认人和材料版本。

### 20.5 判断进度

进度模块显示：2026 年目标 3 家，已确认完成 1 家，尚差 2 家。智能体解释每家企业所处状态，并区分工作未完成、材料不足和年度不符合。

### 20.6 形成后续任务

智能体建议李老师完成 B 企业正式签约，王老师完成 D 企业首次洽谈。负责人确认后生成 7 月任务，A 企业已经完成的签约不重复安排。

### 20.7 编制成果

报告编写人选择年度报告模板和统计截止日期。智能体使用已确认结果形成草稿、指标对照表、证据目录和缺项清单。用户要求修改第三部分时形成新版本，不改变已确认事实。

### 20.8 审核归档

独立审核人核对关键数字、材料版本和引用位置，退回或批准。批准后导出正式文件，报告、引用、审核记录和当时数据快照一并归档。后续新增材料不会静默改写这份历史报告。

### 21.2 页面间连续办理

每个对象详情页都需要提供“相关对象”和“下一步动作”，例如：

- 从指标进入任务、工作记录、证据、进展和报告引用；
- 从任务进入提交记录、材料和对应指标；

- 从报告引用返回原材料的确切版本和位置；

- 办理区只出现当前角色可执行的动作；
- 复杂操作先保存草稿，再提交确认；
- 退回、撤回、作废和删除均要求说明原因；
- 每页提供智能体协助，但不以对话替代表单和正式记录。

## 25. 后续视觉设计的前置要求

产品视觉稿只有在本方案评审后继续调整。后续页面需要明确表现以下内容：

1. 工作台是可办理的，不是只读看板；
2. 教师、负责人、审核人和智能体在同一工作链中协作；
3. 用户能够提交、修改、关联、退回、确认、审核和编制成果；
4. 智能体能够调用各模块办理任务，而不是只给文字答案；
5. 任一结论能够通过专业群知识库看到目标、任务、专业、人员、材料、确认和版本关系；
6. 页面之间沿对象和下一步动作连续跳转，不依赖讲解人返回菜单寻找；
7. 系统文案使用产品语言，说明功能、对象、操作和状态；
8. 业务沟通稿只作为业务来源，不直接决定页面结构和系统文案。

建议优先设计并评审以下五个关键页面，再扩展全站：

1. 建设总工作台；
2. 专业群智能体任务办理页；
3. 教师工作记录与材料提交页；
4. 指标进度与问题处理页；
5. 报告编制、引用和审核页。

这五页能够覆盖“理解任务—实际操作—形成记录—人工确认—输出成果”的核心产品闭环，也能够检验智能体是否真正进入业务办理过程。

## 26. 当前待确认事项

产品方案已经明确整体结构，但进入详细原型前仍需按照需求确认单补齐以下关键输入：

1. 试点专业群、专业名单、核心/支撑关系和建设周期；
2. 三类建设依据的实际版本及批准状态；
3. 一条真实指标的统计规则、证据要求和审核人；
4. 教师一次真实工作提交样例及退回修改样例；
5. 首期报告或申报材料模板及历史合格样例；
6. 本期是否包含周/月/年总结、Excel/PPT 成品及定时生成；
7. 角色、替代审核人和各自查看范围；
8. 学校资料保存位置、临时处理范围和清除要求；
9. 现有工具本期仅人工配合，还是需要验证读取或回写；
10. T15—T17 仅归集资料，还是建设专门办理流程。

这些事项尚未确认时，可以使用经批准并隐去敏感信息的样例完善原型，但页面必须明确显示“演示数据”“草稿依据”或“待确认”，不能表现为学校已经正式确定。

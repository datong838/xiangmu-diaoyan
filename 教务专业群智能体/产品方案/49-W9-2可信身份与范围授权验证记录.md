# W9-2 可信身份与范围授权验证记录

> 版本：v1.1　日期：2026-10-18　状态：身份阶段已验证；角色管理的后续验证见第 50 份记录，文件阶段未完成。  
> 方案依据：第 40、43、44、48 份方案。  
> 验证边界：仅使用合成学校、专业群、人员与会话；不含学校真实账号、真实资料、文件正文、云端智能体或正式试点。

## 1. 本阶段解决的问题

W9-1 的写入信封带有操作者编号，但当时该编号仍来自请求方声明。本阶段由服务端依据不透明会话令牌确认当前人员，读取有效角色和专业群范围，并要求写入信封中的操作者与当前人员一致。由此，已有工作空间、专业、版本、回执和建设账本链不再信任客户端自行声明的身份。

本阶段同时把信息支持人员与业务人员分开：信息支持人员可查看脱敏运行状态，但不能查看专业群名称、专业、资料标题、数量或正文。

## 2. 已实现内容

### 2.1 身份与会话

- 会话令牌只以 SHA-256 校验值存入数据库；
- 服务端拒绝缺少令牌、未知令牌、过期令牌和已撤销令牌；
- 会话对应人员必须处于有效状态；
- `GET /me` 返回当前人员和当前有效角色，不接受客户端传入人员编号替代。

### 2.2 四类首批角色

| 角色 | 当前已验证范围 |
| --- | --- |
| 教师 | 能被可信会话识别；材料办理能力待文件接口实现后验证 |
| 专业群负责人 | 可在本人学校、专业群和周期范围内读取及维护当前已建设的范围对象 |
| 教务审核人员 | 能被可信会话识别；审核动作待后续业务接口实现后验证 |
| 信息支持人员 | 只可读取数据库是否可用、容量等脱敏运行状态，不可读取业务内容 |

“专业负责人”继续作为教师或负责人的专业范围关系表达，不增加第五种固定角色。

### 2.3 现有接口授权接管

- 创建工作空间只允许携带部署侧启动凭证，且接口不提供日常业务入口；
- 新增专业、修改专业群与专业关系等操作要求专业群负责人会话；
- 写入信封中的 `actorId` 必须等于当前会话人员；
- 专业群详情、操作回执和建设账本要求当前人员具有相应范围；
- 无权请求在读取对象标题、数量和内容前被拒绝。

## 5. 当前边界与风险

1. 受控初始化及角色授予、撤销已在后续第 50 份记录中验证；
2. 教师和教务审核人员的业务动作要随材料、任务和审核接口逐项验证，不能仅因角色能登录就宣称能力完成；
3. 文件正文尚未写入受学校控制的目录，材料列表、预览、下载和一次性凭证均未验证；
4. 学校正式身份提供方尚待确认，后续必须通过适配器接入，不能改变本阶段角色和范围合同。

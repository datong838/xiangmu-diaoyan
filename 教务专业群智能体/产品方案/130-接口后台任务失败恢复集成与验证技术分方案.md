# 接口、后台任务、失败恢复、集成与验证技术分方案

> 版本：v0.1 评审准备稿  
> 日期：2026-10-19  
> 状态：评审稿编制完成，等待内部评审；尚未冻结，不编码

## 1. 设计目标

系统的成功标准是业务对象、版本、关系、人工决定、操作记录和用户回执一致。页面显示“完成”、智能体说“已处理”或后台任务执行结束，都不能单独证明业务写入成功。

## 2. 业务动作接口

接口按业务动作设计，不直接暴露任意字段更新。建议分组：

- 组织与范围：建档、任职、授权、撤权、切换工作空间；
- 建设依据：登记文件、建立版本、摘录、形成候选、确认冲突；
- 任务工作：建立计划、派发任务、填写工作、提交、退回、确认；
- 资料知识：收件、换版、内容处理、核对、发布知识、追溯关系；
- 指标进度：固定规则、建立计算、确认进度、形成差距措施；
- 成果报告：选择模板、固定快照、起草、改稿、审核、导出、归档；
- 智能体：建立任务、确认范围、确认计划、执行动作、确认结果、暂停恢复；
- 运行保障：查看任务、对账、重试、备份、恢复和核对。

## 3. 写入请求与回执

### 3.1 请求至少包含

- 请求编号和幂等键；
- 当前用户及当前工作空间；
- 业务动作；
- 目标对象和预期当前版本；
- 本次输入与关系变化；
- 动作目的和必要说明；
- 智能体代拟时的任务编号和人工确认记录。

### 3.2 回执至少包含

- 操作编号；
- 结果状态；
- 对象和新版本；
- 形成或变化的关系、决定和账本编号；
- 冲突、拒绝或缺项说明；
- 是否需要人工确认；
- 后续可执行动作。

## 4. 统一结果状态

| 状态 | 含义 | 后续处理 |
| --- | --- | --- |
| succeeded | 业务事务已完成并可回查 | 显示新版本和下一步 |
| rejected | 权限、状态或业务规则拒绝 | 不重试，按原因处理 |
| conflict | 当前版本或范围已变化 | 重新读取并人工核对 |
| failed | 明确未完成 | 修正原因后可发起新请求 |
| unknown | 调用中断，无法判断是否已写入 | 只读对账，禁止直接重发 |
| pending_confirmation | 已形成候选，等待人工决定 | 进入确认工作区 |

## 5. 后台任务

适合后台执行的工作包括文件处理、内容单元化、索引更新、批量整理、成果生成、格式转换、导出、备份和恢复核对。

后台任务固定输入对象版本和范围，不在执行中直接读取“最新版本”。若关键输入在完成前已变化，结果标记为“基于旧输入”，进入重新核对，不能自动套用当前对象。

任务状态包括等待、运行、等待确认、暂停、成功、失败、取消和结果待核对。重试次数、停止条件和最后错误对用户可见。

## 6. 失败与恢复

| 场景 | 处理原则 |
| --- | --- |
| 参数或必填缺失 | 拒绝并指出具体字段，不建立半成品正式对象 |
| 权限不足 | 拒绝且不暴露越权对象信息 |
| 版本冲突 | 返回当前版本和差异摘要，不自动合并 |
| 数据库事务失败 | 整个业务动作回退，保留技术错误编号 |
| 文件已登记但处理失败 | 保留原件和版本，处理状态失败，可重新处理 |
| 索引失败 | 正式对象仍存在，知识状态显示未就绪，可重建 |
| 云动作超时 | 标记结果待核对，先查询回执或业务对象 |
| 导出失败 | 不改变审核通过状态，不产生正式导出记录 |
| 恢复核对失败 | 环境保持不可正式使用，列出差异 |

## 7. 结果未知对账

```text
调用中断
  → 标记 unknown
  → 使用原请求编号查询操作回执
  → 检查目标对象当前版本、关系、决定和建设账本
  → 找到一致结果：补记为 succeeded
  → 确认没有写入：标记 failed，再由用户决定是否重试
  → 仍无法判断：停止自动处理并交人工核对
```

任何情况下都不能因为页面没有收到响应就直接再次提交。

## 8. 智能体与云动作集成

学校侧建立动作请求，检查用户、范围、任务、资料和输出要求，形成最小任务信封。云端返回候选结果和技术回执。学校侧再次检查任务仍有效、输入版本未变化、结果结构符合要求，再写入候选版本。

云端不能直接调用学校数据库写接口，也不能把结果标记为已确认、已审核或已归档。

## 9. 事件与后续处理

对象建立新版本、材料可处理、知识发布、任务提交、指标确认、成果审核通过等事件可触发后续任务。事件只携带对象引用、版本和必要范围，不复制敏感正文。事件处理失败不回滚已完成的原业务事务，而建立可见的待处理任务和重试记录。

## 10. 与学校现有系统集成

集成前先确认数据来源、授权方式、更新频率、冲突口径和责任人。建议优先采用受控导入导出，再评估实时连接。外部系统数据进入后记录来源时间和版本；工作站中的人工修订不能静默回写外部系统。

可能的适配对象包括统一身份、组织人员、教务系统、办公平台、文件平台和消息提醒渠道，均不在本稿中默认视为已接入。

## 11. 可观测性

业务侧可查看任务状态、处理阶段、开始和结束时间、失败原因、使用对象版本、确认人和回执。技术侧记录请求编号、服务、接口、状态码、耗时、错误类别和重试，不记录不必要的学校正文。

告警需要区分：业务待确认、资料处理失败、服务不可用、队列积压、存储容量、备份失败和越权尝试。

## 12. 验证分层

| 层级 | 验证内容 |
| --- | --- |
| 规则验证 | 状态转换、权限、版本、关系和人工决定 |
| 接口契约 | 请求、回执、错误、幂等和兼容性 |
| 数据一致性 | 版本、关系、决定和账本的事务一致 |
| 集成验证 | 文件、索引、云动作和外部适配 |
| 页面办理 | 四类角色完成真实写入、退回、确认和审核 |
| 失败注入 | 超时、中断、重复、旧版本、部分组件不可用 |
| 恢复验证 | 数据库、文件、索引、范围和账本共同恢复 |
| 学校验收 | 使用校方批准样例和责任人完成端到端工作链 |

代码测试、合成数据和内部页面演示不能替代学校验收。

## 13. 验证证据

每项验收证据应记录：方案版本、用例编号、环境、数据范围、角色、输入对象版本、操作步骤、预期结果、实际结果、业务对象和回执编号、异常情况、核对人和日期。截图用于辅助说明，不能替代对象和版本回查。

## 14. 待评审事项

- 首批业务动作清单及动作等级；
- 后台任务最大时长、重试次数和人工接管条件；
- 外部云动作的超时、对账和保留策略；
- 学校现有系统的连接优先级；
- 消息提醒渠道和发送确认要求；
- 日志、回执和验证证据保留期限；
- 性能、容量、并发、恢复和可用性目标。

# W9 可运行产品技术总方案

> 版本：v1.0　日期：2026-10-18　状态：历史技术初稿，未经正式组织评审，不视为冻结方案。当前评审入口见第 122—128 份文档。  
> 对应波次：W9。  
> 文档职责：把已经通过页面原型验证的产品结构转换为可开发、可部署、可验证的运行架构；不把原型本地状态视为实现。

## 1. 技术建设目标

W9 要形成一套真正能够保存学校建设对象、执行工作流、调用专业群智能体、保留版本和操作记录的产品。首个可运行版本必须证明以下事实：

1. 同一学校可以建立多个专业群，每个专业群包含多个核心或支撑专业；
2. 申报书、建设任务书和实施方案可以登记原件、版本、条款和确认结果；
3. 目标、指标、任务、工作记录、材料、证据和成果形成可查询关系；
4. 教师、负责人、审核人和信息支持人员只能查看和办理其权限范围内的内容；
5. 专业群智能体能在当前权限和知识范围内查询、整理和形成草稿，并在写操作前停在明确的人工控制点；
6. 所有新增、修改、提交、退回、确认、审核和归档都产生不可丢失的版本及建设账本记录；
7. 服务中断、重复请求和结果未知时不会重复写入或覆盖已有事实；
8. 学校资料及其知识索引始终由学校拥有完整权利和控制权。

## 2. 不变约束

### 2.1 数据主权

学校资料、数据库内容、文件原件、知识索引、业务版本、操作账本和备份均属于学校数据资源。它们可以部署在学校内部服务器，也可以部署在学校租赁并控制的私域远程云服务器。

我方提供的云端能力负责解析、整理、生成、检索辅助、任务规划和其他受控动作。云端服务本身不建立、复制或长期保存学校资料库，不把学校数据用于其他学校、模型训练或产品样例。

### 2.2 人工决定

智能体不得替代学校人员完成下列决定：

- 将候选内容确认为正式建设依据；
- 确认材料是否有效、成果是否计入指标；
- 确认指标正式达成；
- 批准正式报告、申报材料、试卷或验收结论；
- 决定跨专业群共享、对外公开或导出受限资料；
- 启用 T15、T16 或新增专业群正式空间。

### 2.3 追加式建设账本

业务对象可以形成新版本，但既有版本、原始材料、人工意见和操作记录不覆盖、不静默删除。更正通过新增版本和替代关系完成。

## 3. 总体运行架构

```text
学校浏览器
  ↓
学校侧 Web 与业务 API
  ├─ 身份、角色、范围和授权
  ├─ 对象、版本、关系和工作流
  ├─ 文件与模板管理
  ├─ 知识索引与确定性查询
  ├─ 建设账本、导出和恢复
  └─ 学校侧动作网关
          ↓ 仅发送本次任务获准的最小上下文
我方云端动作服务
  ├─ 文档解析与内容转换
  ├─ 智能体任务规划
  ├─ 检索结果整理与草稿生成
  ├─ 格式生成与修改建议
  └─ 模型与工具能力编排
          ↓ 返回结果、引用、缺项和建议写入
学校侧人工确认与业务写回
  ↓
学校数据库、文件空间、知识索引与建设账本
```

## 4. 学校侧组成

| 组件 | 责任 | 不承担的责任 |
| --- | --- | --- |
| Web 工作台 | 提供教师、教务、负责人、审核人和信息支持人员工作界面 | 不以浏览器本地状态作为正式业务结果 |
| 业务 API | 校验身份、权限、对象状态、版本和写入条件 | 不接受跳过版本或确认点的直接写入 |
| 关系与版本服务 | 管理对象关系、版本替代、引用和影响范围 | 不自动确认候选关系 |
| 工作流服务 | 管理任务、提交、退回、补充、审核和完成状态 | 不用任务完成代替指标达成 |
| 文件服务 | 保存原件、版本、摘要、指纹、预览和下载授权 | 不静默删除重复文件或损坏原件 |
| 知识服务 | 建立专业群专属对象索引、关系索引和获准文本索引 | 不跨专业群召回，不把未知内容补造成事实 |
| 指标服务 | 按固定规则和输入快照执行确定性计算 | 不替代负责人确认正式进度 |
| 成果服务 | 管理模板、章节、引用、草稿、审核和导出 | 不允许未审核草稿成为正式导出件 |
| 建设账本 | 追加记录动作、版本、确认、异常和恢复结果 | 不提供覆盖或回删历史的普通接口 |
| 动作网关 | 构造最小上下文、调用云服务、核对响应并提交候选结果 | 不把云端响应直接写成学校正式事实 |

## 5. 云端动作服务组成

| 能力 | 输入 | 输出 | 数据保留边界 |
| --- | --- | --- | --- |
| 文档解析 | 单次获准文件或页面、格式和用途 | 结构、文本、表格、图片位置、异常 | 不建立学校文件库；任务完成后清理内容缓存 |
| 内容整理 | 获准材料片段、目标格式、栏目和模板 | 可编辑草稿、来源映射、缺项 | 只记录动作元数据，不记录学校正文 |
| 智能体规划 | 任务、角色、范围、可用能力和对象摘要 | 执行计划、所需输入、停止点 | 会话状态正式保存在学校侧 |
| 检索辅助 | 学校侧已过滤的候选片段和关系 | 排序、摘要、回答草稿和引用 | 不从云端维护学校向量库 |
| 成果生成 | 模板结构、确认事实、引用和用户要求 | 章节草稿、修改说明和待补项 | 生成结果返回学校侧形成版本 |
| 格式转换 | 已批准内容与输出格式 | Word/Excel/PPT/PDF 候选件 | 正式导出件回存学校侧并经权限控制 |

云端日志默认只保留调用编号、学校侧匿名工作区编号、能力名称、耗时、结果状态和错误类别。不得记录文件名、人员姓名、正文、提示内容、生成正文、指标数值或材料片段。

## 6. 一次智能体任务的运行链

```text
用户提出任务
  → 学校侧建立智能体任务和任务范围
  → 权限服务确定可见专业群、专业、周期和对象
  → 知识服务在学校侧检索并形成候选包
  → 用户确认任务理解、资料范围和拟执行动作
  → 动作网关发送最小上下文到云端能力
  → 云端返回结果、引用、未知项和建议动作
  → 学校侧进行字段、版本、权限和引用校验
  → 用户确认、退回或修改
  → 业务 API 写入新版本、关系和建设账本
  → 智能体任务记录最终结果或停止原因
```

## 8. 初始技术选型建议

以下选型属于 W9 技术建议，评审通过后再成为开发基线：

| 层 | 建议 | 选择理由 |
| --- | --- | --- |
| 前端 | TypeScript、React、Vite | 与现有原型技术一致，便于逐页迁移而不复制演示状态 |
| 业务 API | TypeScript、Node.js、Fastify | 共享对象契约和校验类型，适合明确动作接口 |
| 数据库 | PostgreSQL | 支持事务、关系、JSON 扩展、全文检索和可靠版本/账本 |
| 向量索引 | 首期 PostgreSQL `pgvector`，保留独立索引适配口 | 降低首期部署复杂度，同时保留后续扩展能力 |
| 文件空间 | 学校控制的 S3 兼容对象存储或校内文件服务 | 原件与数据库分离，支持版本、校验和备份 |
| 后台任务 | PostgreSQL 任务表 + 事务 Outbox | 首期先保证写入和消息一致，达到规模门槛后再引入独立队列 |
| 身份接入 | 学校统一身份优先，产品内角色和范围授权 | 身份来源与业务权限分离 |
| 接口契约 | OpenAPI + JSON Schema | 可生成客户端、做契约测试和版本兼容检查 |
| 部署 | 容器化，学校内网或学校私域云 | 满足学校控制部署位置和备份恢复 |

## 9. 运行环境分层

| 环境 | 数据 | 用途 | 禁止事项 |
| --- | --- | --- | --- |
| 本地开发 | 合成数据 | 单元、契约和开发调试 | 不复制学校真实资料 |
| 集成验证 | 经批准的脱敏样例 | 全链、权限、失败与恢复验证 | 不作为正式业务结果 |
| 学校试点 | 学校批准的真实或脱敏试点资料 | A01—A11 试点验收 | 未授权范围不得进入 |
| 正式环境 | 学校正式资料 | 持续建设工作 | 无验收版本不得替换试点或正式服务 |

## 10. W9 技术通过门槛

W9 只有同时满足以下条件才可通过：

1. 真实数据库中对象、版本、关系和建设账本可重复创建、查询和回查；
2. 文件原件、指纹、版本、预览权限和恢复通过验证；
3. 至少两个专业群完成搜索、助手、报告和导出隔离；
4. 四类角色完成允许和拒绝用例，无权人员看不到标题、数量、摘要或正文；
5. 智能体任务从理解到写回经过人工确认，越权和缺资料时停止；
6. 重复请求、结果未知、旧版本、并发修改和服务中断不会造成重复写入或静默覆盖；
7. T01—T18 的本期状态与页面、接口和验证记录一致；
8. 备份恢复后对象数量、版本、关系、文件校验值和账本连续性一致；
9. 技术验证使用可执行测试和运行证据，不以页面截图替代；
10. 未实现能力在界面和接口中关闭，不返回伪成功。

# W9-4 任务、工作、材料、指标与差距首链实现方案

> 版本：v1.0　日期：2026-10-18　状态：编码基线。  
> 前置条件：W9-0 至 W9-3C 已验证。  
> 覆盖任务：T04、T06、T07、T08、T10、T11。  
> 贯穿案例：2026 年新增合作企业 3 家；A 企业确认完成 1 家，B 企业推进中，C 企业为历史合作，D 企业待开展。

## 1. 本波目标

把 W9-3 已发布的建设要求转成可以持续办理、可以退回补充、可以核对指标和形成差距任务的运行链：

```text
已发布建设要求和指标
  → 负责人建立并派发任务
  → 教师持续填写工作记录并关联材料
  → 提交确切版本
  → 负责人确认、退回或确认事实但保留证据不足
  → 已确认事实进入指标计算输入
  → 固定规则产生计算快照
  → 负责人确认正式进度结论
  → 未达成、缺材料或口径待确认形成差距
  → 负责人确认后建立补充任务并返回办理链
```

任务完成、工作事实确认、证据确认和指标达成是四种不同结果。任何一个状态不得直接代替其他状态。

## 2. 分切片建设

### W9-4A：计划任务、工作记录与提交退回

覆盖 T04、T07、T08，完成 B 企业任务的派发、工作记录、v1 提交、退回、v2 补充和负责人确认。该切片只形成“工作事实已确认”和“任务已完成”，不写指标结果。

### W9-4B：业绩分类、材料用途与重复控制

覆盖 T06。形成 A、B、C、D 企业的成果候选、分类候选、指标关系候选和人工决定；材料版本可支持多个用途，但同一业务成果的扫描件和电子版不能重复计数。

### W9-4C：指标规则、计算快照、正式进度与差距任务

覆盖 T10、T11。规则固定输入版本和数据截止点，产生可重复计算的候选结果；负责人确认后才形成正式进度。差距按“缺工作、缺材料、年度不符、口径待确认”分类，确认后可转成 W9-4A 任务。

## 3. W9-4A 产品对象

### 3.1 任务与版本

`tasks` 保存稳定任务编号和当前版本指针；`task_versions` 保存每次任务说明、来源要求、责任专业、责任人、协同人、开始/截止日期、预期产出、所需材料、确认人、优先级、状态和调整原因。

任务状态：

```text
draft → assigned → in_progress → submitted → completed
                      ↑             ↓
                      └── returned ─┘
```

- `draft` 仅负责人可编辑；
- `assigned` 后责任人可办理；
- 新工作记录使任务进入 `in_progress`；
- 提交固定任务版本、工作记录版本和材料版本；
- 退回必须有原因和具体补充要求；
- 再提交形成同一提交对象的新版本，不覆盖 v1；
- 负责人确认可将任务设为 `completed`，但不得更新指标正式值。

### 3.2 工作记录与版本

`work_records` 是一次持续建设事项的稳定对象，`work_record_versions` 保存本次做了什么、业务日期、参与人、结果、问题、下一步、关联任务版本和变更原因。修改形成新版本。

工作记录可以长期补充；只有进入已提交版本并由负责人确认的内容，才属于后续指标计算的可用事实候选。

### 3.3 提交、审核和材料关系

`task_submissions` 每个任务一个稳定提交对象；`task_submission_versions` 保存 v1、v2 等提交说明、所引用的任务版本和工作记录版本。`task_submission_materials` 固定本次提交使用的材料版本。

`task_submission_reviews` 保存负责人每次“确认完成、退回补充、确认事实但证据不足”的决定、原因、补充要求和决定人。审核决定追加保存，不覆盖历史。

## 4. W9-4A 权限

| 角色 | 可见范围 | 可执行动作 |
| --- | --- | --- |
| 专业群负责人 | 当前专业群与周期 | 建任务、派发、调整、查看全部任务、审核提交、确认任务完成 |
| 教师 | 本人负责或协同且符合专业范围的任务 | 查看任务、填写本人工作记录、提交、根据退回意见补充 |
| 教务审核人员 | 当前获准范围 | 只读查看任务、提交与审核轨迹，不派发、不代替负责人确认 |
| 信息支持人员 | 无业务正文 | 不返回任务数量、标题、人员、材料或摘要 |

专业范围角色必须同时满足任务专业和人员关系；没有专业标识的群级任务不自动开放给专业范围教师。

## 5. W9-4A 接口

| 接口 | 作用 |
| --- | --- |
| `POST /tasks` | 负责人从正式建设要求建立任务草稿 |
| `POST /tasks/{taskId}/assign` | 固定任务版本并正式派发 |
| `GET /tasks` | 按角色、专业、人员、状态和时间范围查询任务 |
| `GET /tasks/{taskId}` | 查看任务版本、工作记录、提交版本、材料和审核轨迹 |
| `POST /tasks/{taskId}/work-records` | 新建或追加工作记录版本 |
| `POST /tasks/{taskId}/submissions` | 首次提交或对退回提交形成新版本 |
| `POST /task-submissions/{submissionId}/reviews` | 负责人确认、退回或确认事实但标记证据不足 |

所有写接口使用统一写入信封，检查范围、当前版本、幂等键、操作者与角色，并在同一事务写业务变化、回执、建设账本和 Outbox。

## 6. W9-4B 对象与门槛

- `achievement_candidates`：成果候选及业务日期、所属专业、当前正式程度；
- `achievement_material_links`：材料版本对成果的支撑关系；
- `achievement_duplicate_groups`：同一成果的多份材料，不删除原件；
- `indicator_support_candidates`：成果可能支持哪个指标及理由；
- `classification_decisions`：接受、修改、拒绝、待核实及决定人。

“可支持指标”不等于“计入指标数值”。B 企业协议草稿可保留过程成果，但不能直接计为新增企业；C 企业因业务年度不符，不能通过补材料改成本年度新增。

### 6.1 本波产品办理链

1. 教师或专业群负责人从一份或多份已保存材料发起成果候选，填写成果名称、业务日期、所属专业和建议分类；没有材料不能建立成果候选。
2. 发起人可以同时提出“该成果可能支持哪个正式指标”的建议并说明理由。系统只保存建议，不改变指标进度。
3. 同一成果存在扫描件、电子版或多次上传版本时，使用重复材料组表达“材料不同、业务成果相同”。所有原件和版本继续保留。
4. 专业群负责人逐条作出接受、修改、拒绝或待核实决定，并分别确认、拒绝或保留待核实的指标支撑建议。
5. 查询详情同时呈现来源材料、建议分类、人工最终分类、指标支撑决定和重复材料决定，便于后续 W9-4C 固定输入并计算。

### 6.2 分类和决定口径

| 对象 | 建议或决定值 | 含义 |
|---|---|---|
| 成果分类 | `current_year_completed` | 本年度已经形成可核对成果 |
| 成果分类 | `current_year_in_progress` | 本年度正在推进，尚缺正式结果或必要证据 |
| 成果分类 | `historical` | 业务日期属于往年，只能作为历史或持续合作材料 |
| 成果分类 | `unmatched` | 当前无法归入已知分类，需要补充事实或口径 |
| 人工决定 | `accept` | 接受建议分类 |
| 人工决定 | `modify` | 保留原建议并记录修改后的最终分类与理由 |
| 人工决定 | `reject` | 本条不作为成果候选继续使用，但原材料不删除 |
| 人工决定 | `needs_review` | 暂不形成最终分类，保留待核实原因 |

“待开展”属于任务状态，不属于成果分类。D 企业没有洽谈记录或材料时，只能保留为待开展任务，不能为了凑齐 A、B、C、D 四类结果而虚构一条成果。

### 6.3 接口与权限

| 接口 | 产品行为 |
|---|---|
| `POST /achievement-candidates` | 从至少一份已保存材料建立成果候选，并可同时提出指标支撑建议 |
| `GET /achievement-candidates` | 按范围、专业、状态和建议分类查看候选清单 |
| `GET /achievement-candidates/{candidateId}` | 查看候选、全部材料、指标支撑建议、人工决定和重复材料组 |
| `POST /achievement-candidates/{candidateId}/decision` | 负责人原子地处理成果分类和本候选的全部指标支撑建议 |
| `POST /achievement-duplicate-groups` | 对同一成果的至少两份材料提出重复组建议 |
| `POST /achievement-duplicate-groups/{groupId}/decision` | 负责人确认或拒绝重复组，不删除或合并材料 |

- 教师可在本人角色覆盖的专业内发起和查看候选；专业范围角色不能查看其他专业或未标专业的候选。
- 专业群负责人可查看、发起和决定；审核人员只读；信息处支持人员不读取业务内容。
- 所有写入继续使用范围、预期版本、幂等键、操作者和用途组成的统一写入信封，并同步写建设账本和回执。
- 成果决定、指标支撑决定和重复组决定的回执均明确 `indicatorProgressChanged=false`。

### 6.4 A、B、C、D 合成验收口径

- A 企业：正式协议与活动记录形成“本年度已完成”候选；扫描件和电子版组成已确认重复材料组；指标支撑建议可确认，但指标数值仍不变化。
- B 企业：即使助手误建议“已完成”，负责人也能修改为“本年度推进中”，并把指标支撑保留为待核实。
- C 企业：2025 年协议接受为“历史成果”，对 2026 年新增企业指标的支撑建议应拒绝。
- D 企业：无材料时建立成果候选返回校验失败，系统中不存在 D 企业成果；待开展事实由任务链承载。

## 7. W9-4C 对象与确定性计算

- `indicator_rule_versions`：目标值、统计期间、去重键、计入条件和证据要求；
- `indicator_evaluation_runs`：规则版本、截止点、输入摘要和运行状态；
- `indicator_evaluation_inputs`：固定成果、工作事实、材料和人工决定版本；
- `indicator_calculated_results`：候选实际值、目标值、差值和明细；
- `progress_confirmations`：已达成、未达成、资料不足、口径待确认及负责人决定；
- `gap_items`：差距类型、依据、建议动作、责任人和节点；
- `gap_task_decisions`：负责人是否把建议转成正式任务。

计算服务只能执行已经版本化的固定规则。智能体后续只能解释结果、发现异常和提出建议，不能自由生成正式数值。

## 8. 首条合成验收链

1. 从已发布指标要求“2026 年新增合作企业 3 家”建立 B 企业正式签约任务；
2. 负责人将任务派给李老师，要求提交正式合作协议；
3. 李老师填写“已完成洽谈并形成协议草稿”，关联草稿材料后提交 v1；
4. 负责人退回，明确“补充正式签订文件和签订日期”；
5. v1、退回意见和草稿材料继续保留；
6. 李老师补充工作记录和正式协议材料，提交 v2；
7. 负责人确认工作事实并完成任务；
8. 查询显示任务已完成，但指标正式值仍保持原状态，直到 W9-4C 独立计算和确认；
9. W9-4B 将 A 企业确认为本年度已完成成果、B 企业按当时材料正式程度处理、C 企业标为历史成果；D 企业因无材料不建立成果，待开展事实保留在任务链；
10. W9-4C 固定目标、规则、成果和截止点，得到 1/3、尚差 2 的候选快照；
11. 负责人确认“未达成”，并分别为 B、D 形成不同差距原因；
12. 负责人确认补充动作后建立任务，回到 W9-4A 办理。

## 9. W9-4A 自测门槛

- B 企业链完整保留 v1、退回、v2 和两次材料集合；
- 任务完成不写指标正式值；
- 教师只能办理本人且符合专业范围的任务；
- 负责人可派发和审核，审核人员只读，信息支持零泄露；
- 旧任务版本、旧提交版本和重复审核被拒绝；
- 相同幂等键返回同一回执，不产生重复任务或重复提交；
- 直接猜测任务、提交或材料编号不泄露存在性；
- 空库迁移、重复迁移、全工程回归和 OpenAPI 校验通过。

### 9.1 W9-4B 自测门槛

- A 企业扫描件、电子版和活动记录均保留，重复材料组确认后原件数量不变；
- B 企业错误分类建议可被负责人修改，C 企业跨年度支撑可被拒绝；
- D 企业零材料请求被拒绝，不能形成虚构成果；
- 接受、修改、拒绝和待核实四类决定均有运行用例；
- 成果、指标支撑和重复材料决定均不修改指标正式值；
- 教师专业范围、负责人决定、审核人员只读和信息支持零泄露通过；
- 幂等重放返回同一回执，第二次决定和旧状态决定被拒绝；
- 空库迁移、重复迁移、全量集成、全工程回归和 OpenAPI 校验通过。

## 10. 本波不提前宣称

- 智能体自然语言执行和云动作调用；
- 自动通知或学校消息系统接入；
- 真实学校材料、人员和组织数据；
- 真实指标规则的正确性与学校验收；
- 周月年总结、报告、Word/PDF 导出；
- T01—T18 全部完成。

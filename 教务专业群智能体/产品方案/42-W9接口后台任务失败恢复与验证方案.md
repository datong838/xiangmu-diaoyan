# W9 接口、后台任务、失败恢复与验证方案

> 版本：v1.0　日期：2026-10-18　状态：历史技术初稿，未经正式组织评审；作为第 122—128 份评审稿的详细参考。  
> 对应方案：14、15、18、37—41。

## 1. 设计目标

正式系统的成功标准不是“按钮点过了”，而是业务对象、版本、关系、账本和回执处于一致状态。接口和后台任务必须能够区分成功、拒绝、冲突、失败和结果未知。

## 3. 写接口统一请求

```json
{
  "scope": {
    "schoolId": "...",
    "groupId": "...",
    "cycleId": "..."
  },
  "idempotencyKey": "...",
  "expectedVersionId": "...",
  "purpose": "...",
  "humanDecisionId": "...",
  "payload": {}
}
```

所有字段由服务端重新校验。`groupId` 不得从对象内容推断，`humanDecisionId` 只能引用当前用户有权作出的有效决定。

## 4. 统一回执

```json
{
  "receiptId": "...",
  "operationId": "...",
  "status": "succeeded | rejected | conflict | failed | unknown",
  "objectId": "...",
  "previousVersionId": "...",
  "newVersionId": "...",
  "ledgerEntryId": "...",
  "retryable": false,
  "reconcileUrl": "..."
}
```

HTTP 超时或连接断开不能自动解释为失败。客户端保留 `operationId`，通过只读回执接口对账。

## 5. 幂等与并发

- 同一用户、同一动作目的、同一对象版本使用同一幂等键；
- 同一幂等键重复调用返回原回执，不再执行；
- 不同负载复用同一幂等键返回冲突；
- 更新必须携带 `expectedVersionId`；
- 并发变化返回当前版本和差异摘要，由用户重新确认；
- 派发、审核、归档、导出和智能体写回均按写操作处理。

## 6. 后台任务模型

后台任务适用于解析、索引、批量转换、报告生成、导出和备份。状态为：

```text
pending → claimed → running → succeeded
                    ↘ failed_retryable → pending
                    ↘ failed_terminal
                    ↘ result_unknown → reconciling
cancel_requested → cancelled
```

任务保存输入对象版本，不直接读取“最新版本”。当前版本变化时，任务结果标记为基于旧输入，不能自动写入当前对象。

## 7. Outbox 与事件

业务写入和 `outbox_event` 同事务提交。后台分发成功后记录投递结果。消费者按事件编号幂等处理。

首批事件：

- 对象版本建立；
- 关系确认或失效；
- 材料版本可索引；
- 任务派发、退回、完成；
- 指标结果确认；
- 成果版本审核通过；
- 权限撤销；
- 专业群初始化启用。

事件只携带对象引用和版本，不复制敏感正文。

## 8. 失败处理矩阵

| 情况 | 系统行为 | 是否自动重试 |
| --- | --- | --- |
| 输入缺字段 | 返回拒绝及字段问题 | 否 |
| 无权限 | 返回统一拒绝并记录安全事件 | 否 |
| 版本冲突 | 返回当前版本和差异摘要 | 否 |
| 云端限流/暂时不可用 | 保留动作状态和下次可试时间 | 只重试只读或确定可幂等动作 |
| 写操作连接中断 | 标为结果未知，进入对账 | 否 |
| 解析部分成功 | 保留原件和部分候选，列出失败页 | 按失败页建立新任务 |
| 索引失败 | 正式对象仍存在，知识状态显示未就绪 | 可重建索引 |
| 导出失败 | 不产生正式导出记录 | 可用同一操作编号恢复 |
| 备份或恢复校验不一致 | 停止启用，保留差异报告 | 否 |

## 9. 结果未知对账

```text
写请求发出但未取得可信回执
  → 状态标为 unknown
  → 禁止相同目的重新生成新请求
  → 按 operationId 查询回执
  → 检查对象当前版本和建设账本
  → 若已写入，绑定原回执并结束
  → 若确定未写入，人工确认后使用原幂等键恢复
  → 无法确定则保持未知并升级处理
```

## 10. 可观测性

技术日志记录：请求编号、操作编号、匿名工作区编号、接口、状态码、耗时、版本冲突和错误类别。业务账本记录：谁对什么对象做了什么、前后版本、人工决定和结果。

技术日志不得记录学校正文、文件名、人员姓名、查询问题原文或生成正文。排障需要业务内容时走学校限时授权。

## 11. 测试分层

| 层 | 验证重点 |
| --- | --- |
| 单元测试 | 状态转换、规则、权限条件、版本和幂等 |
| 数据库测试 | 事务、约束、并发、跨群隔离、账本连续性 |
| 契约测试 | OpenAPI、错误结构、回执、版本兼容 |
| 服务集成 | 文件、索引、动作网关、工作流和成果服务 |
| 浏览器链路 | 四角色正常办理和拒绝结果 |
| 故障注入 | 超时、中断、重复请求、旧版本、部分成功 |
| 恢复演练 | 数据库、文件、索引和账本一致性 |
| 试点验收 | 需求确认单 A01—A11 |

## 12. W9 证据包

每个开发切片至少保存：

- 对应方案和实现任务编号；
- 数据库迁移版本；
- OpenAPI 版本；
- 自动测试结果；
- 正向和拒绝用例；
- 浏览器或接口运行证据；
- 失败恢复证据；
- 已知限制；
- 方案与实现差异；
- 当前可声明和不可声明内容。

## 13. 当前结论

本方案定义了 W9 接口和可靠性基线。具体路径和字段将在 OpenAPI 契约中冻结；当前尚无可运行 API、后台任务或恢复证据。

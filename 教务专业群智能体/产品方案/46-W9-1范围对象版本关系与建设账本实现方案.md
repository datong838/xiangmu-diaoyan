# W9-1 范围对象、版本、关系与建设账本实现方案

> 版本：v1.0　日期：2026-10-18　状态：编码前冻结稿。  
> 前置：第 38—45 份方案与 W9-0 运行证据。  
> 文档职责：把 SLC-01 最先需要的学校、专业群、专业和建设周期，以及版本、关系、幂等、回执和建设账本冻结为可编码合同。

## 1. 本波解决的问题

W9-1 只建立后续业务共同依赖的可信写入底座：

1. 一个学校工作空间下可以建立专业群、建设周期和多个专业；
2. 专业群和专业的名称、定位等可变内容以新版本修改，不覆盖历史；
3. 核心专业、支撑专业等关系作为正式数据保存；
4. 每次写入同时形成回执、幂等记录、建设账本和待分发事件；
5. 旧版本更新、重复请求、不同请求复用幂等键和跨学校关系必须被拒绝；
6. 写入结果中断后，能够按操作编号只读查询原回执。

本波不实现任务、材料、指标、权限、知识库或智能体，不把范围对象建成误导性的“全业务已可用”。

## 2. 首批对象

| 对象 | 稳定字段 | 可变版本内容 | 关键约束 |
| --- | --- | --- | --- |
| 学校 | `school_id`、`school_code` | 本波只保存合成显示名称 | 一所学校是最高数据范围 |
| 专业群 | `group_id`、`school_id`、`group_code` | 名称、说明 | 当前版本只指向已提交版本 |
| 建设周期 | `cycle_id`、`school_id`、`group_id`、起止年度 | 名称 | 必须属于同一学校和专业群 |
| 专业 | `profession_id`、`school_id`、`profession_code` | 名称、说明 | 可由关系加入一个或多个获准专业群 |
| 群—专业关系 | `relation_id` | 关系角色、有效期、确认说明 | 来源和目标必须同校；本波仅允许核心、支撑 |

显示编号在学校范围内唯一。数据库编号使用随机 UUID，不能从显示编号推测其他学校数据。

## 3. 状态与版本

### 3.1 对象状态

专业群、建设周期和专业首批只使用：

```text
active → archived
```

本波不提供恢复或物理删除接口。归档在后续波次设计权限和影响检查后开放。

### 3.2 版本状态

每次建立或修改直接形成一个不可变的已提交版本。首版 `version_no=1`；后续版本必须同时满足：

- `expectedVersionId` 等于对象当前版本；
- `basedOnVersionId` 等于被修改的版本；
- `version_no` 在同一对象内递增；
- 内容摘要由服务端计算；
- 对象当前版本指针和建设账本在同一事务更新。

创建对象也必须显式携带 `expectedVersionId: null`，避免客户端省略并让服务端猜测操作类型。

## 4. 本波接口

### 4.1 建立专业群工作空间

`POST /workspaces`

一次原子写入建立合成学校、一个专业群和一个建设周期，作为后续范围根。请求仍使用统一写入信封：

```json
{
  "operationId": "客户端生成的稳定编号",
  "scope": {
    "schoolId": null,
    "groupId": null,
    "cycleId": null
  },
  "idempotencyKey": "至少16位",
  "expectedVersionId": null,
  "purpose": "建立专业群工作空间",
  "actor": { "actorId": "synthetic-admin", "actorType": "person" },
  "payload": {
    "schoolCode": "DEMO-S01",
    "schoolName": "演示学校",
    "groupCode": "DEMO-G01",
    "groupName": "人工智能专业群",
    "cycleCode": "CYCLE-2026-2028",
    "cycleName": "2026—2028 建设周期",
    "startYear": 2026,
    "endYear": 2028
  }
}
```

只有工作空间建立接口允许三个范围编号均为空。成功后回执返回正式范围编号。

### 4.2 建立专业并加入专业群

`POST /professional-groups/{groupId}/professions`

在一个事务中建立专业首版、确认群—专业关系、账本和 Outbox。请求范围三项必须完整并与路径专业群一致。关系角色只允许 `core` 或 `supporting`。

### 4.3 修改专业群或专业

- `POST /professional-groups/{groupId}/versions`
- `POST /professions/{professionId}/versions`

必须携带当前 `expectedVersionId`。旧版本请求返回 `version_conflict` 和当前版本编号，不自动覆盖。

### 4.4 只读查询

- `GET /professional-groups/{groupId}?schoolId=...&cycleId=...`
- `GET /action-receipts/{operationId}`
- `GET /ledger?schoolId=...&groupId=...&cycleId=...`

所有只读接口都显式带范围；本波使用合成身份，正式身份和角色授权在 W9-2 加入。没有范围或范围不一致时不返回对象标题和数量。

## 5. 写入信封与回执

本波冻结的写入信封新增 `operationId` 和 `actor`；`expectedVersionId` 必须出现但允许为空：

```text
operationId
scope.schoolId / groupId / cycleId
idempotencyKey
expectedVersionId
purpose
actor.actorId / actor.actorType
payload
```

回执至少返回：

```text
receiptId、operationId、status、objectId、previousVersionId、newVersionId、ledgerEntryId、retryable、reconcileUrl
```

工作空间建立回执可额外返回 `scope`，供客户端后续请求使用。

## 6. 幂等规则

服务端对规范化请求计算摘要：

- 首次幂等键：执行写入并保存请求摘要与回执；
- 相同幂等键、相同摘要：返回原回执，不新增版本、账本或事件；
- 相同幂等键、不同摘要：返回 `idempotency_conflict`；
- 相同 `operationId` 必须对应同一幂等记录；
- 结果未知时只能查询原 `operationId`，不能换键重发同一业务目的。

## 7. 建设账本

账本为追加式记录，本波不提供修改和删除接口。每条记录保存：

- 学校、专业群、周期；
- 操作、回执和幂等记录编号；
- 操作者编号和类型；
- 动作、对象类型和对象编号；
- 操作前后版本；
- 结果状态和发生时间；
- 前一条摘要、当前条目摘要。

工作空间首条账本以学校范围建立账本链；专业群范围确定后，后续条目按学校、专业群和建设周期维持连续摘要。摘要用于发现缺失或篡改，不替代数据库备份和权限。

## 8. 数据库事务

每个写接口按以下顺序执行：

```text
开始事务
  → 验证信封、范围和路径
  → 读取或锁定幂等记录
  → 相同请求直接返回原回执
  → 锁定对象当前版本并校验 expectedVersionId
  → 新增对象、版本或关系
  → 新增回执、幂等记录、建设账本和 Outbox
  → 更新对象当前版本指针
提交事务
```

任一步失败均回滚。回执在同一事务产生，客户端断开不影响服务端按操作编号对账。

## 9. 必须自动验证的用例

1. 建立 DEMO-S01、DEMO-G01 和 2026—2028 周期；
2. 相同请求重复提交，只产生一个工作空间和一条账本；
3. 相同幂等键改变学校或专业群名称，返回幂等冲突；
4. 建立一个核心专业和四个支撑专业，查询得到五个关系；
5. 路径 `groupId` 与请求范围不同，拒绝且不泄露对象信息；
6. 使用旧版本修改专业群，返回版本冲突；
7. 合法修改形成 v2，v1 仍可从数据库回查；
8. 跨学校专业不能加入当前专业群；
9. 每个成功写入只有一条相应账本和一个 Outbox 事件；
10. 按 `operationId` 可以取得原回执；
11. 直接尝试更新或删除账本被数据库阻止；
12. 数据库约束失败时，不留下半个对象或孤立版本。

## 10. 与 SLC-01 和 T01—T18 的关系

W9-1 只完成 SLC-01 的范围根和可信写入机制，为后续任务提供学校、专业群、五个专业和建设周期。它直接支撑 T03 的组织关系底座，也为所有任务提供版本、关系和账本共同能力。

建设任务书、指标、B 企业任务、教师提交和 1/3 指标结果仍分别属于 W9-3、W9-4，不在本波提前实现。

## 11. 编码结论

本方案已把 W9-1 最小范围、接口、事务和验证条件冻结，可开始数据库迁移、领域契约和接口实现。编码必须先完成数据库约束和集成测试，再增加页面；不得扩大到权限、知识库、智能体和任务业务。

> 版本：v1.0　日期：2026-10-19　状态：实施方案已冻结，进入 W9-8A。  
> 前置：第 09、11、38—44、77、82、84、86 份方案；第 45—87 份实现与验证记录。  
> 文档职责：把 W9-8 拆成可执行、可核对、不会越界冒充学校验收的三个分段，并规定试点候选版的证据、资料包和封板门槛。

## 1. 本波目标

W9-8 不再继续按单一功能向后增加模块，而是把 W9-0 至 W9-7C 已形成的运行能力放回完整产品目标中核对，回答五个问题：

1. T01—T18 中每一项现在实际能办理到哪一步；
2. 教师、专业群负责人、教务审核人员和信息处支持人员分别能完成什么，越权时是否不泄露信息；
3. 专业群智能体是否真正调用同一套知识、任务、材料、成果和账本能力，而不是只显示回答；
4. A01—A11 在进入学校真实试点前，哪些可以用合成数据预演，哪些必须等待学校环境和人员；
5. 部署、初始化、备份恢复、使用、问题处理和已知限制是否已经形成可交付的候选资料包。

W9-8 完成后形成的是“可提交学校开展试点的候选版本”。学校真实数据、真实人员独立使用和双方验收属于 W10，不能由合成环境预演替代。

## 2. 核对口径

### 2.1 四种状态必须分开

| 状态 | 判定条件 | 可以怎样表述 |
| --- | --- | --- |
| 已有运行证据 | 有实际对象、写入、查询、拒绝、恢复或导出结果，且有可复核记录 | 合成环境已验证，可进入候选预演 |
| 仅有页面或方案 | 只有视觉入口、字段或设计说明，没有正式工程运行链 | 已设计，尚未实现 |
| 显式关闭 | 产品决定暂不启用，接口和页面不得返回伪成功 | 当前不提供，满足启用条件后另行建设 |
| 需学校现场验证 | 能力依赖学校身份、真实模板、真实资料、基础设施或真实操作者 | 候选准备完成，待 W10 验证 |

“接口存在”“页面可点”“自动测试通过”和“学校验收通过”分别记录，任何一项不得替代另一项。

### 2.2 每个业务任务的完整链

T01—T18 每项按同一结构核对：

```text
用户入口
  → 读取的范围与当前版本
  → 创建或修改的业务对象
  → 专业群知识库和智能体怎样参与
  → 人工确认点
  → 写回位置及后续承接
  → 无权、缺资料、重复、冲突、失败和恢复
  → 当前证据与未完成边界
```

不能因为某一任务复用了公共底座就重复建设一套对象；也不能因为公共底座已实现，就推断该任务的完整办理链已经实现。

### 2.3 十项候选版门槛

| 编号 | 门槛 | W9-8 通过要求 |
| --- | --- | --- |
| G01 | 范围与版本 | 学校、专业群、建设周期、专业、身份和预期版本在所有写入中明确 |
| G02 | 权限与隔离 | 四角色正向能力和负向越权均有证据；无权响应不泄露标题、数量、摘要、文件名或正文 |
| G03 | 可信写入 | 写入具备幂等、并发冲突、人工确认、回执、账本和待发送事件 |
| G04 | 事实与关系 | 依据、指标、任务、工作、材料、成果、报告和实践对象可追溯到固定版本 |
| G05 | 智能体办理 | 查询和受控动作使用固定知识包，计划与具体结果分别确认，暂停后可以按当前事实恢复 |
| G06 | 成果生产 | 固定快照、模板和材料版本，保留引用、缺项、局部修改、独立审核、Word/PDF 和归档 |
| G07 | 多群复制 | 新群只复用结构与方法，不复制事实、权限、资料、审核、报告和智能体历史 |
| G08 | 文件与恢复 | 数据库、学校侧文件、版本、关系、账本、实现状态和隔离证据按同一清单恢复；旧凭证失效 |
| G09 | 性能与可用性 | 在冻结环境和冻结样本下记录关键操作耗时、错误和资源条件；达到候选阈值或明确阻断 |
| G10 | 部署与使用资料 | 部署、初始化、备份恢复、角色使用、问题处理、限制和试点演练资料均可按步骤执行 |

## 3. 分段实施

### 3.1 W9-8A：全量能力盘点与缺口冻结

#### 建设内容

1. 对 T01—T18 逐项建立“产品设计目标—正式工程对象—接口/程序—角色—运行证据—当前状态—缺口—后续波次”矩阵；
2. 对四角色建立“可看、可写、可确认、可审核、可维护、禁止访问”的能力矩阵；
3. 将 A01—A11 拆成可由合成环境预演的步骤和必须由学校现场完成的步骤；
4. 复核显式关闭能力在接口、能力声明、文档和试点材料中口径一致；
5. 清理实现状态文档中笼统、过时或可能造成“已经全部实现”误解的表述。

#### 产物

- 第 89 份：W9-8A 全量能力盘点与试点差距账；
- 更新 `docs/implementation-status.md`；
- 如发现契约或实现缺口，只先登记到缺口账，不在盘点过程中顺手扩大实现范围。

#### 通过条件

- T01—T18 无遗漏，且每项只有一个明确状态；
- 四角色同时覆盖正向和负向边界；
- A01—A11 均拆分“候选预演”和“学校验收”；
- 每个“已运行”结论都有对应文件、接口或验证证据；
- 每个未实现项都有关闭、补齐或 W10 现场验证去向。

### 3.2 W9-8B：候选版运行资料与确定性预演

#### 建设内容

1. 建立候选版运行清单，按固定顺序检查迁移、实现状态、身份、文件根目录、动作网关、关闭能力和恢复前提；
2. 建立一套可重复执行的合成试点预演程序，串起范围初始化、依据、指标、任务、工作提交、分类、进度、差距、智能体办理、总结、成果编制、审核、导出、归档、多群隔离和恢复；
3. 预演程序只调用正式接口和正式维护命令，不直接写业务表，不以页面静态数据替代结果；
4. 为 A01—A11 输出逐项结果、证据位置、未满足原因和学校现场前置条件；
5. 形成部署、初始化、备份恢复、教师/负责人/审核人/信息处使用、问题处理和限制清单候选稿。

#### 产物

- 候选版就绪检查程序；
- A01—A11 合成预演程序与证据；
- 部署与初始化手册；
- 备份恢复手册；
- 四角色使用手册；
- 问题登记、处理和复测手册；
- 已知限制与学校试点前置清单。

#### 通过条件

- 全新合成环境能够按手册初始化并完成预演；
- 同一输入重跑不会重复建立正式对象；
- 失败项不会被汇总为通过；
- 恢复后的旧会话和旧文件票据失效；
- 输出明确标注“合成预演”，不出现“学校验收通过”。

### 3.3 W9-8C：性能、安全、可用性修复与候选封板

#### 建设内容

1. 冻结合成数据规模、机器条件、数据库状态和测量方法，记录关键查询、写入、生成和导出耗时；
2. 对越权、跨群、撤权、重复提交、版本冲突、文件篡改、数据库单独恢复、清单篡改和旧凭证重放做集中负向复核；
3. 对预演和手册实际执行中发现的阻断、误导表述和不可操作步骤做最小修复；
4. 复核 OpenAPI、实现状态、README、方案、手册和证据使用同一能力口径；
5. 形成候选版本标识、已知限制、风险、试点准入条件和 W10 交接清单。

#### 产物

- 性能基线与阈值结果；
- 安全负向回归记录；
- W9-8C 候选版封板验证记录；
- W10 学校试点交接包。

#### 通过条件

- 十项候选版门槛均有当前证据；
- 严重越权、事实错误、审核绕过、原件损坏和恢复失败为零；
- 性能测试条件和结果可重放，不用单次主观体验代替；
- 文档与程序一致；
- 未完成能力继续失败关闭；
- 候选版可以提交学校开展 W10，但仍不宣称真实验收完成。

## 5. 四角色核对范围

### 5.1 教师

重点核对本人任务、工作记录、材料、提交、退回补充、本人负责的实践结果确认，以及不能替代负责人确认指标或替代审核人批准成果。

### 5.2 专业群负责人

重点核对依据、知识发布、指标规则、任务分派、工作处理、分类与支撑关系、进度确认、差距任务、新群配置和建设结果管理；不能替代原责任人确认实践人工结果，也不能绕过独立审核。

### 5.3 教务审核人员

重点核对正式成果、实践案例和规定范围内的独立审核、退回、批准与重审；不能修改原始建设事实、替代教师提交或承担系统维护权限。

### 5.4 信息处支持人员

重点核对身份初始化、角色授予撤销、学校侧文件、运行就绪、备份恢复和问题排查；不能因技术维护身份读取或修改未授权业务正文。

## 7. 不纳入本波的能力

以下能力继续保持关闭或等待学校确认，不因 W9-8“全量核对”而自动扩项：

- T15 教学检查与听评课正式办理；
- T16 出卷与人工审核正式办理；
- 真实文件自动解析和扫描识别；
- 向量检索和外部模型重排；
- 开放式自然语言多轮理解；
- 外部智能服务调用；
- 学校统一身份、正式对象存储和正式消息平台接入；
- 学校真实资料导入、真实 RPO/RTO 和真实试点签收。

## 8. 实施顺序与停止规则

1. 先完成 W9-8A 盘点，不修改业务逻辑；
2. 根据盘点形成 W9-8B 的最小实现清单，先完善相应方案再编码；
3. 任何预演发现范围泄露、账本断链、原件损坏、审核绕过或结果被伪报为通过，立即停止候选封板并修复；
4. 结果未知时先只读对账，不自动重试写入；
5. 同一缺陷最多进行三轮有证据修复，仍未解决则登记为阻断，不降低门槛；
6. W9-8C 通过后才更新为“试点候选版”，在 W10 完成前不得写“学校已验收”。

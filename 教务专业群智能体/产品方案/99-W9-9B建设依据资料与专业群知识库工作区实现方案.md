# W9-9B 建设依据、资料与专业群知识库工作区实现方案

> 版本：v1.0　日期：2026-10-19　状态：编码前方案已冻结。  
> 前置：W9-9A 已通过；W9-3A—C 后端能力已在合成环境验证。  
> 对应任务：T01、T02、T03、T05，并为 T04、T06、T09、T10、T12、T13 提供可信资料和知识输入。

## 1. 本段目标

把已经存在于 API 和数据库中的材料、建设依据、资料吸收、人工确认、正式知识和来源追溯组织成教师与负责人能够连续办理的正式工作区。页面围绕建设对象和办理状态展开，不按接口名称堆叠功能。

本段主线为：

```text
资料登记和保留版本
  → 建立资料吸收批次
  → 查看读取、拆解、缺项和重复状态
  → 人工核对内容单元
  → 将已确认内容登记为建设依据条款候选
  → 负责人确认候选关系
  → 发布为正式知识
  → 检索、查看来源关系和材料用途
```

上传、可读、已拆解、已确认和已发布必须在界面中保持为五种不同事实。

## 2. 工作区结构

### 2.1 建设依据

回答“申报书、建设任务书和实施方案目前有哪些版本，批准状态是什么，适用于哪个周期，哪些要求已经进入正式知识”。

- 首屏按三类依据显示现有文件、当前版本、批准状态、适用日期和来源材料；
- 缺少某一类时明确显示“尚未登记”，不能用另外两类推断补齐；
- 可进入依据办理页查看来源材料、条款候选、确认状态和发布状态；
- 新登记必须选择已存在的材料版本，保存批准状态、适用周期和变更原因。

### 2.2 资料与证据

回答“学校交来的资料在哪里、当前版本是什么、读到了什么、还缺什么、有哪些重复候选、谁需要处理”。

- 材料目录展示标题、资料编号、专业范围、敏感级别、当前版本、来源日期和是否存在原件；
- 资料吸收批次展示批次用途、材料数量、可读状态、待确认内容、待补缺项和待处理重复候选；
- 批次详情保留每个内容单元的原文位置和审核状态；
- 无法读取的资料显示失败原因和下一步，不形成伪内容。

### 2.3 专业群知识库

回答“当前正式可用的建设知识有哪些，为什么命中，来自哪里，与什么要求有关，是否还有冲突或缺项”。

- 支持关键词、依据类型、要求类型、关系类型和适用日期筛选；
- 结果显示正式知识标题、要求编号、要求表述、来源摘录、命中原因、冲突和缺项提示；
- 进入追溯页可沿正式知识、发布、确认、要求、条款、依据、材料和内容单元逐级查看；
- 从材料详情可反查它支撑了哪些正式知识用途；
- 向量检索和外部模型继续显示为未启用，不以普通关键词检索冒充。

## 3. 角色办理边界

| 角色 | 可查看 | 可办理 |
| --- | --- | --- |
| 专业群负责人 | 当前群全部获准依据、材料、吸收批次、候选和正式知识 | 登记依据、建立批次、核对内容、确认候选、发布正式知识 |
| 教师 | 本人及本专业获准材料、当前范围正式知识 | 后续可提交本人资料；本段不扩大既有写权限 |
| 教务审核人员 | 获准查看的依据、L1/L2 批次和正式知识 | 查看与复核，不替负责人作确认或发布决定 |
| 信息支持人员 | 运行状态 | 不显示业务对象标题、数量、摘要和正文 |

页面只负责呈现服务端已经允许的内容，不能用前端隐藏代替服务端权限。

## 4. 分段实现

### W9-9B1：目录、检索和关系追溯

- 激活“建设依据”“资料与证据”“专业群知识库”导航；
- 建设依据目录、材料目录和资料吸收批次目录均从真实 API 读取；
- 正式知识支持结构化检索；
- 知识结果可查看完整来源链，材料可反查正式用途；
- 增加当前范围资料吸收批次目录接口。现有接口只有按编号详情，不能形成学校工作台目录；新接口只返回当前会话获准范围内的摘要，不扩大权限。

### W9-9B2：资料登记与吸收办理

- 材料登记和新版本；
- 建立吸收批次、加入固定材料版本；
- 查看读取结果、内容单元、缺项和重复候选；
- 负责人批量接受、退回或拒绝内容，处理缺项和重复候选；
- 写操作继续显示对象、版本和操作回执，结果未知时停止自动重发。

### W9-9B3：依据条款、候选确认和正式发布

- 从已确认内容单元登记依据条款和建设要求候选；
- 候选关系与正式知识分区显示；
- 负责人逐项确认或拒绝候选；
- 只有批准依据和已确认候选能够发布；
- 发布后回到正式知识检索，核对来源链和材料用途。

## 6. 新增批次目录接口约束

`GET /ingestion-batches?schoolId&groupId&cycleId` 返回当前范围批次摘要：批次编号、标题、用途、资料类别、可见级别、状态、当前版本、建立时间，以及已登记资料、待确认内容、待补缺项和待处理重复候选数量。

- 需要 `ingestion:read`；
- 信息支持或无当前范围角色返回空集合，不泄露数量；
- 教务审核人员不返回 L3 批次；
- 专业群负责人按当前群和周期查看；
- 所有统计在数据库范围条件内计算，不先全库统计再过滤；
- 本段不新增数据库迁移，不修改已有批次详情和写入语义。

## 7. 页面状态与用语

- 页面使用“建设依据、资料批次、待核对内容、正式知识、来源关系”等学校人员可理解的名称；
- 不出现迁移、UUID、向量、接口、数据库表等实现词；
- 内部对象编号只在“核对信息”区按需显示，首屏显示业务编号和标题；
- 加载、空白、无权、失败和关闭能力分别显示；
- 没有资料时提示下一项可办理工作，不把空白显示为异常；
- 任何统计数字都能进入对应明细或明确说明当前阶段尚未开放。

## 8. W9-9B1 自测门槛

1. 批次目录接口允许负责人和获准审核人员读取，拒绝信息支持和跨范围泄露；
2. L3 批次不向教务审核人员泄露标题、数量和摘要；
3. 三个工作区均从真实 API 读取，刷新后不丢失；
4. 知识筛选参数、命中原因、冲突缺项提示和来源追溯完整显示；
5. 材料目录可进入材料详情并反查正式用途；
6. 空数据、无权、404 和一般失败均有明确页面状态；
7. W9-9A 任务首链和后端全量验证继续通过；
8. 浏览器完成“依据目录—知识检索—来源追溯—材料用途—批次目录—批次详情”的真实只读核对链；
9. 页面仍清楚标明 B2/B3 的写入办理尚未开放，不能把 B1 误报为 W9-9B 完成。

## 9. 编码前结论

W9-3A—C 的对象、权限、状态和接口已经复核。W9-9B1 只补一个受现有权限约束的批次目录接口，并把既有读取能力组织为三个正式工作区，不改数据库结构和写入语义。B1 完成后继续实施 B2、B3，才能关闭 W9-9B。

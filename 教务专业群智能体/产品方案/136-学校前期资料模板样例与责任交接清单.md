# 学校前期资料、模板、样例与责任交接清单

> 版本：v0.1 评审准备稿  
> 日期：2026-10-19  
> 状态：评审稿编制完成，等待内部评审；确认后可整理为学校填写版  
> 说明：学校提供的是经学校批准可用于方案核对、演示或试点的资料；每份资料都要说明用途、版本、授权范围和核对人

## 1. 为什么需要前期资料交接

工作站要按照学校真实组织、建设依据、指标口径和成果格式工作，不能只依靠通用示例。前期资料交接的目的，是让双方明确系统应当处理什么、怎样判断正确、谁负责确认，并不要求学校一次性整理完全部历史资料。

建议先围绕一个试点专业群、一个建设周期和一条完整工作链准备最小资料包，再逐步补充。

## 2. 项目与组织资料

| 资料 | 学校需要提供或确认 | 用途 | 核对人 |
| --- | --- | --- | --- |
| 学校和部门信息 | 正式名称、代码、部门/学院关系 | 建立学校和组织范围 | 校方项目负责人 |
| 试点专业群 | 名称、级别、建设周期、当前阶段 | 建立试点工作空间 | 专业群负责人 |
| 专业名单 | 核心专业、支撑专业、专业代码、负责人 | 建立专业群结构和分工 | 专业群负责人 |
| 参与人员 | 教师、专业负责人、专业群负责人、审核人员、信息支持人员 | 建立角色与任务责任 | 校方项目负责人 |
| 跨专业事项 | 哪些任务和成果由多个专业共同承担 | 建立协作和汇总关系 | 专业群负责人 |

## 3. 建设依据文件

### 3.1 已知必须列出的三类文件

| 文件 | 需要确认 | 工作站用途 |
| --- | --- | --- |
| 申报书 | 文件版本、批准状态、适用周期、正式名称 | 整理建设背景、总体目标、方向、预期成果和特色 |
| 建设任务书 | 文件版本、批准状态、年度目标和验收要求 | 整理指标、目标值、完成年度、验收标准和支撑材料 |
| 实施方案 | 文件版本、批准状态、责任和阶段安排 | 整理牵头专业、配合专业、负责人、时间和措施 |

### 3.2 可能需要补充的依据

- 上级正式通知、申报指南和评审要求；
- 指标修订、任务调整和批准记录；
- 学校中心工作和部门年度计划；
- 已有中期检查、年度检查或验收意见；
- 与试点任务直接相关的校内制度和分类规则。

每份文件登记文件名、版本、日期、批准状态、适用周期、提供人、允许用途和最终核对人。未批准文件标为草稿依据。

## 4. 最终成果模板

学校需要提供的是“最终希望得到的文档格式”，而不只是同类参考材料。

| 已知成果类型 | 希望学校提供 | 需要确认的格式信息 |
| --- | --- | --- |
| 国家级/省级/校级申报材料 | 正式通知、申报书模板、填写说明、往年可用样例 | 年度、批次、章节、表格、字数、附件、提交格式和渠道 |
| 建设任务书 | 正式空白模板和填报说明 | 指标表、年度任务、责任和验收材料栏目 |
| 实施方案 | 正式模板或学校采用的结构 | 工作安排、时间、责任、措施和附件要求 |
| 年度建设报告 | 学校或主管部门正式模板 | 统计期间、章节、数据表、支撑目录和签章要求 |
| 中期评审材料 | 正式模板、评审通知和附件清单 | 截止日期、章节、指标对照、附件和提交方式 |
| 终期验收材料 | 正式模板、验收指标和自评要求 | 达成结论、证据目录、签章和归档格式 |
| 专项申报材料 | 已知项目的正式模板，如国家级人工智能试点校 | 项目名称、批次、评分要求、栏目和附件 |
| 周/月/年总结 | 学校实际采用的格式或样例 | 周期、栏目、统计口径和下期计划格式 |
| 工作台账/Excel | 实际表头、字段说明和一份正确样例 | 列名、数据类型、分类和汇总规则 |
| 汇报/PPT | 学校模板、页面结构和一份可用样例 | 页数、版式、必要图表、校徽和输出要求 |

后续出现新的申报、评审或总结事项时，可以继续追加模板。模板需要保留年度、批次和版本，不能用一份通用模板替代所有正式格式。

## 5. 指标和统计规则样例

建议先选择至少 10 个指标，覆盖：

- 数量指标；
- 定性判断；
- 分年度和累计目标；
- 跨专业共同成果；
- 重复成果；
- 无资料和资料不足；
- 不适用事项；
- 指标修订。

每项需要提供目标、期间、计算方式、所需材料、确认人和一份人工标准答案。没有明确规则的指标可以标为待确认，不能让智能体自行决定。

## 6. 日常工作和资料样例

### 6.1 最小工作链样例

建议准备一项真实工作，包括：

- 工作或任务说明；
- 一段聊天摘录或通知；
- 一份文档或表格；
- 一张图片；
- 参与人员和业务日期；
- 形成的结果；
- 负责人对正确归类和使用方式的说明。

### 6.2 异常样例

准备少量重复、损坏、空白、无关、无法读取、缺少来源或无法匹配指标的材料，用于验证系统是否如实说明失败和缺项。

### 6.3 A—D 企业贯穿案例的真实替代

学校可选择一项类似的实际指标，提供已完成、正在推进、历史成果和待开展四类事项，用于核对分类、进度、查询、差距和成果编制。若暂时不能提供，可以继续使用脱敏演示样例，但不能据此形成学校正式结论。

## 7. 查询问题和成果修改样例

建议学校提供：

- 常问的专业群、专业、教师和指标进度问题；
- 对时间范围、完成状态和缺项的实际问法；
- 一份成果初稿及真实修改意见；
- “只修改某一部分、其他不动”的局部改稿样例；
- 审核人常见的退回原因。

这些样例用于设计专业群智能体的任务理解、结果表格、修改范围和审核流程。

## 8. 权限与数据使用确认

| 事项 | 需要学校确认 |
| --- | --- |
| 查看范围 | 教师、专业负责人、专业群负责人、审核人员分别能看什么 |
| 下载和导出 | 哪些资料可下载、谁可批量导出、正式成果由谁导出 |
| 跨专业/跨群 | 哪些内容允许共享、用途和期限 |
| 敏感资料 | 哪些资料不能进入系统或不能进入云动作服务 |
| 样例授权 | 可用于方案核对、演示、试点或验收的范围 |
| 脱敏要求 | 人名、学生、企业、成绩、联系方式等怎样处理 |
| 保留与处置 | 原件、历史版本、日志和临时处理内容的保留规则 |

## 9. 环境与运行信息

- 数据部署在校内服务器还是学校租赁的私域云；
- 支持的浏览器、网络位置和并发人数；
- 首批材料数量、空间和每年新增量；
- 单份文件和单份报告规模；
- 统一身份、组织人员、教务、办公和文件平台情况；
- 备份频率、恢复目标、演练负责人；
- 维护时间、问题联系人和培训批次。

具体数值由学校填写，方案不预设。

## 11. 建议首批最小资料包

1. 一个试点专业群和专业名单；
2. 参与人员及角色；
3. 申报书、建设任务书、实施方案各一个确认版本；
4. 一份年度或中期正式成果模板；
5. 十个指标及人工标准答案；
6. 一项完整日常工作及相关文档、聊天摘录和图片；
7. 一批正常和异常材料样例；
8. 二十个实际查询问题；
9. 一份成果初稿、修改意见和审核样例；
10. 权限、部署、备份和试点责任表。

## 12. 当前结论

本清单将“请学校提供演示资料”拆成了可理解、可准备、可授权和可核对的具体项目。内部评审通过后，可以根据本清单整理学校填写版；学校尚未交接的内容继续标为待确认。

## 1. 本波目标

W9-0 不实现学校业务，而是建立后续可持续开发的正式底座：工程工作区、运行契约、数据库迁移、测试、证据目录和失效关闭行为。它必须证明系统能够真实启动，同时不会把尚未建设的页面、接口或智能体能力包装成完成状态。

## 3. 已实现的运行行为

1. `GET /health` 报告真实服务名、版本和 W9-0 阶段；
2. 没有数据库配置或数据库不可用时，`GET /ready` 以 503 拒绝就绪；
3. 数据库可连接后，`GET /ready` 才返回就绪；
4. 所有尚未建设的业务接口返回 `route_not_found`；
5. 数据库迁移带顺序、内容校验值、事务和并发迁移锁；
6. 已执行迁移被修改时，后续迁移必须失败；
7. 云动作网关明确关闭，长期学校资料存储能力为否；
8. 当前系统状态明确记录为只允许合成数据、业务能力和外部智能服务关闭。

## 6. 已发现并处理的问题

最初测试运行工具依赖安装脚本，受到本机供应链门槛限制。工程已改为使用当前 Node 自带的 TypeScript 测试支持，移除该运行依赖。这样减少了额外二进制安装和环境差异，同时保留正式 TypeScript 编译与类型检查。

当前 Codex 运行环境的 Node 不在默认命令路径中，验证时显式使用了工作区运行时路径。该情况属于当前执行环境差异，普通安装了 Node 的开发环境不需要额外处理；部署文档在 W9 后续波次中继续明确运行时版本。

# W8 资料吸收与成果编制子链原型验证记录

> 版本：v1.0　日期：2026-10-18　状态：内部原型验证记录。  
> 验证范围：`demo` 内部产品视觉稿的资料吸收确认与年度报告章节编写两个子流程。页面使用演示数据，只验证产品承载方式和本地交互，不代表学校事实、正式业务结果或可运行产品已经建成。

## 1. 本轮目的

第 27 份记录已经验证“建设依据—任务分解—工作提交—事实证据—进度判断—差距处理—成果编制”七步主链。本轮继续向两个容易被静态展示替代的环节深入：

1. 建设依据进入系统前，怎样经过原件保全、拆解、候选确认和知识发布；
2. 已确认事实进入成果后，怎样按模板编写章节、局部改稿、审核和开放正式导出。

本轮不增加新的业务范围，分别落实第 16 份知识吸收流程和第 22 份成果编制流程。

## 3. 资料吸收子流程

### 3.1 页面承载

- 登记交接批次、用途和专业群范围；
- 同屏列出申报书、建设任务书、实施方案的版本和当前状态；
- 显示 I0—I10 全过程：登记、保全、完整性检查、识别读取、原文拆解、候选对象、候选关系、冲突缺项、人工确认、知识发布和影响分析；
- 逐项展示候选知识的类型、原文内容、来源位置、确认后的用途和当前状态；
- 支持确认、退回和标记冲突，智能体只负责提取与说明，学校人员负责确认；
- 发布时只发布已经确认的内容，未确认、退回和冲突内容继续留在原批次。

### 3.2 浏览器验证

1. 打开 `#ingestion` 并刷新，页面仍为“资料吸收与知识确认”；
2. 主链高亮“建设依据”；
3. 将 K02“判断条件”从待确认改为已确认，确认数从 `1 / 4` 变为 `2 / 4`；
4. 执行“发布已确认知识”后，页面显示已发布 2 项；
5. K03 继续保持待确认，K04 继续保持口径冲突，没有被本次发布带入正式知识。

这证明页面表达了“候选不等于事实、确认不等于全批通过、发布不覆盖冲突”的产品边界。

## 4. 成果编制子流程

### 4.1 页面承载

- 固定成果类型、学校模板版本、统计期间、输入快照、编写人和审核人；
- 按模板目录进入章节，区分已完成、编辑中、缺项和待编写；
- 当前章节正文可编辑，人工保护段落与助手可改范围分开；
- 右侧同时展示已确认事实、材料引用、历史范围和待确认缺项；
- 专业群助手可以按指定审核口径做局部改稿，但不得改变已确认数字；
- 草稿必须先提交审核，进入待审核状态后才允许退回或批准；
- 只有审核人批准当前版本后，才开放正式导出与归档入口。

### 4.2 浏览器验证

1. 打开 `#report-editor` 并刷新，页面仍为“年度报告章节编写”；
2. 主链高亮“成果编制”；
3. 初始状态下，“退回第三部分”“批准当前版本”“正式导出并归档”均不可操作；
4. 执行局部改稿后，正文仍保留“年度目标 3 家、确认完成 1 家、尚差 2 家”，并保持 B、C、D 企业的不同事实状态；
5. 提交当前版本审核后，退回和批准入口开放，正式导出仍关闭；
6. 审核人批准后，版本由草稿 v3 形成草稿 v4，正式导出与归档入口开放，退回和重复批准入口关闭。

这证明页面区分了事实输入、正文表达、版本变化、人工审核和正式输出。

## 7. 当前限制和风险

1. 候选状态、知识发布、章节版本和审核状态只保存在页面内存，刷新后复位；
2. 三份依据和报告模板均为演示数据，没有读取学校真实文件；
3. 尚未建立真实的原件保全、解析、关系存储、引用回查和知识发布服务；
4. 尚未建立真实身份、角色权限、审核签名、正式导出和建设账本写入；
5. 本轮只覆盖知识吸收和成果编制的代表状态，不能替代 T01—T18 全任务、四角色、多专业及多专业群走查；
6. 因此 W2、W4、W6 和 W8 均获得了新的原型证据，但仍未达到各自通过门槛。

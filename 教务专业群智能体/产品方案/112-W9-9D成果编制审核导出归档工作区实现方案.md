# W9-9D 成果编制、审核、导出与归档工作区实现方案

> 版本：v1.0  
> 日期：2026-10-19  
> 状态：已实施并完成候选环境验证  
> 依据：第 07、22、71—76、96、105、110—111 份方案及现有 W9-6 接口

## 1. 本轮目标

把已经通过 W9-6 验证的学校模板、事实快照、成果编制、局部改稿、独立审核、Word/PDF 导出和归档能力接入正式工作台，形成学校人员能够持续办理的成果生产线。

工作主线是：

```text
学校模板
  → 已确认事实快照
  → 获准使用的材料版本
  → 成果初稿及逐章来源
  → 缺项处理
  → 指定范围改稿
  → 独立审核退回或批准
  → 草稿/正式 Word、PDF
  → 正式归档
```

本轮不重新实现 W9-6 业务规则；重点是补齐可发现列表、正式页面入口和连续办理界面。

## 2. 产品边界

1. 年度报告、中期评审和专项申报材料必须分别使用学校提供并确认的模板版本；
2. 报告数字只来自已经固定的事实快照，不能在编辑时修改目标值、正式进度和差距；
3. 材料必须选择确切版本和用途；
4. 缺事实、缺材料、缺模板说明或存在冲突时明确列出，不能提交正式审核；
5. 局部改稿只改所选章节，未选章节、人工保护内容和锁定事实保持不变；
6. 审核人必须是指定的教务审核人员，并与当前版本作者分离；
7. 正式 Word/PDF 只能来自被批准的确切版本；批准后再修改必须重新审核；
8. 归档要求同一批准版本同时具备正式 Word 和正式 PDF；归档不等于对外报送。

## 3. 页面结构

### 3.1 成果与报告工作台

开放左侧“成果与报告”入口，展示：

- 学校模板数量及当前版本；
- 可使用的事实快照数量和统计期间；
- 成果编制事项及其当前版本、缺项、审核状态、导出和归档状态；
- “建立成果编制事项”和“登记学校模板”入口；
- 负责人、教务审核人员看到各自获准读取和办理的内容。

### 3.2 建立成果编制事项

负责人依次选择：

1. 成果类型和学校模板当前版本；
2. 统计期间一致的事实快照；
3. 获准使用的材料版本、证据角色和用途；
4. 编制编号、标题和建立原因。

提交后，系统按模板形成章节初稿、事实引用、材料目录和缺项；不自动进入审核。

### 3.3 成果详情与编辑

详情页持续显示：

- 当前版本、审核状态和正式导出资格；
- 固定模板、事实快照、统计期间；
- 每个章节的正文、内容形式和事实引用；
- 支撑材料目录；
- 缺项和冲突；
- 版本、改稿、审核、导出和归档轨迹。

负责人可选择一个或多个章节进入改稿区。页面明确显示“本轮只修改这些章节”，把完整新正文和改稿说明提交给服务端。服务端继续负责保护人工内容和锁定事实。

### 3.4 审核、导出与归档

- 无缺项时，负责人指定一名教务审核人员提交当前版本；
- 指定审核人员进入同一详情页办理“退回修改”或“批准”；
- 退回必须填写原因和涉及章节；
- 草稿可按权限导出，页面显著说明不能正式提交；
- 正式导出按钮只在当前版本批准后出现；
- 同一版本正式 Word、PDF 均形成后才能归档；
- 导出文件显示文件名、格式、用途、建立时间和下载入口。

## 4. 最小接口增量

现有 W9-6 已具备全部详情和写接口，但缺少正式工作台所需的范围列表。新增三个只读列表：

1. `GET /reporting-snapshots`：返回当前范围的快照编号、期间、截止点和事实数量；
2. `GET /report-templates`：返回模板编号、成果类型、当前版本、适用期和章节数量；
3. `GET /deliverable-compilations`：返回成果编号、类型、当前版本、缺项数、审核状态、导出数和归档数。

列表复用现有 `reporting:read` 和 `deliverable:read` 权限。无权访问时返回空列表，不泄露数量。详情、改稿、审核、导出和归档接口保持不变。

## 6. 权限

1. 专业群负责人：登记模板、建立成果、改稿、提交审核、导出和归档；
2. 教务审核人员：读取模板和成果，只办理指定给本人的审核；
3. 教师和信息支持人员：首批不读取群级成果正文、数量和文件；
4. 全部对象继续按学校、专业群和建设周期隔离，前端隐藏不能替代服务端权限。

## 7. 自测门槛

### 7.1 自动验证

1. 三个列表接口在负责人和教务审核角色下返回当前范围内容；
2. 教师、信息支持和跨范围请求为零内容或不存在；
3. OpenAPI 路径数不变，操作数增加 3；
4. W9-4C—W9-6C 累积集成测试、全工程构建、类型检查和测试通过。

### 7.2 候选环境页面链

至少完成：

1. 从“成果与报告”查看模板、快照和现有成果；
2. 使用学校模板、已有事实快照和确切材料版本建立一项成果编制任务；
3. 核对章节中的“目标 3、正式确认 1、差距 2”来自快照，材料目录可回到版本；
4. 页面明确显示缺项；有缺项时审核入口不可用；
5. 对无缺项成果验证指定章节改稿、提交审核和审核状态；
6. 对已批准版本验证正式 Word/PDF 信息及归档状态；
7. 刷新页面后章节、版本、审核、文件和归档记录完整恢复。

如候选库没有适合重复办理的无缺项成果，可复用现有已批准归档对象验证读取链，并用新建成果验证写入、缺项和刷新；审核角色的决定继续由累积集成测试证明，不能伪造浏览器通过。

## 8. 风险控制

1. **模板替代风险**：页面只能选择登记在当前范围的学校模板版本；
2. **数字改写风险**：编辑页面不提供指标数字字段，章节锁定事实由服务端核对；
3. **作者自审风险**：审核人选择只列教务审核角色，服务端再次判断独立性；
4. **错误正式导出风险**：正式导出入口以服务端批准状态为准；
5. **旧批准沿用风险**：任何改稿形成新版本，页面状态回到草稿；
6. **下载与资料权利风险**：文件仍保存在学校控制的目录，下载继续经过当前身份和范围校验；
7. **对外报送误解**：归档页面明确说明没有代表学校向外部单位提交。

# W9 专业群知识库与智能体运行技术方案

> 版本：v1.0　日期：2026-10-18　状态：历史技术初稿，未经正式组织评审；作为第 122—128 份评审稿的详细参考。  
> 对应方案：02、03、15、16、23、29、38—40。

## 1. 技术目标

专业群知识库不是通用文件问答库。它要让智能体在指定学校、专业群、专业、建设周期、角色权限和任务目的内，使用经过确认的对象与关系完成查询和办理。

## 2. 知识形态

一次任务可使用的知识由四部分组成：

1. **结构化对象**：指标、任务、人员、材料状态、版本、截止时间和审核状态；
2. **确认关系**：依据来源、任务分解、材料支撑、成果引用、责任和替代关系；
3. **获准文本**：文件版本中允许当前角色和任务使用的条款、段落、表格和图片说明；
4. **运行规则**：指标规则版本、模板栏目、工作流状态和人工控制点。

智能体回答优先使用结构化对象和确定性计算；文本检索用于解释、引用和编制，不替代正式状态。

## 3. 知识进入流程

```text
学校侧收件
  → 原件保存、指纹和格式识别
  → 云端解析能力返回结构候选
  → 学校侧形成条款、表格、图片和候选关系
  → 人工确认、拒绝或标记冲突
  → 已确认内容形成知识版本
  → 建立全文、向量和关系索引
  → 任务按范围检索
```

解析失败、内容缺失、扫描质量差、重复和冲突都保留状态。没有人工确认的候选可以在整理工作区显示，但默认不进入正式指标和报告检索。

## 4. 索引设计

### 4.1 结构化索引

直接查询学校数据库中的对象、状态、版本、责任、时间和关系，适用于进度表、待办、统计和确定性判断。

### 4.2 全文索引

索引获准版本的标题、条款、正文和表格文本。索引项携带学校、专业群、专业、周期、对象、版本、敏感级别、有效期和权限策略。

### 4.3 向量索引

只保存学校侧生成的向量与片段引用。首期使用学校 PostgreSQL `pgvector`；向量记录不能脱离原对象权限单独返回。

### 4.4 关系索引

支持从指标追到依据、任务、责任人、材料、证据和成果，也支持从材料反查其用途、确认人、适用版本和受影响成果。

## 5. 检索顺序

```text
身份和任务范围
  → 结构化过滤
  → 确定性对象查询
  → 全文 / 向量候选召回
  → 关系扩展
  → 版本、有效期和权限二次过滤
  → 排序与去重
  → 形成带来源的任务知识包
```

禁止先做跨范围语义搜索再在结果页隐藏。无权内容不能进入候选、数量、排序或模型上下文。

## 6. 任务知识包

每个知识包固定：

- 任务编号和任务目的；
- 用户、角色和代理关系；
- 学校、专业群、专业和周期；
- 截止时间与规则版本；
- 已确认结构化事实；
- 获准文本片段及来源版本；
- 允许使用的模板；
- 未知、冲突、失效和待确认项；
- 允许调用的动作；
- 必须人工确认的停止点；
- 知识包摘要值和失效时间。

知识包建立后，若关键对象版本变化，任务进入“上下文已变化”，必须重新检查后继续。

## 7. 智能体运行状态

沿用 S0—S9 协议，并落实为持久状态：

| 状态 | 技术结果 |
| --- | --- |
| S0 收到请求 | 建立 `agent_task` 和原始请求版本 |
| S1 识别范围 | 固定学校、群、专业、周期、角色和用途 |
| S2 理解任务 | 形成结构化任务意图和期望输出 |
| S3 检查条件 | 列出已有、缺失、冲突和需确认内容 |
| S4 拟定计划 | 形成步骤、能力、输入、停止点和预期写入 |
| S5 人工确认 | 保存批准、调整或拒绝决定 |
| S6 执行动作 | 每个动作独立幂等、带范围和回执 |
| S7 检查结果 | 校验引用、事实、格式、权限和影响对象 |
| S8 人工确认结果 | 用户确认草稿、关系或拟写入结果 |
| S9 写回与结束 | 学校侧事务写入版本、关系和账本 |

暂停、失败、转交和取消是正式状态，不用聊天文本代替。

## 8. 能力单元

| 能力编号 | 能力 | 只读/写候选 | 正式写入条件 |
| --- | --- | --- | --- |
| AC01 | 对象与关系查询 | 只读 | 无 |
| AC02 | 文档解析与结构提取 | 候选 | 人工确认吸收范围 |
| AC03 | 材料整理与格式转换 | 候选 | 用户确认结果版本 |
| AC04 | 候选分类与重复识别 | 候选 | 负责人逐项确认 |
| AC05 | 计划与任务建议 | 候选 | 负责人确认派发 |
| AC06 | 进度确定性计算 | 计算结果 | 负责人确认正式结论 |
| AC07 | 缺项与补充任务建议 | 候选 | 负责人确认建任务 |
| AC08 | 总结、报告与申报草稿 | 候选 | 审核通过并形成正式版本 |
| AC09 | 局部改稿与版本差异 | 候选 | 审核新版本 |
| AC10 | 知识影响分析 | 只读/候选 | 负责人确认处理方案 |
| AC11 | 导出候选件 | 候选 | 正式成果版本和导出权限 |

T01—T18 通过这些公共能力编排，不为每个任务建立独立的不可复用智能体。

## 9. 动作调用协议

云端动作请求只包含：

- `action_id`、`capability`、`purpose`；
- 一次性范围证明和过期时间；
- 学校侧匿名对象引用；
- 本次获准的最小内容；
- 输入版本摘要和期望输出结构；
- 幂等键、超时和取消标识。

响应必须包含：

- 结果状态；
- 结构化输出；
- 每项结论的来源引用；
- 未知、冲突和缺项；
- 建议写入及影响对象；
- 处理版本、耗时和回执摘要；
- 是否需要人工确认。

响应不直接取得学校侧写权限。

## 10. 提示与资料安全

学校文件、网页、聊天和模板均视为业务资料，不视为智能体运行指令。解析内容中的“忽略规则”“导出全部资料”等文本不得改变任务范围、工具权限或停止点。

系统级约束、能力合同和学校侧授权由程序传入，不与资料正文混在同一可覆写字段。工具参数由结构化计划生成并经服务校验，不能由模型任意拼接对象编号或范围。

## 11. 连续问答

后续追问绑定原任务、范围和知识快照。用户改变专业群、周期、报告模板、统计口径或写入目的时，建立新范围版本并重新确认，不能沿用旧权限或旧截止点。

宽泛问题先返回：建设周期、资料更新时间、总体进度、重点成果、主要差距、近期任务和未知项，再允许下钻专业、教师、指标或材料。

## 12. 停止与失败规则

智能体在以下情况停止并说明所需条件：

- 无权限或范围不明；
- 缺正式模板、规则版本或必要资料；
- 多份依据冲突；
- 关键对象版本已经变化；
- 动作结果未知；
- 云端服务不可用或响应结构不合格；
- 请求要求替代审核、验收或正式批准；
- 请求超出专业群建设范围。

结果未知时使用同一操作标识只读对账，不能生成新标识重复写入。

## 13. 质量验证

### 13.1 检索验证

- 正确范围召回；
- 无权资料零泄露；
- 版本和有效期正确；
- 来源可以回到对象、版本和位置；
- 未知和冲突不会被总结成确定事实。

### 13.2 任务验证

- T01—T18 每项至少一条正常、缺资料、越权和版本变化用例；
- 人工控制点不能通过直接接口跳过；
- 写回后的对象、版本、关系和账本一致；
- 报告改稿保持锁定事实不变；
- 多轮问答的统计截止点和数字一致。

### 13.3 云端数据边界验证

- 云端日志不出现学校正文、文件名、人员姓名和指标内容；
- 调用完成后临时内容按策略清理；
- 学校侧停用云能力后仍能访问和导出自己的既有数据；
- 更换云端能力版本不会改变已归档结果。

## 14. 当前结论

本方案完成知识检索和智能体运行的技术边界。向量模型、解析能力、生成模型、上下文上限、云端临时缓存时限和质量阈值仍需通过合成数据与学校批准样例评测后确定。当前为“已设计”。

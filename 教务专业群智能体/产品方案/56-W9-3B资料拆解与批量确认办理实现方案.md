# W9-3B 资料拆解与批量确认办理实现方案

> 版本：v1.0　日期：2026-10-18　状态：编码基线。  
> 前置条件：W9-3A 已验证。  
> 对应任务：T01、T05，支撑 T02、T03、T04、T06、T09、T13。  
> 数据边界：只使用合成材料和确定性拆解夹具；外部智能能力、真实学校资料和向量检索保持关闭。

## 1. 本波要解决的问题

W9-3A 已能把人工录入的原文条款变成候选关系和正式知识，但尚未承载学校一次性交接或日常提交的大量资料。W9-3B 要把材料版本组织成可以连续办理、可以看到失败和缺项、可以批量核对的吸收流程：

```text
建立资料批次
  → 固定本次材料版本
  → 登记格式和读取结果
  → 拆成带原文位置的内容单元
  → 形成缺项、重复和待整理项
  → 负责人批量接受、拒绝或退回
  → 已确认内容单元进入 W9-3A 条款候选链
```

“上传成功”“可以预览”“已经拆解”“已经确认”“已经发布”是五个不同状态。本波不得把其中任何前置状态显示为正式知识完成。

## 2. 产品对象

### 2.1 资料吸收批次

批次记录批次编号、提交目的、预期用途、资料类型、可见范围、是否允许临时处理、负责人和当前版本。批次版本保存办理状态：草稿、接收中、拆解中、待确认、已收口、失败、归档。

批次收口只表示本批资料已经处理到明确去向，不表示其内容已经发布为正式知识。

### 2.2 批次材料项

一个批次材料项固定一个 `material_version_id`，不得在后台悄悄切换到材料的新版本。材料项版本保存：

- 文件类型：文档、表格、图片、扫描件、模板、聊天摘录或其他；
- 读取状态：已登记、完整可读、部分可读、无法读取、需人工录入、受限；
- 拆解状态：未开始、已拆解、待确认、已确认、已退回；
- 处理说明、失败原因和下一步动作；
- 当前内容单元、缺项和重复候选数量。

材料新版本需要作为新的批次材料项进入，不覆盖旧批次的输入快照。

### 2.3 内容单元

内容单元固定材料版本和材料项版本，类型包括章节、条款、段落、表格、表格行、单元格、图片区域、聊天摘录和其他。每项保存：

- 页码、章节、表格、工作表、行列、段落或图片区域等原文位置；
- 提取文本和摘要值；
- 拆解方式：人工录入、确定性夹具、受控动作结果；
- 置信说明，不使用单一分数代替人工判断；
- 状态：候选、已确认、已拒绝、已退回；
- 确认人、理由和时间。

本波的确定性夹具只用于验证产品链。`action` 类型必须保持关闭，直到动作网关和数据清理验证完成。

### 2.4 缺项

缺项类型包括批准状态、业务日期、责任人员、原文位置、证据、专业归属、适用周期和其他。缺项可以处于待补、已解决或经负责人明确豁免状态。解决和豁免均需说明，不能通过删除缺项制造“全部完成”。

### 2.5 重复候选

重复候选分为相同文件、相同版本、相同成果、相关但不同四级。系统或规则只能提出候选，负责人确认“重复”或“不是重复”。即使确认重复，两个原件和其历史用途仍保留；本波不执行成果计数。

### 2.6 批量核对记录

一次批量核对固定内容单元编号和各自预期状态。负责人可以批量接受、拒绝或退回，但每项保留独立决定。任一对象状态已变化时整批拒绝，不做部分成功，避免用户误以为整批已处理。

## 3. 与 W9-3A 的连接

`basis_clause_versions` 增加可选的 `source_content_unit_id`。使用内容单元建立条款候选时必须满足：

1. 内容单元已经人工确认；
2. 内容单元、建设依据及其材料版本属于同一学校、专业群和周期；
3. 内容单元引用的材料版本与该依据版本引用的材料版本一致；
4. 条款原文摘录和位置必须来自该内容单元，接口不接受调用方另行替换；
5. 后续候选确认和正式发布仍沿用 W9-3A，不因内容单元已确认而自动发布。

由此形成两个人工控制点：先确认“拆解内容是否忠实”，再确认“它与建设要求的关系及正式用途是否正确”。

## 4. 接口切片

| 接口 | 作用 | 关键约束 |
| --- | --- | --- |
| `POST /ingestion-batches` | 建立资料吸收批次 | 负责人明确用途与临时处理边界 |
| `POST /ingestion-batches/{id}/items` | 将材料版本固定到批次 | 只能引用同范围材料版本 |
| `POST /ingestion-items/{id}/results` | 写入读取状态、内容单元、缺项和重复候选 | 使用当前材料项版本；一次事务写入 |
| `GET /ingestion-batches/{id}` | 查看五层状态及异常分类 | 无权时不泄露标题、数量或状态 |
| `POST /ingestion-content-reviews` | 批量接受、拒绝或退回内容单元 | 所有单元仍为预期状态才提交 |
| `POST /ingestion-missing-items/{id}/decisions` | 解决或豁免缺项 | 必须记录理由 |
| `POST /ingestion-duplicate-candidates/{id}/decisions` | 确认或拒绝重复候选 | 不删除任何材料或历史关系 |
| `POST /basis-documents/{id}/clauses` | 从已确认内容单元建立 W9-3A 候选 | 原文和位置由内容单元固定 |

所有写操作继续使用统一写入信封、幂等键、人工决定、建设账本和 Outbox。

## 5. 状态看板口径

批次详情同时返回以下独立数字：

- 已登记材料数；
- 完整/部分可读材料数；
- 无法读取、需人工录入和受限材料数；
- 已拆解材料数和内容单元数；
- 待确认、已确认、已拒绝和已退回内容单元数；
- 待补缺项数；
- 待处理重复候选数；
- 待处理依据冲突数。

看板不提供一个掩盖异常的“总完成率”。批次只有在每个材料项都有明确读取结果、内容单元都有去向、缺项和重复候选都有处理状态后，才允许收口；本切片先实现状态汇总，不开放自动收口。

## 6. 权限

- 教师可建立本人材料的资料批次和查看本人范围内结果；本切片先只开放负责人办理，教师入口在 T01/T04 工作流中接入。
- 专业群负责人可建立批次、加入材料、录入确定性拆解结果和完成人工决定。
- 教务审核人员可查看批次与内容，但不能替负责人完成本切片的批量确认或发布。
- 信息支持人员只看运行健康，不可查看批次是否存在、批次数量、材料标题、拆解文本或异常内容。

## 7. 合成验收链

1. 建立一个“首批建设依据交接”批次。
2. 加入建设任务书文本材料、扫描件材料和一份内容相同的副本，固定各自材料版本。
3. 文本材料登记为完整可读，拆出章节、指标表行和证据要求三个内容单元，同时形成“缺批准状态”缺项。
4. 扫描件登记为无法读取，保存失败原因和“需人工录入”下一步，不生成伪内容。
5. 副本登记为完整可读并形成“相同文件”重复候选。
6. 看板分别显示已登记、可读、无法读取、待确认、缺项和重复候选，不把失败并入完成。
7. 负责人批量接受两个内容单元、退回一个；再次使用旧预期状态提交整批时拒绝且不部分写入。
8. 负责人解决缺项，确认重复候选；两个材料原件仍存在。
9. 用已确认指标表行建立 W9-3A 条款候选；若使用待确认或被退回单元则拒绝。
10. 信息支持人员、另一专业群及直接猜测编号均无法看到批次、数量和文本。
11. 每次写入可由操作回执、建设账本和 Outbox 回查。

## 8. 自测门槛

- 空库迁移、重复迁移和外键范围约束通过；
- 批次输入固定材料版本，材料换版不改变既有批次；
- 六种读取状态和四种内容审核状态均有运行用例；
- 无法读取时保留原件和明确下一步，不产生内容单元；
- 批量决定全成全败，旧状态不会部分写入；
- 缺项和重复只能经人工决定关闭；
- 重复确认不删除材料；
- 只有已确认内容单元能进入 W9-3A，且原文位置不可由请求伪造；
- 跨范围和信息支持零泄露；
- 现有 W9-0 至 W9-3A 回归通过；
- 契约、实现状态、验证记录和代码一致。

## 9. 明确不在本切片宣称的能力

- Word、PDF、Excel、图片和扫描件真实解析质量；
- OCR、公式解析、表格视觉理解和聊天自动采集；
- 云端动作调用与临时内容清理；
- 全文排序、关系遍历和向量检索；
- 任务、指标计算、成果计数和报告生成；
- 学校正式身份、部署、对象存储和备份平台验收。

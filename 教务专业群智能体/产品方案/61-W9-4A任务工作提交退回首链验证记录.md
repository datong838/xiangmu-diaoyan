## 1. 已验证办理链

以“推进 B 企业正式签约”为同一事项，实际完成：

```text
已发布指标要求
  → 负责人建立任务草稿
  → 派发给李老师
  → 李老师填写工作记录
  → 关联协议草稿并提交 v1
  → 负责人退回，要求补正式协议和签订日期
  → 李老师形成工作记录 v2
  → 关联正式协议并提交 v2
  → 负责人确认工作事实并完成任务
```

任务保留 `draft → assigned → in_progress → submitted → returned → in_progress → submitted → completed` 八个版本状态。v1、退回意见、草稿材料、v2 和正式材料均可回看，没有覆盖前一版本。

## 2. 已证明的产品约束

1. 任务只能从已经发布的正式建设要求建立；
2. 负责人建立、派发和审核，责任教师填写与提交，教务审核人员只读，信息支持人员看不到任务数量和正文；
3. 专业范围教师还必须是任务责任人，其他同专业教师不能看到或办理；
4. 每次提交固定任务版本、工作记录版本和材料版本；
5. 旧任务版本提交、旧版本审核和重复审核被拒绝；
6. 同一幂等请求返回同一回执，不重复建立任务；
7. 退回必须写明原因和补充要求；
8. 确认完成的回执明确 `indicatorProgressChanged=false`，任务完成没有修改指标正式进度；
9. 每个关键动作同步写入建设账本和 Outbox。

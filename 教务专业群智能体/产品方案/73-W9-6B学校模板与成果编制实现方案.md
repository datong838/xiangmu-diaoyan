# W9-6B 学校模板、成果编制任务、章节引用与缺项实现方案

> 版本：v1.0　日期：2026-10-18　状态：编码前冻结稿。  
> 对应任务：T13，并为 T14 提供受控改稿基线。  
> 前置：第 13、14、22、39、41、42、71、72 份方案与记录。  
> 本文职责：把学校提供的最终文档模板，与 W9-6A 已确认事实快照、支撑材料和待补内容组成一项可继续办理的成果编制任务。

## 1. 目标

W9-6B 建立以下产品链：

```text
学校提供最终文档模板
  → 登记模板 v1 与章节要求
  → 选择 W9-6A 事实快照
  → 选择获准使用的支撑材料版本
  → 建立成果编制任务
  → 按章节形成可编辑初稿
  → 每段事实绑定快照事实编号
  → 形成支撑材料目录
  → 显式列出缺事实、缺材料和缺模板说明
```

成果编制不重新计算指标。报告中的目标值、确认完成值、差距、任务状态和截止点，必须来自所选事实快照。没有正式模板时只能登记缺项，不能把服务方自设结构标记为学校正式成果。

## 2. 首批成果类型

- `annual_report`：年度建设报告；
- `midterm_review`：中期评审材料；
- `application_material`：学校已提供正式申报通知与模板的申报材料。

不同成果类型必须使用各自模板版本。年度报告模板不能替代中期评审或专项申报模板。

## 3. 对象

### 3.1 模板

- `report_templates`：稳定模板编号、成果类型、学校、专业群、建设周期、当前版本和建立人；
- `report_template_versions`：模板名称、说明、适用期间、版本号、变更原因和内容摘要；
- `report_template_sections`：章节编码、标题、顺序、是否必填、内容形式、所需事实种类和填写说明。

模板版本建立后不可修改。学校更新模板时建立新版本，旧成果继续引用旧模板版本。

### 3.2 成果编制

- `deliverable_compilations`：稳定编制任务编号、成果类型、模板版本、事实快照、期间、当前版本、建立人；
- `deliverable_compilation_versions`：版本号、状态、结构化摘要、变更原因、作者和内容摘要；
- `deliverable_sections`：按模板固定的章节草稿，保存章节编码、标题、生成方式、正文和内容摘要；
- `deliverable_section_facts`：章节使用的事实编号及用途；
- `deliverable_support_materials`：明确选入的材料版本、用途和证据角色；
- `deliverable_missing_items`：缺事实、缺材料、缺模板说明或待解决冲突。

本波只建立 v1 编制稿。W9-6C 才增加指定范围改稿、人工保护块、版本差异、独立审核和正式导出。

## 4. 确定性章节形成规则

模板章节明确需要哪些事实种类：

- `indicator_progress`：形成指标目标、负责人确认实际、差距和截止点；
- `indicator_gap`：形成差距原因与后续措施；
- `task_status`：形成各任务当前状态、责任对象、截止时间和过程数量；
- `support_materials`：形成支撑材料目录，只列学校明确选入的材料版本。

章节正文由结构化事实确定性拼装，并保留事实编号。章节没有所需事实时保持空白并建立缺项，不能用推测补齐。材料目录只列标题、版本、用途和证据角色，不把材料正文复制进编制记录。

## 5. 缺项规则

| 缺项类型 | 形成条件 |
| --- | --- |
| `missing_fact` | 必填章节要求的事实种类在快照中不存在 |
| `missing_material` | 必填材料目录没有选入支撑材料 |
| `missing_template_instruction` | 模板章节没有填写说明或所需事实口径 |
| `unresolved_conflict` | 所选事实或正式知识仍存在未解决冲突 |

缺项在本波只负责显式呈现。补充材料、重建快照或更新模板后，应建立新的成果版本；该版本化处理进入 W9-6C，不能直接覆盖 v1。

## 6. 权限与边界

- 专业群负责人：登记模板及版本、建立成果编制任务、选择支撑材料；
- 教务审核人员：读取模板、编制稿、引用、材料目录和缺项，不得建立或改写；
- 教师：本波不读取群级成果编制任务；后续按章节协作范围单独设计；
- 信息支持人员：不见模板名称、成果标题、章节、材料目录、缺项数量或正文；
- 模板、快照、材料和成果必须属于同一学校、专业群和建设周期；
- 外部智能服务保持关闭，首批章节由学校侧确定性规则形成；
- 编制稿不是正式报告，任何接口都不得返回“已批准”或“可正式导出”。

## 7. 接口

| 接口 | 行为 |
| --- | --- |
| `POST /report-templates` | 登记学校模板 v1 与章节要求 |
| `POST /report-templates/{templateId}/versions` | 基于当前模板版本建立新版本 |
| `GET /report-templates/{templateId}` | 查看模板版本及各版章节 |
| `POST /deliverable-compilations` | 选择模板版本、事实快照和材料版本建立编制任务 v1 |
| `GET /deliverable-compilations/{compilationId}` | 查看成果任务、章节、事实引用、材料目录与缺项 |

所有写入继续使用统一操作信封、范围、期望版本、幂等键、回执、建设账本和 Outbox。

## 8. 状态与停止规则

- 模板 v1 建立后状态为 `active`；建立新版时旧版保持只读；
- 成果编制 v1 状态为 `draft`；有缺项时同时返回 `hasMissingItems=true`；
- 成果类型必须与模板成果类型一致；
- 编制期间必须落在事实快照期间内，并首批要求完全一致；
- 模板版本、快照或材料跨范围时按不存在处理；
- 模板章节编码重复、顺序重复、没有章节或章节要求不完整时拒绝；
- 必填章节无事实时建立缺项，不伪造正文；
- 旧模板版本不能被更新；建立新版必须提供当前版本编号；
- 同一幂等请求不重复建立模板、版本或成果任务；
- 编制确认、独立审核和正式导出接口在本波不存在。

# W9-7 选配事项、实践项目、多专业群复制与恢复分段实现方案

> 本文职责：把 W9-7 拆成可独立验证的工程段，避免把实践项目、多群复制、选配开关和恢复验证混成一次大改。

## 1. 本波目标

W9-7 验证两项产品能力和一项运行保障：

1. 一项真实生产或实训工作，能够以资料和人工事实进入专业群建设链，形成可审核案例，但不替代实操、检测和验收；
2. 一个新专业群能够复用对象结构、办理流程和模板结构，重新登记自己的依据、专业、人员、权限与指标，并证明没有复制原群事实；
3. 数据库、学校侧文件和实现状态可按同一恢复清单核对，故障与重复执行不造成重复正式记录或不可解释状态。

本波不启用 T15 教学检查和 T16 考试事项。系统只登记两项能力为“未启用”，不建立教师待办、不暴露试卷正文接口、不把原型页面当作已实现功能。

## 2. 分段实施

### W9-7A 实践项目与案例首链

覆盖 T17，形成：

```text
教师建立实践项目草稿
  → 分批关联现有材料版本和参与关系
  → 登记人工检测或验收结果候选
  → 专业群负责人核对项目身份、人数、活动次数和建设任务关系
  → 原责任人确认人工结果
  → 助手按已确认事实形成案例草稿和支撑材料目录
  → 审核后形成案例版本
```

首批只管理已发生事实和已存在材料，不连接生产设备，不自动评分，不自行判断验收通过，不直接增加指标正式值。

### W9-7B 新专业群初始化与隔离

覆盖 T18，形成：

```text
选择一个已验证群作为结构参考
  → 建立新群初始化草稿
  → 选择可复用流程、模板结构和角色类型
  → 明确列出禁止复制的事实与授权
  → 新群登记独立周期、专业、人员、依据和指标
  → 执行跨群搜索、查询、报告、导出和智能体隔离检查
  → 新群负责人确认后启用
```

复用记录只保存“参考了什么结构及哪个版本”，不复制申报书正文、任务书正文、人员、企业、目标值、完成值、材料、权限、审核决定、报告和历史对话。

### W9-7C 恢复清单与故障验证

为一个学校范围形成恢复清单，固定：数据库迁移版本、对象数量、当前版本摘要、关系数量、文件清单与 SHA-256、账本边界和实现状态。恢复只在隔离环境执行，恢复后重新核对同一清单；RPO、RTO 仍由学校在试点前确认，系统不预填承诺值。

## 3. W9-7A 产品对象

- `practice_projects`：项目范围根，含学校、专业群、周期和可选专业；
- `practice_project_versions`：名称、合作单位、起止日期、活动次数、参与人数、公开范围、状态、变更原因和作者；
- `practice_project_versions` 中的参与汇总：首批分别保存学生人数和教师人数，不建立学生身份库；参与办理人员继续通过责任人和操作记录表达；
- `practice_project_materials`：关联现有材料版本、材料用途和过程阶段；
- `practice_result_candidates`：人工检测、交付、验收或企业评价的原责任人、结论、日期和材料依据；
- `practice_result_decisions`：由原责任人确认或退回候选结果；
- `practice_construction_links`：负责人确认项目与现有任务、要求或成果的关系；
- `practice_case_compilations`、`practice_case_versions`：固定已确认事实和材料形成案例草稿及审核版本；
- `practice_case_citations`：案例内容到项目版本、人工结果、材料和建设关系的引用。

所有确认、版本、引用和关系均追加保存。人数、活动次数、企业数分开表达；实践项目不得直接写入指标确认表。

## 4. W9-7A 角色和动作

- 教师：建立本人负责的实践项目草稿，补充项目版本、材料和参与汇总；只能确认由自己负责的人工结果；
- 专业群负责人：核对项目事实、参与汇总、活动次数和建设关系，发起案例编制；不能代替人工检测责任人确认检测结果；
- 教务审核人员：审核案例版本，不能修改原项目事实或材料；
- 信息支持人员：只看运行健康和恢复清单技术结果，不见项目名称、人员、企业、材料和案例正文；
- 专业群智能体：整理已确认项目事实、检查缺项、形成案例草稿和支撑目录；缺少验收时明确标记，不能写成已验收。

## 5. W9-7B 复制硬约束

1. 初始化必须建立新专业群标识和新建设周期，不能复用源群编号；
2. 可复用项使用白名单：对象结构、流程编码、模板章节结构、角色类型和验收脚本；
3. 禁止项使用黑名单并由服务端复核：业务正文、人员、企业、目标、进度、材料、权限、审核、成果、对话；
4. 新群未完成依据、专业关系、负责人和查看范围配置时保持草稿；
5. 启用前运行跨群零泄露检查，至少覆盖列表、详情、搜索、助手、数量、下载、报告和导出；
6. 同一人员兼任两群时，每次请求仍必须携带并校验当前群与周期；
7. 源群模板后续变化不自动覆盖新群已确认模板版本；
8. 源群归档或停用不改变新群状态。

## 6. T15/T16 关闭状态

实现状态明确保存：

- `teachingInspectionEnabled=false`；
- `examWorkflowEnabled=false`；
- 不登记相关业务路由；
- 未实现路由继续返回不存在，不返回演示成功；
- 教师待办和验收统计均不出现 T15/T16；
- 后续只有在学校确认范围、责任人、材料、敏感正文和验收口径后，才能另立方案开启。

## 7. 分段通过门槛

### W9-7A

1. 项目、参与汇总、材料、人工结果和建设关系分别保存且可追溯；
2. 缺验收材料时案例明确显示缺项，不得写成已验收；
3. 20 名学生、2 名教师、1 次活动和 1 家企业分别表达，不互相代替；
4. 人工检测或验收只能由原责任人确认；
5. 案例引用固定项目版本和材料版本，后续修改不覆盖旧案例；
6. 案例审核与作者分离，未通过版本不能作为正式成果输入；
7. 指标“目标 3、完成 1、尚差 2”不因建立实践案例而变化；
8. 教师、负责人、审核人和信息支持的范围拒绝符合方案。

### W9-7B

1. NEW-G02 可建立独立周期和专业关系；
2. 初始化记录能说明复用了哪些结构及版本；
3. NEW-G02 中没有 A—D 企业、张老师、目标 3、完成 1 或原群报告内容；
4. 八个入口的跨群访问均为零泄露；
5. 新群未满足配置时不能启用；
6. 新群启用、源群归档及模板后续变化相互独立。

### W9-7C

1. 空库迁移和重复迁移通过；
2. 在隔离目标上恢复数据库和学校侧文件；
3. 恢复前后对象数量、当前版本、关系、文件摘要、账本边界和实现状态一致；
4. 缺文件、摘要不符、迁移不符或清单不完整时恢复核对失败；
5. 信息支持只能看到技术核对项，不见业务正文。

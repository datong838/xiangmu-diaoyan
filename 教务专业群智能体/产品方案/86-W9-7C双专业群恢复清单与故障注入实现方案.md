# W9-7C 双专业群恢复清单与故障注入实现方案

> 版本：v1.1　日期：2026-10-19　状态：已按方案实现并通过合成环境验证，结果见第 87 份记录。  
> 前置：第 42、52—53、77、82—85 份方案与记录。  
> 本文职责：把 W9-7C 的恢复对象、恢复清单、访问凭证处置、核对算法、故障注入和通过门槛冻结为可执行方案。

## 1. 要解决的问题

W9-2 已经证明单批材料的数据库记录与学校侧文件可以共同恢复，但专业群工作站现已包含两个专业群、多个建设周期、组织权限、依据、知识、任务、智能体、报告、成果、实践案例和跨群隔离证据。只检查“文件还在”已不足以说明工作站恢复完成。

W9-7C 要证明：一个学校的数据库与学校侧文件恢复到隔离环境后，各专业群仍保持原来的对象范围、当前版本、事实关系、文件内容、建设账本和实现状态；恢复出来的旧登录会话与旧文件访问票据不能继续使用；任何关键差异都会阻止恢复环境启用。

## 2. 产品边界

本波实现恢复清单的生成、恢复后只读核对、恢复目标访问凭证失效处理和一次性故障演练，不建设正式备份调度平台，不承诺未经学校确认的 RPO、RTO，也不接入真实学校备份设施。

恢复清单只包含技术标识、数量、摘要和状态，不包含学校材料正文、报告正文、人员姓名、企业名称或原始文件名。信息支持人员可据此判断恢复是否完整，但不能借恢复清单读取业务内容。

## 3. 一体恢复对象

一次恢复必须把以下内容视为同一份学校工作空间：

1. 数据库迁移及其校验值；
2. 一个学校下全部专业群和建设周期的业务记录；
3. 各对象的当前版本指针与历史版本；
4. 组织、角色、授权范围和跨群隔离验证记录；
5. 依据、知识、任务、工作记录、指标、成果、实践项目和智能体办理记录之间的关系；
6. 学校侧全部已登记文件及其字节数和 SHA-256；
7. 建设账本首尾边界和完整链摘要；
8. 当前实现状态；
9. 登录会话和文件访问票据的安全处置结果。

索引、缓存和派生展示可以重建，但不能替代上述事实和证据。

## 4. 恢复清单结构

恢复清单采用 `professional-group-recovery-manifest/v1`，包括：

- `schoolId`：本次恢复的学校范围；
- `migrations`：已应用迁移名称与文件校验值；
- `implementationState`：实现状态及其摘要；
- `databaseTables`：除访问凭证表外全部业务表的记录数和整表摘要，用于覆盖通过父对象归属学校、但自身没有 `school_id` 的章节、引用和探针明细；
- `schoolTables`：所有带 `school_id` 表在该学校范围内的记录数和整表摘要；
- `scopes`：每个“专业群 + 建设周期”下各表的记录数和摘要；
- `currentPointers`：所有当前版本指针的数量和摘要；
- `relationships`：关系、引用、分工、支撑和授权类表的数量和摘要；
- `files`：技术存储键、字节数和 SHA-256；
- `ledgerBoundary`：账本数量、首条、末条和完整链摘要；
- `isolationEvidence`：八入口隔离核对数量、通过数量和摘要；
- `credentialBaseline`：会话与文件票据总数及源端活动数量，只用于恢复后安全处置核对；
- `manifestDigest`：除生成时间和自身摘要外，其余内容的规范化整体摘要。

整表摘要由数据库行的规范化表示计算，但清单只保存摘要，不输出行内容。全库摘要保证子表不漏项，学校与专业群周期摘要用于确认范围边界；表、范围、文件和迁移均按稳定顺序排列，重复生成可用于判断事实是否变化。

## 5. 恢复流程

```text
冻结源学校写入
  → 生成并封存恢复清单
  → 导出数据库
  → 复制学校侧文件
  → 在隔离目标恢复数据库与文件
  → 运行迁移一致性检查
  → 使恢复出的旧会话和旧文件票据全部失效
  → 按恢复清单重新计算并核对
  → 执行双专业群范围与八入口隔离复核
  → 核对通过后形成恢复演练证据
```

恢复目标的访问凭证失效属于允许的安全变化。清单不要求 `revoked_at` 与源端相同，但要求会话和票据记录身份集合未丢失、恢复后活动数均为 0。后续验证只能建立恢复环境专用的新会话。

## 6. 核对规则

恢复核对必须同时满足：

1. 清单格式完整且整体摘要正确；
2. 本地迁移文件、源端已应用迁移和恢复库迁移三者名称及校验值一致；
3. 实现状态与源清单完全一致，且 `recoveryManifestEnabled` 只在本波整体验证后开启；
4. 学校表、专业群周期表、当前版本指针和关系摘要完全一致；
5. 文件无缺失、无多余、无字节数差异、无 SHA-256 差异、无暂存残留和软链接；
6. 建设账本数量、首尾边界和完整链摘要一致；
7. 隔离验证记录完整且最后一次八入口验证为全部通过；
8. 恢复出的旧会话和旧文件访问票据均不可继续使用；
9. 恢复目标只读核对不修改业务对象、版本、关系或账本。

任一项不满足，结果为失败，输出差异类别和技术标识，不输出业务正文。

## 7. 双专业群复核

恢复完成后，以同一名兼任两个专业群的合成人员建立恢复环境专用会话，明确携带目标专业群和周期重新核对：

- 专业群详情；
- 知识查询；
- 专业群助手；
- 统计数量；
- 材料访问；
- 报告；
- 导出；
- 建设账本。

每个入口既要证明本群内容可用，也要证明把源群对象带入目标群时被拒绝或零召回。恢复清单一致不能替代这项业务范围复核。

## 8. 故障注入

故障只在一次性合成恢复环境执行，至少覆盖：

| 故障 | 预期结果 |
| --- | --- |
| 删除一个已登记文件 | 报告缺失文件并失败 |
| 改写一个文件但保持路径不变 | 报告字节数或 SHA-256 不一致并失败 |
| 删除或改写一个迁移清单项 | 报告迁移不一致并失败 |
| 删除恢复清单必填段或改写摘要 | 报告清单不完整或整体摘要错误并失败 |
| 未执行恢复目标访问凭证失效 | 报告活动会话或活动票据仍存在并失败 |
| 尝试用恢复前旧票据读取文件 | 返回拒绝，不产生新的业务账本记录 |
| 中断初始化或只恢复数据库不恢复文件 | 保持未通过，不允许把目标标为可用 |
| 八入口任一项跨群泄露 | 整体恢复验证失败 |

每项注入后重建干净恢复目标，不在异常状态上叠加下一项结论。

## 9. 程序结构

在 `packages/db` 增加：

- 恢复清单规范化、摘要、生成和核对核心；
- `recovery:manifest:create` 只读生成命令；
- `recovery:reset-access` 恢复目标专用凭证失效命令；
- `recovery:manifest:verify` 只读核对命令；
- 清单完整性、篡改、缺文件和文件被改的自动测试。

在 `apps/api/scripts` 增加一次性恢复环境业务复核脚本，复用现有 API 和八入口隔离能力，不增加第二套业务判断。

命令必须显式提供数据库、绝对文件根目录、学校标识和清单路径。凭证失效命令还必须同时提供 `RECOVERY_TARGET_CONFIRM=ISOLATED_RESTORE` 与 `RECOVERY_SECURITY_RESET_CONFIRM=REVOKE_RESTORED_ACCESS`，否则拒绝执行。

## 10. 迁移与实现状态

本波只在功能与故障验证全部通过后增加状态迁移：

```json
{
  "phase": "W9-7C-verified",
  "recoveryManifestEnabled": true
}
```

恢复清单本身保存到受控证据目录，不写入业务表，避免“为证明恢复而改变被恢复事实”。状态迁移进入源库后，必须重新生成最终清单并再完成一次全新恢复验证。

## 11. 通过门槛

1. 空库迁移和重复迁移通过；
2. 含两个专业群的同一学校数据库及文件恢复到新的隔离目标；
3. 清单所有技术核对项一致；
4. 恢复前旧会话和旧票据失效，恢复专用新会话可按权限工作；
5. 八入口本群可用、跨群拒绝或零召回；
6. 七类故障均被准确识别并失败关闭；
7. 生成和核对输出不含业务正文、人员姓名、企业名称和原始文件名；
8. 全量构建、类型检查、数据库测试、领域测试、API 测试和项目基线检查通过；
9. 方案、代码、验证记录、持续目标清单和实现状态一致。

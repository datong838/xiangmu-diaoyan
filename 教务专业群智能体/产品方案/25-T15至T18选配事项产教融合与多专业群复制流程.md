# T15—T18 选配事项、产教融合与多专业群复制流程

> 版本：v1.0　日期：2026-10-18　状态：内部评审稿。  
> 对应波次：W7。  
> 文档职责：把教学检查、考试事项、真实生产实训资料和多专业群初始化转换为可办理、可确认、可隔离的产品流程，同时明确未确认范围不得成为默认承诺。

## 1. 产品目标与范围门槛

T15—T18 不属于同一种业务，但共同承担“补齐选配场景并验证产品可推广”的作用：

1. T15、T16 先保留产品位置，是否进入首期由学校确认；
2. T15 只处理已有人工检查、评价和整改记录，不生成教学评价；
3. T16 只跟踪出卷事项和人工审核，是否保存试卷正文需另行确认；
4. T17 只归集真实生产与实训过程材料，不替代实操、检测、验收，也不控制生产设备；
5. T18 复制对象结构、流程、模板和配置方法，不复制试点群的业务事实。

每项功能启用前都必须有范围配置。未启用的功能不显示为教师待办，也不进入验收统计。

## 2. 页面与工作区

| 页面 | 主要对象 | 关键写操作 |
| --- | --- | --- |
| 选配能力设置 | 能力开关、适用专业、资料范围、负责人、验收口径 | 申请启用、确认范围、停用、变更范围 |
| 教学检查归集台 | 人工检查记录、听评课记录、问题、整改反馈 | 登记、整理、关联、确认问题、关闭整改 |
| 考试事项跟踪台 | 出卷任务、要求、节点、提交记录、人工审核意见 | 新建、提交、退回、补充、审核确认 |
| 产教融合案例工作台 | 实践项目、参与人、过程记录、标准、检测/交付结果 | 归集、补充、确认、关联建设任务、形成案例 |
| 多专业群初始化向导 | 新专业群、建设周期、专业关系、依据、人员、权限、模板 | 建立草稿、逐项确认、校验隔离、启用 |
| 复制差异对照页 | 可复用配置、新群独立内容、禁止复制内容 | 选择结构、调整配置、排除事实、确认初始化 |
| 专业群助手任务页 | 当前任务、范围、步骤、缺项、待确认动作 | 整理、检查、生成草稿、等待确认、写回 |

## 3. 四类流程之间的关系

```text
学校确认选配范围
  → T15/T16 在指定专业和人员范围内启用
  → 人工记录或任务进入办理流程
  → 已确认结果可作为专业群建设过程材料

真实生产或实训项目发生
  → T17 归集真实任务、参与、过程和人工结果
  → 负责人确认与建设任务的关系
  → 形成产教融合案例及支撑目录

试点工作方式通过验证
  → T18 选择可复用结构、流程和模板
  → 新专业群重新导入依据、组织、人员和权限
  → 隔离校验通过后独立启用
```

T15—T17 形成的材料只有经过人工确认才能进入建设依据、指标、成果或报告链；任何关联都不能重复增加同一项指标数量。

## 4. 选配能力启用与变更

### 4.1 启用条件

启用 T15 或 T16 前，学校至少确认：适用专业群和专业、资料类型、业务负责人、参与角色、办理节点、是否涉及敏感正文、保留期限以及验收方式。

### 4.2 产品处理

系统先建立“待确认配置”，展示将新增的页面、角色待办、可查看资料和输出结果。负责人确认后才启用。后续范围变化形成新版本，既有业务记录仍按当时配置解释。

### 4.3 停用处理

停用只阻止新事项进入，不删除历史记录。未结束事项需逐项决定继续办理、转出或终止，决定进入建设账本。

## 5. T15：教学检查、听评课记录与问题跟踪

### 5.1 发起方式

- 教务人员登记既有教学检查表；
- 教师提交听评课记录及后续反馈；
- 从专业群课程、合作活动或建设任务中关联一条已发生的检查记录；
- 请专业群助手“把本月检查记录整理成问题清单”。

### 5.2 固定输入

系统固定原始记录版本、检查日期、检查对象、人工评价、提交人、适用专业和可见范围。智能体不得改写原评价，也不能用自动分析代替人工评价。

### 5.3 归集与问题办理

1. 助手从记录中整理检查事项、已有人工评价、问题和后续要求；
2. 经办人核对整理结果，确认哪些内容构成正式问题；
3. 负责人指定责任人、完成节点和需要补交的材料；
4. 责任人提交反馈或材料，原问题进入待复核；
5. 有权人员确认整改完成、继续整改或不适用；
6. 与建设任务有关的内容经确认后建立关系，形成过程材料。

### 5.4 示例走查

A 企业参与校企合作课程，已有人工检查记录指出“企业导师到课记录不完整”。系统保留原检查表和人工评价，形成一条待整改问题；责任教师补交到课材料，负责人复核后确认完成。该记录可以支撑合作活动质量，但不能使“新增合作企业”从 1 家变成 2 家。与企业合作无关的检查记录独立归入教学管理，不强行关联专业群指标。

### 5.5 写回与边界

写回检查记录、问题、整改任务、反馈、人工复核和建设材料关系。默认不做课堂质量自动评分、不替代听评课人员、不自动关闭问题。

## 6. T16：考试出卷事项与人工审核跟踪

### 6.1 发起方式

教务人员从考试事项列表新建出卷任务，填写课程、要求、负责人、截止时间、审核人和提交物类型；也可批量导入已批准的安排。

### 6.2 安全分层

产品把“任务跟踪信息”和“试卷正文”分开：

- 默认层只保存课程、节点、责任人、提交状态、审核结论和待处理问题；
- 试卷正文、答案和评分标准只有在学校明确存放位置、可见人员和保护要求后才能启用；
- 智能体默认不读取正文，也不生成正式试题和审核结论。

### 6.3 办理流程

```text
登记出卷任务
  → 责任教师查看要求并提交指定结果
  → 审核人进行人工审核
  → 通过 / 退回并写明问题
  → 教师补充后提交新版本
  → 审核人确认当前版本
  → 形成考试工作过程记录
```

助手可提醒节点、检查栏目完整性、整理退回意见和对照版本，但不能代替审核人通过试卷。

### 6.4 示例走查

A 企业参与的合作课程需要期末出卷。张老师提交后，教务人工审核并要求补充实践题评分标准；张老师补充新版本，审核人确认通过。最终记录可作为课程建设过程材料，但不能证明新增企业数量，也不能改变指标“已确认 1 家、尚差 2 家”。

### 6.5 异常处理

- 超期未交：保留提醒和责任状态，不自动标记失败；
- 退回后误交旧版本：提示版本不一致并要求重新确认；
- 审核人变化：记录变更原因和生效时间；
- 正文权限不足：只显示任务状态，不泄露文件名、摘要或内容。

## 7. T17：真实生产与实训资料形成产教融合案例

### 7.1 本期产品定位

当前阶段先建立“真实资料归集—人工确认—建设关系—案例编制”能力。生产排程、设备控制、实训过程自动评分和产品质量自动验收均不在本期范围。

### 7.2 资料结构

一个实践项目可以归集：真实任务单、合作单位、参与教师和学生、适用技术标准、过程记录、人工检测结果、交付/验收记录、企业评价和公开范围。缺少的内容以缺项显示，不能由助手补造。

### 7.3 办理流程

1. 教师建立或选择真实实践项目；
2. 分批提交任务、过程、人员和结果材料；
3. 助手按案例结构整理材料，标出冲突、缺项和不可公开内容；
4. 负责人确认项目身份、参与人数、活动次数和适用建设任务；
5. 人工检测或验收结果由原责任人确认；
6. 系统形成案例草稿和支撑材料目录；
7. 审核后作为建设成果或报告输入，保留所有来源版本。

### 7.4 示例走查

A 企业签约后开展一次真实生产实训，20 名学生和 2 名教师参加，形成任务单、学生过程记录、企业评价和成果验收记录。助手可整理为“A 企业校企协同育人实践案例”，并分别记录企业数、活动次数和参与人数。企业数量仍只计算 A 企业 1 家；摘要不能替代学生实操、精度检测或成果验收。

### 7.5 写回

写回实践项目、参与关系、材料版本、人工结果、公开范围、建设任务关系、案例版本和支撑目录。以后材料变更触发影响复核，不静默改写已归档案例。

## 8. T18：多专业群复制与独立初始化

### 8.1 可复制内容

- 建设依据、指标、任务、材料和成果的对象结构；
- 资料吸收、任务办理、审核和版本管理流程；
- 经确认的通用模板结构和栏目；
- 角色类型、权限配置方法和验收脚本；
- 智能体能力编排及停止、确认规则。

### 8.2 禁止复制内容

- 试点群的申报书、任务书、实施方案正文；
- 专业、教师、企业、学生和人员身份；
- 指标目标值、已完成数、工作事实和材料；
- 权限授权、审核结论、报告正文和历史对话；
- 示例中的 A、B、C、D 企业、张老师及“目标 3 家、完成 1 家”。

### 8.3 初始化向导

```text
建立新专业群草稿
  → 登记建设周期和专业关系
  → 导入本群建设依据并完成版本确认
  → 配置人员、角色和查看/办理范围
  → 选择可复用流程与模板结构
  → 设置本群指标、任务和报告要求
  → 执行跨群事实与权限隔离检查
  → 负责人确认后独立启用
```

每一步都显示已完成、待确认、缺少和冲突项。未完成依据和权限配置时，专业群助手只能处理已获准范围内的准备任务。

### 8.4 差异保留

系统允许各专业群拥有不同的专业层级、指标口径、材料清单、报告模板、审核链和选配能力。复用的是办理机制，不要求所有专业群被压成同一业务模型。

### 8.5 隔离验证

使用两个明确标识的样例群验证：

1. 新群能够使用同一流程建立自己的依据和任务；
2. 搜索、助手查询、报告编制和导出都不能出现试点群事实；
3. 同一教师兼任两个群时，仍按当前群和当前角色获取权限；
4. 模板结构更新不会自动覆盖已确认的群内版本；
5. 一个群停用或归档不影响另一个群运行。

## 9. 专业群智能体在四类流程中的作用

| 场景 | 可以做 | 必须等待人工 | 不可以做 |
| --- | --- | --- | --- |
| T15 | 整理人工记录、提取问题、跟踪材料 | 正式问题、整改结论、建设关联 | 自动评价课堂、替人关闭问题 |
| T16 | 提醒、检查栏目、整理审核意见、对照版本 | 试卷审核、敏感正文范围、最终通过 | 默认读取试卷、自动命题或批准 |
| T17 | 整理真实资料、生成案例草稿、检查缺项 | 项目事实、人数、人工检测/验收、公开范围 | 替代实操检测、控制生产设备 |
| T18 | 生成初始化清单、检查缺项与串用风险 | 新群依据、组织、权限、指标和启用 | 复制事实、权限、进度和报告 |

智能体任务卡始终显示当前专业群、资料范围、所用版本、已完成步骤、待确认项和写回对象。切换专业群必须显式切换上下文，不能沿用上一个群的任务范围。

## 10. 角色动作

| 角色 | 主要动作 |
| --- | --- |
| 教师 | 提交已有记录、办理整改或出卷任务、归集真实实践材料 |
| 专业负责人 | 核对专业内事实、课程/实践关系和材料完整性 |
| 专业群负责人 | 确认选配范围、建设关系、案例和新群配置 |
| 教务/管理人员 | 登记检查与考试要求、设置审核链、处理跨部门事项 |
| 审核人员 | 作出人工检查复核、试卷审核或成果审核决定 |
| 信息支持人员 | 配置学校确认的资料空间、账号和运行保障，不决定业务事实 |
| 专业群智能体 | 整理、检查、提醒、生成草稿和写回已确认结果 |

## 11. 页面连续导航

每个选配事项都提供“事项登记—当前办理—人工确认—建设关联—归档”的节点导航；T18 提供“新群建立—依据—组织权限—配置—隔离检查—启用”的初始化导航。主页面和子页面相互连接，退回意见直接进入待修改版本，建设材料关系可返回原事项。

## 12. 原型走查脚本

### 12.1 T15 走查

导入一份人工教学检查记录，整理出“企业导师到课记录不完整”，建立整改事项，补交材料并由负责人确认；验证人工原评价未被改写，企业数量未重复增加。

### 12.2 T16 走查

新建一项出卷任务，完成提交、人工退回、补充评分标准和重新审核；使用无正文权限账号确认只能看到任务状态。

### 12.3 T17 走查

归集 A 企业实践项目的任务单、20 名学生、2 名教师、过程和验收材料，形成案例草稿；验证企业数、活动数和人数分别统计，缺验收时不能写成已验收。

### 12.4 T18 走查

从试点配置建立第二个样例专业群，导入独立任务书、人员和目标；运行搜索、助手查询和报告草稿，确认不出现 A—D 企业、张老师及 1/3 进度。

## 13. 验收门槛

- T15、T16 未经学校确认不会默认启用或进入首期验收；
- 人工评价、审核、检测和验收结论均保留原责任人和版本；
- 选配流程的材料只有经确认才与建设任务或成果建立关系；
- T17 能形成真实案例和支撑目录，同时清楚显示缺项和公开范围；
- T18 复制结构和方法，新群事实、人员、权限、进度和成果完全独立；
- 智能体在四类流程中都能协助办理，但不能越过人工确认和数据范围；
- 页面可沿流程前进和返回，不依赖使用者熟记菜单；
- 所有写入、退回、确认、范围变化和跨对象关系进入版本记录及建设账本。

## 14. 仍待学校确认

1. T15、T16 是否进入首期及各自适用范围；
2. T15 整改栏目、责任人和问题办结规则；
3. T16 审核层级、退回规则以及是否保存试卷正文；
4. T17 首个真实实践案例、材料清单、学生参与要求和公开范围；
5. T18 实际推广对象、专业数量、实施批次和阶段安排。

# 专业群知识库资料吸收与确认流程详细设计

> 版本：v1.0　日期：2026-10-18　状态：内部评审稿。  
> 对应波次：W2、W4。  
> 文档职责：说明学校资料怎样进入专业群知识库、怎样形成候选事实和关系、怎样经人确认后支撑任务、进度和成果。

## 1. 设计目标

专业群知识库不是把文件上传后即可问答。资料必须经过“接收—保全—读取—拆解—建立候选关系—人工确认—发布使用—持续更新”的过程，才能成为可靠的建设知识。

流程同时保障：

- 原始资料始终可追溯；
- 读取失败和缺项不会被隐藏；
- 智能体提取内容与学校确认事实分开；
- 多专业群、多专业和多周期不会相互混用；
- 新版本不会悄悄改写历史报告；
- 资料权利、查看范围和临时处理记录完整。

## 2. 资料入口

| 入口 | 适用情况 | 创建的首个对象 |
| --- | --- | --- |
| 教师/教务上传 | 日常文件、图片、表格、工作说明 | 原始材料、材料版本 |
| 批量资料交接 | 项目初始化或阶段性交接 | 资料交接批次、资料包 |
| 工作记录附件 | 说明一次真实工作 | 工作记录草稿、材料版本 |
| 依据文件登记 | 申报书、任务书、实施方案 | 依据文件、文件版本 |
| 成果编制选材 | 针对报告任务补充资料 | 编制任务输入快照、材料版本 |
| 经批准的聊天摘录 | 学校允许提交的交流记录 | 原始材料及提交说明 |
| 既有系统导入 | 学校确认的台账或导出数据 | 导入批次、行级对象和错误清单 |

产品首期不默认自动采集教师聊天、邮箱或其他系统内容；是否连接及范围另行确认。

## 3. 十一步吸收流程

```text
I0 建立交接批次与范围
  → I1 接收并保全原件
  → I2 安全与完整性检查
  → I3 文件识别和可读性处理
  → I4 内容拆解与原文定位
  → I5 建立候选对象
  → I6 建立候选关系
  → I7 重复、冲突和缺项检查
  → I8 人工核对与确认
  → I9 发布到可用知识范围
  → I10 影响分析与持续更新
```

### I0 建立交接批次与范围

记录提交人、提交目的、学校、专业群、专业、建设周期、资料类型、预期用途、可见范围和是否允许临时处理。无法确定归属的资料进入“待分派资料”，不自动放入任一专业群。

### I1 接收并保全原件

保存原文件、文件名、大小、时间、校验标识和提交说明，生成材料编号与版本编号。整理、转换和抽取结果作为派生内容保存，不覆盖原件。

### I2 安全与完整性检查

检查文件是否完整、是否重复上传、格式是否允许、是否存在受限内容标记。无法处理的文件仍保留登记状态，并明确错误原因和后续动作。

### I3 文件识别和可读性处理

识别文档、表格、图片、扫描件及其他类型，形成可预览内容和读取状态：完整可读、部分可读、无法读取、需人工录入。可预览不等于内容已确认。

### I4 内容拆解与原文定位

按资料类型拆解：

- 依据文件：章节、条款、表格、指标、节点和材料要求；
- 工作资料：事件、时间、参与人、专业、过程、结果和附件；
- 表格：工作表、表头、行记录、单元格和统计字段；
- 模板：栏目、章节、必填项、格式和填报说明；
- 图片/扫描件：文字区域、表格区域和原图定位。

每条提取内容保存页码、章节、表格、单元格或图片区域等定位信息。

### I5 建立候选对象

智能体或规则可以提出候选条款、目标、指标、任务、工作记录、事实、成果、企业、人员或专业等对象。候选对象带来源、置信说明和待核对项，未确认前不参与正式统计。

### I6 建立候选关系

候选关系包括归属专业、对应任务、支持指标、责任人员、重复、冲突、引用和版本替代等。系统显示推荐理由与来源，允许逐条修改。

### I7 重复、冲突和缺项检查

- 同内容或同成果的多个文件进入重复组；
- 不同依据目标值、适用期或责任不一致时建立冲突；
- 缺批准状态、业务日期、责任人、原文定位或证据时建立缺项；
- 无法匹配的内容保留为待整理项，不强行归类。

### I8 人工核对与确认

教师核对本人工作，专业负责人核对专业归属，专业群负责人核对建设关系和指标用途，指定人员处理依据冲突。用户可以接受、修改后接受、拒绝或退回补充。

### I9 发布到可用知识范围

确认结果进入专业群知识库，并按照权限成为任务、查询、进度和成果编制的可用输入。发布记录固定对象版本、确认人、适用范围和时间。

### I10 影响分析与持续更新

新材料或新版本进入后，系统检查其是否替代旧版本、补足证据、改变事实或影响已形成结论。只生成影响清单，不自动改写已确认进度和正式报告。

## 4. 吸收状态看板

资料批次不能只显示“上传成功”，应展示五个层次：

| 层次 | 说明 | 示例指标 |
| --- | --- | --- |
| 已登记 | 原件已经登记并可追溯 | 100 份 |
| 可读取 | 系统可以预览或提取 | 92 份 |
| 已拆解 | 已形成内容片段和定位 | 87 份 |
| 待确认 | 已提出候选对象或关系 | 43 项 |
| 已确认 | 已进入可用知识范围 | 31 项 |

另外单列：读取失败、重复待处理、冲突、缺项、受限和未覆盖，不能合并进“处理完成”。

## 5. 专业群知识归属

归属判断按以下顺序：

1. 用户明确选择的学校和专业群；
2. 当前任务或工作记录已有的专业群；
3. 资料中可核对的专业、项目和周期信息；
4. 智能体候选建议；
5. 人工最终确认。

资料可与多个专业关联，但必须有一个管理范围和每条关系的授权。跨专业群使用时建立独立授权关系，不复制原件形成无法追踪的副本。

## 6. 资料类型专用处理

### 6.1 建设依据文件

形成文件版本、批准状态、适用周期、原文条款、目标、指标、任务、节点和证据要求。三类文件之间的对应关系为候选，负责人确认后才成为共同建设依据。

### 6.2 日常工作与业绩材料

形成工作记录、参与人、业务日期、专业、任务、材料、成果和候选指标关系。上传日期不能代替业务发生日期。

### 6.3 模板与合格样例

模板拆成结构与格式要求；合格样例仅用于帮助理解写法，不能作为当前专业群事实。模板版本变化后提示受影响的编制任务。

### 6.4 表格数据

保存原始工作簿和导入批次，逐行记录成功、失败、重复和待确认；公式值与显示值的处理规则需明确，不能只保留转换后的文本。

### 6.5 图片、扫描件和聊天摘录

保留原图和提交上下文，提取内容必须能回到图片区域；聊天摘录记录提交人、时间范围、参与方说明和学校批准用途。

## 7. 重复与唯一性

重复判断分四层：

- 相同文件：文件内容完全一致；
- 相同版本：内容与业务含义一致，仅文件名不同；
- 相同成果：不同材料支持同一成果或企业；
- 相关但不同：同一对象在不同时间的活动或补充证据。

系统只提出重复候选；涉及成果计数时必须按统计规则和人工确认处理。删除重复文件不能删除它曾支持的历史关系。

## 8. 冲突处理

冲突卡至少包含：冲突主题、各来源原文、文件版本和批准状态、适用周期、影响的指标/任务/报告、建议处理人和当前决定。未解决冲突相关的正式计算与成果内容标记为待确认。

## 9. 权限与资料权利

- 原件、提取内容、结构化事实和智能体结果均属于学校资料范围；
- 可见范围在接收时登记，后续确认关系不会自动扩大查看范围；
- 临时处理需记录资料、目的、时间、处理位置和清除结果；
- 服务能力不携带学校资料跨客户复用；
- 学校可以按约定导出原件、结构化对象、关系、版本和操作记录。

## 10. 与 T01—T18 的连接

| 吸收结果 | 直接支持的任务 |
| --- | --- |
| 原件、工作记录、待整理项 | T01、T04 |
| 可编辑整理任务和来源清单 | T02 |
| 组织、专业和责任候选关系 | T03 |
| 条款、目标、指标和证据要求 | T05 |
| 成果、重复组和指标候选关系 | T06 |
| 已确认事实、材料和任务进展 | T08—T12 |
| 模板、输入快照、引用和缺项 | T09、T13、T14 |
| 专用过程资料 | T15—T17 |
| 初始化结构与差异清单 | T18 |

## 11. 验收用例

1. 同一协议扫描件和电子版不会被重复计算成两个企业成果。
2. 无法读取的扫描件仍可下载原件并进入待人工处理清单。
3. 一条指标可回到任务书具体表格或章节。
4. 不同文件目标冲突时不自动选择任一数值。
5. 未确认候选关系不进入正式进度。
6. 新版本进入后旧报告引用仍指向原版本。
7. 无权限用户看不到材料正文，智能体也不能泄露提取内容。
8. 新专业群只能看到其独立资料和经授权的共享材料。

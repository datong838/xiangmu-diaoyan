# W9-5 专业群智能体与云动作网关分段实现方案

> 版本：v1.0　日期：2026-10-18　状态：编码前冻结稿。  
> 前置：第 02、15、41、60—64 份方案与验证记录。  
> 本波目标：让专业群智能体以受控产品任务调用 W9-3、W9-4 已验证能力，不以聊天文本替代业务对象、人工决定或建设账本。

## 1. 本波要解决的问题

W9-0 至 W9-4C 已经具备范围、身份、文件、正式知识、任务、工作记录、成果分类、指标计算、进度确认和差距任务。W9-5 要把这些能力组织成专业群智能体可持续办理的工作方式：

1. 用户的一次请求形成稳定的智能体任务，不随页面刷新或对话结束丢失；
2. 智能体只读取当前身份获准的专业群、专业和周期内容；
3. 本次使用的知识、事实、规则、版本、允许动作和停止点形成固定知识任务包；
4. 智能体先给出可检查计划，再调用产品动作；
5. 查询、建议、草稿和正式决定严格分层；
6. 越权、缺资料、冲突、版本变化和结果未知时能够暂停、对账并继续；
7. 云端服务只提供能力，不拥有学校资料，日志和持久层不保存学校正文。

## 2. W9-5 分段

| 分段 | 建设内容 | 完成标志 |
|---|---|---|
| W9-5A | 智能体任务、任务版本、S0—S5、知识任务包、确定性计划和人工计划确认 | 一次请求可形成可追溯任务；知识包固定输入和允许动作；需写入的计划未经确认不能进入执行态 |
| W9-5B | 受控动作目录、动作运行、幂等回执、本地动作网关和业务写回 | 智能体可调用已验证的只读动作和草稿动作；每个动作有独立回执；正式决定仍由业务接口和授权人员完成 |
| W9-5C | 连续对话、上下文变化、暂停恢复、云端最小上下文和边界验证 | 后续指令绑定原任务；关键版本变化触发重新检查；云端日志和持久层无学校正文 |

外部生成模型不是 W9-5A 的前置条件。5A 使用确定性意图和计划夹具验证任务协议，不能据此宣称自然语言理解已经完成。

## 3. W9-5A 核心对象

### 3.1 智能体任务

- `agent_tasks`：稳定任务编号、学校、专业群、专业、周期、发起人、当前状态、当前版本和创建时间；
- `agent_task_versions`：用户原话、结构化意图、预期产出、截止点、当前 S0—S9 阶段、变更原因和内容摘要；
- 版本只能追加，旧请求、旧计划和旧状态均可回查。

首批结构化意图只开放：

- `query_indicator_progress`：查询某次指标计算、正式进度、差距和来源；
- `prepare_gap_follow_up`：基于已确认差距准备后续任务草稿计划；
- `query_task_status`：查询任务、工作记录、提交和退回状态；
- `search_formal_knowledge`：查询已发布知识及来源。

未进入首批目录的请求保存为 `unsupported_intent` 并停在待补条件，不返回泛化伪结果。

### 3.2 知识任务包

- `agent_knowledge_packs`：任务、任务版本、范围、统计截止点、输入摘要、允许动作、人工停止点、失效时间和状态；
- `agent_knowledge_pack_items`：引用正式知识、任务版本、指标规则版本、计算运行、正式进度或差距等对象，只保存固定对象编号、版本、用途和摘要；
- 知识包不跨专业群拼接；未获授权的对象不能进入数量、摘要或缺项提示；
- 关键引用版本变化后，旧知识包标记 `stale`，任务返回 S3 重新检查。

### 3.3 处理计划与人工决定

- `agent_plans`：按顺序保存步骤、能力编号、动作代码、读写级别、预期产出和人工停止点；
- `agent_plan_decisions`：发起人或相应负责人对计划作出 `approve`、`adjust` 或 `reject`；
- 纯查询计划可以形成 `ready_to_execute`，但仍保留计划版本；
- 任何拟建立草稿、修改对象或提交业务的计划必须先 `waiting_plan_confirmation`；
- 计划确认只允许进入动作执行阶段，不等于确认任务、指标、证据或报告等正式业务结果。

## 4. 状态实现

| 协议阶段 | W9-5A 产品状态 | 形成结果 |
|---|---|---|
| S0 | `received` | 原始请求版本 |
| S1 | `scope_fixed` | 学校、群、专业、周期和当前身份 |
| S2 | `intent_structured` | 意图、对象和期望产出 |
| S3 | `conditions_checked` / `waiting_for_input` | 已有、缺失、冲突、无权和版本状态 |
| S4 | `plan_ready` | 可见步骤、动作和停止点 |
| S5 | `ready_to_execute` / `waiting_plan_confirmation` / `rejected` | 纯查询可执行，写候选需人工决定 |
| S6—S9 | W9-5B、5C | 动作、检查、结果确认和写回 |

暂停、取消和失败是正式状态。任务已完成的部分不会因后续步骤暂停而消失。

## 5. 首批接口

| 接口 | 行为 |
|---|---|
| `POST /agent-tasks` | 在当前身份和范围内建立智能体任务，固定原始请求和结构化意图 |
| `GET /agent-tasks` | 按当前身份和范围查看任务列表，不返回跨范围数量 |
| `GET /agent-tasks/{taskId}` | 查看任务版本、知识包、条件检查、计划和人工决定 |
| `POST /agent-tasks/{taskId}/plan-decisions` | 对需要确认的计划批准、调整或拒绝 |

`POST /agent-tasks/{taskId}/refresh-context` 留到 W9-5C 实现，用于上下文变化后的重新检查和连续办理；W9-5A 不返回模拟刷新成功。

所有写接口继续使用操作编号、幂等键、范围、操作者、期望版本和用途组成的统一写入信封，并写入操作回执、建设账本和 Outbox。

## 6. 首批计划目录

| 意图 | 读取对象 | 计划步骤 | 人工控制点 |
|---|---|---|---|
| 查询指标进度 | 指标规则、计算运行、正式进度、差距、来源输入 | 固定范围和截止点 → 读取已确认结果 → 组织带来源答复 | 无正式写入；不得自行确认进度 |
| 准备差距后续 | 正式进度、已确认差距、现有任务 | 读取差距 → 检查是否已有任务 → 形成不同差距的任务草稿计划 | 负责人确认计划；后续建任务仍是草稿 |
| 查询任务状态 | 任务版本、工作记录、提交与退回记录 | 固定任务 → 汇总状态与待办 → 说明来源 | 只读；不能替负责人确认完成 |
| 查询正式知识 | 已发布知识、适用范围和来源 | 按权限检索 → 去重排序 → 返回来源和未知项 | 只读；草稿知识不进入回答 |

## 7. 权限和数据边界

- 教师：可建立本人任务查询、本人任务状态和获准知识查询；不能建立群级指标进度或差距办理任务；
- 专业群负责人：可建立四类首批任务并确认含草稿写入的计划；
- 教务审核人员：可建立只读查询任务，不确认写入计划；
- 信息支持人员：只能查看运行健康，不读取任务原话、知识包内容或业务结果；
- 智能体使用发起人的现有权限，不获得独立扩大范围的身份；
- W9-5A 不调用外部服务，原始请求和知识包保存在学校侧；
- 后续云端请求只能使用匿名引用和获准的最小内容，外部响应没有学校侧写权限。

## 8. 失败、幂等和恢复

- 指定对象不属于当前学校、专业群或周期时按不存在处理；
- 结构化意图与对象类型不匹配时拒绝建立可执行计划；
- 缺少必需对象时保存任务和缺项，状态为 `waiting_for_input`；
- 同一幂等键和同一请求返回原回执，不同请求返回冲突；
- 旧任务版本不能确认新计划；第二次计划决定返回冲突；
- W9-5C 刷新上下文时必须创建新知识包和任务版本，不得修改旧版本；
- 任务取消后不能继续确认计划；
- 结果未知时按操作编号查询原回执，不使用新操作编号重建任务。

## 9. W9-5A 自测门槛

1. 负责人以“查一下 2026 年新增合作企业指标现在完成多少”为原话建立指标进度查询任务；
2. 知识包固定规则版本、计算运行、正式进度、差距和截止点，能回到 W9-4C 来源；
3. 只读计划直接进入 `ready_to_execute`，但不会执行正式进度确认；
4. “根据 B、D 差距准备后续任务”形成不同步骤并停在 `waiting_plan_confirmation`；
5. 负责人批准计划后只进入待执行状态，不直接建立或派发任务；
6. 教师不能建立群级指标和差距计划，审核人员只能读取自己的查询任务，信息支持零业务可见；
7. 缺对象、对象跨群、意图不支持、旧版本、重复决定和幂等冲突均有明确结果；
8. 知识包固定本次对象和版本，旧知识包保持不可改写；上下文变化后的刷新在 W9-5C 验证；
9. 数据库迁移可在空库顺序执行并重复执行；
10. OpenAPI、类型检查、全工程回归、全量集成和方案一致性检查通过。

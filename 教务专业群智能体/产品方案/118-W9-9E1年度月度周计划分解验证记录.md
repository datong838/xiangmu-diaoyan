## 1. 验证结论

W9-9E1 已把年度、月度、周计划建设为独立、可写、可确认、可追溯的产品对象，并与既有任务链建立受控关系。年度计划不设上级，月计划必须承接已确认年度计划，周计划必须承接已确认月计划。每个子计划同时固定父计划的确切确认版本，避免上级后来修改后历史依据被悄悄改变。

该结果补齐 T07 在合成候选环境中的完整首链，但学校计划模板、真实计划、真实人员和现场使用仍属于 W10，不能据此宣称学校验收完成。

## 2. 产品办理链

```text
正式建设依据
  → 负责人建立年度计划并确认
  → 负责人建立月计划并固定年度计划确切版本
  → 负责人建立周计划并固定月计划确切版本
  → 将已确认计划关联建设任务
  → 教师按任务办理，负责人按计划查询和总结
```

计划确认不会自动派发任务；计划与任务建立关系不会改写任务状态；任务完成不会自动认定计划完成、指标达成或成果正式成立。

## 3. 已完成的产品能力

| 能力 | 验证结果 |
| --- | --- |
| 计划对象与版本 | 年、月、周计划具有稳定身份和不可变版本，可改稿、确认或退回 |
| 层级约束 | 月计划只能承接年度，周计划只能承接月度，错误层级返回明确提示 |
| 确切版本关系 | 子计划固定父计划当时的确认版本，父计划后续换版不改写历史 |
| 计划与任务 | 已确认计划可关联同范围任务，关系只追加且不改变任务状态 |
| 来源依据 | 计划必须引用当前学校、专业群、周期内的正式知识 |
| 负责人工作台 | 可建立、换版、确认、退回、关联任务并查看完整计划树 |
| 教师范围 | 只读本人负责或与本人任务关联的计划 |
| 教务范围 | 获准专业群只读，不代替负责人确认 |
| 信息支持范围 | 不读取计划标题、内容或数量 |
| 刷新恢复 | 层级、版本、决定和任务关系均由数据库恢复 |

## 4. 技术与数据约束

新增四类正式对象：计划、计划版本、计划决定、计划任务关系。版本、决定和任务关系均为追加式记录。数据库进一步保存 `parent_plan_version_id`，并用外键证明该版本确实属于指定父计划；层级形状、周期范围、人员、专业、来源知识和任务范围由服务端再次核对。

正式页面新增“年度月周计划”总览、建立计划和计划详情。接口新增计划列表/建立、详情、换版、决定和任务关联，共 5 个路径、6 个操作。原有任务、指标、成果、总结和智能体流程未被改写。

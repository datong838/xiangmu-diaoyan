# W9-8B 候选版资料包与确定性预演实现方案

> 版本：v1.0　日期：2026-10-19　状态：编码前方案已冻结。  
> 前置：第 88 份分段方案、第 89 份全量能力盘点；编码前已复核第 38—44 份 W9 技术方案。  
> 目标：把分散的运行能力、验证证据和操作说明整理成可以重复执行、不会误报学校验收的试点候选资料包。

## 1. 本段不新增业务功能

W9-8B 解决的是“怎样可靠地准备和预演现有产品”，不是补齐第 89 份中所有业务缺口。本段不新增年度—月—周计划对象，不建设 T15/T16，不开启真实自动解析、向量检索、开放式自然语言理解或外部智能服务。

代码变化只增加三类候选保障：

1. 一份机器可核对的候选版清单；
2. 一个失败关闭的就绪检查程序；
3. 一组学校可执行的部署、恢复、角色使用、问题处理和试点准备手册。

## 2. 候选版清单

新增 `pilot/pilot-candidate-manifest.json`，作为 W9-8B 的机器可读事实清单，固定记录：

- 18 个 T 任务及其状态：`runtime_chain`、`partial_runtime`、`closed`；
- 4 个角色及其产品边界；
- A01—A11 的候选预演状态和 W10 现场条件；
- G01—G10 门槛当前状态；
- 显式关闭能力；
- 所需手册和证据文件；
- 当前工程阶段、最后迁移和 OpenAPI 最低路径/操作数量。

约束：

- T01—T18 必须恰好各出现一次；
- A01—A11 和 G01—G10 必须连续且无遗漏；
- 四角色必须恰好为教师、专业群负责人、教务审核人员、信息处支持人员；
- T15/T16 必须为 `closed`；
- G09 在 W9-8C 前不得写成通过；
- A11 在 W10 前不得写成学校验收通过；
- 清单只能引用工程内存在的证据和手册。

## 3. 就绪检查程序

新增 `scripts/verify-pilot-candidate.mjs`，分为静态核对和运行环境核对。

### 3.1 静态核对

普通 `pnpm verify` 必须执行，检查：

1. 清单结构、编号、数量和允许状态；
2. T01—T18 状态与第 89 份盘点一致；
3. 关闭能力在领域状态中均为 `false`；
4. 动作网关启用本地确定性模式、外部端点为空、不保存学校正文；
5. OpenAPI 至少包含清单声明的路径和操作数量；
6. 最后迁移是 W9-7C，恢复清单能力已开启；
7. 所有候选手册和证据引用存在；
8. 文档不得出现“W9-8 已完成学校验收”之类越界结论。

静态核对失败即返回非零状态，不能继续生成候选结论。

### 3.2 运行环境核对

显式提供 `DATABASE_URL` 和 `SCHOOL_FILE_ROOT` 时增加检查：

1. 数据库可连接；
2. 42 个迁移均已登记且最后迁移正确；
3. 数据库实现状态与代码实现状态一致；
4. 学校文件根目录存在、可读写且位于工程目录之外；
5. 数据库登记文件均存在并可校验；
6. 恢复或正式运行前的必要配置没有缺失。

未提供运行环境变量时只通过静态门槛，并在结果中明确 `runtimeEnvironmentChecked=false`，不得伪报运行环境就绪。

### 3.3 输出

程序向标准输出给出 JSON 摘要，可通过 `PILOT_CANDIDATE_REPORT_PATH` 另存完整报告。报告至少包括：

- 检查时间、代码阶段、清单版本；
- 静态检查结果；
- 是否检查运行环境；
- T、角色、A、G 和关闭能力统计；
- 手册与证据引用数量；
- 失败项和下一步。

## 4. A01—A11 确定性预演

新增 `apps/api/scripts/verify-w9-8b-pilot-rehearsal.mjs`，它不复制业务实现，而是以全新合成数据库运行正式迁移和现有正式接口集成链，再按候选清单汇总 A01—A11。

### 4.1 执行原则

- 必须显式提供 `TEST_DATABASE_URL` 和独立的 `SCHOOL_FILE_ROOT`；
- 数据库必须是专用合成环境，调用方通过 `PILOT_REHEARSAL_CONFIRM=SYNTHETIC_ISOLATED` 明确确认；
- 先迁移，再运行全套 API 集成测试；
- 不直接写业务表来伪造产品结果，测试中的身份引导数据例外仍按既有受控测试方式；
- 每个 A 项根据实际覆盖范围输出 `rehearsed`、`partial`、`deferred` 或 `school_required`；
- A03、A04 不得因人工拆解和结构化查询通过而写成自动解析或开放问答通过；
- A10 留给 W9-8C；A11 只形成手册和角色脚本，真实独立使用仍为 `school_required`；
- 预演报告明确标注“合成预演，不是学校验收”。

### 4.2 预演证据

预演程序保存：

- 迁移执行结果；
- 集成测试通过、失败和跳过数量；
- A01—A11 分项状态与对应运行链；
- 关闭能力复核；
- 数据库和文件根目录标识的脱敏摘要；
- 失败项与复跑要求。

若有任一预期执行的集成测试跳过，预演整体不得通过。

## 8. 风险与控制

| 风险 | 控制 |
| --- | --- |
| 汇总程序只检查文件存在，造成假就绪 | 运行环境模式必须实际连接数据库、核对迁移、实现状态和文件清单 |
| 现有集成测试被跳过仍返回整体成功 | 解析测试结果；任何预期测试跳过都使预演失败 |
| 把 A03/A04 部分能力写成完整智能能力 | 清单限定允许状态并在脚本中强制 A03/A04 为 `partial` |
| 自动测试替代真实人员使用 | A11 固定为 `school_required`，只输出演练材料 |
| 手册命令误用于真实学校数据 | 所有预演命令要求独立合成确认值和独立文件根目录 |
| 资料包与工程状态漂移 | `pnpm verify` 每次检查清单、手册、实现状态和关闭能力 |

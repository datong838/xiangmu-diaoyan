# T09、T12—T14 查询、总结、成果编制与改稿跨页面办理流程

> 版本：v1.0　日期：2026-10-18　状态：内部评审稿。  
> 对应波次：W6。  
> 文档职责：把自然语言查询、周期总结、正式成果编制、指定口径改稿、审核、导出和归档连成一条可核查的产品链。

## 1. 产品目标

教师或教务人员可以先用一句话了解建设情况，也可以把同一批已确认事实用于周月年总结、年度报告、中期评审或新申报材料。产品需要同时满足：

- 查询快，但不丢范围、截止点和来源；
- 总结可持续修改并形成下期任务；
- 正式成果严格使用模板、输入快照和引用；
- 用户可以指定分析口径和局部修改范围；
- 智能体负责协助编写，学校人员负责事实确认、审核和正式使用。

## 2. 页面与工作区

| 页面 | 主要作用 | 关键写操作 |
| --- | --- | --- |
| 智能查询工作区 | 用自然语言查询专业群、专业、人员、指标和材料 | 调整范围、保存结果、导出、转成任务或编制输入 |
| 查询结果详情 | 展开表格、来源、未知项和数据截止点 | 固定快照、补充筛选、进入对象 |
| 周期总结编辑页 | 编写周/月/年总结与下一周期计划 | 编辑、引用、确认、生成后续任务 |
| 成果编制中心 | 管理申报、报告、中期、验收等编制任务 | 新建、选模板、选期间、分工、检查资料 |
| 章节编写台 | 按模板编写正文、表格和支撑目录 | 编辑、请助手写、引用、标记缺项、保护人工内容 |
| 改稿对照页 | 按指定口径或反馈形成新版本 | 选择范围、生成新稿、对比、接受/拒绝 |
| 成果审核页 | 独立核对事实、引用、模板和版本 | 退回、批准、重新审核 |
| 导出与归档页 | 生成学校需要的正式文件和证据目录 | 导出、核对、作废、归档 |
| 专业群助手任务页 | 跨查询、编制和改稿持续协助 | 理解、计划、生成草稿、等待确认、写回 |

## 3. 总体流程

```text
自然语言提出问题（T12）
  → 明确专业群、期间、对象和权限
  → 生成带来源的表格/说明
  → 保存查询快照或进入具体对象

已确认工作、进度和查询快照
  → 周月年总结与下期计划（T09）
  → 或创建正式成果编制任务（T13）
  → 固定模板、期间、截止点和输入版本
  → 生成章节草稿、表格、引用和缺项
  → 用户按指定口径或反馈局部改稿（T14）
  → 独立审核
  → 导出、归档和后续影响复核
```

## 4. T12：自然语言查询进度并形成表格

### 4.1 查询入口

用户可以从工作台、专业群助手、指标页、教师页或专业档案提出日常问题，例如：

- “今年还有哪些任务书指标没有达成？”
- “张老师本月完成了什么，还缺哪些材料？”
- “五个专业分别提交了哪些建设成果？”
- “哪些指标只是材料不足，哪些工作还没做？”

### 4.2 范围确定

智能体先使用当前页面的专业群、建设周期和角色；缺少统计期间或问题涉及多个专业群时，明确提示用户选择。查询范围随结果一同保存。

### 4.3 查询计划

助手展示准备读取的对象类型、是否需要运行进度计算、结果栏目和可能缺少的信息。只读查询不要求额外确认，但不能超出当前用户权限。

### 4.4 查询结果结构

默认表格可按问题调整，至少能展示：专业/责任人、任务或指标、目标、已确认内容、待完成内容、缺失材料、节点、数据截止点和资料更新时间。

表格之外同时显示：

- 使用的范围和统计口径；
- 已确认事实与系统计算；
- 未找到、未确认或冲突内容；
- 来源入口；
- 可以继续执行的动作。

### 4.5 查询后的动作

用户可以：

- 进入指标、任务、教师、材料或报告详情；
- 保存查询快照；
- 导出表格内容；
- 把缺项转入差距工作台；
- 以当前结果创建周期总结或成果编制任务。

### 4.6 写回边界

普通查询不改变业务状态。保存快照只固定当时的范围和结果；转成任务或编制输入时需要明确写回动作和人工确认。

## 5. T09：周月年总结和下一周期计划

### 5.1 与即时查询的区别

查询回答“现在看到什么”，周期总结是一个需要编辑、确认和持续承接的正式业务对象。它固定期间、原计划、已确认事实、计划差异、遗留事项和下期安排。

### 5.2 新建总结

用户选择周、月或年、专业群/部门口径、统计期间和模板。系统固定输入快照，并列出未确认和更新时间过旧的资料。

### 5.3 智能体生成

助手按“本期完成—计划与实际差异—未完成及原因—遗留事项—下期计划”生成草稿，每条事实附来源。建议性内容明确标为计划或建议。

### 5.4 编辑与确认

用户可直接编辑、增加人工判断、调整表达和安排。负责人确认总结后，遗留或下期事项可选择生成任务；不能因写进总结就自动派发。

### 5.5 定时与手工

手工发起和定时生成分别配置。定时只产生待编辑草稿，不能自动发布或替负责人确认。

### 5.6 写回

保存总结版本、引用、遗留关系、下期计划和后续任务。总结不会反向覆盖任务、工作和指标源事实。

## 6. T13：用平时积累形成正式成果

### 6.1 创建成果编制任务

用户选择成果类型，例如：

- 专业群建设年度报告或年度自评；
- 中期评审材料；
- 终期验收材料；
- 国家级人工智能试点校申报材料；
- 省级“人工智能+教育”应用场景申报材料；
- 后续新增的学校正式成果。

如果模板、通知或提交格式尚未提供，任务进入“资料不足”，助手列出所需条件，不直接套用未经确认的通用模板。

### 6.2 冻结编制条件

编制任务固定：

- 学校、专业群和建设周期；
- 成果类型和使用者；
- 模板及版本；
- 正式通知、填写说明和历史样例；
- 统计期间和数据截止点；
- 指标修订和计算快照；
- 输入材料、事实和工作版本；
- 编写人、负责人和审核人；
- 提交格式和截止时间。

### 6.3 编制前检查

系统先显示：模板章节、必填字段、已有内容、缺失内容、口径冲突、过期材料和待确认数字。负责人决定是否在缺项状态下先形成草稿。

### 6.4 章节编写

中间为可编辑正文和表格；左侧为模板目录与章节状态；右侧为事实卡、来源、引用、缺项和专业群助手。助手按章节调用已确认事实，不能只凭相似材料自由拼写。

### 6.5 引用与支撑目录

每个关键事实和数字可回到条款、事实、进度计算、材料版本或口径决定。系统生成支撑材料目录，区分正式证据、过程材料和历史参考。

### 6.6 示例数据走查

年度报告可写：目标新增 3 家，截至 6 月 30 日已确认 A 企业 1 家，B 处于协议确认，D 尚在启动，当前完成 1 家、尚差 2 家。A 的正式协议和活动记录进入支撑目录；B 草稿只能作为过程材料；C 可说明历史基础，不能计入本年度新增。

### 6.7 写回

生成成果编制任务、输入快照、章节草稿版本、引用、缺项和支撑目录。正式成果不反向改写源事实；发现事实错误时返回对应业务对象纠正并重新编制受影响内容。

## 7. T14：按指定分析口径和反馈多轮改稿

### 7.1 接收修改要求

用户可以从章节、整份成果或审核退回意见发起，例如：

- “第三部分按我的意见修改”；
- “从按专业汇总改为按任务书指标汇总”；
- “A、B、C、D 四家企业改成已完成、推进中、历史合作、待开展四类”；
- “删除这一节，保留我手写的开头”。

### 7.2 确认修改范围

系统显示基版本、允许修改章节、人工保护块、分析口径、必须保持的事实和本次审核意见。范围不明确时先询问，不能整篇重写。

### 7.3 形成新版本

助手只读取允许修改范围及其相关来源，生成新草稿版本，同时给出修改前后差异、引用变化和未执行意见的原因。

### 7.4 事实保护

无论怎样调整结构和表达，已确认“目标 3、完成 1、尚差 2”的事实不能被改成更好看的数字；B 的草稿不能写成正式签约，C 不能写成本年度新增。

### 7.5 用户处理

用户可以逐块接受、继续编辑、恢复基版本内容或拒绝建议。接受结果仍是草稿，只有提交审核后才进入成果审核。

### 7.6 写回

写回修改要求、范围、新版本、差异、引用核验和修改说明。多轮改稿形成连续版本链。

## 8. 审核、导出与归档

### 8.1 提交审核

编写人提交确切版本和哈希。系统检查模板必填项、待确认数字、无来源关键事实、失效引用和缺少附件。

### 8.2 独立审核

审核人查看成果版本、事实核对、引用状态、缺项、修改历史和支撑目录。可退回并说明具体章节与原因，或批准当前版本。作者不能自审。

### 8.3 重新审核

退回修改生成新版本，原批准或退回记录保留。新版本必须重新提交，不能沿用旧版本批准状态。

### 8.4 导出

草稿可带明显标识导出供内部修改；正式导出必须来自批准版本。Word/PDF、附件目录、命名规则和在线填报内容按模板配置。

### 8.5 归档和影响

归档保存模板、输入快照、正文、引用、审核和导出件。以后依据或证据失效时，系统提示受影响成果并由负责人决定是否重审或作废，不静默修改归档正文。

## 9. 页面连续导航

```text
问题已理解
  → 查询范围已确定
  → 查询结果与来源
  → 保存快照 / 创建总结 / 创建成果任务
  → 模板与输入检查
  → 章节编写
  → 指定范围改稿
  → 审核
  → 导出与归档
```

主节点页与子页面互相连接：查询结果可进入具体对象，章节可打开引用来源，审核意见可直接进入被退回章节，归档成果可回查当时的输入快照。

## 10. 专业群智能体的产品角色

### 查询时

澄清范围、组织结果、说明来源和未知项，并提供下一步动作。

### 总结时

对照计划和事实形成草稿，区分遗留与下期建议，不自动派发。

### 编制时

检查模板与材料，按章节组织已确认内容，建立引用和缺项。

### 改稿时

保护人工内容和事实，只修改指定范围，生成版本差异。

### 审核时

可协助检查模板、数字和引用，但不能批准成果。

## 11. 角色分工

| 角色 | 主要动作 |
| --- | --- |
| 教师 | 查询本人工作、补充成果所需事实和材料、修改分工章节 |
| 专业负责人 | 核对专业事实和章节内容 |
| 专业群负责人 | 确认统计口径、总结、编制条件和关键事实 |
| 报告编写人 | 编辑、组织章节、处理缺项和提交审核 |
| 审核人 | 独立退回或批准具体版本 |
| 教务/校级人员 | 按授权范围查看和办理校级成果 |
| 专业群智能体 | 查询、整理、生成草稿、局部改稿、检查和写回 |

## 12. 原型走查脚本

1. 询问“今年还有哪些任务书指标未达成”；
2. 检查结果范围、截止点、来源、缺证据和口径待确认项；
3. 保存查询快照并创建月度总结草稿；
4. 从同一事实创建年度报告编制任务；
5. 选择正式模板、截止点和审核人，查看缺项；
6. 生成一章正文、一个指标表和支撑材料目录；
7. 用户要求第三部分按另一口径修改并保护人工段落；
8. 对比两版差异，核对目标 3、完成 1、尚差 2 未改变；
9. 提交审核，审核人退回一处无效引用；
10. 修复后重新提交并批准；
11. 导出正式 Word/PDF 并回查输入快照与引用；
12. 模拟一份证据失效，检查成果进入影响复核而非自动改写。

## 13. 验收门槛

- 查询、总结和成果编制使用同一套已确认事实和进度快照；
- 即时查询、总结对象和正式成果的状态边界清楚；
- 每份正式成果固定模板、期间、截止点、输入版本和审核人；
- 多轮修改只影响指定范围并保留人工内容与版本差异；
- 关键事实和数字可回到具体来源；
- 缺模板、缺资料、冲突和失效引用不会被隐藏；
- 智能体不能批准、发布或把建议写成完成事实；
- 用户可沿一条主线完成查询到归档，无需依靠讲解人寻找菜单。

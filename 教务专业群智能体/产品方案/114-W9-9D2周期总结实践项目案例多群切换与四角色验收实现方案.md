# W9-9D2 周期总结、实践项目与案例、多专业群切换及四角色验收实现方案

> 版本：v1.0  
> 日期：2026-10-19  
> 状态：已实现并完成合成候选环境验证  
> 依据：需求确认单、产品方案 38—44、71—87、96、105、112—113 及现有 W9-6、W9-7 服务

## 1. 本轮目标

W9-9D1 已把学校模板、事实快照、成果编制、局部改稿、审核边界和文件导出接入正式工作台。D2 继续把已经验证的周期总结、实践项目、实践案例和多专业群范围承载接入同一产品，使负责人、教师、教务审核人员和信息支持人员能够在各自职责内连续工作。

本轮不是重复描述业务条款，也不重新实现后端规则。产品主线是：

```text
同一专业群和建设周期
  ├─ 已固定事实快照 → 周/月/年总结 → 补充说明 → 负责人确认
  ├─ 实践项目 → 过程材料 → 人工结果 → 负责人确认 → 建设任务关系
  │      └─ 已确认项目 → 五章实践案例 → 缺项处理 → 独立审核
  └─ 同一人员获准参与多个专业群时
         → 明确切换范围 → 重新读取本群对象 → 跨群对象不可见、不可办理
```

## 2. 产品边界

1. 周期总结只使用确切事实快照，页面不能编辑事实编号和正式数值；确认总结不自动新建或派发任务。
2. 实践项目记录项目事实、参与人数、材料、人工结果和建设关系；学生只保留汇总人数。
3. 人工结果只能由登记的原责任人确认，项目提交后由专业群负责人确认或退回。
4. 实践案例只从已确认项目及确切项目版本形成；锁定事实章节不可改，反思等允许章节可按审核意见形成新版本。
5. 实践案例审核人与当前版本作者分离；缺项未清零时不能送审。
6. 多专业群切换只使用当前登录人员真实有效的角色授权。切换后必须重取当前范围数据，不能沿用上一群缓存。
7. 信息支持人员只处理运行和支持事项，不读取周期总结正文、实践项目内容、案例正文或业务数量。
8. T15、T16 继续关闭；本轮不增加实时数字人、自然语音、虚拟仿真或未确认的选配能力。

## 3. 正式页面结构

### 3.1 周期总结工作区

在“成果与报告”内增加“周期总结”页签：

- 展示总结编号、类型、期间、事实快照、当前版本和最近决定；
- 从当前范围可用事实快照建立周、月、年总结；
- 详情按“本期完成、计划差异、未完成、遗留事项、下期建议”展示，每项可回到事实编号；
- 负责人只补充编辑说明并形成新版本，不直接修改锁定事实；
- 明确提供退回或确认当前版本的动作和决定记录。

### 3.2 实践项目工作区

新增“实践项目与案例”一级入口。项目列表展示：

- 项目编号、标题、合作单位、期间、责任人、状态；
- 活动次数、学生汇总人数和教师人数；
- 已关联材料、人工结果和建设任务关系数量；
- 当前角色可以执行的下一步。

项目详情把“写项目事实、挂材料、登记人工结果、本人确认结果、提交负责人、退回补充、负责人确认、建立建设关系”组织为连续办理区。页面始终显示当前版本和状态，刷新后从服务端恢复。

### 3.3 实践案例工作区

案例与实践项目并列呈现，但明确说明案例来自已确认项目。案例详情展示：

- 固定项目版本、五章正文及每章引用；
- 缺项、事实锁定、允许修改的章节；
- 当前版本、版本差异、送审和审核决定；
- 负责人按退回意见局部修改，教务审核人员对指定版本退回或批准。

### 3.4 多专业群范围切换

顶部范围区从 `/me` 的有效角色形成可选范围：

- 显示学校、专业群、建设周期和当前角色；
- 同一群有多个角色时可以切换角色；同一人员有多个群授权时可以切换专业群与周期；
- 切换后重新验证所选角色，清空当前页面临时状态并回到总览；
- 页面不接受手工输入无授权的专业群或周期；
- 当前范围的页面标题、列表请求和写入信封必须一致。

## 4. 最小接口增量

现有服务已经有详情和写接口，正式页面只补可发现列表：

1. `GET /cycle-summaries`：返回当前范围总结、当前版本和最近决定；
2. `GET /practice-projects`：返回当前角色可读项目的当前状态及关系数量；
3. `GET /practice-cases`：返回当前角色可读案例的当前版本、缺项和审核状态。

列表沿用现有读取权限与专业范围：

- 负责人读取本群；
- 教师只读取本人负责或获专业授权的项目与相应案例；
- 教务审核人员只读取其获准审核范围；
- 信息支持人员返回空集合；
- 跨学校、跨群、跨周期、跨专业对象不泄露标题、数量或存在性。

多专业群切换不新增服务端“代切换”接口，继续由 `/me` 返回的真实角色授权和每次请求的明确范围共同约束。

## 6. 四角色页面责任

| 角色 | 周期总结 | 实践项目 | 实践案例 | 多群切换 |
| --- | --- | --- | --- | --- |
| 专业群负责人 | 建立、改稿、确认或退回 | 建立、查看、退回或确认、建立建设关系 | 建立、改稿、送审 | 仅切换到本人有效授权范围 |
| 教师 | 首批不建立群级总结 | 建立本人项目、写事实、挂材料、确认本人结果、提交 | 读取本人项目形成的案例，不承担独立审核 | 仅切换到本人有效授权范围 |
| 教务审核人员 | 读取获准范围 | 读取获准范围 | 办理指定给本人的退回或批准 | 仅切换到本人有效授权范围 |
| 信息支持人员 | 不读正文和数量 | 不读业务内容和数量 | 不读正文和数量 | 只进入获准的支持范围 |

前端是否显示按钮只帮助使用，不能替代服务端再次授权。

## 7. 自测与候选验收门槛

### 7.1 自动验证

1. 三个列表在负责人、教师、审核人员和信息支持人员下分别返回符合现有权限的内容；
2. 跨范围请求不返回标题、数量或对象存在性；
3. OpenAPI 操作数增加 3，既有路径的写语义不变；
4. 周期总结、实践项目、实践案例原有完整状态链继续通过；
5. Web 构建、页面测试、API 类型检查和累积集成测试通过。

### 7.2 浏览器连续办理

候选环境至少完成：

1. 负责人从快照建立周期总结，查看五类条目，补充说明并形成新版本；
2. 教师建立或进入本人实践项目，填写事实、关联确切材料版本、登记并确认本人结果后提交；
3. 负责人退回或确认项目，并对已确认项目建立建设任务关系；
4. 负责人从已确认项目建立案例，页面准确显示缺项和五章引用；
5. 负责人送审，独立教务审核人员退回或批准确切版本；
6. 同一人员在两个获准专业群间切换，页面数据、标题和操作范围同步变化；
7. 信息支持人员业务页面为空或无权，但支持职责入口保持可用；
8. 刷新、退出再进入后，版本、状态、关系和决定均从数据库恢复。

候选库缺少某角色或某类真实可办数据时，使用正常身份与角色管理接口补充合成角色和合成事项；不得修改数据库伪造页面通过。无法在浏览器完成的门槛必须明确保留，不用接口测试冒充页面验收。

## 8. 异常恢复与停止规则

1. 版本冲突：保留输入，重新读取当前版本，提示用户核对后再提交；不自动覆盖。
2. 写入结果未知：保留操作编号并进入对账提示；不自动重发。
3. 会话失效或角色撤销：清除当前工作范围并回到进入页；不继续使用旧页面数据。
4. 切换范围失败：保留原有效范围，不形成半切换状态。
5. 材料、快照或项目版本已变化：拒绝使用过期版本，要求重新选择。
6. 页面需要放宽现有权限或改变已经验证的状态机时停止编码，先修改方案并重新评审。

## 9. 完成口径

D2 只有在三个工作区、真实范围切换、四角色浏览器链和异常恢复均通过后才可以标记完成。完成 D2 仍不等于学校现场验收；W10 还需要学校提供真实范围、模板、人员、资料和环境并逐项签收。


## 10. 实现与验证结果

本方案已经按最小增量实现。周期总结、实践项目、实践案例、多专业群切换及四角色页面均接入正式工作台；三个列表接口、OpenAPI 契约、权限过滤和页面办理链通过自动验证。候选浏览器完成负责人、教师、教务审核和信息支持四角色核对。

验收中发现项目材料按全部历史版本重复统计，已修正为只显示当前版本材料；历史关系继续保留在数据库与建设账本。完整证据见第 115 份验证记录和工程 `evidence/W9-9/2026-10-19-d2-cycle-practice-scope-role-validation.md`。

D2 完成仍不代表学校现场验收。下一阶段只在学校确认真实范围、人员、资料和环境后进入 W10-B。

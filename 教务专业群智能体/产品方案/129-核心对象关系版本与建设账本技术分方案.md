# 核心对象、关系、版本与建设账本技术分方案

> 版本：v0.1 评审准备稿  
> 日期：2026-10-19  
> 状态：评审稿编制完成，等待内部评审；尚未冻结，不编码  
> 设计目的：为重写入工作台、专业群知识库和智能体受控执行提供同一套可信事实底座

## 1. 设计原则

1. 稳定对象与可变内容分开；
2. 内容修改形成新版本，不覆盖旧版本；
3. 关系是独立的业务事实，不隐藏在备注或文档正文中；
4. 智能体建议、系统计算和人工确认分别保存；
5. 状态变化和人工决定针对确切版本；
6. 同一业务动作中的版本、关系、决定和账本保持一致；
7. 历史只能追加更正和替代，普通业务操作不能抹去；
8. 当前状态可以快速查看，历史过程仍能完整重建。

## 2. 核心对象域

| 对象域 | 主要对象 | 解决的问题 |
| --- | --- | --- |
| 范围与组织 | 学校、部门、专业群、专业、人员、任职、建设周期 | 谁在什么范围内参与建设 |
| 建设依据 | 依据文件、文件版本、原文条款、建设要求、冲突、决定 | 建设要求从哪里来、当前以哪个版本为准 |
| 目标与指标 | 目标、指标、年度目标、统计规则、证据要求 | 要达到什么、怎样判断 |
| 计划与任务 | 年/月/周计划、计划版本、任务、节点、责任 | 工作怎样分解和安排 |
| 日常工作 | 工作记录、参与人、结果、提交、退回 | 实际做了什么、怎样核对 |
| 资料与证据 | 材料、材料版本、内容单元、用途、证据关系、审核 | 有哪些来源、能证明什么 |
| 进度与问题 | 计算运行、输入快照、进度结论、差距、问题、措施 | 完成多少、还差什么、下一步是什么 |
| 成果与报告 | 模板、模板版本、成果、成果版本、章节、引用、审核、导出 | 怎样形成正式结果 |
| 智能体任务 | 请求、范围、知识包、计划、动作、回执、候选结果、确认 | 智能体怎样受控参与 |
| 可信记录 | 状态变化、人工决定、关系变化、建设账本、归档快照 | 过程怎样追溯和恢复 |

## 3. 稳定对象与版本

稳定对象保存编号、所属范围、对象类别和建立时间。版本保存可变化的名称、正文、目标值、负责人说明、结构和业务字段。

```text
对象 O-001
  ├─ 版本 V1：初始内容
  ├─ 版本 V2：根据退回意见修改
  └─ 当前版本指针 → V2
```

建立新版本时必须声明所依据的当前版本。如果提交时当前版本已变化，系统返回冲突和差异摘要，由用户重新检查，不能自动覆盖。

## 4. 关系模型

关系至少记录：

- 关系类型；
- 起点对象和版本；
- 终点对象和版本或稳定对象；
- 所属学校、专业群和建设周期；
- 来源、提出方式和理由；
- 候选、已确认、已拒绝、已撤回或已失效状态；
- 提出人、确认人和有效期；
- 替代或影响的关系。

重点关系包括：属于、负责、参与、来源于、分解为、支撑、对应、引用、替代、影响、共享和汇总。跨专业共同成果通过多条参与关系表达，不复制成多份成果。

## 5. 人工决定

人工决定单独记录，不写进对象备注。决定包括：

- 确认依据版本；
- 处理文件冲突；
- 确认事实或证据关系；
- 批准任务调整；
- 确认指标进度；
- 审核成果版本；
- 批准跨群共享、正式导出或撤回。

决定记录对象、版本、决定类型、结论、理由、决定人、角色、时间和适用范围。撤销决定通过新的决定记录完成。

## 6. 状态变化

状态变化记录前状态、动作、后状态、操作者、依据版本、原因和时间。不同对象使用各自状态机，但共享以下规则：

1. 页面只展示当前允许的动作；
2. 服务端再次校验状态转换；
3. 退回必须保留原因和待补要求；
4. 已确认或已审核对象修改后重新进入相应确认流程；
5. 失败或拒绝不伪造成成功状态；
6. 任务状态不直接改写指标状态。

## 7. 建设账本

建设账本是追加式业务操作记录，至少包括：

- 操作编号和请求编号；
- 学校、专业群、专业和建设周期；
- 操作者、角色和代理方式；
- 业务动作和对象；
- 操作前版本和操作后版本；
- 新增、确认、拒绝、撤回或替代的关系；
- 人工决定引用；
- 结果：成功、拒绝、冲突、失败、结果待核对或已恢复；
- 时间和关联回执。

账本不复制大文件和敏感正文，只保存可回查引用、摘要和校验信息。普通用户不能修改或删除既有账本记录。

## 8. 一次写操作的原子边界

以“负责人确认 A 企业材料支撑 2026 年新增合作企业指标”为例，同一业务事务需要共同完成：

1. 校验负责人角色、专业群范围和当前材料版本；
2. 校验年度指标、统计规则和材料业务日期；
3. 建立正式证据关系；
4. 建立人工确认决定；
5. 必要时形成进度重新计算待办，但不直接改写正式进度；
6. 写入建设账本；
7. 返回对象、关系、决定和账本编号。

任何一步失败，本次正式确认都不应处于部分成功状态。

## 9. 快照与历史报告

周期总结、指标计算和成果编制固定输入快照。快照保存对象和版本清单、规则版本、统计截止时间和范围条件。后续新增工作或资料不会静默改变既有总结和报告；需要更新时建立新快照和新成果版本。

## 10. 去重与幂等

- 文件内容指纹用于发现重复文件，但不同学校和专业群不能因此共享正文；
- 同一材料的扫描件和电子版可进入重复候选组，由人员判断关系；
- 同一业务请求编号重复提交返回原结果；
- 幂等不能掩盖输入版本变化，版本不同视为新的业务意图；
- 重复材料不等于重复成果，业务去重仍需规则和人工决定。

## 11. 删除、更正和归档

未被引用且仍为个人草稿的对象可以按学校规则删除或作废；已提交、已确认、已引用或已归档的内容通过撤回、失效、更正版本和替代关系处理。学校的数据处置权需要与历史可追溯、审计和正式成果完整性共同设计，具体保留期限待评审。

## 12. 多专业群范围

对象和关系均带范围。跨群关系必须显式授权，不能通过相同编号、相同文件指纹或相似内容自动建立。新群初始化产生新的对象编号和独立版本链。

## 13. 评审用例

1. 两名人员同时修改同一工作记录，后提交者收到版本冲突；
2. 教师提交 v1，负责人退回，教师补充形成 v2，两个版本均可查看；
3. A 企业材料被确认支撑指标，关系和决定可追溯；
4. C 企业为历史合作，不能因材料在 2026 年上传而计入当年新增；
5. 规则换版后重新计算形成新运行，旧报告仍使用旧快照；
6. 重复请求不产生两项任务；
7. 撤回正式关系后保留原确认与撤回决定；
8. 跨专业群已知编号不能读取对象信息。

## 14. 待评审事项

- 哪些对象必须版本化，哪些简单配置只保留变更记录；
- 正式归档后的更正规则和保留期限；
- 跨专业共同成果的贡献与计数关系；
- 人工决定是否需要电子签名或双人确认；
- 建设账本对学校普通用户、审核人员和审计人员的展示范围；
- 历史数据导入时怎样标记来源可信度和缺失信息。

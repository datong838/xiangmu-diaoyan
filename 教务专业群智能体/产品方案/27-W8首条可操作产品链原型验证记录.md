## 1. 本轮目标

把“2026 年新增合作企业 3 家”从总览中的局部交互扩展为一条可连续进入的产品办理链：

```text
建设依据
  → 任务分解
  → 工作提交
  → 事实证据
  → 进度判断
  → 差距处理
  → 成果编制
```

## 3. 产品实现内容

### 3.1 全站七步办理导航

业务页面顶部持续显示当前指标及七个办理节点。用户可直接进入前后步骤，不需要返回左侧菜单。总览提供“开始办理”；进度判断和差距处理提供明确的后续入口。

### 3.2 进度判断页

页面固定当前指标、统计期间、规则版本和数据截止点；逐项显示 A—D 企业事实和材料结论；将系统计算“1/3”与学校确认分开。审核人员可以退回核对或确认当前阶段结论，页面说明确认后保存所用规则、材料版本、人员和截止点。

### 3.3 差距处理页

页面把同一个差距拆成三种原因：B 为材料不足，C 为期间不符，D 为工作尚未发生。每项建议都显示责任人、完成节点、预期产出和来源快照；只有点击“确认并建立任务”后才转为已确认状态。

## 4. 与产品方案的一致性

| 产品要求 | 原型承载 |
| --- | --- |
| 系统计算与人工结论分开 | 进度页左右分区并使用独立状态 |
| 完成率不能直接手改 | 页面只显示计算结果，没有完成率编辑入口 |
| 差距按原因处理 | B、C、D 使用不同原因和动作 |
| 智能体建议不能自动派发 | 差距页明确建议草稿，按钮由负责人确认 |
| C 年度不符不能补附件计入 | C 的动作是归入历史资料，不计入本年新增 |
| 补充任务完成后重新计算 | 页面说明返回进度判断重新计算 |
| 页面连续导航 | 七个节点全站持续可见，可逐项进入 |

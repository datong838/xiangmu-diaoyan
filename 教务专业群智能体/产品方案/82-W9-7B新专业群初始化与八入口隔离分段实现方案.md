# W9-7B 新专业群初始化与八入口隔离分段实现方案

> 版本：v1.2　日期：2026-10-19　状态：B1、B2 均已在合成环境验证，W9-7B 整波完成。  
> 前置：12、25、31、38—43、77、80—81。  
> 本文职责：把 T18 从前端初始化演示转成真实范围对象、独立配置、启用门槛和八入口零泄露验证。

## 1. 本段目标

在同一学校中，以一个已经验证的专业群作为方法参考，建立另一个拥有独立编号、建设周期、专业关系、人员权限、建设依据、指标和报告模板的新专业群。系统只记录参考了哪些结构和规则，不复制源群业务事实。

W9-7B 分为两个可独立验证的工程段：

- **B1 初始化草稿与独立配置门槛**：建立新群和周期的初始化范围，记录结构参考，逐项核对新群自己的配置，负责人确认后启用；
- **B2 八入口隔离与独立变化**：对列表/详情、知识搜索、智能体、数量统计、材料下载、报告、导出和建设账本执行真实跨群拒绝与零泄露检查，并验证源群归档、模板变化不影响新群。

B1 通过只开启 `groupInitializationEnabled`；B2 全部通过后才开启 `crossGroupIsolationVerified`。W9-7B 通过不代表学校真实第二专业群已经确定或投入使用。

## 2. 初始化对象

### 2.1 初始化记录

`group_initializations` 保存：

- 学校、源专业群和源建设周期；
- 新专业群、新建设周期；
- 发起人、目标负责人；
- 当前状态版本和当前检查版本；
- 建立时间。

`group_initialization_state_versions` 逐版保存状态、所依据的检查版本、变化原因、确认人和内容摘要；`group_initializations.current_version_id` 只指向最新版本。状态采用：`draft → ready_for_activation → active`，也可从 `draft` 或 `ready_for_activation` 进入 `cancelled`。每次检查、启用和取消都追加状态版本，旧版本禁止修改或删除。

### 2.2 结构参考

`group_initialization_structure_refs` 只允许以下白名单：

1. `object_model`：对象结构版本；
2. `workflow_rule`：办理流程编码或版本；
3. `template_schema`：模板栏目结构版本；
4. `role_type`：角色类型；
5. `acceptance_script`：验收脚本版本。

每条只保存类型、编码、来源对象/版本、用途和摘要，不保存源群正文。源对象后续变化不会自动改变新群已经确认的参考记录。

### 2.3 禁止复制检查

`group_initialization_forbidden_checks` 固定检查：

- 依据正文和正式知识；
- 人员及授权；
- 企业和实践项目；
- 目标值、完成值和进度；
- 材料及文件；
- 审核决定；
- 报告正文和导出件；
- 智能体任务、知识包和对话。

每项保存检查范围、检查时的源群数量、目标群数量、命中对象摘要和结论。B1 要求初始化刚建立时目标群上述业务对象数量均为 0。

### 2.4 配置检查版本

`group_initialization_checks` 和 `group_initialization_check_items` 固定一次检查的范围、截止点和结果。检查完成后追加一个初始化状态版本：全部通过进入 `ready_for_activation`，有缺项保持 `draft`。B1 的五项独立配置为：

1. 至少一个已确认专业关系；
2. 新群自己的申报书、任务书和实施方案三类批准依据；
3. 至少一名当前有效的专业群负责人；
4. 至少一条本群指标规则；
5. 至少一个本群报告模板版本。

检查结果只能来自目标群数据库事实，不能由请求方传入“已完成”。缺项形成具体数量和对象类型，不能启用。

### 2.5 启用决定

`group_initialization_decisions` 固定检查版本、检查摘要、决定人和原因。只有目标群当前有效负责人可以启用；启用时再次计算五项配置，检查版本过期或事实变化时拒绝。启用后目标群和周期从 `initializing` 变为 `active`。

## 3. B1 接口

1. `POST /group-initializations`：源群负责人发起初始化，原子建立目标群、目标周期、目标负责人授权、结构参考和禁止复制基线检查；
2. `GET /group-initializations/{initializationId}`：查看初始化、全部状态版本、结构参考、禁止复制检查、配置检查版本和决定；
3. `POST /group-initializations/{initializationId}/checks`：提交当前初始化状态版本，重新计算五项独立配置，形成不可变检查和新状态版本；
4. `POST /group-initializations/{initializationId}/activate`：提交当前初始化状态版本和确切通过检查版本，由目标群负责人确认启用；
5. `POST /group-initializations/{initializationId}/cancel`：提交当前初始化状态版本，在启用前取消，目标群和周期转为归档，不删除记录。

建立接口使用源群范围；后续检查和启用接口使用目标群范围。这样可避免持有源群权限的人在没有目标群授权时继续操作。

## 4. B1 事务与失败规则

建立初始化必须在一个数据库事务中完成：初始化记录、目标群、目标群首版本、目标周期、目标负责人授权、结构参考、禁止复制基线、操作回执、建设账本和 Outbox 任一失败，全部回滚。

目标编号、周期编号、结构参考或目标负责人无效时拒绝，不留下目标群。相同幂等请求返回原回执；相同幂等键不同内容冲突。不能使用源群编号或源周期编号，也不能把目标建到另一学校。

目标群处于 `initializing` 时，只允许初始化配置类写入，不进入普通使用列表。首批通过接口显式读取和办理，不能依赖前端隐藏。

## 5. B2 八入口隔离矩阵

| 入口 | 正向检查 | 跨群拒绝或零召回 |
| --- | --- | --- |
| 列表/详情 | 目标群只见本群对象 | 已知源对象编号直接访问返回不可见 |
| 知识搜索 | 目标群只命中本群正式知识 | 搜源群企业、人名、指标原文为 0 |
| 智能体 | 目标群知识包只固定本群引用 | 传入源群目标对象时拒绝 |
| 数量统计 | 目标群计数只含本群 | 不因源群存在而增加 |
| 材料下载 | 目标群授权只对本群材料版本 | 源群下载凭证不能在目标群复用 |
| 报告 | 目标群成果只引用本群快照 | 不能选择源群快照或模板正文 |
| 导出 | 导出包只含目标群文件与摘要 | 无源群标题、材料或报告内容 |
| 建设账本 | 目标群账本链独立连续 | 不返回源群操作、编号或摘要 |

任何一个入口泄露标题、数量、摘要、正文、文件名或对象存在性，B2 均不通过。

## 6. 角色和权限

- 源专业群负责人：可以发起初始化，并选择目标负责人；不能因源群身份自动查看目标群业务；
- 目标专业群负责人：获得一条明确的新群授权，负责独立配置、检查和启用；
- 教师：只有获得目标群及专业授权后，才能进入目标群办理；
- 教务审核人员：按目标群明确授权处理指定审核，不自动沿用源群审核范围；
- 信息支持人员：只可读取初始化技术状态、错误类型和检查编号，不见任何业务正文；
- 专业群智能体：每个任务固定一个专业群和周期，切换群必须建立新的任务范围。

同一人员兼任两个群时，两条授权独立存在。请求必须显式携带当前群和周期，系统不使用“上次所在群”或默认群。

## 7. 不复制清单

B1/B2 明确禁止复制：

- 申报书、任务书、实施方案正文及正式知识；
- 专业、教师、企业、学生或其他人员身份；
- 目标值、完成值、任务、工作记录、材料和进度；
- 权限、审核决定、成果、报告正文、导出件和归档；
- 智能体任务、知识包、计划、动作结果和历史消息；
- A—D 企业、张老师及“目标 3、完成 1、尚差 2”等合成事实。

专业和人员即使现实中相同，也必须通过目标群独立关系与授权重新登记，不能复制源关系行。

## 8. 贯穿验证案例

源群继续使用现有合成人工智能专业群及 2026—2028 周期，含 A—D 企业、指标 1/3、任务、材料、报告和实践案例。建立 `NEW-G02`：

1. 发起初始化后，NEW-G02 只有独立群、周期、目标负责人授权和结构参考；禁止复制八类对象数量均为 0；
2. 此时运行配置检查，应列出专业关系、三类依据、指标和模板缺项，不能启用；
3. 在 NEW-G02 范围独立建立专业、三类依据、指标和模板；
4. 再次检查五项配置全部通过；
5. 使用确切检查版本由目标负责人启用；
6. B2 对八个入口运行正向和拒绝检查，搜索“A 企业”“张老师”和“新增合作企业 3 家”均不能返回源群事实；
7. 源群后续模板变化或归档不改变 NEW-G02 已确认结构和启用状态。

## 9. 分段通过门槛

### 9.1 B1

1. 初始化事务失败不留下专业群、周期、授权或参考记录；
2. 新群编号和周期独立，目标负责人授权为新建事实；
3. 结构参考只包含五类白名单，不含源群正文；
4. 八类禁止复制对象初始数量均为 0；
5. 五项配置由数据库事实计算，缺项时不能启用，每次检查都形成新的不可变状态版本；
6. 通过检查后只有目标负责人能用确切初始化状态版本和检查版本启用；
7. 取消、重复提交、过期检查和越权均有明确拒绝；
8. 源群对象、状态和账本不被初始化改写。

### 9.2 B2

1. 八入口正向使用均落在目标群范围；
2. 八入口跨群编号直访、查询和引用全部拒绝或零召回；
3. 同一人员双群任职仍按请求范围独立授权；
4. 源群归档和模板变化不改变目标群；
5. 全新数据库迁移、重复迁移、全量测试和恢复前后隔离检查通过。

## 10. 实现边界与下一步

B1 首批不自动复制模板章节；只记录可参考的模板结构版本，目标群仍需建立自己的模板版本。这样可以先证明“参考关系”和“新群事实”分开，避免把源模板正文作为隐性业务复制。

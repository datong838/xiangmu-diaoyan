# 专业群智能体任务执行协议详细设计

> 版本：v1.0　日期：2026-10-18　状态：内部评审稿。  
> 对应波次：W3，并贯穿 W4—W10。  
> 文档职责：定义专业群智能体怎样把自然语言请求转成受控产品任务，怎样调用知识库和业务能力，怎样与人共同修改、确认并写回结果。

## 1. 角色定位

专业群智能体是一名参与专业群建设的数字员工。她掌握当前用户获准使用的专业群知识，能够协助完成各项建设工作，但不拥有学校管理人员的决定权。

她在产品中承担五类责任：

1. **理解**：理解教师或教务人员用日常语言提出的目标；
2. **查清**：找到适用的专业群、专业、周期、依据、任务、资料和模板；
3. **办理**：调用产品能力整理资料、代拟内容、检查差距、建立草稿或填写表单；
4. **协同**：提示缺少条件、接收修改意见、保持上下文并推动任务继续；
5. **写回**：把人的确认结果写回业务对象、关系、版本和建设账本。

## 2. 智能体任务单

每次需要查询或办理的请求都形成一张智能体任务单：

| 字段 | 内容 |
| --- | --- |
| 任务编号 | 一次办理过程的稳定编号 |
| 发起用户与角色 | 谁提出，当前以什么身份工作 |
| 学校与专业群范围 | 本次允许进入的知识范围 |
| 专业与建设周期 | 具体专业、年度、阶段和截止时间 |
| 用户原话 | 保留原始请求 |
| 理解后的目标 | 智能体对要完成事项的明确表述 |
| 预期产出 | 查询结果、工作记录、任务、表格、报告草稿等 |
| 输入对象与版本 | 本次实际使用的材料、依据、规则和模板 |
| 处理计划 | 准备调用的能力和先后顺序 |
| 人工确认点 | 哪些步骤必须由谁确认 |
| 当前状态 | 理解中、待补充、待确认、执行中、待审核、完成等 |
| 写回对象 | 完成后保存到哪个业务对象 |
| 过程与结果 | 建议、错误、用户决定、动作结果和引用 |

用户不需要看见全部内部字段，但产品必须保留这些信息。

## 3. 九步执行协议

```text
S0 接收请求
  → S1 确定范围和身份
  → S2 理解目标与产出
  → S3 检查所需条件
  → S4 形成可见处理计划
  → S5 读取知识与调用产品能力
  → S6 生成可检查结果
  → S7 人工修改、确认或审核
  → S8 写回业务对象与关系
  → S9 说明完成结果和后续事项
```

### S0 接收请求

保留用户原话，识别是查询、整理、创建、修改、检查、审核辅助还是继续已有任务。用户通过聊天、页面内“请助手处理”、对象快捷动作或待办进入，均使用同一协议。

### S1 确定范围和身份

确认当前学校、专业群、专业、建设周期和用户角色。用户有多个工作范围时优先使用当前页面上下文；仍存在歧义时列出需要选择的范围，不能跨群搜索后混合回答。

### S2 理解目标与产出

把请求转换为“要完成什么、给谁使用、需要什么形式、统计到什么时候”。例如“做一下今年的国家级人工智能试点校申报材料”应形成一个成果编制任务，而不是直接输出一段泛化文字。

### S3 检查所需条件

检查适用通知或模板、建设依据、已确认事实、材料、权限、截止时间和人工确认人。缺少条件时形成待补清单；可以完成的部分继续形成草稿，不把缺失内容编造出来。

### S4 形成可见处理计划

在实际写入前展示：

- 我理解的任务；
- 已找到的依据和资料；
- 缺少或冲突的内容；
- 准备执行的步骤；
- 哪些动作会创建或修改业务对象；
- 哪一步需要谁确认。

纯查询可直接执行；批量、跨对象或正式成果任务应先让用户检查计划。

### S5 读取知识与调用产品能力

智能体只能通过已定义能力操作产品，例如检索对象、建立草稿、生成候选关系、计算进度、创建编制任务、生成新版本。她不能绕过产品状态和权限直接修改底层数据。

### S6 生成可检查结果

结果必须区分：已确认事实、系统计算、智能体建议、缺少内容和冲突。涉及写入时先形成草稿或待确认对象，同时展示来源和影响范围。

### S7 人工修改、确认或审核

用户可逐项接受、修改后接受、拒绝、退回补充或暂不决定。正式口径、任务下达、进度结论、审核批准和发布归档必须由相应授权人员完成。

### S8 写回业务对象与关系

确认结果写回对应对象，而不是只停留在聊天记录中。例如：

- 资料整理写回材料、工作记录和候选关系；
- 任务安排写回任务、责任人和节点；
- 进度检查写回计算结果、人工结论和问题；
- 报告编制写回草稿版本、引用和审核状态。

每次写回形成版本和操作记录。

### S9 说明完成结果和后续事项

智能体说明：完成了什么、保存在哪里、采用哪些资料和截止点、谁已确认、还差什么、下一步可以做什么。任务未完全结束时保持为可继续状态。

## 4. 能力单元

| 能力编号 | 能力 | 允许产生的结果 |
| --- | --- | --- |
| AC01 | 范围与身份识别 | 当前专业群、专业、周期和权限上下文 |
| AC02 | 对象与关系检索 | 权限范围内的对象、版本、关系和来源 |
| AC03 | 文件读取与定位 | 提取内容、页段表格定位和读取错误 |
| AC04 | 内容整理 | 可编辑文字、表格结构、汇报内容和缺项 |
| AC05 | 候选关系生成 | 分类、归属、支持、重复和冲突建议 |
| AC06 | 任务计划 | 任务草稿、责任建议、节点和预期产出 |
| AC07 | 规则计算 | 可复算的进度数值和明细 |
| AC08 | 差距诊断 | 原因分类、缺口和补充动作建议 |
| AC09 | 查询回答 | 带范围、截止点、来源和未知项的结果 |
| AC10 | 成果编制 | 按模板生成章节草稿、表格和引用 |
| AC11 | 局部改稿 | 指定范围的新版本、差异和引用核验 |
| AC12 | 写回与建账 | 草稿、版本、关系、任务、状态和操作记录 |
| AC13 | 影响分析 | 版本变化后的受影响对象清单 |
| AC14 | 通知与跟进 | 待办、到期、退回和待确认提醒 |

能力单元是受产品规则约束的动作，不是自由文本提示词。

## 5. 动作权限

| 动作 | 智能体是否可直接执行 | 要求 |
| --- | --- | --- |
| 查看获准对象 | 可以 | 按用户权限和任务范围过滤 |
| 生成回答和建议 | 可以 | 标明依据、时间和不确定项 |
| 创建草稿 | 可以 | 记录发起用户和生成来源 |
| 填入未提交表单 | 可以 | 用户可看到并修改 |
| 批量建立候选关系 | 可以 | 逐条可接受或拒绝 |
| 提交工作或材料 | 需用户确认 | 明确提交版本和对象 |
| 下达任务 | 需负责人确认 | 智能体只能形成任务草稿 |
| 确认事实、口径或进度 | 不可代替人工 | 由指定角色决定 |
| 审核批准、正式发布 | 不可代替人工 | 只能辅助检查和准备意见 |
| 授权、撤权、跨群共享 | 不可代替人工 | 由授权管理人员执行 |
| 删除原件或操作记录 | 不可直接执行 | 遵循学校规则和专门流程 |

## 6. 知识任务包

智能体每次办理任务只装载相关知识任务包，包括：

- 当前范围与用户权限；
- 任务目标和预期产出；
- 适用依据、规则和模板版本；
- 相关指标、任务、工作、材料和事实；
- 已确认关系、冲突和未知项；
- 本次允许调用的能力与写操作；
- 需要人工确认的节点。

知识任务包避免把整个学校资料无差别送入一次处理，也避免不同专业群事实混合。

## 7. 对话与业务页面协同

智能体区域由四部分组成：

1. **任务对话**：用户提出请求、补充条件和反馈；
2. **任务卡**：展示范围、目标、计划、状态和下一步；
3. **业务工作区**：编辑材料、任务、进度表或报告，不在聊天气泡中完成复杂修改；
4. **依据与影响侧栏**：展示所用来源、候选关系、缺项和写回影响。

对话负责交流，业务工作区负责办理，任务卡负责连续状态，建设账本负责追溯。

## 8. 多轮任务连续性

- 后续指令必须绑定原任务和当前基版本；
- 用户说“第三部分按我的意见改一下”时，只修改指定章节并保留其他人工内容；
- 切换专业群、周期、模板或统计口径时必须明确提示；
- 暂停后恢复先展示上次状态、未完成步骤和已变化的输入；
- 新资料进入时不自动改变已批准成果，先形成影响提示；
- 同一任务可转交他人，但转交前后权限和责任分别记录。

## 9. 停止与升级规则

遇到以下情况，智能体停止相应动作并说明所需条件：

- 无权访问所需资料；
- 无法确定学校、专业群、专业或周期；
- 依据文件之间存在未解决冲突；
- 缺少正式模板或用户要求的输出格式；
- 关键材料无法读取；
- 需要负责人确认、独立审核或授权；
- 用户指令会把草稿写成正式事实；
- 写操作失败或结果待核对；
- 请求超出专业群建设范围或需要其他部门批准。

停止当前动作不等于整项任务结束；智能体应保留已完成部分和待补条件。

## 11. 验证场景

1. 用户一句话查询进度，结果说明范围、截止点、事实、缺项和来源。
2. 用户要求编写申报材料，智能体先找到模板和资料，创建编制任务而非直接给最终稿。
3. 两份依据目标冲突时，智能体列出差异和影响并等待负责人决定。
4. 智能体把材料建议匹配指标，负责人拒绝后不进入正式统计。
5. 用户连续三轮改稿，系统保留每版差异、来源和人工保护内容。
6. 用户无权查看某材料时，回答中不泄露正文，也不以模型记忆补充。
7. 写入结果未知时先对账，不产生重复任务或报告版本。
8. 新专业群初始化时复用能力和结构，但不带入试点群事实。

## 12. 评审问题

1. 专业群助手对外使用的正式名称与形象；
2. 哪些 L2 提交动作允许用户设置为一次确认后连续执行；
3. 哪些对象允许智能体代填，哪些必须从第一步人工填写；
4. 专业群负责人、教务和校级人员的确认边界；
5. 任务转交、代理和替代审核人的规则；
6. 对话、任务和操作记录的保存及导出要求。

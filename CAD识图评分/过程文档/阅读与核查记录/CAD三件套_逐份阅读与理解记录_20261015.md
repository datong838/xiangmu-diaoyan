## 二 三件套的整体含义

三件套不是三份孤立的采购或归档文件，而是把资料转为可复用审查能力的建设路径：

**资料及图纸 → 来源核准与事实提取 → 判据和知识 → 经确认的正反案例 → 按对象与语境检索 → 审查、解释与改进 → 专家纠正后积累。**

- 判据库解决“凭什么、在什么条件下能判”，核心为读取层、出处层、命题层、应用层分开，保留适用条件和例外。
- 知识资料解决“这是什么、为什么、何时适用”，资料源包含国标、教材、正误图册、专家经验、公开数据和CAD源文件，各有用途，不能混作同一种依据。
- 案例库解决“这一类对象在这一种语境下，正确/错误的实际表现是什么”，需要结构、正反例和确认记录，靠检索与受控积累复用，而不是依靠对话变长或模型权重自动学习。
- DXF报告是从方案走向源数据验证的记录，证明了一部分字段和差异可读；没有证明所有对象语义、全部32项判据和完整产品都已实现。

### 需要与事实分开的表述

1. 文中“五个直径字符都不是标准符号”又称其中的⌀为标准符号，存在文字内部矛盾；也不能未经原标准验证就把图形规范等同Unicode码位要求。
2. “所有分隔符全部丢弃”不能在尚未解析上下偏差、尺寸链及语境前执行。
3. 文中“人工核实最高”和另一处来源优先级把人工放在OCR之后，并非一致的质量定义。要按单项证据与核准过程判断，不照抄总排序。
4. 不可搜索与图上符号不存在是不同事实；SHX转曲不自动证明符号外形丢失。
5. 许可、模型型号及“原生文本零风险”等说法仅记为资料观点，后续选型和规则发布须独立核实。

### 样例字段与结论冲突

- 标为JSON Schema的代码块实际是示例对象，没有正式Schema的类型与验证约束。
- 必填说明写`object.what_is_it`，示例实际为`recognition.what_is_it`。
- `CONFIRMED`与确认人/日期“待填”、负例“待补”不一致。
- js6案例的确认说明却写深度箭头，显示案例来源混入。
- `VALUE_ERROR`举例是机器把28读26，不能由此给实际图纸判FAIL。
- `SYMBOL_LOST`也要区分图上缺符号与机器漏识，不能不回图就一律判错图。
- §4.2线宽实例为T05，§5.2把同样数据写到T02，需核对，不能转抄。
- 专家经验不一定有国标条款；“rule.clause必填”要按来源类型分别处理。
- “必须正反例完整”和“无反例只降置信”存在不同发布强度，应在正式发布要求中明确。

## 七 检测脚本的逐段理解

83行已全文静态阅读；这次没有运行，也没有修复。

| 功能 | 实际做法 | 可靠性边界 |
|---|---|---|
| 页面文字/绘图统计 | 全文统计≥50字符页、字符和drawing数量 | 阈值可能把少字页或图例页归为无文本；drawing数量不等于有可理解语义 |
| 首段字体遍历 | 前6页遍历字体后只pass | 不产生分类证据，不能认为完成了字体嵌入检查 |
| pdffonts | 前8页调用外部工具，拆行取`tk[-3]` | 通常输出末尾为emb/sub/uni/object ID；固定负索引可能读到uni列，不能作为已正确解析emb的证明 |
| 图像比例 | 仅中间页，图片像素数之和除以页面point面积 | 像素/point单位不一致，受DPI和图片资源复用影响，不是页面图像实际覆盖率 |
| 分类 | 无文本按drawing>100分流；有嵌入计数且图倍率<3判原生 | 只属启发式，不足证明原生/隐藏OCR或语义可信；OCR隐藏层也可能嵌入字体 |
| 异常 | 部分异常直接pass，pdffonts没有明确核验退出状态 | 工具失败可能被当成无字体证据，而不是检测失败 |
| 目录/输出 | 仅目录直属PDF；结果不显示T0开头的文件 | 不能拿该输出证明整个工程图目录完整检查过 |

脚本是资料质量初筛工具，不是原文正确性或“零OCR风险”的认证工具。上述为静态分析，非本轮运行结果。

## 九 对上一轮方案的复盘及后续约束

上一轮目标态方案已覆盖对象关系、三库、解释建议、License和验收等主干，但形成时未完成本轮这样逐段不遗漏的全文阅读。它继续保留为草案，本轮没有把它改称最终方案，也没有继续改写内容。

后续方案需明确继承的不只是三个库名，还包括：四层证据判定、对象语境分类、类型化尺寸解析、正反例、视觉范例、专家与提取者职责分开、三道入库质量检查、检索过滤与排序、版本来源，以及从种子到客户复核回流的资产路线。

后续不得直接继承：未核标准条款、零OCR风险、全部分隔符可丢弃、字段可读即100%判定、全部PDF路线无效、未经核实的模型/许可/价格/数据规模、未知对象的强违规结论、虚填确认状态和历史成本估算。

写方案前先读本记录并核对源文件哈希；文件变动则补读变化部分并更新理解，不能把旧阅读清单当永久有效。

## 十 保存和记忆边界

本记录、全文阅读清单与原资料共同形成可恢复的项目上下文。会话压缩或后续接手时应先读取本记录，再按具体问题回到源章节。保存索引与要点不等于把全部文档永久装入模型记忆；本记录也不替代原页、专家确认或独立验证。

国标知识库怎么建（分三层，别全扔向量库）

1）标准原文/条款层（RAG 检索用）

机械识图最常用、检索结果可支持的现行/常用项：
几何/形位公差：GB/T 1182‑2018（形状/方向/位置/跳动，对应 ISO 1101）、GB/T 17852‑2018 轮廓度、GB/T 17851‑2022 基准与基准体系、GB/T 4249‑2018 公差原则、GB/T 16671‑2018 最大/最小/可逆实体要求、GB/T 1184‑1996 未注形位公差
尺寸与注法：GB/T 4458.4 尺寸注法、GB/T 4458.6 剖视断面、GB/T 17450 图线、GB/T 16675 简化注法、GB/T 15754‑2025 圆锥、GB/T 16892‑2022 非刚性件
公差与配合：GB/T 1800.1/1800.2 极限与配合、GB/T 1804 未注线性/角度一般公差（f/m/c/v）、GB/T 6414 铸件、GB/T 12362 锻件
表面/螺纹/其他：GB/T 131 粗糙度、GB/T 196/197 普通螺纹、GB/T 1095/1096 键槽、GB/T 4459 机械制图符号系列
专家资料：企业《设计手册》《DFM禁忌》《典型零件公差模板》《历史返工案例库》
向量库只存“可引用条款”；数值表（IT等级、未注公差值、粗糙度数表、螺纹极限）单独存结构化表，别让模型背。

2）结构化规则表（直接查，不RAG）
未注线性公差默认等级映射：GB/T 1804‑f/m/c/v → 按公称区间取±值
未注形位等级：H/K/L → 平面度/圆度/同轴等默认值
粗糙度默认：未注加工面/非加工面/配合面 Ra 预设（按你们行业改）
螺纹可行域：M×螺距在不同直径/精度等级的公差带
铸件/冲压/机加工艺公差带宽：沙铸±0.5~2mm 之类经验值做“过度公差”报警
3）专家经验规则（转成 if‑then）

用确定性代码写，不交给LLM自由判断：
尺寸链：检测到封闭环（一组尺寸首尾覆盖同一总体长度且无留空）→ 报警“封闭尺寸链，需改留技术间隙”
形位公差：有位置度/同轴/对称/跳动但无基准字母 → 缺基准；基准A/B/C未在视图找到基准符号 → 断链
公差原则：标Ⓜ/Ⓙ/Ⓛ但无相应基准或理论正确尺寸 → 不合法；最大实体配位置度才合理
配合可行性：孔轴同级IT、基孔/基轴制反推间隙/过盈，超出工艺能力报警
粗糙度vs公差：高精度尺寸配Ra过大、或低精度配Ra过小 → 成本不合理
标题栏一致性：材料/热处理/表面处理/重量/BOM数量互校；技术要求引用标准号在知识库不存在 → 标“标准疑似废止/未收录”
三、规则引擎在链路里的位置（关键）

不要只让 Claude/ GPT “按国标检查”，要让规则引擎先跑，模型只做规则解释和补抽。

示例伪代码：

hits = []

# 规则层（确定性）

hits += rule_missing_datum(facts)                 # 形位无基准

# 国标RAG（软证据）
for f in low_confidence(facts, thr=0.7):
    f.citations = gb_rag.query(f"GB依据: {f.type} {f.symbol} {f.nominal}")

# 推理层（顶级模型）
sol = gpt56sol.reason(facts, hits, citations, tools=[python_stackup])

return build_report(facts, hits, sol, opus)   # 严重项强制人工

三、训练数据准备

1. 数据清洗规则
剔除：人工复核认为“无法判断”的样本；OCR置信度低于阈值且人工未修正的；图纸分辨率过低（<150DPI）的。
平衡：确保每个类别（线性尺寸/直径/公差/形位公差/粗糙度/螺纹）数量均衡，避免模型偏科。
多视图：同一张图的多个视图切片要带“属于同一张图”的标识，让模型学习跨视图关联。
2. 数据增强
几何变换：旋转±5°、透视畸变、缩放（模拟扫描偏差）
噪声注入：高斯噪声、椒盐噪声、模糊（模拟老图纸）
颜色抖动：灰度化、对比度调整（模拟不同扫描仪）
增强只用于图像，JSON标注不变，能显著提高泛化能力。

## 一、关键是把三件事分别做可靠

| 环节 | 要解决的问题 | 我的判断 |
|---|---|---|
| **读出信息** | 尺寸、公差、粗糙度、基准、技术要求写了什么 | 可以推进，需用真实图验证小字符和特殊符号 |
| **建立关联** | 这个尺寸标的是哪个孔？基准指向哪个面？ | **核心难点**，单靠 OCR 文本和坐标不够 |
| **判断违规** | 在什么条件下适用哪条规则，是否存在例外 | 可以规则化，但必须经过机械专家审核 |

比如识别出“⌀20”和“±0.02”只是第一步；必须知道它们分别属于哪个对象，才能可靠检查。

**原方案最需要补强的是中间的“对象与标注关联层”。**

## 二、PDF 应分两条处理路线

### 1. CAD 导出的矢量 PDF

建议同时利用：

- PDF 中可提取的文字和线条；
- 页面渲染图；
- 局部高分辨率裁剪。

不能假设所有 PDF 都保留完整文字和几何语义：有些文字已经变成轮廓，尺寸标注也可能只是分散的线条与字符。系统需要先检查文件实际保留了什么。

### 2. 扫描或图片型 PDF

使用图像识别和 OCR，重点处理倾斜、模糊、小字号和标注密集区域。

这一类应**单独统计效果**。识别不清时保留“无法判定”，不能根据模型猜测生成确定违规结论。

DWG/DXF 则作为补充输入：能够读取原生对象时利用这些信息，并与渲染结果核对。它们可以提供更多证据，但也要考虑标注被拆散、字体和外部引用缺失等情况。

## 三、哪些检查适合先做

下面是工程上的分级判断，**不是已经测出的准确率**：

| 类别 | 示例 | 实施判断 |
|---|---|---|
| 信息与表达检查 | 标题栏必填项、技术要求字段、标注格式 | 适合首批实现 |
| 局部关联检查 | 基准引用能否找到、尺寸及公差是否对应正确对象 | 可以推进，需重点测试关联准确性 |
| 跨视图检查 | 同一特征在不同视图是否一致、尺寸是否矛盾 | 难度较高，先限定零件类型 |
| 设计与工艺判断 | 尺寸是否充分、配合是否合理、是否易加工 | 常依赖图外信息，宜先输出专家建议 |

**“图上没有识别到”不等于“图上没有”。** 缺失类问题尤其容易误报，需要回看原图、检查其他视图及技术要求。

## 四、我建议调整成这条技术路线

```text
PDF / DWG / DXF
       ↓
文件分析、解析与渲染
       ↓
文字、符号、线条、视图提取
       ↓
建立“几何对象—尺寸—公差—基准”的关联
       ↓
判断规则适用条件 → 执行规则检查
       ↓
问题定位、依据、建议、待确认项
```

这里有三个原则：

- **模型负责抽取和提出候选判断，规则负责执行明确条件。**
- **专业规则必须包含适用条件和例外。** 国标条款、企业规则、专家建议分开管理。
- **审校必须能回到原图。** 第二个模型只看第一个模型的结果，无法可靠发现前面漏掉的信息。

因此，我不会把“Mistral → GPT → Claude 三模型串联”直接确定为最终架构。可以作为候选链路，但是否需要每一步，应由真实样本对比决定。

## 五、怎样证明它确实可用

第一阶段需要的材料是：**客户真实 PDF，以及专家标出的违规位置和依据。** 不需要先准备学生评分表。

验证时至少包含：

- 正确图纸，检查系统会不会乱报问题；
- 已知违规图纸，检查能否找到问题；
- 合理但少见的画法，检查是否误判；
- 不清晰或信息不足的图纸，检查能否正确转人工。

按每条规则分别统计**误报、漏检、定位和依据准确性**，不要只给一个笼统的“识图准确率”。

**最终判断：这个项目值得推进。第一阶段能否成功，主要取决于图纸信息关联和规则适用性做得是否扎实。把这两层验证好，第二阶段就有可复用的技术基础。当前还没有客户样本实测，因此我认可技术路线的可行性，但暂不认可任何具体准确率承诺。**

## 一、核心判断：知识缺口的定位

### 1.1 我们缺的三种知识（32 条复核实证）

| 缺口 | 具体卡在哪 | 32 条中的证据 |
|---|---|---|
| **① 对象识别** | 不知道画的是什么 | T03-1（装配图还是零件图）、T05-3（是不是滚动轴承）、T01-8（Ø 是孔还是外圆）、T04-2（是不是移出断面） |
| **② 公差配合逻辑** | 知道符号但不懂为什么这么标 | `Ø60 js6`、`54 0/-0.2`、`Ø142 +0.028/+0.003`、`4×M4 ↓8` |
| **③ 工艺合理性** | 老师傅经验 | T03-4、T04-5（材料与工艺要求） |

**关键判断**：**教材能补 ①②，补不了 ③。** ③ 只能靠你们专家。别指望教材解决全部问题。

### 1.2 🔴 必须修正的前提：教材 ≠ 图册

| | 教材 | **正误图册** |
|---|---|---|
| 讲什么 | 怎么画**对** | **怎么画错 + 正确对照** |
| 结构 | 章节递进 | **配对案例** |
| 对判据库 | 补"为什么" | **直接就是案例** |
| **优先级** | 第二 | **第一** |

**都值得买，但先买图册。**

### 1.3 正误图册的结构天然匹配判据库

从公开样章看到的实际结构：

```
(a) 错误画法  vs  (b) 正确画法
+ 引用的国标条款号
```

实例（公开样章原文）：

> 「GB/T 4459.1-1995《机械制图 螺纹及螺纹紧固件表示法》3.2/3.3：有效螺纹的终止界限用**粗实线**表示，需画螺尾时用与轴线成 **30° 的细实线**，而不是弧线」
> 「GB/T 4457.2-2003：指引线为细实线……与相应图线所成角度应**大于 15°**」
> 「GB/T 4458.4《机械制图 尺寸注法》4.3.4：尺寸数字不能被任何图线所通过」
> 「GB/T 4458.1-2002 5.10：较小斜度结构……其他图形按小端画出」
> 「GB/T 16675.2-1996：球半径应使用 **SR** 表示」

**这正是判据库需要的五要素**：对象类型 + 条款依据 + 正例 + 反例 + 解释。

## 三、DWG / DXF：价值在"真值"，不在"训练"

### 3.1 🔴 概念澄清：DWG 里没有 DXF

| | **DWG** | **DXF** |
|---|---|---|
| 性质 | AutoCAD **原生二进制** | **交换格式**（文本/二进制） |
| 关系 | 原始文件 | 从 DWG **导出**得到 |
| 完整性 | 完整 | ⚠️ **有损**（丢线、丢属性都可能） |
| 方向 | 源 | DWG → DXF（单向） |

**`.dwg` 文件里不存在"dxf 资料"。** DXF 必须用转换工具（如 ODA File Converter）**导出**。

**且转换有损**——行业实测：「DWG → DXF 会丢信息……**必须当成有损转换，不是无损管道**」。主体几何能保留，细节会丢。

### 3.2 用途区分（关键）

| 用途 | 判断 |
|---|---|
| 喂给模型"学" | ❌ 堆几何没用，模型学不会"读懂" |
| **作为真值来源** | ✅ **这才是 DWG/DXF 的真正价值** |

方案集已定的原则：**精度靠结构化数据**。DWG/DXF 是**判据的校验基准**，不是训练材料。

### 3.3 当前状态：未收到

全盘搜索确认：`*.dwg` 0 个，`*.dxf` 0 个。手上只有 22 份国标 PDF + 10 张图纸 PDF + docx/md/xlsx。

### 3.4 平台限制与绕过方案

若平台不支持 `.dwg` 上传：

1. 导出 DXF 时选 **ASCII 格式**（不要选二进制 DXF）
2. 把 `.dxf` **改名成 `.txt` 或 `.md`**
3. 上传后我方改回 `.dxf`，用 ezdxf 解析，**效果与原版 DXF 一致**

若文件过大：分张传，或先传一张最小的试通。

**退路**：截图 + 读图 —— 但已证明不可靠（28 读成 26 那次），不到万不得已不走。

### 3.5 拿到后第一批验证内容

| 优先级 | 验证项 | 收益 |
|---|---|---|
| 1 | **线型（T02-5 / T04-3）** | LINETYPE 字段直接读，**100% 程序化** |
| 2 | **T03-1 图纸性质** | 确认装配图 vs 零件图，决定会不会系统性误报 |
| 3 | **T05-3 对象识别** | 认出滚动轴承 |
| 4 | **尺寸真值批量核对** | `Ø60 js6`、`54 0/-0.2`、`28+0.05/0` 一次性全量验证 |

**最小验证**：用 T01 的 `Ø72` 打通 ezdxf 链路，确认 `%%c` 能正确解出，再批量推。

## 六、三条必须注意的坑

### 6.1 教材不能当条款依据 —— 国标才是

教材引用的国标版本可能滞后（如清华田凌版 2013 年出版，引用多为 2013 年前标准）。我们实际用的是：

```
4458.4-2003、131-2006、1182-2018、1800.1-2020、15754-2025
```

**规则（不变）**：条款依据一律以**国标原文**为准（方案集"出处层"）；教材只补"**为什么**"与"**适用条件/例外**"——这正是 32 条复核里最缺的部分。

### 6.2 买电子版必须验货

用已交付的 `标准PDF文本层检测.py` 跑一遍。

**教材/图册类扫描件概率比国标更高**，尤其要验。真判据是：字体是否嵌入 + 是否整页扫描图 + 实际乱码检测。

### 6.3 图册的价值在"图"，不在"文字"

图是位图的话，仍需**人工核形态**——我们已在 `↓深度` vs `∨埋头孔` 上踩过一次（图像描述把箭头写成「▽8」）。

### 7.1 分类维度

```
行业 → 零件类型 → 特征 → 错误类型
机械 / 电工电子 / 装饰建筑
  └ 盘套类 / 轴类 / 箱体类 / 叉架类
      └ 孔 / 轴 / 螺纹 / 键槽 / 中心孔 / 倒角
          └ 符号错 / 线型错 / 公差错 / 遗漏 / 冗余
```

### 7.2 每条案例必填 5 字段

| 字段 | 为什么 |
|---|---|
| **对象类型** | 这是孔还是轴——**解决"读懂"的核心** |
| **国标依据（条款号）** | 可追溯到原文 |
| 正例 + 反例 | 配对才有判别力 |
| 人工确认状态 | 未确认的不能进训练 |
| 判据适用条件/例外 | 防止过度泛化 |

### 7.3 成长机制：只有三种可行

| 机制 | 可行 | 说明 |
|---|---|---|
| 模型权重自己变强 | ❌ | 基础模型不因使用改变权重 |
| **上下文内学习** | ✅ | 已验证有效 |
| **外部记忆库/RAG** | ✅ **这是产品** | 案例库检索增强，跨会话留存 |
| 微调 | ⚠️ | 灾难性遗忘，需万级数据 |

**"留存记忆、一直成长"能产品化，但不是让模型变强，是让外部知识库变厚。**
→ **架构决策：做案例检索系统，不做模型训练。**

### 7.4 注入机制：检索式，不是全量灌入

规则多了会互相干扰（T03-1 上已见：装配语境与零件语境结论相反，两条同生效会打架）。

**正确做法**：按对象类型**动态注入**最相关的几条规则。

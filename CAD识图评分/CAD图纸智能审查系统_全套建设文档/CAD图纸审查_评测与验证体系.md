# CAD 图纸审查 · 评测与验证体系
## 怎么证明"系统本身"是对的

> 版本 v1.0 ｜ 2026-10-15
> 配套：《可解释证明体系》保证**单条判定**可信；本文保证**整个系统**可信。
> 核心命题：**单条判定可复核 ≠ 系统整体可靠。** 必须另建一套对系统本身的验证机制。

---

# 一、为什么评测是独立的难题

## 1.1 三个天然困难

| 困难 | 表现 | 后果 |
|---|---|---|
| **① 没有天然 ground truth** | 图纸的"正确答案"需要专家逐条标注 | 评测集本身就是稀缺资产 |
| **② 正确率会自欺** | 只测"错图能不能查出"，会漏掉误报 | 系统越激进，分数越高 |
| **③ 小样本** | 图纸数量有限，单次结果偶然性大 | 裸报 100% 不可信 |

## 1.2 本体系的三条对策

```
① → 用「正误配对图」制造天然 ground truth
② → 强制「双向审计」，反向（误报）权重高于正向
③ → 强制「误差棒」，多次重跑，不裸报数字
```

# 二、评测集设计

## 2.1 三类评测集

| 集 | 用途 | 构成 | 规模建议 |
|---|---|---|---|
| **G1 金标准集** | 判分基准 | 正误配对 + 专家逐条标注 | 5 组起（T01–T05） |
| **G2 泛化集** | 验证泛化 | 新图纸，未知答案 | 每阶段新增 ≥10 |
| **G3 对抗集** | 专测误报 | **全部是正确图** | ≥10，与 G1 不重叠 |

**G3 是关键**：专门用来检验系统会不会把对的判成错的。
没有 G3，就没有反向审计的载体。

## 2.2 金标准集的构造（用现有资产）

**已有种子**：T01–T05 正误配对，DXF 中已定位 10 个标注组（1/17/10/9/26/18/17/17/11/11，共 137 个标注）。

```
组2(17) ↔ 组6(18)    T01 正/误
组3(10) ↔ 组4(9)     待定图号 正/误
组7(17) ↔ 组8(17)    T04 正/误
组9(11) ↔ 组10(11)   待定图号 正/误
组5(26)              T03（仅一变体，⚠️不能作为正确图基准）
组1(1)               孤立标注
```

**⚠️ 必须处理的两点**：

| 问题 | 处置 |
|---|---|
| **组5（T03）无配对，且疑为错误图** | **不得作为"正确图"基准**；T03 相关判据标"待补" |
| 组3/组4、组9/组10 图号未确认 | 需读标题栏块内容确认后方可定案 |

**这是评测集的诚实边界**——不能拿未确认的数据当基准。

## 2.3 金标准条目结构

```yaml
- id: GT-T01-001
  sheet: T01_矩形花键套
  variant: CORRECT              # CORRECT / WRONG
  handle: "2438"
  target: "直径标注 Ø80"
  expected:
    display: "Ø80"
    canonical: {base: 80.0, prefix: DIAMETER}
    compliant: true
  paired_with: GT-T01-001W      # 对应错误变体的句柄 271E
  confirmed_by: "专家/日期"
  context: {sheet_kind: PART, view: 主视}
```

**配对字段 `paired_with` 是金标准集的核心价值**——它让"同一处的正误对照"成为可能，天然消除标注歧义。

# 三、分层指标体系

**不设单一"准确率"**——单一指标必然被优化到失真。按四层能力分别设指标。

## 3.1 C1 看清（读数）

| 指标 | 定义 | 目标 |
|---|---|---|
| **捕获率** | 1 − MISSING / 有效分母 | **100%** |
| 值准确率 | 读数 == 真值的条目占比 | ≥99%（结构化源） |
| 符号完整率 | 1 − symbol_loss 率 | 100% |
| **分母披露** | NOT_ON_PAGE 移出数 | **必须披露** |

**分母纪律**：
```
有效分母 = 真值 token 总数 − NOT_ON_PAGE
例：38 − 3 = 35
```
移出分母的每一项**必须列出**，不得借此注水。

## 3.2 C2 看懂（识物）

| 指标 | 定义 | 目标 |
|---|---|---|
| 对象识别准确率 | 正确识别的对象 / 全部对象 | ≥90% |
| **语境判定准确率** | 图纸性质（装配/零件）判定正确率 | **≥99%** ⭐ |
| 孔/轴判别准确率 | — | ≥95% |
| 识别拒答率 | 置信不足主动拒答的比例 | 越低越好，但**不得为 0**（0 说明在硬猜） |

**语境判定单独设为高目标且权重最高**——它决定一整类规则的适用性，判错就是系统性误报。

## 3.3 C3 知因

| 指标 | 定义 | 目标 |
|---|---|---|
| 依据可溯源率 | 判定中 `verified=true` 的占比 | **100%（标准类）** |
| 解释完整率 | 五要件齐全的判定占比 | 100% |
| 建议可用率 | 专家认可"建议可操作"的比例 | ≥80% |

## 3.4 C4 判合规（★核心）

| 指标 | 定义 | 目标 | 权重 |
|---|---|---|---|
| **正向查出率** | 错图查出的违规 / 实际违规 | 100% | 中 |
| **反向误报率** | 正图被误判的违规 / 正图总项 | **0** | **最高** ⭐ |
| 严重度分档正确率 | — | ≥90% | 中 |
| 存疑率 | PENDING / 全部判定 | 越低越好，但**不为 0** | 监控项 |

**为什么反向权重最高**：误报会摧毁用户信任，且**误报比漏检更隐蔽**——漏检用户看不到，误报每次都刺眼。

# 四、双向审计（本体系的核心机制）

## 4.1 正向：错图能不能查出

```
输入：错误变体
期望：系统报出全部预设违规
判定：查出 N/N ⇒ 通过
```

## 4.2 反向：正图会不会误报 ★

```
输入：正确变体（G1 的 CORRECT 侧 + G3 对抗集）
期望：系统报出 0 条违规
判定：误报 0/N ⇒ 通过
任何一条误报 ⇒ 阻断
```

### 4.2.1 反向审计的三种产物

| 产物 | 含义 | 处置 |
|---|---|---|
| **真误报** | 规则/识别错了 | 修 bug，**阻断发布** |
| **例外未覆盖** | 规则对，但漏了例外 | 补 `exceptions` |
| **语境误判** | 规则对，语境判错 | 修 context_guard |

**这三种要分开统计**——它们指向不同的修复动作，混在一起会掩盖根因。

### 4.2.2 反向审计是"可证伪性"的实操检验

在《可解释证明体系》中要求每条规则自带反例。
**反向审计就是检验这条要求的手段**：

> 一条规则若对正图报错 → 它的反例清单一定不完整 → 该规则不合格。

## 4.3 审计的自动化

```bash
run_eval_round --round R3
  → 跑 pipeline
  → 生成判定
  → 正向审计（错图）
  → 反向审计（正图）★
  → 分层指标汇总
  → 误差棒（多次重跑）
  → 回归门禁
  → exit 0 / 2
```

**每轮必跑双向**，不允许只跑正向。

# 五、误差棒与稳定性

## 5.1 为什么必须有误差棒

模型推理有非确定性（尤其 VLM/LLM）。**单次结果可能是运气。**

**已采用的口径**（沿用并扩展）：
- 关键图纸做 **≥3 次完整重跑**
- 报告：闭环口径 100%（±0）、纯自动 ±5.6pt
- **分母抖动**也要报告（分母变化说明读数不稳定）

## 5.2 三次重跑的记录格式

```
图纸        第1次   第2次   第3次   均值    波动
T05正确     100%    100%    100%    100%    ±0
T02正确     35/35   35/35   35/35   100%    ±0
分母        35      35      35      35      0
```

## 5.3 漂移的分档（重要）

**不是所有变化都是缺陷。**

| 类型 | 例子 | 判定 |
|---|---|---|
| **良性抖动** | 标签措辞变化、severity 微调 | 记录，不阻断 |
| **安全关键翻转** | CORRECT ↔ VIOLATION、符号有无 | **阻断** |

**分档是必须的**——不区分会把正常波动当故障，或把真故障当噪声放过。

**温度=0 不是万能解**：reasoning 思维链本身非确定，降温只能减少不能消除。
**危险子集靠"会诊点名 + 回归门禁"双网兜住**，不能只靠调温度。

# 六、失败的记录与复盘

## 6.1 失败必须分类记录

每次评测的失败项，按五类归档：

| 类 | 定义 | 归因 |
|---|---|---|
| **F1 读错** | 读数与真值不符 | M2/M4/M5 |
| **F2 识错** | 对象/语境判错 | M3 |
| **F3 判错** | 规则误用（含例外遗漏） | M6 |
| **F4 漏判** | 应报未报 | 规则缺失 or 召回不足 |
| **F5 误报** | 正图报错 | **最高优先** |

**每类单独统计趋势**——合并统计会掩盖哪一层在拖后腿。

## 6.2 失败案例即资产

```
失败项 → 完整记录（输入/输出/期望/根因）→ 修复 → 回测 → 入 G1
```

**修复一条失败，必须同时把它加进评测集**——否则下次还会犯。

## 6.3 诚实记录原则（沿用全程口径）

**失败、失败原因、未解决项一律记录，不掩盖。**

特别地：
- 明知未验证的条款 → 标 `verified=false`，**不参与自动判罚**
- 明知算法未达标的（如形态识别）→ 标"待人工"，**不假装已解**
- 评测集本身的缺陷（如 T03 缺配对）→ **在评测报告中显式声明**

# 七、回归门禁

## 7.1 门禁规则

| 门禁 | 触发 | 动作 |
|---|---|---|
| **GATE-1 反向误报** | 正图误报 > 0 | **exit 2 阻断** |
| **GATE-2 可溯源** | 任一自动判罚 `verified=false` | 阻断 |
| **GATE-3 分母** | 分母变动未披露 | 阻断 |
| **GATE-4 交叉表** | verdict × grade 交叉表异常 | 阻断 |
| **GATE-5 安全翻转** | 出现安全关键翻转 | 阻断 |
| GATE-6 指标回退 | 分层指标低于上轮 | 告警 |

**自动放行项的 grade 白名单**：
`{CORRECT, CASE_DIFF, VALUE_EQ, FILL, SPLICE, NOT_ON_PAGE, None}`
出现白名单外 → 阻断。

## 7.2 门禁的工程特性

- **基线固化进 `run_eval_round`**，不靠人工记
- **exit 2** 而非警告——让 CI 真正拦住
- 良性抖动与安全翻转**分档判定**，不一律阻断

# 八、分阶段验收

| 阶段 | 验收对象 | 通过标准 |
|---|---|---|
| **P1 数据底座** | M1/M2 | DXF 实体解析 100%；标注解析 ≥99%；线型轴可用 |
| **P2 识物** | M3 | 对象识别 ≥85%；**语境判定 ≥99%** |
| **P3 判规** | M5/M6 | 判据 100% 可溯源；**G3 反向误报 = 0** |
| **P4 闭环** | M4/M7/M8 | 双向审计稳定通过；先例库生效 |
| **P5 规模化** | M9/M10 | 门禁生效；G2 泛化集达标 |

**每阶段验收必须包含**：
1. 双向审计（正向 + 反向）
2. 三次重跑 + 误差棒
3. 失败分类统计
4. 评测集增量（本阶段新增多少条）

# 十一、诚实标注（评测体系自身的局限）

| 项 | 说明 |
|---|---|
| G1 种子规模 | 仅 6 组配对（11 条），**样本极小**，结论不可外推 |
| G3 对抗集 | **尚未建立**，是当前的**最大评测缺口** |
| 指标目标值 | 为设计目标，需首轮实测校准 |
| T03 | 缺正确变体，相关判据无法评测 |
| 组3/组4、组9/组10 | 图号未确认，暂不能定案 |
| 误差棒口径 | ±5.6pt 来自既有小样本，**泛化后需重测** |
| 反向误报 0 | 是**目标**，非现状；未跑 G3 前不得宣称达成 |

---

*本体系的核心承诺：不只证明"系统说了什么对"，更要证明"系统本身可靠"。
凡未达标注条件的项，一律如实列入"未决与诚实声明"，不包装成通过。*

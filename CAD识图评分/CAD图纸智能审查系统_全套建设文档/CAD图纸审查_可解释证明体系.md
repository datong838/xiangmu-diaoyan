# CAD 图纸审查 · 可解释证明体系
## 让每一条判定都能被复核、被质疑、被推翻

> 版本 v1.0 ｜ 2026-10-15
> 本文解决一件事：**系统给出的每一条"合格/不合格/扣分"，必须拿得出一份人能看懂、能复核、能推翻的证明。**
> 配套：《工程实施方案》（怎么做成）、《目标态建设技术方案》（做成什么样）

---

# 一、什么叫"可解释证明"

## 1.1 三种层次，我们要的是第三种

| 层次 | 表现 | 问题 |
|---|---|---|
| **L-A 给结论** | "此图不合格" | 无法质疑，无法改进 |
| **L-B 给依据** | "不合格，依据 GB/T 4458.4 表 A.1" | 不知道依据怎么套到这处图上 |
| **L-C 给证明** ⭐ | 观测 → 事实 → 依据 → 推理 → 结论，**每一步可复算** | **这才是可解释证明** |

**判据**：一份结论若换一个人（专家）拿着同样的材料，能**独立重现**推理过程并**同意或推翻**——才算 L-C。

## 1.2 证明的五个要件（缺一不可）

```
① 断言    ── 对哪一处、说了什么         （定位）
② 事实    ── 图上实际是什么             （可复算的观测）
③ 依据    ── 凭什么说它对/错            （标准 / 经验 / 数学）
④ 推理    ── 从②③怎么走到结论          （可验证的逻辑）
⑤ 结论    ── 判定 + 严重度 + 处置       （可执行的输出）
```

**缺任何一项，结论只能标"存疑"，不得自动判罚。**

---

# 二、依据的三类来源（用户说的"标准或经验"）

这是本体系的核心分类。**三类依据的证明力不同，必须分开表示。**

## 2.1 三类依据对照

| 类别 | 来源 | 证明力 | 表示要求 | 可否自动判 |
|---|---|---|---|---|
| **① 标准依据** | 国标/行标条款 | **强** | 标准号 + 条款号 + 原文 + verified | ✅ 可 |
| **② 经验依据** | 行业惯例、老师傅经验、设计手册 | **中** | 来源 + 表述 + 置信度 + 适用场景 + 背书人 | ⚠️ 需确认 |
| **③ 数学校据** | 几何、公差计算、尺寸链 | **强** | 公式 + 代入值 + 计算结果 | ✅ 可 |

## 2.2 ① 标准依据的表示

```yaml
basis:
  class: STANDARD
  standard: "GB/T 1800.1-2020"
  clause: "§4.1.2.5 注3"
  clause_text: "基本偏差的概念不适用于 JS 和 js。它们的公差极限是相对于公称尺寸线对称分布的。"
  verified: true                 # 是否已核到原文
  verified_by: "复核人/日期"
  source_file: "GB_T 1800.1-2020….pdf"
  source_locator: "原生文本层 p.12"   # 或 "OCR p.13"（含风险标记）
  ocr_risk: LOW                  # 示例候选值；有文本层不等于符号/图例/语义零风险
```

**关键字段 `verified`**：
- `true` → 仅表示依据来源已核准；还须核准图面事实、对象关联、适用条件和例外，才能形成相应结论。第一阶段输出检查意见，不作学生扣分。
- `false` → **只能标"疑似"，不得判罚**

## 2.3 ② 经验依据的表示（★用户特别强调的"经验"）

经验依据**不能伪装成标准**。它必须有自己的诚实的表示：

```yaml
basis:
  class: EXPERIENCE
  statement: "螺纹孔的深度标注应留出丝锥导向余量（约为 2.5 牙）"
  source_kind: DESIGN_MANUAL     # 设计手册 / 行业惯例 / 专家口述
  source_ref: "《机械设计手册》第X卷第X章"
  endorsers: ["专家A", "专家B"]   # 背书人
  confidence: 0.8
  applicability:
    - "仅适用于盲孔螺纹"
    - "通孔不适用"
    - "已成文企业标准者优先于本条"
  auto_judge: false              # ★ 默认不自动判罚
  presentation: "提示项，非判罚项"
```

**经验依据的三条纪律**：

1. **不冒充标准** — 输出中必须明示"依据为经验，非国标强制"
2. **默认不自动判罚** — 作为**提示/建议**输出，由专家决定是否采纳
3. **必须带适用边界** — 无边界的经验规则比没有更危险

> **经验的工程定位**：它是**"合理性"**的判断来源，不是**"合规性"**的判罚来源。
> 合规性由标准定，合理性由经验补。两者在报告中分栏呈现。

## 2.4 ③ 数学校据的表示

```yaml
basis:
  class: MATH
  formula: "合格区间 = [base + lower, base + upper]"
  inputs: {base: 142.0, upper: 0.028, lower: 0.003}
  result: "[142.003, 142.028]"
  steps:
    - "base + lower = 142.000 + 0.003 = 142.003"
    - "base + upper = 142.000 + 0.028 = 142.028"
```

**数学校据是最强的一类**——完全可复算，无争议。
凡能用数学判的，**一律优先用数学**，不用模型。

# 三、证据链模型（五层）

```
┌─ L1 原始观测层 ────────────────────────────────┐
│  DXF 实体 / 图像像素 / OCR 文本                  │
│  可复算：给定文件，任何人跑同一程序得同一结果      │
└──────────────────────┬──────────────────────────┘
                       ▼
┌─ L2 事实层 ───────────────────────────────────┐
│  解码后的确定事实                                │
│  「标注 ANN-271E 的模板为 {<>}，无 %%c 前缀」     │
│  「该标注关联的轮廓经射线法判定为内轮廓 → 孔」     │
└──────────────────────┬──────────────────────────┘
                       ▼
┌─ L3 依据层 ───────────────────────────────────┐
│  适用的标准条款 / 经验条目 / 数学公式              │
│  含 verified 状态、适用条件、例外清单              │
└──────────────────────┬──────────────────────────┘
                       ▼
┌─ L4 推理层 ───────────────────────────────────┐
│  事实 + 依据 → 结论 的逻辑                       │
│  「孔 → 依 §4.1.2.5 应大写 → 观得 h7 → 违反」     │
│  必须列出：前提、匹配、例外检查                    │
└──────────────────────┬──────────────────────────┘
                       ▼
┌─ L5 结论层 ───────────────────────────────────┐
│  判定 + 严重度 + 处置建议 + 可复现命令            │
└────────────────────────────────────────────────┘
```

## 3.1 每层都必须可复算

| 层 | 复算方式 |
|---|---|
| L1 | 重跑解析程序，比对字节 |
| L2 | 给定解码规则，人工可验 |
| L3 | 翻标准原文 / 查经验条目 |
| L4 | 逻辑可逐步核对 |
| L5 | 由前四层唯一推出 |

**若某一层不可复算，整条链的结论降级为"存疑"。**

# 四、证明书：每条 Finding 的完整输出

## 4.1 标准格式

```
═══════════════════════════════════════════════════════
判定编号    FIND-002
判定结论    ❌ 违反（VIOLATION）
严重度      MAJOR
═══════════════════════════════════════════════════════

【① 断言｜定位】
  图幅：T01_矩形花键套 · 主视图
  目标：标注 ANN-16D5（句柄 16D5）
  位置：(x=..., y=...)
  原文显示：Ø42 h7

【② 事实｜可复算的观测】
  F1. DXF 模板：{%%c%% <> h7}  →  %%c 解码为直径符号 ⌀
  F2. 测量值：42.000
  F3. 关联几何：defpoint 命中轮廓环 LOOP-042
  F4. 射线法判定：LOOP-042 为内轮廓 → 该要素为「孔」
  F5. 公差带字母：h（小写）
  （复算命令：python verify.py --handle 16D5）

【③ 依据｜标准】
  GB/T 1800.1-2020 §4.1.2.5
  「孔用大写字母 (A…ZC)，轴用小写字母 (a…zc)」
  出处：原生文本层 p.12（OCR 风险：无）
  verified: true
  适用条件：线性尺寸公差代号体系
  例外：不适用 JS/js（对称公差）

【④ 推理｜逐步】
  R1. 由 F4，目标要素为「孔」
  R2. 由 §4.1.2.5，孔的基本偏差代号应为大写
  R3. 由 F5，实际为小写 h
  R4. 例外检查：h ≠ js，不适用对称公差例外
  R5. ⇒ 违反

【⑤ 结论与处置】
  判定：违反（MAJOR）
  建议：公差带代号改为大写 H7
  DXF 修正：模板 {%%c<> h7} → {%%c<> H7}
  反向验证：修正后应无此 Finding
═══════════════════════════════════════════════════════
【可推翻方式】
  若「LOOP-042 实为外轮廓」→ 本判定不成立
  推翻入口：人工重判要素类型（--rejudge F-007）
═══════════════════════════════════════════════════════
```

## 4.2 四个关键设计

### ① 断言必须可定位到句柄

不写"某处有错"，写**句柄 + 坐标 + 原文**。定位不到句柄的判定不输出。

### ② 事实必须可复算

每条事实附**复算命令**或**复算方法**。专家可自行验证。

### ③ 推理必须列例外检查

**只写"符合/违反"而不写"例外已排除"的推理是不完整的。**
标准条款几乎都有例外，跳过例外检查是误报的主要来源。

### ④ 必须给出可推翻方式

**一份不可推翻的证明不是证明，是断言。**
每条判定都要写明"若 X 成立，则本判定不成立"，并提供推翻入口。

# 五、评分的可解释：每个扣分都有证明

## 5.1 评分 = 扣分项的集合，不是黑箱总分

**设计原则**：**先有逐项证明，后有总分**；总分是派生物，不是独立计算。

```
Score = 100 − Σ(扣分项权重)
每个扣分项 ⇔ 一条 Finding ⇔ 一份证明书
```

**禁止**：先算总分，再倒推扣分项。**必须**先有逐项判定，总分由扣分项累加得出。

## 5.2 扣分项的四维

| 维度 | 取值 | 说明 |
|---|---|---|
| **严重度** | CRITICAL / MAJOR / MINOR / INFO | 违规性质 |
| **依据强度** | STANDARD / EXPERIENCE / MATH | 证明力 |
| **置信度** | 0–1 | 事实与推理的可靠度 |
| **可推翻性** | 已列推翻条件 / 未列 | 未列不得自动扣分 |

**扣分规则**：
- 严重度 × 依据强度 × 置信度 → 扣分权重
- **经验依据默认只扣 MINOR 或不扣分**，仅作提示（除非企业标准已采纳）
- **置信度 < 阈值 → 不自动扣分**，转人工

## 5.3 评分报告结构

```
┌────────────────────────────────────────┐
│  总分：87 / 100                          │
├────────────────────────────────────────┤
│  【合规性扣分】依据标准                    │
│   −8  MAJOR   Ø80 缺直径符号  [FIND-001] │
│   −5  MINOR   ...              [FIND-00x]│
├────────────────────────────────────────┤
│  【合理性提示】依据经验（不扣分）           │
│   ○  螺纹底孔深度建议留导向余量            │
│   ○  未注圆角 R3~R5 建议统一              │
├────────────────────────────────────────┤
│  【未决项】待人工                         │
│   ?  符号形态（↓深度 vs ∨埋头孔）待确认    │
├────────────────────────────────────────┤
│  分母说明：有效标注 35 项（38 − 3 未印）   │
│  误差棒：±5.6pt（6 次重跑）                │
└────────────────────────────────────────┘
```

**三栏分离是刻意的**：合规（标准）、合理（经验）、未决（待定）——**不混为一栏**，避免经验冒充标准。

# 六、可证伪性设计（最容易被忽略的一环）

## 6.1 每条规则必须自带反例

```yaml
- id: R-HATCH-ADJACENT-001
  rule: "装配图相邻件剖面线方向应相反或间距不等"
  counter_examples:
    - desc: "零件图（非装配）不适用本条"
      guard: "sheet.kind != ASSEMBLY → skip"
    - desc: "同一零件跨视图应方向一致、间距相同——与本条结论相反"
      guard: "same_part == true → 使用 R-HATCH-SAMEPART-001"
  falsifiable: true
```

**没有反例的规则不许入库。**

## 6.2 反向审计是制度，不是选项

| 方向 | 做法 | 目标 |
|---|---|---|
| 正向 | 错图能否查出 | N/N |
| **反向** | **正图是否误报** | **0/N** |

**反向审计的意义**：一条规则若对正图报错，它的反例清单一定不完整。
**反向审计是检验"可证伪性"的实操手段。**

## 6.3 存疑优于误判

```
if 任一要件缺失 or 例外未排除 or 置信 < 阈值:
    verdict = PENDING（存疑）
    扣分 = 0
    转人工
```

**存疑不算错**——它是系统诚实的表现。误判才是缺陷。

# 七、人机分工：什么能自动证明，什么不能

| 判定类型 | 能否自动证明 | 原因 |
|---|---|---|
| 数值/公差计算 | ✅ 完全可 | 数学，可复算 |
| 线型合规 | ✅ 完全可 | 结构化字段，确定性 |
| 控制码存在性（`%%c` 有无） | ✅ 完全可 | 模板级 diff，零歧义 |
| 孔/轴大小写（几何判定后） | ✅ 可 | 两条独立路径交叉验证 |
| 尺寸链闭合 | ✅ 可 | 数学 |
| **符号形态**（↓ vs ∨） | ⚠️ 半自动 | 形近义异，需视觉+人工 |
| **对象识别**（是否轴承/断面） | ⚠️ 半自动 | 需置信度 + 人工兜底 |
| **图纸性质**（装配 vs 零件） | ⚠️ 半自动 | 决定一整类规则，误判代价大 |
| **工艺合理性** | ❌ 不能 | 只能作经验提示，不判罚 |
| **设计意图** | ❌ 不能 | 不在能力范围 |

**原则**：**能自动证明的必须自动证明（快且准）；不能的诚实标"待人工"，不用模型硬凑。**

# 八、证明的存储与复用

## 8.1 证明即案例

每条被人工确认的 Finding（含证明书）→ **自动成为一个案例**。

```
案例 = 证明书 + 人工裁决 + 适用边界
```

**这是"成长"的真实机制**：不是模型变强，是**证明库变厚**，下次同类问题可直接引用先例。

## 8.2 先例引用的证明力

| 情形 | 证明力 | 处置 |
|---|---|---|
| 完全命中（对象、语境、值全同） | 强 | 可直接引用 |
| 部分命中（对象同、值不同） | **弱** | **拒绝自动放行**（fail-closed 相似度门槛） |
| 语境不同 | 无 | 不适用 |

**fail-closed 门槛是必须的**——"看起来像"就放行，正是错误推广的来源。

## 8.3 证明的版本化

标准会换版，条款会改。**每条证明必须绑定到标准版本**：

```
GB/T 131-2006 §11.2.1   ← 绑定到 2006 版
GB/T 131-1993 §x.x      ← 旧版，仅作历史版本参考
```

**客户已定口径**：按最新版本判，但**可指出该写法出自哪一版**，对错由评判人决定。
工程实现：判据带 `version_scope`，输出时同时给**现行版结论**与**历史版归属**，不自行判"旧版即错"。

# 九、输出的三种形态（面向不同角色）

| 角色 | 形态 | 内容 |
|---|---|---|
| **制图员** | 修正清单 | 哪里错、改成什么、怎么改（含 DXF 修正建议） |
| **审核专家** | 证明书 | 五要件完整、可复算、可推翻 |
| **管理者** | 评分报告 | 三栏分离、分母披露、误差棒 |

**同一份数据，三种视图**——不做三套系统，做一套证明 + 三种渲染。

# 十、验收标准（可解释性专属）

| 项 | 标准 |
|---|---|
| 每条自动判罚 | 五要件齐全 |
| 依据可溯源率 | **100%**（标准类） |
| 经验类依据 | 100% 明示"非国标强制" |
| 例外检查 | 每条推理含例外排除步骤 |
| 可推翻性 | 每条判定含推翻条件与入口 |
| 反向审计 | 正图误报 **0/N** |
| 存疑项 | 明确列出，不计分不入违规 |
| 不可溯源项 | 不得自动判罚 |

**红线**：
- 出现"依据 GB/T XXXX"却无法定位到条款原文 → 阻断
- 经验依据被当作标准判罚 → 阻断
- 总分与扣分项不闭合（总分 ≠ 100 − Σ扣分） → 阻断

# 十一、与已有方案的关系

| 文档 | 回答 |
|---|---|
| 《工程实施方案》 | **怎么做成**（模块、算法、流程） |
| 《目标态建设技术方案》 | **做成什么样**（四层能力、架构、路线） |
| **《可解释证明体系》** | **凭什么可信**（证据链、证明书、评分溯源） |

三者是同一件事的三个切面。**可解释性不是附加功能，是系统的合格线**——没有它，前面两套都不成立。

---

# 十二、诚实标注

| 项 | 说明 |
|---|---|
| 证明书格式 | 本文设计为**目标格式**，需与专家确认字段完备性 |
| 经验依据的采集 | 依赖专家输入，**本文无法自动生成经验内容** |
| 扣分权重公式 | 需按业务调优，本文给结构不给定值 |
| 自动/半自动/不能的划分 | 基于当前技术判断，**随能力建设会变动** |
| 部分条款 verified 状态 | 少数条款仍待核原文，核前不得自动判罚 |

---

*本体系的核心承诺：系统输出的不是"答案"，是"证明"。人可以不同意，但一定能看懂、能复核、能推翻。*

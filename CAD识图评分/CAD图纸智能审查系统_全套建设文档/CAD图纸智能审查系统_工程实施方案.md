# 一、做成这件事的总体路线

## 1.1 问题本质

一张机械图纸的合规审查，本质是三个子问题的串联：

| 子问题 | 数学性质 | 可行手段 |
|---|---|---|
| **① 图上写了什么**（读数） | 信息提取 | 结构化直读为主，视觉为辅 |
| **② 画的是什么**（识物） | 几何/语义推断 | 特征工程 + 规则推理 |
| **③ 合不合规**（判据） | 约束满足 | 规则引擎 + 条款溯源 |

**做成的关键，是把这三件事分别用最合适的手段解决，而不是用一种手段（例如"让大模型看图"）通吃。**

## 1.2 顶层设计：**双通道 + 判据引擎 + 进化环**

```
        ┌─────────────────────────────────────────┐
        │            输入：DWG / DXF / PDF / 图像      │
        └───────────────┬─────────────────────────┘
                        │
          ┌─────────────┴─────────────┐
          ▼                           ▼
 ┌──────────────────┐      ┌──────────────────┐
 │  通道 S（结构化）   │      │  通道 V（视觉）     │
 │  DXF 实体级直读    │      │  渲染→OCR→VLM     │
 │  确定性、可复算     │      │  兜底、补盲、佐证   │
 └────────┬─────────┘      └────────┬─────────┘
          │                         │
          └───────────┬─────────────┘
                      ▼
          ┌──────────────────────┐
          │  L3 归一 + 对齐 + 互证   │  ← 决定"信谁"
          └───────────┬──────────┘
                      ▼
          ┌──────────────────────┐
          │  M3 几何重建 + 对象识别  │  ← 决定"是什么"
          └───────────┬──────────┘
                      ▼
          ┌──────────────────────┐
          │  M6 判据引擎（规则库）   │  ← 决定"合不合规"
          │  语境守卫 + 例外 + 溯源  │
          └───────────┬──────────┘
                      ▼
          ┌──────────────────────┐
          │  L4 仲裁 → L4c 会诊     │  ← 决定"要不要交人"
          └───────────┬──────────┘
                      ▼
          ┌──────────────────────┐
          │  L5 人工闭环 → 回写先例 │  ← 决定"下次更准"
          └───────────┬──────────┘
                      ▼
                审查报告（逐项 + 条款 + 建议）
```

**六字诀**：**直读取真、视觉补盲、归一互证、识物定性、判据定规、闭环进化。**

## 1.3 三条不可违背的设计律

**律一 · 确定性优先**
凡是能从结构化数据确定性得到的量（尺寸、公差、线型、控制码），**一律不许走模型推断**。结构化事实优先，但仍与图面显示核对；源数据冲突、显示异常和代理对象均可触发视觉复核，不让源字段覆盖待检图的原始观察。

**律二 · 格式先于数值**
`Ø50` ≠ `050`，`φ20` ≠「中 20」。token 的物理格式先合规，再看数值；**格式可疑一律 fail-closed 进人工**，不静默放行。

**律三 · 判据可溯源**
每条判定须携带依据类型、来源、版本、核准状态及适用前提。国标规则另需标准号、条款和原页；经验依据使用核准专家/手册来源，不虚填国标条款。未核准或前提不足只标存疑；核准本身也不自动证明违规。

# 二、数据模型（全系统的共同语言）

先定义数据结构，后面所有模块都在这套模型上工作。

## 2.1 七层对象模型

```
Drawing           图纸（一份文件）
 └ Sheet          图幅/图框（一张图，一套文件可含多张）
    ├ View        视图（主视/剖视/断面/局部/向视）
    │  ├ GeometryEntity   几何实体（LINE/ARC/CIRCLE/HATCH/...）
    │  ├ Feature          识别出的特征（孔/轴/螺纹/键槽/剖面区...）
    │  └ Annotation       标注（尺寸/公差/粗糙度/形位/文字）
    │      └ Token        标注内的原子项（数值/符号/公差带）
    └ TitleBlock  标题栏（图号/材料/比例/图名）
```

## 2.2 核心 Schema

### Annotation（标注）

```json
{
  "id": "ANN-2438",
  "handle": "2438",
  "type": "DIMENSION",
  "view": "V-主视",
  "layer": "7标注层",
  "raw_template": "{%%c<>}",
  "measurement": 80.0,
  "display_text": "Ø80",
  "tokens": [
    {"kind": "PREFIX", "code": "%%c", "unicode": "⌀", "semantic": "DIAMETER"},
    {"kind": "VALUE",  "raw": "<>",  "resolved": 80.0}
  ],
  "tolerance": {"form": "NONE"},
  "attach": {"defpoints": [[x1,y1],[x2,y2]], "target_geometry": ["GEO-…"]},
  "source": "DXF",
  "confidence": 1.0
}
```

### Feature（识别出的对象）

```json
{
  "id": "F-007",
  "kind": "HOLE",
  "subtype": "THROUGH_HOLE",
  "evidence": {
    "geometry": ["GEO-101","GEO-102","GEO-103"],
    "annotations": ["ANN-2438"],
    "layer": "1轮廓实线层 / 3中心线层"
  },
  "geometry_attrs": {"diameter": 80.0, "axis": [...], "depth": null},
  "context": {"sheet_kind": "PART", "view_type": "SECTION"},
  "confidence": 0.92,
  "recognizer": "R3-回转体孔轴判别"
}
```

### Finding（审查结论）

```json
{
  "id": "FIND-001",
  "target": {"annotation": "ANN-271E", "feature": "F-007"},
  "verdict": "VIOLATION",
  "diff_type": "SYMBOL_LOST",
  "rule": {
    "id": "R-DIM-DIAM-001",
    "standard": "GB/T 4458.4",
    "clause": "表 A.1 序号1",
    "clause_text": "直径符号 ⌀ 应置于尺寸数字之前",
    "verified": true
  },
  "observed": "80",
  "expected": "Ø80",
  "severity": "MAJOR",
  "suggestion": "在尺寸数字前补直径符号（DXF 模板改为 {%%c<>}）",
  "context_guard": {"sheet_kind": "PART", "applies": true},
  "evidence": {"ground_truth_handle": "2438", "diff": "%%c 缺失"},
  "review_state": "AUTO"
}
```

## 2.3 为什么必须建 Feature 层

**没有 Feature 层，判据只能"看图说话"（字符串匹配）；有了 Feature 层，判据才能"按对象判"。**

例：`H7` 是否合规？——字符串看不出。必须先回答"这是孔还是轴"，Feature 层给出 `kind=HOLE`，判据才成立。

**Feature 层就是"看懂"这一能力的工程载体。**

## M1　接入分流

**做法**：三问定路由。

```python
def route(path):
    if is_dxf(path):        return "STRUCTURED", read_dxf
    if is_pdf(path):
        if has_vector(path) and has_text_layer(path): return "PDF_VECTOR", pdf_vector
        if has_vector(path):                           return "PDF_VECTOR_CURVED", pdf_vector
    return "RASTER", raster_pipeline
```

**矢量有效比判据**（区分真矢量与"盗版伪层"）：

```
矢量有效比 = 有效矢量图元数 / 页面对象总数
真矢量 0.72 ~ 0.86 ；伪层（整页位图伪装）0.10 ~ 0.20
```

**判据选取**：用 `pdffonts` 检查字体嵌入 + `get_drawings()` 统计图元 + 整页位图检测，三者综合，不单凭一项。

## M2　结构化直读（真值通道，全系统基石）

### 2.1 读取

```python
import ezdxf
doc = ezdxf.readfile(path)        # 支持 ASCII / 二进制 DXF
msp = doc.modelspace()
```

**实体清单**（实测分布，作为设计输入）：
`LINE / ARC / CIRCLE / LWPOLYLINE / SPLINE / HATCH / SOLID / TEXT / MTEXT / DIMENSION / INSERT / ACAD_PROXY_ENTITY`

### 2.2 控制码解码（第一道解码）

```python
CONTROL = {
    "%%c": "⌀",   # 直径
    "%%d": "°",   # 度
    "%%p": "±",   # 正负
    "%%%": "%",
}
```

**关键认知**：直径符号在 CAD 数据源里**不是 Unicode 字符，是 `%%c` 控制码**。
不解码 = 丢失语义；解码后可与视觉通道的 `⌀/Ø/φ` 归一比对。

### 2.3 标注模板解析（第二道解码）

DIMENSION 的 `text` 字段是**模板**，不是最终文本。形态：

```
{%%c<>}                                         直径 + 测量值
{%%c<> H7}                                      直径 + 公差带（孔，大写）
{%%c<> h7}                                      直径 + 公差带（轴，小写）
{\A1;{%%c<>}{}{\H0.71x;\C2;\S+0.028^ +0.003;}}  直径 + 堆叠公差
{\A1;{<>}{}{\C3;%%p0.1}}                        对称公差 ±
{4*M<> EQS}                                     4×M□ 均布
{M<>-6H}                                        螺纹
{90%%d}                                         角度
```

**解析器设计**（四步）：

```
step1  剥离格式控制：\A1; \H0.71x; \C2; \f…|…;  → 只留内容
step2  展开 <>       → 替换为 actual_measurement
step3  展开 \S上^下; → 堆叠公差，拆为 (upper, lower)
step4  解码 %%c/%%d/%%p
```

**输出的规范形式**：三元组 + 标注类型

```python
Canonical = {
  "base": 142.0,
  "upper": +0.028, "lower": +0.003, "tol_form": "LIMIT",     # 极限偏差
  # 或
  "base": 60.0, "tol_form": "ISO_CODE", "class": "js6",      # 公差带代号
  # 或
  "base": 65.0, "tol_form": "SYMMETRIC", "half": 0.1,        # 对称公差
  "prefix": "⌀", "suffix": None
}
```

**公差带代号不可拆分铁律**：`js` 是双字母整体，拆成 `j6`/`s6` 全错。
基本偏差封闭集（GB/T 1800.1 表 4）：

```
a b c cd d e ef f fg g h js j k m n p r s t u v x y z za zb zc
双字母（7）：cd ef fg js za zb zc
禁用字母：   I i  L l  O o  Q q  W w
```

### 2.4 线型轴（第三道解码，格式层）

```python
layer_linetype = {lay.dxf.name: lay.dxf.linetype for lay in doc.layers}
# 实体可覆盖图层线型：entity.dxf.linetype，ByLayer 时回落图层
```

线型表定义（含名称与图案语义）：

| 线型 | 图案 | 工程含义 |
|---|---|---|
| `CENTER` / `CENTER2` | `___ _ ___ _` | 中心线、对称线 |
| `PHANTOM` / `PHANTOM4` | `___ _ _ ___` | 双点画线：假想轮廓、相邻辅助件、极限位置 |
| `DASHED` / `DASHED2` | `__ __ __` | 虚线：不可见轮廓 |
| `Continuous` | 实线 | 可见轮廓、剖面线、尺寸线 |

**为什么把它单列一轴**：线与数字同属"格式层"，**零歧义、零模型调用、可复算**。
这是判据里最硬的一类证据——应当优先于任何视觉判断。

### 2.5 空间索引

```python
from rtree import index
idx = index.Index()
for e in entities: idx.insert(id, bbox_of(e))
```

**用途**：标注 ↔ 几何的关联（这是 M3 识物的基础）。
关联方法：取标注的 `defpoint`（定义点），在空间索引中查 **k 近邻几何**，再按"是否落在尺寸界线上"筛选。

### 2.6 代理实体的处理

部分符号由 CAD 厂商模块（如 ZWCAD 机械模块）以 `ACAD_PROXY_ENTITY` 存储，DXF 中只有**显示缓存**。

**三级处理策略**：

| 级别 | 做法 | 得到什么 |
|---|---|---|
| L1 | 提取显示缓存几何（虚拟线/文字） | **位置 + 形状**（可判"有无""朝向"） |
| L2 | 装对应 Object Enabler 原生读取 | **参数**（粗糙度值、公差类型） |
| L3 | 视觉通道识别 + 人工确认 | 语义兜底 |

**设计原则**：L1 必做（零成本），L2 争取，L3 兜底。**任何时候都不因为"读不到参数"就放弃判"有无/位置/朝向"。**

## M3　几何重建与对象识别（"看懂"的实现）

这是全系统技术含量最高、也是决定性的一块。**做法：特征工程 + 规则推理，不是端到端模型。**

### 3.1 第一步：视图分割

```
输入：全部实体 + 图框（INSERT 位置已知）
输出：每个视图的实体子集与类型
```

**方法**：
1. 从图框 INSERT 得到各图幅矩形
2. 实体按包围盒归属图幅（跨图幅者按质心）
3. 图幅内按投影区域聚类 → 视图
4. 视图类型判定（见 3.5）

### 3.2 第二步：轮廓重建

```
输入：LINE / ARC / CIRCLE / LWPOLYLINE
输出：闭合环（Loop）集合 + 环的包含关系树
```

**算法**：
1. 端点吸附（tolerance = 0.5×最小线宽），建图
2. 求最小环基（或按角度优先遍历找闭合路径）
3. 环按面积排序，构建**包含树**（点在环内判定用射线法）

**包含树**是识别"孔 vs 轴"的关键结构。

### 3.3 第三步：孔/轴判别（核心算法）

**问题**：一个 `%%c` 直径标注，指的是孔还是外圆？

**算法**（三步，全部确定性）：

```
① 标注 → 几何：取 defpoint，空间索引查最近轮廓环
② 判内/外：
   取该环上一点 P，向环外作射线 R
   统计 R 与"该环所属零件外轮廓"的交点数
   奇 → P 在外轮廓内部 → 内轮廓 → 孔
   偶 → P 在外轮廓外部 → 外轮廓 → 轴/外圆
③ 交叉验证：
   孔 → 公差带应为大写（H7、H10）
   轴 → 公差带应为小写（h7、f7）
   若 ② 与 ③ 冲突 → 提 Finding（这正是 T01-8 类问题）
```

**这条算法的意义**：把"看懂"变成了确定性计算，而不是让模型猜。

### 3.4 第四步：特征识别器族（R1–R4）

| 识别器 | 判什么 | 算法要点 |
|---|---|---|
| **R1 图纸性质** | 零件图 / 装配图 | 明细栏存在性 + 件号（序号标注）+ 多零件剖面线角度差 + 标题栏图名 |
| **R2 标准件** | 轴承 / 螺纹 / 齿轮 / 弹簧 / 键 | 国标表示法的几何指纹（见下） |
| **R3 要素特征** | 孔/轴/螺纹/键槽/中心孔/倒角 | 轮廓 + 标注 + 图层联合判 |
| **R4 视图类型** | 主视/剖视/断面/局部/向视 | 剖面线存在 + 剖切符号 + 视图箭头 A + 断裂边界 |

**R2 标准件的几何指纹**（按国标表示法设计）：

| 对象 | 国标 | 指纹 |
|---|---|---|
| 滚动轴承 | GB/T 4459.7 | 矩形框 + 内圈外圈双圆 + 滚动体（圆/叉）+ **无剖面线** |
| 螺纹 | GB/T 4459.1 | 牙顶粗实线 / 牙底细实线 交替 + 终止线粗实线 |
| 齿轮 | GB/T 4459.2 | 齿顶圆粗实线 / 分度圆点画线 / 齿根圆细实线（可省略） |
| 弹簧 | GB/T 4459.4 | 螺旋线（多段等距圆弧）+ 支撑圈 |
| 矩形花键 | GB/T 4459.3 | 内外花键齿形线 + 中心线 + 标注 `6×…×…×…` |
| 中心孔 | GB/T 4459.5 | 60° 锥孔 + 型式代号（A/B/C/R） |

**R1 图纸性质判据**（最高优先级，因为它决定一整类规则的适用性）：

```
若 存在明细栏 ∧ 存在件号（序号+指引线）∧ 存在两个以上剖面线角度簇
    → 装配图
否则 → 零件图
```

> **为什么 R1 优先级最高**：装配图中"相邻件剖面线方向必须相反/间距不同"是强制要求；
> 若误判为零件图，会把**正确画法判成违规**——这就是系统性误报的来源。
> 必须做成**带 context_guard 的规则**：只有 `sheet_kind == ASSEMBLY` 时才启用。

### 3.5 置信度与降级

每个 Feature 输出 `confidence`。低于阈值时：
- 不自动判定 → 转 L4 仲裁 → 仍不足则 L5 人工
- **绝不硬猜**

## M4　视觉识别（补盲与佐证）

**定位**：不是主力，是**结构化拿不到时的补**，以及**结构化结果的独立佐证**。

### 4.1 渲染（有 DXF 时的正确用法）

```
DXF → 高 DPI 渲染（300–600 dpi）→ 分区切片
```

**关键技巧**：
- 用 DXF 已知坐标做**定向裁剪**（只裁需要的区域，如某个标注周边）
- 不要整图喂模型——小裁片精度远高于整图
- 配准：DXF 坐标 ↔ 图像坐标用 RANSAC 求仿射，θ 吸附到 90° 倍数

### 4.2 双引擎独立信源

| 引擎 | 角色 | 特点 |
|---|---|---|
| M1 轻量 OCR | 打底 + 坐标源 | 快、稳、召回高 |
| M2 文档 VLM | 交叉 | 输出干净（LaTeX/表格/符号），工程图召回偏低 |

**互补机制**：按 M1 的 box **分区送识**给 M2，补工程图召回；同图**多尺度对撞**互证。

### 4.3 中性转录（防"抄答案"）

争议 token 送视觉引擎时：**只给裁图，不给 OCR 原文**。
否则模型会顺着 OCR 的错误输出"顺杆爬"，两个引擎犯同一个错——这正是互证失效的主因。

**守卫**：若中性转录得到的值与 OCR 不同，且数字被改写，**维持人工**，不自动采纳。

## M5　归一与互证

### 5.1 归一三层

| 层 | 做什么 | 例 |
|---|---|---|
| **码位归一** | Unicode 等价类 | 已核准直径语境中的编码候选 → 受限语义比较；ψ等仅作OCR混淆候选 |
| **LaTeX 归一** | 命令 → Unicode | `\psi`→ψ、`\downarrow`→↓、`\vee`→∨ |
| **数值归一** | 字符串 → 三元组 | `+0.028/+0.003` → `(upper, lower)` |

**符号等价类表**（语义 → 码位集合 → 位置约束）：

| 语义 | 码位 | 约束 |
|---|---|---|
| 直径 | ⌀U+2300；Ø/φ等需语境及原图核准；ψ不作为无条件等价字符 | 数字前 |
| 深度 | ↓U+2193 ↧U+21A7 | 数字前 |
| 数量 | ×U+00D7 *U+002A | 数字前 |
| 沉孔 | ⊔U+2294 | 数字前 |
| 埋头孔 | ∨U+2228（仅字符编码事实，埋头形态待原页核准） | 数字前 |
| 弧长 | ∩U+2229 ｜ 斜度 ∠U+2220 ｜ 锥度 △U+25B3 | 数字前 |

位置是必要线索之一，不能单凭“数字前”确定语义；所有专业形态须核原页和关联对象。语义比较一致不等于原画法合规，PASS/FAIL读取状态不得直接映射为图纸违规。

**LaTeX转录层**（仅表示识读输出，不能推断标准原文使用该命令；未核专业形态不得发布）：
`\psi` `\downarrow` `\vee` `\sqcup` `\cap` `\angle` `\triangle` `\pm`

### 5.2 四分类 + 两类硬错误

对齐后按差异分类，**这决定了处置方式**：

| 类别 | 含义 | 处置 | 判定 |
|---|---|---|---|
| `agree` | 双引擎一致 | 放行候选 | PASS |
| `contradict` | 互斥 | 进仲裁 | — |
| `single` | 单信源 | 语境补证 | — |
| `symbol_loss` | **语义符号缺失** | 🔴 **不可归一** | **FAIL** |
| `value_error` | 数值不同且非格式差异 | 🔴 | **FAIL** |
| `case_diff` | 仅大小写（如 H7/h7） | **语义判**（孔轴） | 视语境 |

> **最重要的一条分界**：
> 前几类是"**写法不同**"，可归一；`symbol_loss` / `value_error` 是"**信息实质丢失/改变**"，**绝不可归一**。
> 把两者混同，就是误报与漏报的根源。

### 5.3 形态守卫

部分符号**形近义异**（`↓`深度 vs `∨`埋头孔；`⊔`沉孔 vs `⏋`锪平）。
纯文本层无法区分 → **形态判定必须走视觉或人工**。
设计上：形态存疑的 token 强制进 L4/L5，**不自动归一**。

## M6　判据引擎（"判合规"的实现）

### 6.1 规则表示

采用**声明式规则 DSL**，规则与代码分离（领域专家可维护）：

```yaml
- id: R-DIM-DIAM-001
  name: 直径符号缺失
  standard: "GB/T 4458.4"
  clause: "表 A.1 序号1"
  clause_text: "直径符号 ⌀ 应置于尺寸数字之前"
  verified: true

  when:
    feature.kind: [HOLE, SHAFT]
    annotation.has_diameter_geometry: true
  expect:
    annotation.prefix: DIAMETER
  on_fail:
    verdict: VIOLATION
    diff_type: SYMBOL_LOST
    severity: MAJOR
    suggestion: "在尺寸数字前补 ⌀（DXF 模板改为 {%%c<>}）"

  context_guard:
    sheet_kind: [PART, ASSEMBLY]     # 不限
```

```yaml
- id: R-HATCH-ADJACENT-001
  name: 装配图相邻件剖面线方向
  standard: "GB/T 4457.5"
  clause: "§4.7"
  clause_text: "相邻零件的剖面线方向应相反，或方向一致但间隔不等"
  verified: true

  when:
    sheet.kind: ASSEMBLY            # ★ 语境守卫：仅装配图启用
    hatch.adjacent: true
  expect:
    hatch.angle_delta: "!= 0 OR spacing_delta != 0"
  on_fail:
    verdict: VIOLATION
    severity: MAJOR

  context_guard:
    sheet_kind: [ASSEMBLY]          # 零件图下本规则不生效
```

### 6.2 规则库组织

按"**对象 → 方面**"二维组织，避免规则散乱：

```
对象维：DIMENSION / TOLERANCE / SURFACE / GTOL / HATCH / LINETYPE
         / THREAD / GEAR / BEARING / KEY / CENTER_HOLE / VIEW / TITLE
方面维：存在性 / 完整性 / 格式 / 数值 / 方向 / 位置 / 一致性
```

每条规则必须有：`standard + clause + clause_text + verified + context_guard + exceptions`。

### 6.3 误报防护三件套

| 机制 | 做法 |
|---|---|
| **语境守卫** | 规则只在指定 `sheet_kind / feature.kind / view_type` 下生效 |
| **例外清单** | 每条规则带 `exceptions`（如标准锥度可用 GB/T 157 编码替代，不能判错） |
| **严重度分级** | CRITICAL / MAJOR / MINOR / INFO，分级处置 |

**设计要点**：规则数量增长后最大风险是**互相打架**。
对策：所有规则强制声明 `context_guard`，引擎在执行前做**冲突检测**（同目标上出现互斥结论时，进仲裁而非任选其一）。

### 6.4 执行流程

```
for sheet in drawing:
    features = M3(sheet)
    for f in features:
        rules = rule_index.query(f.kind, f.context)     # 检索式，非全量
        for r in rules:
            if r.context_guard.match(f.context):
                result = r.evaluate(f)
                if result.failed: findings.append(Finding(...))
```

**检索式注入，不全量灌入**——规则多了会互相干扰，按对象类型动态取 Top-K。

## M7　仲裁与会诊

### 7.1 五轴融合

| 轴 | 证据来源 | 权重特性 |
|---|---|---|
| 轴1 格式 | 控制码 / 码位 / 线型 | **确定性，最高** |
| 轴2 数值 | 测量值 / 公差三元组 | 确定性，高 |
| 轴3 语境 | 图纸性质 / 物理量 | 中 |
| 轴4 几何 | 实体拓扑 / 关联 | 高 |
| 轴5 符号 | 视觉证据轴 | 中（补盲时才用） |

**融合原则**：**确定性轴优先**。当轴1/轴2 已给出确定性结论时，轴5 只作佐证，不推翻。

> 这条是对"让模型拍板"的直接否定：**模型产证据，判决权归规则轴。**

### 7.2 fail-closed 设计

```
if 任一确定性轴异常 or 格式可疑 or 规则冲突 or 置信 < 阈值:
    → REVIEW（交人工），绝不静默放行
```

### 7.3 图纸级会诊（L4c）

- 通道 A：拿终稿清单做**整图语义核查**（自圆其说 / 数值域 / 公差风格 / 图名互证）
- 通道 B：**真看整图**视觉复核（条件触发，控制成本）
- **降级不改文本**：会诊只能把 AUTO → `REVIEW_CONSILIUM`，**绝不直接改结论**
- 人工一键采纳：`--pick consilium`

## M8　人工闭环与进化

### 8.1 闭环结构

```
AI 判 → 专家纠 → 案例入库 → 检索命中 → 下次更准
```

**核心认知**：**模型不会因为使用而变强，但外部知识库会变厚。**
所以"成长"的工程实现 = **案例检索系统**，不是微调。

### 8.2 先例库

| 字段 | 作用 |
|---|---|
| 对象指纹 | 用于相似度检索 |
| 正例 + 反例 | 判别力来源 |
| 条款 + verified | 溯源 |
| 语境 | 适用范围 |
| 人工确认 | 可信度 |

**fail-closed 相似度门槛**：命中相似但**不完全相同**的 token → **拒绝放行**，交人工。
这条防止"看起来像"导致的错误推广。

### 8.3 DXF 真值通道

有源时，DXF 读数**可直接采纳为真值**（不需要人工确认），因为它是确定性的。
人工确认主要服务于**无源场景**和**语义判断**（对象类型、符号形态）。

## M9　判分与审计

### 9.1 七档判分

```
CORRECT      正确
CASE_DIFF    仅大小写/形式差异（需语义判定）
VALUE_EQ     数值等价（格式不同）
SUGGESTED    建议值
SPLICE       拼接（多来源合并）
FILL         补读填充
NOT_ON_PAGE  页内不存在（移出分母，必须披露）
MISSING      漏读（分母内，算失败）
```

**分母纪律**：`NOT_ON_PAGE` 移出分母**必须披露**，不得借此注水。
例：38 真值 − 3 个 NOT_ON_PAGE = 35 有效分母。

### 9.2 双向审计

| 方向 | 做法 | 目标 |
|---|---|---|
| 正向 | 对**错图**查是否查出错 | N/N |
| **反向** | 对**正图**验是否误报 | **0/N** |

**反向审计比正向更重要**——误报会摧毁用户信任。

### 9.3 误差棒

同一图多次完整重跑，报告均值与波动（如 ±5.6pt）。
**小样本必须标误差棒，不裸报 100%。**

# 四、关键算法专题（四个卡脖子的地方怎么解）

## 专题一：孔 / 轴判别（决定一整类公差判据）

已在 M3.3 给出。**补充交叉验证规则**：

| 几何判定 | 公差带字母 | 结论 |
|---|---|---|
| 孔 | 大写（H7） | ✅ 一致 |
| 轴 | 小写（h7/f7） | ✅ 一致 |
| 孔 | 小写 | ❌ 违规（Finding） |
| 轴 | 大写 | ❌ 违规（Finding） |

**依据**：GB/T 1800.1 基本偏差代号——孔大写、轴小写。
**这条判据的价值**：它是**几何判定与符号判定的交叉验证**，两者独立，冲突即可靠报错。

## 专题二：剖面线合规（装配图最大误报源）

```
输入：所有 HATCH（角度 angle、间距 spacing、基点）
步骤：
 1. 按视图分组
 2. 提取每个 HATCH 的 (angle mod 180, spacing)
 3. 构建邻接图（两 HATCH 的剖面区域是否相邻：边界共享/距离 < ε）
 4. 对每条邻接边判：
     合格 ⇔ (角度不同) OR (角度相同 AND 间距不同)
 5. 同一零件跨视图：方向应一致、间距应相同（相反判据！）
```

**注意第 5 条与第 4 条方向相反**——这正是"语境"重要性的最佳例证：
- 相邻**不同**零件 → 必须不同
- 同一零件**不同视图** → 必须相同

**两条规则必须靠 context_guard 隔离**，否则必打架。

## 专题三：线型合规

```
期望线型表（GB/T 4457.4 用途）：
  中心线 / 对称线        → CENTER 系
  假想轮廓 / 相邻辅助件  → PHANTOM（双点画线）
  不可见轮廓             → DASHED
  可见轮廓 / 剖面线      → Continuous
判法：
  实体实际线型 = (entity.linetype != ByLayer) ? entity.linetype : layer.linetype
  比对期望表，不符 → Finding
```

**这是零模型调用、纯确定性的一类判据，应当优先建设。**

## 专题四：表面结构符号（131）合规

难点：符号本体常为代理实体，参数读不到。

**分级判法**：
| 层级 | 可判 | 手段 |
|---|---|---|
| 存在性 | 该表面是否标注了粗糙度 | 代理实体位置 + 关联表面 |
| 朝向 | 符号尖端是否指向材料外并接触表面 | 显示缓存几何 + 表面法向 |
| 数值 | Ra 值 | 代理文字 / 视觉识别 |
| 注写方向 | 与尺寸数字方向一致 | 文字角度比对 |

**核心**：即使参数读不到，**存在性、朝向、方向这三类仍可用几何判**——不要因为拿不到参数就整体放弃。

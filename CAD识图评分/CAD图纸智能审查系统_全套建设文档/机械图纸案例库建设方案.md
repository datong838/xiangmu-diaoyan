# 机械图纸案例库建设方案

> **定位**：与另外两份文档互补，三者是输入→加工→产品的关系。
> - 《CAD判据库建设方案集》→ 解决「判据从哪来、怎么不出错」
> - 《机械图纸知识库_资料源与采购方案》→ 解决「知识从哪来、怎么喂进去」
> - **本文件** → 解决「案例怎么组织、怎么积累、怎么用起来」
>
> **核心判断**：本项目真正的护城河**不是模型，是案例库**。模型谁都能调，案例库是独有的。

## 零、为什么必须做案例库（来自 32 条复核实证）

### 0.1 一句话结论

**32 条复核：命题层通过 21 条，应用层只确认了 1 条（T05-5）。**

差的 20 条，**全部卡在同一个地方**——不是"看不清符号"，而是「**不知道画的是什么**」：

| 条目 | 国标说了什么 | 卡在哪 |
|---|---|---|
| **T03-1** | 装配图相邻件剖面线方向**相反** | 先要知道这是**装配图还是零件图**——判反即系统性误报 |
| **T05-3** | 滚动轴承**不画**剖面符号 | 先要认出「这是滚动轴承」 |
| **T04-2** | 移出断面轮廓用粗实线 | 先要认出「这是移出断面」 |
| **T01-8** | 孔大写 H / 轴小写 h | 先要知道这个 Ø 是孔还是外圆 |

**四条全是同一类问题：对象识别。**
国标条文逐字读到了、判据成立了，但**套不上去**——因为不知道画的是什么。

> **国标是语法书，不是语感。** 案例库的作用就是补这个语感。

### 0.2 一个反直觉但重要的判断

| 喂法 | 效果 | 证据 |
|---|---|---|
| 喂**更多图纸图片** | ⚠️ 收效有限 | BlueprintSymVL 实测：图越密越退化、相似符号混淆、**会幻觉符号** |
| 喂 **DXF 结构化 + 标注案例** | ✅ 有效 | 行业实测五种路线，纯图像全败，**DXF 提取 + 截图校正胜出** |

**原因**：VLM 擅长语义理解，不擅长几何度量。让它"看"两条线是否平行，只能看像素近似；工程要数学严格。

→ **"零件形状识别不出来"这个痛点，靠堆图片解决不了，得靠结构化几何 + 案例。**

## 一、案例库架构

### 1.1 三层结构

```
┌─────────────────────────────────────────┐
│  L3  检索注入层                          │
│      按对象类型动态注入最相关规则         │
├─────────────────────────────────────────┤
│  L2  案例层  ★核心资产                   │
│      案例条目（正误对 + 判据 + 确认状态） │
├─────────────────────────────────────────┤
│  L1  基础层                              │
│      判据库（国标条款） + 符号等价类表    │
└─────────────────────────────────────────┘
```

| 层 | 内容 | 来源 |
|---|---|---|
| **L1 基础层** | 判据（条款号+原文）、符号等价类、归一化规则 | 已建：《判据库建设方案集》 |
| **L2 案例层** | **案例条目**（本方案重点） | 待建：本文件 |
| **L3 注入层** | 检索式动态注入 | 待建：§6 |

### 1.2 🔴 架构决策：做检索，不做训练

| 机制 | 可行 | 说明 |
|---|---|---|
| 模型权重自己变强 | ❌ | 基础模型**不因使用改变权重**——"不能自主学习"是对的 |
| **上下文内学习** | ✅ | 已验证有效（十几轮复核即实例） |
| **外部记忆库 / RAG** | ✅ **这是产品** | 案例库检索增强，跨会话留存 |
| 微调 | ⚠️ | 灾难性遗忘，且需万级数据 |

**"留存记忆、一直成长"能产品化，但不是让模型变强，是让外部知识库变厚。**

→ **架构决策：做案例检索系统（L2+L3），不做模型训练。**

## 二、分类体系

### 2.1 四维分类树

```
行业 (Industry)
 └ 零件类型 (PartType)
    └ 特征 (Feature)
       └ 错误类型 (ErrorType)
```

| 维度 | 编码 | 取值 |
|---|---|---|
| **行业** | `IND` | `MECH` 机械 / `ELEC` 电工电子 / `ARCH` 装饰建筑 |
| **零件类型** | `PT` | `DISK` 盘套类 / `SHAFT` 轴类 / `BOX` 箱体类 / `FORK` 叉架类 / `STD` 标准件 |
| **特征** | `FT` | `HOLE` 孔 / `SHAFT_F` 轴 / `THREAD` 螺纹 / `KEY` 键槽 / `CENTER` 中心孔 / `CHAMFER` 倒角 / `SECTION` 剖面 / `DIM` 尺寸标注 / `GTOL` 几何公差 / `SURF` 表面结构 / `WELD` 焊接 / `SPRING` 弹簧 / `GEAR` 齿轮 / `BEARING` 轴承 |
| **错误类型** | `ET` | `SYM` 符号错 / `LTYPE` 线型错 / `TOL` 公差错 / `MISS` 遗漏 / `REDUN` 冗余 / `VIEW` 视图错 / `ANNO` 标注错 |

### 2.2 案例 ID 编码规则

```
CASE-{IND}-{PT}-{FT}-{ET}-{序号}

例：
CASE-MECH-DISK-HOLE-SYM-001    端盖孔符号错误
CASE-MECH-DISK-DIM-TOL-002     端盖尺寸公差错
CASE-MECH-BOX-SECTION-SYM-001  箱体剖面线方向
```

### 2.3 🔴 一个必须单独处理的维度：语境（Context）

这是 T03-1 教给我们的教训——**同一条判据在不同语境下结论相反**。

| 语境 | 编码 | 影响 |
|---|---|---|
| **图纸性质** | `CTX-ASSEM` 装配图 / `CTX-PART` 零件图 | T03-1：剖面线方向相反仅在**装配语境**强制 |
| **对象类型** | 孔 / 轴 / 端面 | T01-8：H 大写仅对孔成立 |
| **视图类型** | 主视/剖视/断面/局部 | T04-2：移出断面才用粗实线 |

**案例条目的"适用条件"字段必须显式记录语境**，否则会像 T03-1 那样正反规则打架。

### 3.2 必填字段（6个）与发布边界

任务类型必须区分机器读错READ_ERROR、参考差异REFERENCE_DIFF和规则违规RULE_VIOLATION。参考图差异不得自动作为国标违规；原始观察保留，不用正确答案静默补写错图。下列示例仅说明结构，CONFIRMED必须有真实审核人、时间、证据和版本。

| 字段 | 为什么必须 |
|---|---|
| **① `object.what_is_it` 对象类型** | **解决"读懂"的核心**——是关键缺口之一；阻塞需逐条区分读取、对象、关联及条件 |
| **② 依据类型、来源、版本与核准状态** | 国标需条款和原页；专家经验需审核记录，不虚填国标条号 |
| **③ `positive_example` + `negative_example`** | **配对才有判别力** |
| **④ `human_confirmation`** | 未确认的不能进训练 |
| **⑤ `applicability.exceptions`** | 防止过度泛化 |
| **⑥ `object.context`** | 语境决定判据是否适用（T03-1 教训） |

### 3.3 `diff_type` 分类（用于区分"可归一化"与"实质错误"）

这是十几轮踩坑归纳出的**关键区分**：

| `diff_type` | 含义 | 处理 | 判定 |
|---|---|---|---|
| `CODEPOINT` | 码位不同、语义相同（Ø/φ/⌀、↓/↧、×/*） | **等价类归一** | PASS |
| `WHITESPACE` | 空格差异（`Ø60 js6` vs `Ø60js6`） | 正则解析 | PASS |
| `SEPARATOR` | 分隔符差异（`/` vs 空格 vs `^`） | 三元组归一 | PASS |
| `LATEX` | LaTeX 命令（`\psi` / `\downarrow`） | LaTeX→Unicode 映射 | PASS |
| **`SYMBOL_LOST`** | **语义符号丢失（`Ø80` → `80`）** | 🔴 **不可归一，必须报错** | **FAIL** |
| **`VALUE_ERROR`** | 数值错误（28 读成 26） | 🔴 不可归一 | **FAIL** |
| `SEMANTIC` | 语义不同（深度 vs 埋头孔） | 🔴 需形态核实 | PENDING |

> **核心规则**：前四类归一后判 PASS；`SYMBOL_LOST` / `VALUE_ERROR` 一律 FAIL。
> **这是"Ø80 → 80"那次教给我们的**——符号缺失是"有/无"问题，不是"写法"问题。

## 五、T01–T05 正误对：被低估的核心资产

### 5.1 为什么稀缺

行业共识：**工程图纸最缺配对数据**——"需要同一张图的扫描件+精确 DXF 配对，**只有加工厂才有**"。

**但我们有 T01–T05 各一对正误图 = 5 组正误配对。** 目前仅用于复核，其实可以当**案例库的种子**——每组自带"哪里被改了、改得对不对"。

### 5.2 五组资产盘点

| 组 | 零件 | 已知改动 | 案例化状态 |
|---|---|---|---|
| **T01** | 矩形花键套 | Ø72 等 | 部分（码位比对） |
| **T02** | 端盖 | **线宽 2.04→0.84pt**（唯一确认） | ✅ 已闭环 |
| **T03** | 传动箱 | 待定（T03-1 语境关键） | 部分 |
| **T04** | 顶尖 | 待定（T04-2 存疑） | 部分 |
| **T05** | 轴承盖 | **T05-5 已确认** | ✅ 已闭环 |

### 5.3 迁移路径（把 5 组转成案例条目）

```
Step 1  拿到 DXF/DWG（平台限制见资料源方案 §3.4）
Step 2  ezdxf 提取实体差异（几何 + 文字 + 线型）
Step 3  对每个差异点填 6 个必填字段
Step 4  审核人/日期/证据/版本和适用条件齐全后置 CONFIRMED
Step 5  按 §2.2 编码入库
```

**预期产出**：5 组 × 若干差异点 ≈ **15–30 条带配对的高质量案例**。

## 六、检索注入机制（L3）

### 6.1 🔴 为什么不能全量灌入

规则多了会**互相干扰**。实证：T03-1 在装配语境与零件语境下**结论完全相反**，两条规则同时生效会打架。

### 6.2 注入策略

```
输入：图纸 → 识别对象类型 + 语境
  ↓
检索：按 (PT, FT, CTX) 匹配案例子集
  ↓
排序：优先 CONFIRMED > 有配对反例 > 定义级依据
  ↓
注入：只注入 Top-K（建议 K = 5–8 条）
  ↓
判定：模型按注入规则判，输出 diff_type + verdict
```

### 6.3 排序权重（建议）

| 因子 | 权重 | 理由 |
|---|---|---|
| `status == CONFIRMED` | ×3 | 未确认的不该主导判定 |
| 有 `negative_example` | ×2 | 配对才可靠 |
| `clause_verified == true` | ×2 | 条款已核实 |
| 有 `context` 且匹配 | ×2 | 语境匹配才适用 |
| 规则级（定义级 > 图例级 > 条文级） | ×1.5 | 依据强度 |

### 6.4 One-shot 视觉范例（建议引入）

来自 BlueprintSymVL 基准：查询时**给模型一个符号的视觉样例**，可"消除对不可靠先验知识的依赖"。

**这直接治我们的符号码位病**——⌀/Ø/φ 混淆，与其让模型猜，不如**给它看符号原图**。

建议位置：L2 案例条目中增加 `visual_exemplar` 字段（符号原图裁切）。

## 七、标注流程

### 7.1 三角色分工

| 角色 | 职责 | 不可兼任 |
|---|---|---|
| **① 提取员**（程序 + AI） | 从 DXF/图面提取候选差异 | — |
| **② 制图专家** | 判定对象类型、确认形态、判对错 | 不可由①兼任 |
| **③ 录入员** | 填字段、入库 | 可复核① |

专家审核是关键环节，既需要工时，也形成可复用资产。

### 7.2 质量控制（三道闸）

| 闸 | 内容 | 不通过则 |
|---|---|---|
| **闸1：依据可追溯并适用** | 国标需条款核准；经验需来源/审核/版本；适用条件与例外已核 | 不得输出确定判定 |
| **闸2：形态人工核实** | 符号形态必须人工确认（↓ vs ∨ 教训） | 标 `PENDING` |
| **闸3：配对完整性** | 尽量有正例+反例 | 无反例则标注置信度降级 |

### 7.3 标注工时估算

| 阶段 | 单条工时 | 说明 |
|---|---|---|
| 提取（程序） | 待测 | 自动执行仍有运行及研发维护成本 |
| **专家判定** | **10–30 min** | 主要成本 |
| 录入 | 5–10 min | 半自动 |

**行业共识**：一张图纸完整标注需专业工程师**数小时**。我们按"差异点"而非"整图"标注，可大幅降低。

### 7.4 闭环

```
AI 判 → 专家纠 → 案例入库 → 下次命中
```

**每一轮纠正都在加厚资产。** 这是产品能"成长"的真实机制。

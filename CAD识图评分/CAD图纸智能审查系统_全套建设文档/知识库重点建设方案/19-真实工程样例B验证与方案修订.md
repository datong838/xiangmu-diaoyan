## 2. 已形成的工程链与未完成部分

图面指定线段 → 明确角色绑定及证据 → 指定依据版次和原页 → 方法输入/条件检查 → 比值计算与测量区间 → 局部结果与解释 → 后续改进前提。这已比“找到相似图片或条款摘要”前进了一步。

正常分支有真实原件和计算结果；换绑为尺寸线、缺单位、未核对依据、版次改变、源哈希不一致、例外未知、非等比变换等均不得进入确定比值判断；例外成立输出不适用。反例是DERIVED_PERTURBATION，不计为新图纸或独立盲测。

测量不确定度0.0001pt来自本实验解析精度边界，独立于工程公差；以输入宽度区间计算比值区间，不声称标准允许此误差。相似案例和图上几何推断不得替代对象用途确认。

尚未把本轮对象/关系/方法回执整合进统一Schema与SQLite，也尚无实际检索入口、可信人工确认持久化、全工程条件和依据适用确认。故A03跨源工程链的技术试验已有证据，但完整可发布工程闭环差距仍保留，不按测试绿色自动关闭。

## 3. 复现过程中发现的问题

PDFMiner 20251230的do_w已乘CTM缩放，直接沿用旧版“读取linewidth后再乘CTM”会把1.44pt算成1.08pt、0.72pt算成0.54pt。本轮独立解释器明确保留原w，于paint_path按当前CTM只换算一次；等比缩放、w后变换、非等比、状态恢复与坐标反例均已测试。该修复只在新原型内，未改已有OCR或评分判据工具。

首次尝试bundled解释器合并运行时发现缺jsonschema，产生两个导入错误，未计通过。随后新建隔离.venv-evidence，复用PDF依赖并安装jsonschema，最终合并54项全部通过。旧Python3.9契约环境保留；独立复现依赖写入requirements-evidence.lock.txt。环境不混用，方法回执记录实际解析器版本。

Poppler对标准中的某些字体/文字层给出语言映射警告；相关页扫描图可正常显示，已目视核对；不把抽取文字当唯一原文。截图见原型reports/real_b目录；原件不改写。

复核局部位置时，初选细线operation0属于中心线位置，不能作为尺寸线证据。现改为φ80两箭头之间的水平尺寸线operation767（正确图），更新原件定位并重新通过54项测试。数值相同不证明语义角色相同；标注图见[正常线对定位图](/Users/ddt/work/projects/ai_agent/cad/engineering-kb/reports/real_b/normal_pair_overlay.png)。

## 4. 对知识库方案的直接修订要求

1. **方法和知识同样要记版本。** 输入、解析器、单位语义、坐标、精度、错误与适用限制都需进入MethodRun；旧脚本名不保证数值含义不变。
2. **知识关系有各自证据。** “这段是轮廓线”“这段属于剖切符号”不能只有bbox接近；助手绑定、几何解析、客户确认分别记录。
3. **来源类别不能带入结论。** 文件名正确/错误是来源标签，不是规范真值；历史应用确认须保留当时范围，不能作为新版本自动适用。
4. **知识条目必须包含不适用和近似陷阱。** 表1类别、第5章比值、表2线组/圆整、教学额外要求分别组织，不能只提炼成“线宽必须0.7”。
5. **检索与执行分开计时、分开验收。** 本轮54项测试约0.518秒是方法测试耗时，不是资料检索P95，更不能支持1TB秒级已达成。

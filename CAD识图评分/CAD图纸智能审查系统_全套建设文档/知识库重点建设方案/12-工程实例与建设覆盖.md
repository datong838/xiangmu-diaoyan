# 工程实例与知识建设覆盖

KB-DESIGN-003；2026-10-16。以下全部为设计演练，不是已执行审查或已核对标准条款。示例不声称任何具体图纸已经有错。

## 1. 例一：读到h7，是否应改为H7？

| 环节 | 应有知识/事实 | 当前可能状态 |
|---|---|---|
| J0 | 是判断读取、对照答案，还是做规范审查 | 先区分任务，不能把参考差异直接当违规 |
| J1/J2 | 原图确为h7吗，文字/字体/控制码/单位是否清楚 | raw与解释分开，不先转大写 |
| J3 | 关联到孔、外圆还是邻近对象；尺寸线/引线绑定如何 | 关系不明则保留多个分支 |
| J4/J5 | 该处功能、配合意图及检查项是否可知 | 功能未知不凭图形猜设计要求 |
| J6 | 哪条规则适用，大小写要求的前提和例外是什么 | 需来源、对象、标注归属共同支撑 |
| J7/J8 | 比较/计算已完成吗，得到哪类结论 | 可报告读取差异；工程结论可能仍待补证 |
| J9/J10 | 为什么改、改字符还是改设计，是否存在其他方案 | 缺配合意图时不指定唯一新公差 |
| J11 | 改后其他视图、配合件、尺寸链是否受影响 | 未执行复检则建议仍是待验证 |

涉及D01表达、D02对象、D03关联、D04规范、D05原理，必要时D06工艺/D07诊断/D08验证。仅检索“H7解释”无法覆盖整条链。

关键反例：对象相同但标注实际附着另一特征；图形相同但原字符不同；同一h7在不同对象/任务下应返回不同分支。验证系统是否按事实改变判断，而不是背诵一个答案。

## 2. 例二：某区域没有剖面线，是不是漏画？

首先证明“这个区域确实已读清”，再确认区域属于哪个对象以及视图性质。轴承等标准件、剖切关系、相邻零件、通用说明等都是待查条件，不先从外观认定。

- J1：图面无剖面线观察与“识读没有发现”分别保存。
- J3：对象/区域/视图/剖切关系都需要来源位置。
- J5：至少考虑“正常表达”“读取丢失”“对象认错”“可能漏画”等解释。
- J6：按确认的对象与视图检索具体条件和例外，不能把用户称呼当确认事实。
- J7—J9：只有适用规则和事实能共同支持时，才形成该类规范结论；否则说明最小缺口。
- J10/J11：候选改法及复检范围要包括相关视图，不能盲目添加剖面线。

库里建设的不是大量“没剖面线”的图片，而是区分上述情形的方法、条件、例外和可定位对照。图片为这些结构提供证据，并可帮助发现新类型。

## 3. 例三：标注形式没发现问题，是否适合加工和检验？

J0先明确这是工艺建议任务，不冒充国标违规审查。D06需要材料、几何、设备/工序、精度、装夹、装配与检验条件；图面未包含的条件不能从典型教材例子补成事实。

在缺现场条件时，可列工艺路径候选、需要补充的参数及风险；不宣称“必然做不出来”。如果已有具体设备/工艺输入，J7通过相应方法/工具计算或验证，J8输出适用范围内的工程意见。

J10的改法可能在加工、检验、装配、功能与成本之间权衡。规范无问题不等于方案经济，某工厂难做也不等于图纸违反规范。多目标冲突保留，不能让系统假装存在唯一最佳答案。

## 4. 例四：修改建议看似合理，为什么还要复检？

设想修改一个尺寸或视图表达。新建议需要回查关联标注、其他视图、配合件/基准、制造和检验方法、原要求与例外。

J11建立受影响子图并重跑相关检查；无法自动识别全部影响时明确覆盖范围，必要时补人工核对。成功经验必须绑定改前/改后版本、实际动作和结果；未执行建议只能保存为建议。

反例是“当前错误消失，但另一个视图不一致”或“满足参考答案却违背已知设计约束”。两者用来检验知识库是否只优化局部外观相似。

## 5. 建设覆盖矩阵如何用

[13-知识职责与判断环节矩阵.csv](13-知识职责与判断环节矩阵.csv)将D认知域、J步骤、所需知识单元、运行证据与验证例连接。本轮矩阵是建设清单，所有能力状态为DESIGN_ONLY；不是全量机械知识清单。

每个主题至少检查：

1. 对象/表达是否定义清楚，有无易混对象。
2. 标注、视图和实体之间的关联方法是什么。
3. 哪些图外条件影响结论，能否从当前资料得到。
4. 适用条件、例外与冲突是否表达。
5. 判断方法和必要工具输入/精度是否明确。
6. 哪些结论类型可以给，哪些不能给。
7. 是否有反例/边界，而不只是典型正确图。
8. 改进有何约束，如何证明改好且无已知回归。

对于只解释术语的任务，部分项可标不适用并说明；不能要求所有资料都变成完整方法包。

## 6. “全面”的新增衡量方法

前一版按对象/页/索引覆盖计量，本版增加按“主题×D职责×J步骤”计量。每格记录NOT_STARTED、HAS_SOURCE、HAS_KNOWLEDGE、HAS_METHOD、HAS_EXAMPLE、TESTED_FOR_SCOPE中的适用状态，可有多个状态并存。

有资料但没有方法，有方法但缺反例，有反例但没测当前语境，都是不同缺口。只统计真实登记的主题和任务，不声称矩阵填满就穷尽整个机械领域。

用户提出新问题时可以新增主题/关系/条件，形成开放的未知清单；不能为了保持100%覆盖把新问题排出范围。能力扩展的价值是走通新的工程判断分支，而不只是增加GB和向量数。

## 7. 首期建议组合

原先四个建议主题保留为扩展候选：孔/轴与公差语境、装配/零件剖面表达、标准件剖视例外、符号丢失与读取差异。2026-10-21首批按[31](31-知识吸收完整性与工程判断正确性补强.md)收敛为KB-PILOT-01孔/轴标注与公差语义。每主题同时建设D01—D08中实际需要的知识，拿正常/错误/边界/未知/修改后样例做端到端演练。

资料来源的优先级按缺口决定：对象概念不足先补教材；条件与例外不足补标准原页；工艺推理不足补手册/现场条件；纠错不足补正误对照；方法可靠性不足补验证。这比无差别扩大图片量更能针对当前问题，同时不否定大量图像对识别泛化与检索样本的价值。

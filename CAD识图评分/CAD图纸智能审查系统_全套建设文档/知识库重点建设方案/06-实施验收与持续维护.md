# 实施路线、验收与持续维护

KB-DESIGN-005；2026-10-21。以下是目标工作包；17—25已有局部原型验证，未完成生产实施及规模验收。先用小实例检验方案，再逐步实现和修订；不把文档地位或文档数量当交付能力。

## 1. 建设工作包

| 工作包 | 范围与交付 | 完成门槛 |
|---|---|---|
| W0 资产与测量基线 | 全部获准来源/归档成员登记；模态、单位、许可、分母和不可解析清单 | 登记范围 100% 可追溯、无未解释遗漏；不声称全部已理解 |
| W1 目录与运行基础 | 来源/版本、当前确认、原文定位、访问及发布基础；小主题试验并行 | 合同兼容、当前状态可查、来源可回溯；局部原型不替代生产发布保证 |
| W2 工程知识与方法 | 主题概念/关联/条件/判据/解释/改进/复检，知识单元与Wiki增量编译 | 真实正常/错误/未知例有来源和方法；未验证范围明确，跨源矛盾保留 |
| W3 检索质量与任务验证 | 按D/J缺口、多主题双路检索、经验验证、独立题集与组件对照 | 测适用性/步骤证据/长尾/例外，Q0/Q1按实测校准；不只测文本相似度 |
| W4 大容量扩展 | 数百 GB→1 TB 代表性独有原件，补语义/视觉覆盖 | 真实容量、对象数、模态、P95、冷读取、备份恢复报告 |
| W5 持续更新 | 差分、代际发布、撤销、重建、冲突与经验回写 | 增量与重建结果对照、故障演练、当前/历史一致 |

W0分两条并行流：W0-A先对声明范围内的物理文件/原包做来源、大小、版本与状态登记；W0-B按包逐批枚举成员、页和记录，持续输出各层级分母及未完成范围。W1可在一个成员清单已完整的小快照上开始，不等待全库数百万成员枚举完；但不能将小快照的100%外推为全库覆盖。

W0 的全量登记不因“先选一万样本”跳过。W1/W2 重语义计算可先选约一万组代表样本，但不能据此宣布全库检索已达标。W4 必须满足声明的 1 TB 原件和逻辑对象规模，不能复制同一小数据集凑字节。

实施时列出具体代码/数据目录、可回退步骤、验证和受影响功能，按用户工作范围推进。探索分类和选型不需要另走文档审批；实际外部账号、费用或专业未知等问题按当时具体情况处理。

## 2. 评测集的建立

首期建议 300 个真实任务：Q0 精确 60、Q1 局部 120、Q2 跨域/全量 40、故障与治理 60、无答案/歧义 20。每题可附多个标签，但按主类统计防止重复计数。

100 题开发校准，200 题锁定验收；各类分层抽取。标准原文、专家复核和已知图纸提供金标准。例外/不同版本/近似反例/稀有细节必须出现，不能只问索引中最常见的主题。

[08-验收场景种子.csv](08-验收场景种子.csv)是本轮场景设计，所有行都为 NOT_RUN，需绑定真实 source_version、期望证据 ID 和责任人后才能执行；不是已有 300 题金标准。

CAD 按 PDF-only/CAD 增强、单图规范/参考答案对照/解释任务分别建立子集；按零件家族、来源、图纸模板和正反对分组划分；同一图不同渲染/增强不得跨训练提示与评测集。评测专家确认不因案例被索引而自动泄露，留出集案例正文不进入 few-shot 库。

## 3. 质量与性能指标

| 指标 | 定义 | 初始门槛建议 |
|---|---|---|
| 登记可追溯率 | 已获准登记对象/发现对象，含 unsupported 明细 | 声明范围 100%，任何差异逐项解释 |
| 定位正确率 | 证据 ID 能回到正确版本/页/图块/实体 | 锁定集 100%，错误为阻断缺陷 |
| 精确项召回 | 正确编号/大小写/符号候选是否命中 | 指定关键集 100%，不外推任意文本 |
| Recall@20 | 金标准相关单元被候选覆盖的比例 | 总体≥90%，分类报告长尾与各模态 |
| 必需证据角色齐备率 | 对象/规则/例外等 mandatory 角色全部存在的任务比例 | 可回答验收集≥95%；关键审查缺失则拒判 |
| 依据适用错误 | 过期/未核/不同语境证据被当有效依据 | 关键负例集 0/N |
| 无证据确定回答 | 缺证据仍确定回答的次数 | 指定无答案集 0/N |
| 访问边界泄漏 | 越权资料/摘要/缓存暴露 | 故障与权限集 0/N |
| Q0 延迟 | 预处理且在线条件下端到端检索 | P95≤1 秒 |
| Q1 首批/标准包 | 第一批可读证据/完整证据包 | P95≤2 秒 / ≤5 秒 |
| Q2 覆盖回执 | 有范围与未完成项的任务回执 | ≤5 秒；完整时间实测披露 |

Recall@20 不是全量知识完备性证明；0/N 不是永远零误报。报告 N、问题分层、误差区间和实测限制；例如零错误时仍给出合适的二项置信区间，不将有限样本换成生产保证。

规则执行准确率、C2 对象识别、C3 解释正确性、最终答案支持率另测，不能被检索召回率替代。人工评分至少定义争议处理与复核流程。

## 4. 性能测量协议

固定机器/系统、存储、供电、模型与服务版本、原件/单元/向量数量、索引代际和权限配置。分开测单并发与并发 4，至少 1000 次查询回放，含足够长尾；报告 P50/P95/P99、超时率、RSS、交换、CPU 与读取量。

结果缓存冷但服务已就绪作为 Q1 主口径；同题缓存热单列。操作系统页缓存冷、进程启动、模型加载、外置盘唤醒、网络不稳定分别建立场景，不混进一个漂亮平均数。采样时允许的 OS 缓存控制方式需声明，无法清除就标“近似冷”。

计时范围包括请求进入、目录与索引、证据读取/校验直到包可用；答案首 token/最终完成和远程模型耗时单列。发布过的 corpus 中存在未解析范围，回执仍要披露；不能把困难问题都排到 Q2 来人为提高 Q1 达标率，分类规则须在验收前固定。

## 5. 必做对照实验

A 全文/精确基线；B 仅向量；C 全文+向量融合；D C+K2 路由；E D+全域稀疏旁路；F E+必需关系展开/反例；G F+精排；H G+缓存。

同题同权限同版本比较召回、适用性、时间、资源。若某层没有质量或延迟收益，暂不引入；路由降低长尾召回则不能因平均速度更快而通过。模型选型以中文、工程符号、代码和 CAD 图块代表集测试，不用一般排行榜分数替代。

## 6. 故障与退化验收

- 外置盘失联：源不可用状态正确，不误写内置盘同名路径；恢复后按版本继续。
- 单个解析任务崩溃/损坏包：隔离并保留记录，不影响其他独立作业，未完成分母不被删除。
- 索引发布中断：只能看到旧完整代际或新完整代际，不能混拼。
- 来源/标准更新：派生知识和缓存正确标记复核，保留旧证据用于有权限历史审计。
- 权限/用途许可撤销：旧摘要、关系、结果缓存不能泄漏；读取时验证水位。
- 语义服务不可用：Q0/全文基线仍可用，回执显示缺少的检索通道。
- 对象语境错误、标准冲突、配对缺反例：显示未知或争议，不靠分数掩盖。
- 报告要求“全部”：分页/计数与范围清单完整，Top-K 不能伪装穷举。

## 7. 项目内维护骨架

实施后建议在独立知识库项目中设置 project-memory：README（入口）、00（短摘要）、01（当前状态）、02（决定）、03（检查点）、04（注册）、05（关系）、06（变更/待复核）、07（资产）、08（来源到知识/规则/案例映射）、09（历史）、10（机器可读发布状态）。

这是借鉴，不复制 MRPMES 的业务事实、编号或当前状态。四个当前入口共享同一 KB 修订号，短摘要目标≤1500 中文字；历史按批追加到历史记录，不向四入口反复追加整批内容。

机器索引由数据库/manifest 维护，人读 Markdown 是投影；生成失败时不能让 Markdown 声称已发布。任何“已实现/已验收”状态必须链接实际运行回执，文档指纹不能代替阅读或验证。

## 8. 每轮维护动作

收集变更 → 变更清单 → 影响分析 → 差分解析/复核 → 同题回归 → staging 验收 → 原子发布 → 更新当前入口/决定/检查点 → 保存历史与成本截点。

新资料首先登记，不自动改写已确认知识；有冲突保留双方原文和范围。经验升级需验证依据，撤销经验需失效传播。更新慢于目标 SLA 时明确 backlog，不能继续声称知识实时。

SLA 初始建议：新增文件在已运行服务事件触发后 5 分钟内登记，语义索引按批次发布；真实可承诺时间由 W1 吞吐测试确定。未运行服务时没有自动发现承诺。本轮不安装任何定时或后台服务。

## 9. 分期交付清单

每次必须交付 corpus manifest/分母、覆盖报告、索引与模型版本、评测题与金标准来源、运行结果和失败明细、资源/费用、已知缺口、恢复记录和下一工作包。

W4 完成才允许声明“已在所述 1 TB 规模验证”；W3通过只支持实际声明并验收的主题，当前第一批按31收敛，不能预先写成四主题都通过。服务健康、样例演示、静态检查、某模型能启动都不能替代最终验收。

## 10. 当前待决事项

这些不会阻止本轮完成架构方案，但实施时必须在相应工作包入口补齐，不能用想象值填成实测事实。

## 11. 工程知识能力的新增验证维度

| 维度 | 怎么验证 | 不可用什么替代 |
|---|---|---|
| D域职责区分 | 相同主题分别问语义、规范、工艺、纠错，观察依据与结论是否变化 | 所有问题都返回一段国标 |
| J链缺口识别 | 删除对象绑定/单位/图外条件，检查能否说清缺什么与下一动作 | 模型自报高置信度 |
| 事实/缺失区分 | 未读区域、清晰局部缺项、其他视图已有三类对照 | 没有检测框就说漏画 |
| 关系正确性 | 对象不变仅换标注附着关系，预期适用分支随之改变 | 只统计对象识别率 |
| 条件与例外 | 同图换任务/版次/装配语境，保留正常边界 | 相似案例多数投票 |
| 方法执行 | 给出可复算输入/单位/工具记录，检查未运行时不编结果 | 解释文字貌似专业 |
| 解释忠实性 | 每条理由能对应观察/条件/来源/计算，测试反证与冲突 | 引用数量多 |
| 改进与复检 | 改前改后及受影响视图/尺寸比较，构造局部改好但另一处出错 | 用户觉得建议不错 |
| 经验泛化边界 | 同方法换设备/材料/工况，检查不适用/未知处理 | 一次成功就写通用规律 |

每项先建立可复核样例与预期行为，再决定数量门槛；本轮不编造实测分数。以主题×D×J记录覆盖，核心角色随任务变化，不要求所有问答都填满12步。

## 12. 对照实验与推进顺序修订

在原A—H检索对照外，新增I（相同资料但按D职责选知识）、J（I加当前步骤/缺口）、K（J加条件/反例）、L（K加方法/复检信息）。使用同一组独立问题比较适用性、错误泛化、缺口识别、最终结果与时间成本。

先做一条有真实证据的小链，发现字段/职责不合理就改文档和模型；不等待全机械分类或所有资料解析完成。TB级登记可与小型知识工程并行，但大规模索引不应先于证明知识组织有用。

首期300题的总规划保留，新增场景用于补足各主类而非简单扩张分母；开发/验证划分仍防同源泄漏。08是种子设计，新增行不是已执行证据。

## 13. 按实备/采购资料调整首轮工作

W0先纳管现有标准、真实PDF/CAD、已下载数据的登记状态；W1选一个公差/对象主题，将标准原页、现有图样和到货教材/手册/图册接入同一知识小包。手册的有关篇目从首轮参与，不因总体分期而推迟工艺知识建设。

到货前不编书内正文：用已取得材料做可验证部分并记录缺口。到货后先核版权页/目录/介质和小样质量，再逐主题补概念、条件、方法、对照和复检。每主题交付具体source_unit与D/J映射，不用“买了几本”或“200个例子”直接替代能力数量。


## 14. 自查后建议的第一轮实施准备

成熟度详见[15自查报告](15-成熟度与实施就绪自查报告.md)。截至20261016，16—25已有最小运行合同和局部原型验证，26已有文件级任务；完整生产Schema/错误合同、独立金标准和大容量性能仍未完成，不能直接当成整库验收。

先交付一个可重放的小快照与最小数据合同，再做两条试验：A为图面文字/JSON/人工确认的来源冲突检索；B为真实图纸对象与一条已核依据的适用性判断。A成功不能代替B，B缺条款或对象证据时如实返回缺口。手册正文未取得时先保留工艺角色未知，不等采购或全量OCR完成才开工，也不编造工艺结论。

首轮应明确拟建代码目录、输入输出样例、幂等/失败处理、调用预算、验证及回退；详细建议顺序与退出条件列在15。该段原为首次自查时的准备建议；后续独立原型已按17—25局部落地，尚未全量建库。本轮再自审见30。

## 15. 持续知识编译与经验维护验收（2026-10-19）

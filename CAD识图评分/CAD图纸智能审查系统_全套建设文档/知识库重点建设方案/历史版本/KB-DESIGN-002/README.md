# 工程知识库建设方案

日期：2026-10-16；KB-DESIGN-002；探索草案，可整体重构。文档不是固定权威，方案结构和选型都可根据实例修订；本轮没有实现知识库服务。

**建设对象：能支撑图纸理解、对象关联、条件判断、依据使用、原因解释与改进验证的工程知识体系。** 资料库提供广度，工程知识与方法提供深度，检索让它们在任务中及时可用。

## 两条主轴与一个存储底座

| 部分 | 核心设计 |
|---|---|
| 知识组织轴 | 来源S × 认知职责D × 对象/任务 × 条件/版本；国标、教材、手册、正误图册与专家经验各有贡献，不能互相冒充 |
| 工程判断轴 | J0—J11可组合：任务范围、事实质量、表达语义、对象关系、工程情境、问题假设、条件例外、判据计算、结论分型、解释、改进、复检回写 |
| 大容量底座 | K0—K5六层记忆：原件、全量定位、轻量导航、专项索引、知识方法、任务证据；仍保留TB级完整可达与秒级定位目标 |

用户提出的五步主线仍是骨架：**图面事实 → 对象关联 → 适用条件 → 判据执行 → 解释与改进**。新增加的环节补齐链前的任务与证据、链内的语义/情境/例外，以及链后的复检，不是每问强制走12步。

## 对容量与速度的承诺方式

> TB原件完整保存与登记 → 约100 MB常驻导航 → 磁盘索引按需 → 定位相关集合 → 读取小证据包 → 按任务执行必要方法。

100 MB不是全部知识的无损压缩，相关1 GB不是每问整体读入模型。首批证据P95≤2秒、标准证据包P95≤5秒仍是待测目标，不包括整图识别、复杂计算和改图复检的全部时间。

## 本轮的设计变化

检索不只返回“最相似资料”，还返回“当前环节缺什么、哪些方法可用、条件/例外是否已知、怎样验证”。知识库积累可复用概念、关联方法、条件规则、解释、对照和验证经验；图片是重要证据与学习样本，不以无差别堆图代替这些结构。

对资料规模继续计量，同时新增“主题×知识职责×判断环节”覆盖。允许未知、争议和暂定解释；没有足够证据的结论不伪装成事实，但无需给每条资料附加审批流程。

## 当前与下一步

本轮仅更新方案与设计附件；没有新建数据库、运行规则/识图引擎或恢复定时跟进。上一版保存在[历史版本](../KB-DESIGN-001/README.md)，用于比较，不限制修改。

建议先选一个真实主题，同时做资料定位、知识提炼和J链演练，验证这些分类/字段是否有用；不要先建完整机械本体，也不要先给千万图片生成向量。工作包见06。

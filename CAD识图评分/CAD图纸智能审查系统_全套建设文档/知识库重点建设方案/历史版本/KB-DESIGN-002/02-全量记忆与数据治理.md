# 全量记忆、定位与数据治理设计

KB-DESIGN-002；2026-10-16；设计态。字段为实施合同建议，不是已建数据库。

## 1. 统一身份：不能只靠路径和文件名

资产的逻辑身份与内容版本分开：asset_id 在改名、移动时保留；asset_version_id 绑定实际内容哈希。相同字节可共用物理对象，但不同来源、许可和用途仍保留各自登记，不能把去重变成来源合并。

建议以 SHA-256 标识新纳管原件版本。既有下载官方 MD5 回执保留为来源校验记录；后续纳管可另算 SHA-256，不能把补算哈希冒称官方提供。

## 2. 核心对象合同

| 对象 | 关键字段 | 必须成立的关系 |
|---|---|---|
| Asset | asset_id、project、tenant、source_family、owner、license_scope、role | 一个资产可有多个版本与位置 |
| AssetVersion | version_id、asset_id、content_hash、bytes、media_type、acquired_at、valid_time、recorded_at | 版本内容不原位覆盖 |
| Location | version_id、volume_id、relative_path、archive_chain、member_id、compression、availability | 位置变化不改变内容身份 |
| Unit | unit_id、version_id、parent_unit_id、kind、locator、raw_ref、parse_run_id | 页/章节/表行/图块/实体属于确定来源版本 |
| ParseRun | parser、version、config_hash、input_version、output_hash、status、errors | 重跑结果与旧结果可并存比较 |
| Coverage | scope、snapshot、denominator_manifest、registered、parsed、indexed、verified、excluded、failed | 所有数量有可重现分母 |
| KnowledgeItem | knowledge_id、kind、statement、conditions、exceptions、status、source_units | 没有来源只能是明确标注的假设 |
| Relation | from、to、type、scope、source_units、status、revision | 不凭相似度自动产生替代/有效关系 |
| Decision | decision_id、scope、state、rationale、authority_ref、effective_revision | 候选与采纳分列 |
| QueryReceipt | query_id、snapshot、routes、shards、missing、timings、evidence_ids | 超时和缺失不能伪装成完整结果 |
| IndexGeneration | generation、input_manifest、parser_profile、embedding_profile、checksums、status | 一次查询使用可复现代际 |
| ChangeEvent | source_version、change_type、affected_items、review_status、release | 更新可传播至派生物和缓存 |

所有可检索内容继承源资产的项目、权限、许可与版本限制，包括摘要、缩略图、向量 payload、关系边和缓存。普通场景可以单项目；扩展多租户必须显式隔离，不能只凭用户问题中的项目名过滤。

## 3. 定位合同：从答案一步回原件

| 类型 | 最小定位 | 不能只保存什么 |
|---|---|---|
| Markdown/源码 | 内容版本 + 标题/符号 + 行段或字节段 | 只有当前路径和易漂移行号 |
| PDF/扫描件 | 文件版本 + 页号 + 原坐标框 + 裁剪/旋转变换 | 只有 OCR 文字 |
| 表格 | 工作表/表名 + 行列/键 + 表头/单位 | 孤立单元格数值 |
| DXF | 文件版本 + layout + 块引用路径 + handle + 变换矩阵 | 只有截图坐标或全局 handle |
| 图像 | 原图版本 + 像素框 + 分辨率 + 图块到原图变换 | 只有图像描述向量 |
| ZIP 成员 | 归档版本 + 成员序号/路径 + 校验 + 压缩信息 | 只有成员名（可能重复） |
| TAR.GZ 成员 | 同上 + 派生可随机访问对象映射 | 假定压缩流可按未压缩 offset 直接 seek |
| 巨型 JSON | 文件版本 + record_key/指针 + 派生记录块位置 | 每问加载整份数 GB JSON |

存储 API 使用注册 ID 读取，禁止接受任意文件路径或 `../` 归档路径。嵌套压缩深度、单成员大小、总展开量和解压时间设上限；异常项隔离、登记、可恢复，不静默跳过。DWG/DXF 解析进程隔离，不运行数据集自带脚本。

## 4. 六种覆盖要分别记

1. 已发现：目录扫描发现对象。挂载失败不等于该目录没有资料。
2. 已登记：来源、版本、定位和用途登记完成。
3. 已解析：指定表示提取成功，不等于语义准确。
4. 已索引：该表示已进入指定查询通道。
5. 已核验：指定证据/标注通过相应核验；不是对整份文件所有内容的认可。
6. 工程适用已确认：规则/经验在指定对象、版本和条件下获准使用。

每层保留 pending/failed/unsupported/restricted/quarantined，不将不支持的资料从分母删除。去重前文件数、去重后字节对象数、原件/派生件数分别记。

覆盖报告示例：某快照有 10000 个 PDF，其中 10000 已登记、9000 解析成功、8000 文字质量达标、7000 进入向量索引。只可以宣称相应范围达标，不能宣称全库已经学会。

归档覆盖同时统计“归档对象数”和“逻辑成员数”。一个 ZIP 下载校验通过不能替代几十万成员的可检索覆盖。未知成员总数必须先列目录才能生成真实分母。

## 5. 语义保持与结构化提炼

原始表示永远可回查。规范化值、模型提取、人工修订以独立字段保存：raw、normalized、interpretation、validation。不能用 normalized 覆盖 raw。

条款切分保留前置条件、例外、注释、图表和交叉引用；表格保留表头/单位/脚注；图纸保留视图与对象关系。摘要需附 derived_from 单元清单与“未覆盖内容”，不宣称覆盖所有细节。

来源/依据类型初步分为 STANDARD、MANUAL、EXPERT_RECORD、TEXTBOOK、CONTRAST_ATLAS、DATASET、TOOL_DOCUMENTATION、REFERENCE_ANSWER、PROJECT_AGREEMENT；每类保存自己的核验主体、版本和适用条件。专家/手册经验不虚填国标条号，教材不自动成为强制规则，答案对照不自动等于规范违规。

解释、引用原文、规则条件和执行表达式分列。模型总结不得直接成为可执行规则。规则表达式需独立评审和测试，不能把自然语言“应当”自动转成否决条件。

## 6. 来源、假设与验证状态

知识项以“来源已定位、内容已核对、适用范围已试验、存在假设/争议、来源已变化”等独立标记描述，不强制每条术语经过同一审批状态机。普通内容可立即检索；是否足以支持某类工程结论，由当前用途、条件和验证记录决定。原001状态机保留在历史版本，不作为实施前置。

条款同时具备来源原页、准确定位、标准版本、适用范围和核验记录，才允许 clause_verified=true。规则当前能否用于特定判断还取决于工程对象和版本条件，不由确认次数或相似分决定。

**原始可见内容、图面真值、对象语义和合规结论不是同一层证据。** DXF 中读到 H7 可以是直接观察；该特征是孔需要语境证据；该标注合规还需要适用条款。

现行状态用显式发布/替代关系确定，不以文件名日期最大或编号最大决定。同一文档可以包含多个时期的结论，适用性和验证记录应细化到章节或知识项。

## 7. 关系与完整性闭包

首批明确关系：derived_from、paired_with、depicts、applies_when、exception_to、supersedes、contradicts、verified_by、depends_on。

每条规则必须能定位适用条件和已知例外；每个案例关联对象与语境；每个经验关联输入、步骤、验证和边界。关系展开默认限制 1—2 跳，但规则的 mandatory 依赖（条款版本、例外、确认记录）不能因跳数上限静默省略；缺失则返回证据不足。

图数据库不是前提：关系表与有界查询先行；热点邻接可缓存。全库自动抽取图谱仅作候选，人工/结构化证据审核后才能作为已核对的知识关系使用。

## 8. 更新、撤销和发布

发布流程：发现变化 → 新 AssetVersion → 差分解析 → 重建受影响 Unit/索引/知识 → 依赖影响列表 → 质量检查 → 新 generation → 原子切换当前清单。

目录库与向量库不假设分布式原子事务。使用清单驱动的 staged/validated/published 状态：查询只读已发布 generation，投影带相同版本键；切换未完成时保留旧完整代际，不混拼新旧结果。

权限撤销与敏感资料下架优先于重建：维护当前访问/撤回记录，读取和缓存命中时再次核对；无法复核即拒绝释放内容。旧代际只供有权限的审计，不绕过当前撤销。

知识项和回答缓存按 source_versions、generation、权限/许可作用域及规则版本失效。来源变化只说明需影响分析，不自动推断所有下游事实都错；反之也不能继续把旧指纹当成新版本已核实。

## 9. 持久性与恢复

原件、登记数据库、知识确认记录、发布清单与加密/权限配置属于不可丢的核心资产；向量和摘要可重建但保留版本和构建成本记录。外置盘不是备份，至少另一独立介质/获准存储保有恢复副本，定期真实恢复抽验。

文件删除使用 tombstone 保留逻辑身份，明确业务撤回/物理丢失/路径迁移；备份保留与删除要求需在实施时确认。硬盘离线时已缓存摘要只能显示其来源不可访问状态，不能声称刚核对过原文。

多写入者使用一个发布维护者或数据库串行事务；不同作业写独立 staging。项目 Markdown 入口由同一修订号批次发布，避免“最后写入覆盖”造成状态冲突。

## 10. 覆盖清单的机器约束建议

每个发布快照保存对象分母清单的 ID/hash，Coverage 的六种计数须能通过该清单和逐对象状态重算。一个对象可同时具备 text_indexed=true、image_indexed=false、semantic_verified=false，不能用单一布尔 done 覆盖所有模态。

主键/引用约束包括：Unit 必须引用确定 AssetVersion；Relation 两端存在且有范围；KnowledgeItem 的来源引用存在；已发布 IndexGeneration 只引用校验完成分片；QueryReceipt 引用其实际读取 generation。删除或撤销保留 tombstone，使旧回执仍可解释。

“全量搜索”需指定对象层级（文件/成员/页/实体）、模态、权限和用途作用域、解析快照和版本集合。页面因格式不支持而失败时，依然在分母中；明确不纳管的资料单独列 excluded_reason，不以技术失败当范围排除理由。

## 11. 工程知识与任务实例的数据补全

| 对象 | 新增字段组 | 要避免的混淆 |
|---|---|---|
| KnowledgeItem | source_type、domain_ids(D01—D08)、object_types、task_types、condition_refs、exceptions、explanation_refs、hypotheses、verification_scope | 来源类别≠职责≠正确性，摘要不是图纸事实 |
| CapabilityUnit | stage_ids(J0—J11)、input/output_roles、method、tool_requirements、unknown_behavior、counterexamples、validation_refs | 方法定义不等于某次运行成功 |
| DrawingObservation | raw、locator、channel、reading_quality、inspected_scope、alternatives_checked、source_version | 没识别到≠图上不存在 |
| Object/RelationHypothesis | candidates、relation_type、supporting/refuting_evidence、coordinate_frame、state | 有孔和H7不等于二者已关联 |
| EngineeringContext | name/value/unit、source、valid_scope、assumed/observed、unknown_reason | 常见工艺经验不能冒充客户当前设备能力 |
| AssessmentTask | task_type、scope、inputs、context、questions、evidence_gaps、stage_states、search_budget | 单图审查/读取比较/答案对照混在一起 |
| MethodRun | method/version、input_versions、parameters/units、tool/version、precision、results、completion_status | 检索命中不能当计算已执行 |
| Finding | kind、target、supporting_evidence、conditions、counter_evidence、missing_inputs、scope、method_run | 多个结论类型不能合成一个无范围PASS |
| ImprovementProposal | target/diff、rationale、preserved_constraints、alternatives、side_effects、validation_plan、execution_status | 给建议不等于已改图或已验证 |
| Recheck/ExperienceEvent | before/after、affected_subgraph、checks_run、new_issues、actual_result、reuse_scope | 用户认可思路≠工程效果证实 |

字段是当前候选设计，可按用途精简；不让一个普通术语记录背负全部任务字段。知识域、环节和能力单元定义见10/11。

## 12. 关系与条件的精细语义

新增 annotates、belongs_to、projects_to、section_of、mates_with、datum_of、requires_input、supports/refutes、affects、rechecked_by；区别几何事实、语义候选和知识依赖。关系需有对象版本与证据，置信度只作辅助，不能用一个分数替代来源质量、关联确定性、条件完整性和方法验证。

条件采用TRUE/FALSE/UNKNOWN，来源矛盾另记CONFLICTED。保存条件表达式、求值输入与未知原因；“规则不适用”“规则适用但不满足”“还无法知道是否适用”是三件不同的事。

覆盖台账增加topic_id×domain_id×stage_id×task_type。资料覆盖、知识职责覆盖、工程环节覆盖分别统计，分母来源于当前定义的主题与任务，不宣称穷尽机械工程。每次新增真实问题允许新增缺口，不能为了100%覆盖排除未知问题。

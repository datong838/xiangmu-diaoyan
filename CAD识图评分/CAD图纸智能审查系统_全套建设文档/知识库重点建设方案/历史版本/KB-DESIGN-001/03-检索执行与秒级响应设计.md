# 检索执行与秒级响应设计

KB-DESIGN-001；2026-10-16；性能数字均为待验收目标。容量与部署条件见 [05](05-容量资源与构建部署方案.md)。

## 1. 三类请求，三种承诺

| 类型 | 示例 | 返回与时限目标 |
|---|---|---|
| Q0 精确定位 | 找指定标准版本/条款/API/图纸 ID | 已索引在线范围 P95≤1 秒返回可定位候选或明确缺口 |
| Q1 局部工程问答 | H7/h7 在某对象上的含义；找同语境正反案例 | P95≤2 秒首批可用证据，P95≤5 秒标准证据包 |
| Q2 全域/深度 | 全库归纳所有相关例外；整份复杂图审查；首次扫描件理解 | ≤5 秒返回范围/任务回执，完整耗时按工作量实测；不冒称已分析完 |

Q0/Q1 的条件：解析与索引已发布、服务和检索模型已就绪、所需存储在线，按声明并发测量。缓存热/结果缓存冷、进程冷启动、操作系统页缓存冷、外置盘首次唤醒分别记录。首批结果必须包含可读证据，不是旋转图标、摘要标题或“正在查找”。

秒级掌握的产品含义是快速建立**有出处的知识地图与第一批关键证据**。全量答案若确实需要读 1 GB 内容或重新识图，属于 Q2。不能用 Q2 快速受理回执冒充完成。

## 2. 请求合同

输入包含 query、project/tenant、principal、用途、时间/标准版本、对象语境、模式、deadline、允许模态。未知条件标 UNKNOWN，不自动猜测为某确定对象。

硬边界：权限、用途许可、来源版本有效性。语义线索：零件类型、视图、材料、特征等。未确认的语义线索只能用于排序或分支，不能过早硬过滤造成漏召回。

默认在线过程不依赖多次远程大模型规划。查询意图采用规则/词典/轻量分类；必要时允许一次有界计划补充，但其延迟单列，超时仍可走精确和关键词基线。

## 3. 确定性执行流程

1. 固定访问作用域与 index generation，加载当前撤销/权限水位。
2. 提取原始精确项：标准编号、版次、条款、句柄、代码标识、数字/单位、符号。保留大小写、正负号及 raw 字符串。
3. 并行执行 K2 导航、K1 精确定位和全域稀疏检索。精确编号不等待路由完成。
4. 根据导航选择通常 2—8 个主题分片，执行结构化过滤、语义召回，图像问题增加图像通道。分片数量是起始预算，不是固定完整性保证。
5. 合并候选，以来源/内容族去重，保留不同版本和矛盾证据；稀疏与稠密结果用 RRF 等方式融合，参数由评测选择。
6. 对规则/案例补齐必要关系：适用条件、例外、正反对、对象/视图证据及版本替代记录。
7. 精排通常只处理 20—40 个候选，输出通常 8—16 个知识单元。数值是初始预算；上游 Top-K 不够必须在回执中承认或升级模式。
8. 读取定位原文/图块，检查源版本、许可、hash/已发布不可变状态、坐标及必要字段；装配证据包。
9. 发出 QueryReceipt；若不足，扩大路由或返回部分结果，不能声称无相关知识。
10. 生成答案或交审查引擎；引用校对与“支持了哪些结论”单独验证。

不在每问重新对整个 1 TB 做哈希；通过入库完整校验、不可变存储、代际绑定和抽检保证版本。对可变外部原件先做变化检测，存在疑点则读取/哈希该对象或标待复核。

## 4. 防止路由丢失全库知识

K2 只负责加速，不是唯一检索入口。保留一条覆盖所有已发布文本单元的全域关键词索引、所有对象的精确目录及未解析队列入口。

路由策略：主题 top-3 起步，同时保留跨主题稀疏候选；存在独立精确项时优先直达；候选少、分数集中但缺例外、主题不确定、问题要求“全部”时扩大分片。高风险审查至少同时访问适用标准/词典与案例域，不只访问相似图片域。

跨分片搜索可使用分片词汇统计与内容描述跳过明显无关分片，但概率路由不得作为证明“全库不存在”的依据。Bloom filter 等可作词项存在性加速，其本身不能给出语义完整性证明；如后续引入，必须版本绑定并验证无假阴性的实现前提。

范围穷举查询只有在该作用域内清单完整、所有相关字段已解析且所有必要分片完成时，才可以对**该结构化范围**给出没有匹配记录的结论。自然语言语义检索无结果只表示本轮未找到充分证据。

首期可不给所有图像建向量，但所有图像必须登记；未建图像索引的覆盖缺口随查询回执显示。“全量已登记、部分语义可检索”是合法的阶段状态，不能偷写为全模态全量可检索。

## 5. 证据包，不是原件大搬运

证据单元包含：evidence_id、knowledge_id、asset_version、locator、raw_excerpt/image_crop、单位/表头/条件、来源角色、核验状态、支持的子问题、关联例外、冲突、适用范围、读取状态。

默认预算建议：原文读取合计≤16 MB；证据文本≤8000 token；图块≤6 张、总解码像素≤12 MP；图像实际模型 token 用量由所选模型另测。满足结论所必需的信息超预算则升级 Q2/分批，不能截掉例外后输出确定结论。

相关原件集合的 1 GB 仅作文件/单元清单。若读取全文不可避免，执行器建立子任务和覆盖表，逐批完成并汇总。任何子任务未完成都显示 incomplete，不以摘要填补未读内容。

“完整证据闭包”限定为选定任务模板中的必需角色，例如：事实观察、对象语境、适用规则、例外、版本、核验。它不是逻辑上证明全世界没有其他知识；评测还须检测模板自身遗漏。

## 6. 延迟预算（Q1 设计预算）

| 串行阶段 | P95 工程预算 | 主要控制 |
|---|---:|---|
| 作用域/快照/查询解析 | 0.15 秒 | 本地元数据，不远程规划 |
| 导航、稀疏和精确召回 | 0.30 秒 | 并行，有全域直达 |
| 分片语义/属性召回与融合 | 0.60 秒 | 有界 fan-out、磁盘缓存 |
| 首批原文核对与输出 | 0.65 秒 | 优先读小证据 |
| 首批余量 | 0.30 秒 | 首批合计设计 2 秒 |
| 精排、关系扩展、其余原文装配 | 2.30 秒 | 候选/字节受控 |
| 完整包余量 | 0.70 秒 | 标准包合计设计 5 秒 |

各阶段 P95 预算相加只是工程分配，**不等于端到端 P95 的统计证明**；最终必须端到端测量，并报告阶段分布。网络模型生成、用户首 token、最终回答完成单独计时。磁盘唤醒/OCR 不塞进余量掩盖。

## 7. 回执与不确定性

QueryReceipt 最小字段：query_id、requested_scope、corpus_snapshot、index_generation、coverage_snapshot、searched_shards、skipped_shards/reason、unparsed_scope、timed_out_steps、retrieval_modes、evidence_versions、source_access、latencies、next_actions。

输出状态：SUFFICIENT_FOR_TASK、PARTIAL、CONFLICTED、SOURCE_UNAVAILABLE、NOT_FOUND_IN_SEARCHED_SCOPE、NEEDS_CONTEXT。SUFFICIENT_FOR_TASK 只表示任务模板所需证据角色齐备，不保证推理和答案自动正确，更不等同审查 PASS。

覆盖缺口必须以用户可理解的范围表达，例如“未检索 2 个尚未解析的扫描标准包”；不能只给一个泛化的模型置信度。

## 8. 缓存与失效

缓存分四类：导航、检索候选、已读取原文、最终证据包。缓存键含项目/权限与用途作用域、查询规范化版本、index generation、源版本、检索配置、标准版本和语境。不得只用问题文本作 key。

模型/分词器/索引代际变化时清理相关结果；权限与撤销每次读取权威水位。存储离线可以用明确标记的不可变已核副本，但需要区别“副本可用”与“原位置在线”。冷热缓存分别验收，不以同一问题重复千次代替真实负载。

## 9. 一次完整例子

问题：“这张图没有给轴承画剖面线，是不是错了？”

- 将“轴承”作为用户线索，要求图纸局部证据，不先认定对象成立。
- 查标准件/剖视相关词典、案例、标准版次及例外，保留“普通零件需要剖面线”的对照分支。
- 若轴承身份未确认：返回对象识别证据和缺口，审查为 PENDING，不能把最相似案例结论直接贴上去。
- 若对象和剖视语境确认：以已核条款判断适用性；案例帮助解释，不替代标准。
- 引用原图区域、实体/块路径、标准原页、条款核验记录及反例；回执记录未访问的资料。

## 10. 最坏情况

标准编号存在但页未解析：Q0 定位到原件并标全文不可检索，进入待解析；不凭模型补条款。

长尾主题被粗目录漏分：精确/全域关键词路径仍可命中；纯视觉且未建图像索引则明确缺口，不能承诺已覆盖。

多个分片超时：按时返回已核证据 + PARTIAL，可按许可继续深度任务；不在秒级预算外偷偷循环模型。

更新正在发布：固定旧完整代际或等待新代际，不混合。来源撤销时即使旧缓存命中也阻断内容释放。

## 11. 证据包合同示例（示意，不是真实检索结果）

```json
{
  "query_id": "example-only",
  "task_type": "RULE_VIOLATION",
  "status": "NEEDS_CONTEXT",
  "scope": {"project": "CAD", "purpose": "review"},
  "snapshot": {"corpus": "to-be-bound", "index_generation": "to-be-bound"},
  "object_context": {"feature": "UNKNOWN", "view": "UNKNOWN"},
  "evidence": [],
  "mandatory_roles": ["drawing_observation", "object_binding", "approved_basis", "exceptions"],
  "missing_roles": ["object_binding", "approved_basis"],
  "coverage": {"manifest_ref": "to-be-bound", "completeness_claim": "none"},
  "source_access": "NOT_READ",
  "next_action": "先补图纸定位、对象关联和经核准依据"
}
```

接口中区分 candidate_ids 与 evidence：候选 ID 命中不能算已经读取的 evidence。status 与 missing_roles 由执行器检查，不能由模型为了结束任务随意改为充分。

检索执行器的逻辑约束：先 scope/snapshot，再多路 candidate，后 mandatory 关系、原文读取与权威核对；任何阶段的预算耗尽都产生可解释的 partial 原因。模型只消费已装配证据，不凭候选标题声称已读正文。

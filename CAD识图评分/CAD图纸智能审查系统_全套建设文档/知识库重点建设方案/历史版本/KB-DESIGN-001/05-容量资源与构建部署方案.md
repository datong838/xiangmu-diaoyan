# 容量、资源、构建流水线与部署方案

KB-DESIGN-001；2026-10-16。以下均为规划算例与预算，不是实测用量或硬件采购结论。GB/TB 使用十进制，GiB/TiB 另写。

## 1. 容量由什么决定

原件字节 R、逻辑对象 N、结构化单元 U、向量点 V、向量维度 D、原始/派生比例、索引副本与版本保留数分别测量。不能只用“1 TB”推算全部索引。

规划算例：R=1 TB，N=1000 万对象，U=5000 万文本/结构化单元，选其中 V=200 万高价值单元建稠密向量，D=768。仅为不同数量级的容量练习，未证明当前数据具有该分布。

### 1.1 最小算术

| 项 | 公式 | 算例 |
|---|---|---:|
| 精简对象登记原始行 | N×200 B | 1000 万×200 B = 2 GB |
| 单元精简定位行 | U×128 B | 5000 万×128 B = 6.4 GB |
| 导航卡 | 50000×1000 B | 50 MB |
| 原始 float32 向量 | V×D×4 B | 200 万×768×4 = 6.144 GB |
| 原始 float16 向量 | V×D×2 B | 同上 = 3.072 GB |
| 原始 int8 量化码 | V×D×1 B | 同上 = 1.536 GB |

200 B/128 B 是估算的编码后载荷，**不包含**数据库 B 树、字符串溢出、事务日志、全文索引、关系、ANN 图和副本。量化后仍可能保留原向量做重排，不能把 1.536 GB 当全索引大小；引擎与编码支持需实测。

### 1.2 100 MB 常驻导航工作集示例

| 内容 | 目标大小 |
|---|---:|
| 主题/资料族路由卡 | 50 MB |
| 分片描述、关键词与跨主题映射 | 20 MB |
| 常用实体/标准/别名入口 | 10 MB |
| 当前发布、覆盖摘要与状态 | 5 MB |
| 索引页引用与余量 | 15 MB |
| 合计 | 100 MB |

此预算不包含模型权重、数据库页缓存、完整目录、所有关系和全库向量，也不是把 100 MB 文本装进一次模型提示。工作集超标时按需分页/淘汰，不删全量 K1/K3。先观察主题密度，必要时允许 200 MB 级工作集；100 MB 是优化方向而非优先于召回完整性的红线。

## 2. 1 TB 资料的存储预算方法

S_total = 原件 + 独有派生内容 + 全文/向量/属性索引 + 缩略图 + 当前构建临时量 + 旧代际保留 + 工作缓存 + 安全余量。备份容量另计，去重收益只在测量后扣除。

规划边界算例：原件 1.00 TB + 派生 0.10 TB + 索引 0.12 TB + 图像派生 0.04 TB + 临时 0.15 TB + 旧代际 0.12 TB + 缓存 0.03 TB + 余量 0.25 TB = **1.81 TB**，不含独立备份、系统和其他项目。

这不是推荐把 1 TB 知识库直接塞满一个标称 2 TB 盘：当前解压比例、代际峰值和剩余空间必须实测。扫描图、CAD 渲染和 tar 成员全部展开可能远超算例；采用分批构建与按需物化。

建设前先检查真实可用空间、文件系统、备份位置和峰值构建需求；磁盘保留至少 max(100 GiB, 下一批峰值估计)。不足暂停新批次，保留作业断点，不删除原件腾空间。

## 3. “相关 1 GB”如何秒级定位

只定位清单不需读完 1 GB；从 B 树/倒排/ANN 获得 ID 与位置，再读取几十个片段。顺序传输 1 GB，在假定有效 500 MB/s 时理论仅传输约 2 秒，在 100 MB/s 时约 10 秒；尚未包含随机 I/O、解压、OCR、模型推理和竞争。

因此 Q1 读取有界小证据，Q2 才逐批处理全部相关集合。随机读取几万小文件即使字节少也可能很慢：派生层用可寻址记录块、分片文本容器、数据库页或分区列式文件，避免只靠数百万散文件。

归档原件不变，派生对象可内容寻址；大 tar.gz 在入库阶段顺序扫描一次，将需要随机访问的单元物化为独立内容对象/记录块并登记映射。ZIP 读取指定成员仍需成员内解压；超大单成员 JSON 也需流式分段。

## 4. 24 GB Mac 本地资源预算

本节只是设备档位设计，不假设已在 M5 上测出吞吐。

| 组件 | 常驻预算上限建议 |
|---|---:|
| 操作系统与其他应用预留 | 8 GB |
| 目录/全文服务及其缓存 | 2 GB |
| 语义索引服务及热点页 | 4 GB |
| 查询 embedding / 精排模型 | 3 GB |
| 检索服务、并发证据解码 | 1 GB |
| 弹性余量 | 6 GB |
| 合计 | 24 GB |

100 MB K2 计入服务预算，不能再将模型和向量常驻额外无上限叠加。GPU 使用统一内存，不能将 GPU 显存另算成免费容量。内存压力/交换增长时先降低离线作业和精排并发，不先损失精确检索。

离线构建与在线服务分时或按配额运行：CPU 解析初始 1—2 worker，重 OCR/视觉作业初始 1 worker，批量向量写入限速。MacBook Air 长时间满负载的散热与供电条件影响吞吐；实测持续 30 分钟以上，不能只看前一分钟峰值。

本地原型先服务 1 个交互请求，另测并发 4；尚未达到时保留单用户范围说明。查询不要求 NVIDIA GPU；大批量 OCR/视觉编码可作为独立工作站任务，但外发资料和费用另行授权。

## 5. 推荐部署与迁移触发条件

原型：内置盘有限的 K2、目录与热点；外置 SSD 原件、主要索引和 staging。分片目录可在内置盘缓存，但检查外置卷 UUID/标识，禁止磁盘脱落时误写同名内置路径。

本地服务选型：SQLite 目录/关系/全文基线；Qdrant 原生 ARM64 支持与依赖在 W1 验证后固定，若服务容器化，内存开销一并计入。Windows/Linux 单机服务可复用数据合同，但不直接假定索引二进制跨版本/架构通用。

触发扩展：RSS/内存压力持续超预算、并发 4 的 P95 超标、建立下一代索引空间不足、离线建设侵占在线响应、可靠性要求超出移动外置盘。先把构建任务移到获准工作站，仍不够再将目录迁移 PostgreSQL/全文迁移服务型引擎，业务 ID/定位/发布合同保持稳定。

SSD 检索、大规模索引方法可以借鉴 DiskANN，但不把其论文硬件/数据集成绩搬成 Mac 的承诺，也不要求第一期集成该实现。见 [07](07-依据审阅与设计决策.md)。

## 6. 六段离线流水线

| 段 | 工作 | 输入/输出及断点 |
|---|---|---|
| P0 发现与登记 | 列目录/归档成员，记录来源和限制 | immutable 输入清单；新对象即有入口 |
| P1 验货与分型 | 校验、格式、安全限制、重复簇 | 每对象状态；坏件/不支持不消失 |
| P2 结构提取 | 原生文字、CAD 实体、表格、视图候选；必要 OCR | 记录级输出、质量和覆盖缺口 |
| P3 知识组织 | 单元、主题、关系候选、条款/案例人工核验 | 候选与确认库分开 |
| P4 索引生成 | 全文/属性全覆盖目标、精选语义、视觉后续补齐 | 代际、模型、分片和清单绑定 |
| P5 验收发布 | 校验、评测、发布、影响传播 | 原子 manifest 切换与回滚点 |

每个任务的幂等键建议为 input_version + parser/profile_version + output_kind。完成标志只能在输出落盘、校验、登记提交后写入；同一键只允许一个写入者，失败保留临时输出，重试最多 3 次/轮并记录退避；完整性冲突停止该对象，其他独立对象可继续。

优先读原生结构，已有可靠文字不重复 OCR。OCR 不自动“修正”图纸尺寸；疑似关键符号产生候选和复核队列。巨型 JSON 流式解析，图像分批，禁止一次把全库载入内存。

## 7. 建设成本与工期如何估计

先对各模态抽样测量 bytes/s、pages/s、records/s、CPU 时、峰值 RSS、派生/索引放大率和失败率；简单/密集/损坏/扫描/长尾分层取样。

预计时间按每类 N_i / throughput_i 求和，并考虑实际 worker 数、资源争用、重试和专家复核；不能将最简单 PDF 的速度外推到 CAD 与扫描件。

模型调用成本按实际页/图/输入输出 token、缓存和当日价格独立记录；本地运行记录 CPU/GPU 时间与电量估计来源。离线建库费、在线查询费、索引重建费和人工核验费分列。没有规模测量前不报“几天建完 1 TB”或固定总价。

## 8. 备份与可重建性

外置盘承载不等于已有备份。原件、目录、确认经验/决定、权限与发布 manifest 优先备份；索引备份与从原件重建时间权衡。新代际发布前验证可回退，定期选一个分片从备份恢复并运行查询回放。

不安装常驻定时任务是本次边界；实施阶段维护可由明确启动的批处理/服务事件驱动，再根据用户要求设置巡检。不会为此恢复之前被停用的下载跟进。

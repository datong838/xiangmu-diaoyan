# CAD识图规范检查——第一阶段任务与目标

## 当前进度

能力验证准备：客户已提供18份标准与T01–T05少量正误样例、32条纠错标签，通用专家经验后续补充。当前围绕32项整理相关规则与证据，由用户肉眼审核后再做小范围识图验证；尚未完成能力验证。样例用于提炼和回测可证明样例能力，新图适用范围后续验证。

## 一、项目定位

第一阶段建设一套面向机械 CAD 图纸的智能规范检查系统。系统接收客户提供的 PDF 图纸，并支持 DWG、DXF 源文件作为辅助输入，依据经核准的国家标准、客户专家经验和项目判据库，识别图纸中的不规范点，定位问题位置，说明判定依据，输出可复核的检查结果。

第一阶段形成的是“图纸规范检查能力”。标准答案图纸、评分项和权重驱动的学生图纸自动评分属于第二阶段，在第一阶段的识别、判据、证据和报告能力稳定后再建设。

## 二、第一阶段目标

1. 建立从图纸上传、解析、识别、规则检查、模型复核到报告输出的完整业务流程。
2. 将国家标准条款和专家经验转化为可维护、可版本化、可追溯的判据库。
3. 对图纸中的尺寸、符号、视图、图线、公差、基准、技术要求等内容进行识别和规范检查。
4. 每个问题均保留原图位置、识别内容、命中判据、依据来源和置信度，支持人工回看与复核。
5. 对识别不清、依据不足或存在争议的项目输出“无法判定”，进入人工复核队列。
6. 通过代表性客户图纸验证误报、漏检、定位和依据引用质量，形成可演示、可试用、可迭代的第一阶段产品。
7. 为每个客户独立开通 License，实现客户、期限、额度、功能范围和使用记录的隔离管理。

## 三、业务处理流程

```text
客户图纸与规则资料
        ↓
PDF解析 / DWG、DXF转换与渲染
        ↓
OCR与图像识别，提取文字、尺寸、符号、图线和坐标
        ↓
结构化要素解析与跨视图关联
        ↓
国标判据、专家规则和确定性规则检查
        ↓
大模型推理与结果复核
        ↓
问题定位、依据引用、置信度与人工复核分流
        ↓
结构化结果与规范检查报告
```

系统对每项判据输出三种状态：

| 状态 | 含义 | 处理方式 |
| --- | --- | --- |
| 命中 | 有证据表明图纸存在对应问题 | 写入问题清单并回标原图位置 |
| 未命中 | 已执行该项检查，当前证据表明符合要求 | 写入已检查项，保留检查记录 |
| 无法判定 | 图像不清、要素关联失败、资料不足或依据存在争议 | 进入人工复核队列，不自动给出合规或违规结论 |

## 四、实施阶段与主要任务

### 4.1 资料准备

客户提供或组织整理以下资料：

- 项目适用的国家标准、行业标准和企业标准。
- 专家经验、企业制图规则、常见错误案例和争议处理原则。
- 代表性 PDF、DWG、DXF 图纸，包括正确图、错误图及已知问题说明。
- 图纸类型、专业范围、优先检查项和验收关注点。
- 专家标注、规则确认、复核结论及争议裁决。

研发工作包括：

- 定义资料接收清单、格式、命名和版本要求。
- 完成资料导入、图纸预处理、标准索引和规则数据结构设计。
- 区分国家标准明文判据与专家经验判据，避免将经验规则错误标注为国标要求。
- 对国标引用记录标准号、版本、条款、页码和证据图，保留可追溯依据。

客户已整理并提供的标准、图纸和专家支持属于客户承担的资料与专家支持，不计入研发费用。

### 4.2 能力验证

选取约 10 至 20 张有代表性的客户图纸进行小规模验证，覆盖清晰 PDF、扫描件、不同零件类型及典型错误。能力验证不是简单调用若干次 API，而是验证完整技术链路能否达到产品研发条件。

重点验证：

- PDF、DWG、DXF 的解析、转换和渲染质量。
- OCR 对文字、尺寸、公差、符号、标题栏和技术要求的识别效果。
- 图像模型对图线、视图、剖视、局部结构和空间关系的理解能力。
- 判据检索、规则命中、证据定位和依据引用的正确性。
- 多模型链路的稳定性、单张处理时间和 API 成本。
- 误报、漏检、定位错误、错误引用和无法判定的主要原因。

能力验证完成后形成验证报告，明确可直接实现的检查项、需要专家补充的判据、暂不具备稳定能力的检查项以及产品原型范围。

### 4.3 产品原型

基于验证结果实现可运行原型，打通以下最小闭环：

1. 上传一张图纸。
2. 自动解析并识别图纸要素。
3. 执行一批优先级较高的规范检查规则。
4. 在原图上标出问题位置。
5. 展示问题说明、依据、置信度和复核状态。
6. 导出结构化结果或检查报告。

原型阶段优先证明“能找到问题、能说明原因、能回到原图核查”，并用客户样本评估稳定性。

### 4.4 产品设计与研发

产品研发包括以下模块：

| 模块 | 主要任务 |
| --- | --- |
| 图纸管理 | 上传、分类、状态管理、版本管理、批次管理和原文件留存 |
| 格式处理 | PDF解析；DWG、DXF 转换、渲染和必要的图层信息提取 |
| OCR与图像识别 | 提取文字、尺寸、公差、符号、标题栏、技术要求、图线和坐标框 |
| 要素结构化 | 将识别结果转换为尺寸、视图、基准、公差、粗糙度、螺纹等结构化对象 |
| 判据库 | 管理国标判据、专家规则、适用范围、版本、证据和启停状态 |
| 规则引擎 | 执行确定性规则、数值查表、关联检查和一致性检查 |
| 模型推理与复核 | 处理复杂关系、补充解释、交叉复核，并控制不确定结论 |
| 证据与回标 | 保存问题位置、原图截图、识别原文、判据来源和处理链路 |
| 人工复核 | 处理低置信度、无法判定和争议项，记录复核结论 |
| 检查报告 | 输出问题清单、严重程度、依据、位置、建议和已检查项 |
| 系统管理 | 用户、角色、日志、配置、API用量和运行监控 |
| License管理 | 按客户开通、停用、续期和限制系统使用权限 |

### 4.5 演示与交付

- 使用客户代表性图纸演示从上传到报告的完整流程。
- 展示问题位置、依据来源、判据类型、置信度和人工复核入口。
- 对演示中发现的规则遗漏、误报和交互问题进行修正。
- 完成交付部署、基础配置、使用说明和必要的操作培训。
- 为客户创建独立 License，并配置约定的期限、额度和功能范围。

### 4.6 客户试用与验收

- 客户在约定范围内上传真实图纸进行试用。
- 客户专家复核系统输出，反馈误报、漏检、错误定位和错误依据。
- 研发侧根据反馈调整识别参数、规则条件、判据适用范围和报告表达。
- 使用独立测试图纸进行验收，避免只使用开发期间反复调试的样本。
- 输出试用总结和验收报告，记录已达到的能力、适用范围和待后续建设项。

## 五、判据库建设要求

### 5.1 国家标准判据

- 必须核对标准名称、版本、条款号、页码和原文证据。
- 正式报告引用应能够回到标准原页或条款证据图核验。
- 标准状态需区分现行、过渡和废止，并保留版本变更记录。
- 标准原文中的数值表、映射表和范围条件应结构化保存，供规则引擎直接查询。

### 5.2 专家经验判据

- 明确标记为“专家经验”或“企业规则”，不填写虚构的国标条款号。
- 记录规则来源、适用条件、判断逻辑、反例和误报风险。
- 由客户组织专家确认、复核和争议裁决。
- 研发负责将确认后的规则转化为系统可执行、可配置、可追溯的判据。

## 六、客户 License 管理

每个客户使用独立 License，至少管理以下内容：

- 客户标识和 License 编号。
- 试用版或正式版。
- 生效日期、到期日期、暂停、恢复、撤销和续期状态。
- 可用账号数、并发用户数、图纸处理量和 API 使用额度。
- 可使用的图纸类型、检查规则、报告功能和部署环境。
- 试用转正式的状态变更。
- 登录、图纸处理、额度消耗和管理操作的审计记录。

License 管理功能属于第一阶段产品研发范围，相关开发工作包含在全栈研发人力中。第三方 CAD 解析或转换工具自身的商业授权应按实际选型另行确认。

## 七、第一阶段交付物

1. CAD 识图规范检查 Web 系统或可部署应用。
2. PDF 主输入及 DWG、DXF 辅助输入处理能力。
3. OCR、图像识别、要素结构化和规则检查链路。
4. 国家标准判据库和客户专家经验规则库。
5. 问题证据回标、人工复核和检查报告功能。
6. 客户、用户、权限、用量、日志和 License 管理功能。
7. 能力验证报告、测试记录、试用总结和验收报告。
8. 部署说明、系统配置说明和用户操作说明。

## 八、验收重点

第一阶段不使用单一“准确率”作为验收结论，至少分别检查以下指标：

| 指标 | 验收关注点 |
| --- | --- |
| 误报率 | 正确图纸或正确标注被错误判为问题的比例 |
| 漏检率 | 已知错误点未被系统发现的比例 |
| 定位准确性 | 问题回标位置是否与真实错误位置一致 |
| 依据准确性 | 标准号、版本、条款和专家规则是否适用且引用正确 |
| 三态输出准确性 | 无法确认的问题是否正确进入“无法判定”和人工复核流程 |
| 稳定性 | 同类图纸重复处理的结果是否稳定，异常是否可追踪 |
| 性能与成本 | 单张图纸处理时间、API调用量和平均处理成本是否在约定范围内 |

T01 至 T05 正误图纸及现有专家纠错点可作为第一批能力验证和回归测试材料。正式验收还需使用未参与开发调试的独立客户图纸，并由客户专家确认真实问题点。

## 九、第一阶段范围边界

第一阶段包含：

- CAD 图纸内容识别与结构化。
- 基于国标和专家经验的规范检查。
- 问题定位、依据说明、人工复核和报告输出。
- 判据库、用户、日志、用量和逐客户 License 管理。

第一阶段暂不包含：

- 根据标准答案图纸和评分细则自动计算学生分数。
- 题目、评分项、分值、扣分规则和教师评分工作台。
- 基于大规模标注数据训练或微调自有本地视觉模型。
- 未经核准的专家意见自动作为国家标准依据使用。

上述学生图纸评分能力属于第二阶段。第二阶段将复用第一阶段形成的图纸解析、要素识别、判据库、证据定位、人工复核和 License 基础能力。

## 十、阶段完成标准

第一阶段完成应同时满足以下条件：

1. 代表性客户图纸能够稳定进入系统并完成处理。
2. 已纳入范围的判据能够实际执行，并输出命中、未命中或无法判定。
3. 问题结果能够回标原图，并给出经核准的国标依据或明确标识的专家经验依据。
4. 低置信度和争议项能够进入人工复核，不被自动包装成确定结论。
5. 系统能够为不同客户独立开通 License，并记录额度和使用情况。
6. 完成演示、部署、客户试用和独立测试集验收，形成可复查的结果记录。
7. 第一阶段已知限制、暂不支持的图纸类型和待第二阶段建设内容均有明确说明。

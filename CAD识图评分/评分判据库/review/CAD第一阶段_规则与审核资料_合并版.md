# CAD第一阶段判据库设计

## 阶段与目标

当前为能力验证。先围绕客户T01–T05的32条纠错标签，整理能追溯、能复核的规范检查判据；不预设全部可自动判断。22份客户标准已收集，不意味着标准体系齐全或版本现行。

## 技术路径

原始PDF/源图 → 页面文字、符号、线条与坐标 → 尺寸/符号/视图的对象关联 → 带适用条件和例外的规则 → 违规候选、证据位置或无法判定。

PDF优先保留文本、矢量与图像多种通道；若后续拿到DWG/DXF，再补几何实体和标注关联。多模态模型可抽取并审核对象关系；能确定表达的规则用代码执行，复杂判断保留人工核准，不要求本阶段所有规则都代码化。

## 分层与状态

- L1：属性或查表检查；仍依赖符号、用途及尺度正确读取，不能因为归类L1就直接全自动放行。
- L2：标注与对象、跨视图、尺寸端点关系。关联不清时无法判定。
- L3：材料、工艺等图外知识。信息不足只给核查建议。

三态输出：发现违规候选 / 在已检查范围未发现违规 / 无法判定。未发现不等于整张图合格。每条记录依据类型、版本、条款、PDF物理页码、引文、完整上下文、适用条件、例外、图上证据、审核状态。

## 已确认的边界

1. 剖切符号粗实线不推出必须比轮廓线更粗或固定0.7mm。
2. 角度数值应以标注为依据，不能由绘图外观与数值不一致直接判定数值错误。
3. 关键词零命中不证明所有标准无明文；经验卡都是待客户专家核准候选。
4. 文字OCR准确不代表公差偏差、符号、引线和对象关系准确。保留原图位置并记录分歧。
5. 当前规则来自这批样例；后续仅以图像和规则输入回测，能验证样例处理能力。需记录是否输入标准答案及结果；新图适用性另验证。

## 当前工作顺序

整理32项相关原文与图例 → 用户肉眼复核 → 修改并确认验证范围 → 少量API能力测试 → 原型 → 产品研发 → 演示交付 → 试用。当前不进入图纸识别运行。

# 依据核准与多方复核技术方案

## 目标

核准引文、命题、适用条件与案例关系，减少看漏、看错和错误推导。按32个纠错点整理相关条款，不先把22份标准全量转规则。

## 四个分开记录的判断

1. 读取：文字、尺寸、符号、上下偏差、箭头、线型分别读到什么；坐标及原页是什么。
2. 出处：引文是否在声明的版本、条款、页码；正文与图例、脚注、前后页是否齐全。
3. 命题：原文是否支持该规则；是否加入原文没有的要求；例外是否遗漏。
4. 应用：规则是否适用于图中对象；对象关联或图外信息是否充分。

机器OK只用于完整引文位置匹配，不代替第3、4项。原页及裁图均为证据呈现形式，不因标注E0/E1就自动通过。

## 多模型审核方法

选用能力不同的模型，先分别读取同一原资料、填写明确字段与证据，再比较差异。记录模型版本、提示、输入范围、原图坐标、读取结果、规则结论及不确定项。重要小符号、偏差、箭头和对象关系优先单列；不只复述先前模型答案。

结论一致可提高可用性，但可能共享错误。结论分歧留待原图及人工核准；不按多数票改写标准。模型无法确认就输出无法判定。客户专家提供实践经验、圈定争议目标及解释合法例外。

## 样例与回测

同批图提炼规则后，用图像读取能力和规则回测，可验证方案对样例的处理能力。标记为样例回测；不得把32条答案作为识别输入，也不得称已证明新图泛化。规则冻结后增加新图验证适用范围，非当前资料整理的前置要求。

## 当前停止点

先提交完整相关页、正误图及32项审核表给用户肉眼复核。本轮不执行新的模型API调用或图纸识别测试。后续用户确认后再执行小规模能力验证。

## 文件与分发

源数据为review/claims.json、review/pending_claims.json、evidence/batch.json及criteria/convention。生成器负责同步pack_v1。相对文件路径统一以评分判据库根目录为基准；须一并分发所引用的国标、工程图审核和evidence，单独pack_v1不是自包含。

管理侧review/manager含核查探针答案，不分发；已看答案的本轮审查不算盲测。若提供两道不同页码探针给同一模型，会有相互提示，只用于一致性检查；真正盲检应独立分配且不附已有audit裁决。

# OCR可信度与限定范围检索审计

## 已发现的风险

文本层即使汉字比例较高也可能丢失条款数字和符号；OCR可能把剖读成部。原引文工具用短前缀、单个分句或全页LCS召回，可能误给精确通过。部分旧裁图只含“外花键”“波浪线”等短语，不能证明整项规则。

当前撤销原17条OK与3条模糊通过的认证；旧窄裁图不再引用。完整相关页已进入复核包，机器状态统一待重核。本轮没有重跑批量OCR，避免在用户肉眼审核前继续能力测试。

## 最小工具修正

verify_cite：完整引文匹配才可OK；部分或连续窗口近似仅模糊候选；不再启用跨位置分句或全页LCS拼凑；依赖缺失标ERROR；裁图合并匹配区域。匹配不验证规则语义。

negative_evidence：缺OCR不记为零；检索命中仅是候选原文，零命中仅表示限定资料与词表未检出。文本层和已有文本缓存来源未核准时不能称两个独立OCR审核。

build_review_pack：同步审核状态，附上下文完整页及客户正误图；补待资料项；明确路径和管理侧答案边界。

## 人工查看次序

先原页及条款标题，再正文、图例、脚注和前后页；最后对照正误图中的具体对象。重点检查φ/R/Sφ/SR、H/h、公差上下偏差、几何公差图形、线宽/线型、箭头及是否指向同一个面或孔。

## 尚未覆盖

22份PDF共488页完成文件与页数清点；本轮重点核查32项涉及的条款与图例，并查看全部10张正误图。未对488页逐页逐字做视觉认证，DWG未解析，版本现行性未核准，专家通用经验及部分外部标准待补。

## 当前交叉读取结果

新增4份标准234页全部执行PP-OCRv4、显式PP-OCRv5 Mobile和Apple Vision；另十张客户图及29个旧标准引用页，共273页。无缺页，三路各270页有文字框、3页空结果；1182 PDF第2、4、131页已回看为空白扫描页。空结果不当条款不存在。矢量两解析器通过CTM换算后核对，详细范围与分歧见08报告；未认证488页逐字无误。

# 新增国标与OCR矢量交叉复核方案

## 范围与现状

2026年10月9日清点22份国标，新增1182-2018（132页）、131-2006（39页）、1800.1-2020（36页）、15754-2025（27页），总488页。围绕现有32条标签补齐出处、适用条件和例外；132页文件做全页读取索引及重点原页核准，不声称每页每符号都已人工认证。

10张客户PDF均有矢量路径而无可提取文字。文字可能为轮廓路径，矢量是页面绘制对象，不自动等于CAD语义实体。新增标准多数是扫描页，不得从图像生成假矢量证据。

## 双向核查

A：文字层/独立OCR保留每个文本框坐标与原图；选取代表页比较中文、字母大小写、数值、符号，选适合本机和材料的组合，不能仅据通用排行榜称最优。
B：PyMuPDF提取原始矢量路径与pdfplumber独立解析核对坐标、线宽分布；导出直线长度、曲线近似长度、子路径端点与几何闭合状态。保留closePath原操作标志，不能将一组绘制指令都判断为同一个闭合对象。线宽单位pt，纸面mm转换须标示，真实零件长度必须另有图样比例/源图标定。
C：把文字框与路径绘在同一原页坐标，圈定关键符号和关联；两通道差异进入原图视觉核准。文字轮廓与实体线、剖面线与轮廓线不凭长度/闭合性自动分类。读取一致只是读取线索，不直接批准规则。

## 文件与脚本

新增评分判据库/tools/pdf_crosscheck.py（清点、OCR与矢量结构化证据）、tools/vision_ocr.swift（若本机支持Apple Vision，作为不同OCR引擎对照）、tools/test_pdf_crosscheck.py（反例与几何验证）。其他现有工具只做必要同步；完成后更新规则源数据、pack_v1、映射表、审核入口、复核报告、合并版及交接清单。原PDF/DOCX/DWG/Excel不修改。

中间缓存及证据放evidence/crosscheck_20261009；模型库放本机临时依赖目录，版本、模型哈希、DPI与引擎参数记录。优先本地免费工具，不因选型擅自上传客户PDF到付费第三方API。

## 核准顺序

完整索引四份新增标准 → 反查五条W卡及T01-8/T03-3 → 查看表格图例和前后条款 → 分离符号识别、要素关联与适用性 → 同步32项规则状态。旧8份关键标准按已有引用页补OCR交叉核对；客户图矢量提取用于资料复核，尚非新图自动规范检查或学生评分。

## 自测与完成口径

已知直线/矩形/开放曲线、多子路径、填充图形、零宽线、旋转页和无矢量扫描页反例；实际10图两解析器路径/坐标与宽度差异记录，不能仅测试数目相等。OCR缺页/空结果保留失败，不当零命中；逐页覆盖索引可查。

完成时输出已确认修正、仍需客户专家裁定和读取限制；不把旧报告已有通过当新检查结果，不自动宣称新版标准已现行有效。费用按实际对话Token日志与官方模型价格、不计缓存记录，OCR本地执行无外部API费用。

## 四、双解析器矢量实测与单位陷阱

十张客户PDF均为矢量绘制、无文字层和图像对象。文字多数由轮廓路径绘成，闭合字形、箭头、框线不能当成零件轮廓。

MuPDF与独立PDFMiner/pdfplumber分别读取路径、坐标和线宽。发现T01正确图、T04错误图、T05正误图含0.75等比CTM：pdfplumber的原始w=1.92换算到页面为1.44pt；w=0.96换算为0.72pt。若直接比较原始w会误判。现保留原始值、CTM和页面值，非等比变换不伪算单个线宽。

换算后十图所有描边线宽分布一致。8图逐对象bbox/线宽差异计数0；T03正误图各1个差异，是填充路径拆分和非描边宽度差异，保留原记录，不把它当图纸违规。路径计数不等于零件实体计数，bbox/宽度一致也不证明符号和用途正确。

T05已把候选路径位置覆盖在原图：剖切端线页面宽度正确图2.04pt（纸面约0.720mm），错误图0.84pt（约0.296mm），可见轮廓主粗线1.44pt（约0.508mm）、主细线0.72pt（约0.254mm）。这些是PDF默认页面尺寸下的绘制值，打印缩放会改变纸面毫米；不是量取零件的尺寸，也不能由此推出标准要求端线必须大于轮廓。端线角色已视觉核对，实际选线组还需核准。

导出直线精确页面长度、贝塞尔128弦近似长度、独立子路径首尾、几何闭合和closePath操作。显式长度与末子路径隐式闭合边分列。闭合不等于零件轮廓闭合；没有进行拓扑重建、跨视图实体配准、DWG语义解析或自动违规判定。

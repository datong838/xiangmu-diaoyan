# CAD第一阶段判据库设计

## 阶段与目标

当前为能力验证。先围绕客户T01–T05的32条纠错标签，整理能追溯、能复核的规范检查判据；不预设全部可自动判断。22份客户标准已收集，不意味着标准体系齐全或版本现行。

## 技术路径

原始PDF/源图 → 页面文字、符号、线条与坐标 → 尺寸/符号/视图的对象关联 → 带适用条件和例外的规则 → 违规候选、证据位置或无法判定。

PDF优先保留文本、矢量与图像多种通道；若后续拿到DWG/DXF，再补几何实体和标注关联。多模态模型可抽取并审核对象关系；能确定表达的规则用代码执行，复杂判断保留人工核准，不要求本阶段所有规则都代码化。

## 分层与状态

- L1：属性或查表检查；仍依赖符号、用途及尺度正确读取，不能因为归类L1就直接全自动放行。
- L2：标注与对象、跨视图、尺寸端点关系。关联不清时无法判定。
- L3：材料、工艺等图外知识。信息不足只给核查建议。

三态输出：发现违规候选 / 在已检查范围未发现违规 / 无法判定。未发现不等于整张图合格。每条记录依据类型、版本、条款、PDF物理页码、引文、完整上下文、适用条件、例外、图上证据、审核状态。

## 已确认的边界

1. 剖切符号粗实线不推出必须比轮廓线更粗或固定0.7mm。
2. 角度数值应以标注为依据，不能由绘图外观与数值不一致直接判定数值错误。
3. 关键词零命中不证明所有标准无明文；经验卡都是待客户专家核准候选。
4. 文字OCR准确不代表公差偏差、符号、引线和对象关系准确。保留原图位置并记录分歧。
5. 当前规则来自这批样例；后续仅以图像和规则输入回测，能验证样例处理能力。需记录是否输入标准答案及结果；新图适用性另验证。

## 当前工作顺序

整理32项相关原文与图例 → 用户肉眼复核 → 修改并确认验证范围 → 少量API能力测试 → 原型 → 产品研发 → 演示交付 → 试用。当前不进入图纸识别运行。
